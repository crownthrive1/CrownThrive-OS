## DAIL Evidence Spine v2 Source Build — 2026-08-26

## Outcome

DAIL v2 is source-implemented for controlled testing across the CrownThrive OS and CHLOM repository family. The build extends the existing global logical chain; it does not create a replacement ledger, ninth framework, voting participant, virtual-world runtime or native Substrate deployment.

The build includes:

- an additive Supabase migration that preserves legacy 1.0/1.1 verification and the documented correction while adding a full v2 provenance preimage;
- append-only ingress, external-verification, processing, anchor and factory-continuation receipt contracts;
- a Stripe webhook adapter that verifies exact raw bytes, multiple `v1` signatures, overlapping versioned secrets and the 300-second replay window before DAIL admission;
- provider event ID and idempotency conflict controls;
- an OS adapter and adversarial fixtures for hash mutation, reorder, truncation against an independently held head, replay, trust separation and fail-closed writes;
- bindings for all five Pentafabric layers and all twelve modern CHLOM capability pallets;
- PentaContour and continuation contracts using deterministic digests, leases, fencing, readback, rollback and independent-verification gates. Claim acquisition, expiry reclaim and crash certification remain runtime-pending; and
- a source projection into `chlom-protocol` with stable P01–P12 machine records, public-safe schemas and a pure TypeScript Stripe verifier.

## Evidence boundary

Stripe HMAC admission is `E4_EXTERNAL_SYMMETRIC_VERIFIED`: the source bytes originate outside CHLOM and pass provider signature and freshness checks, but the receiver also holds the shared secret. It is therefore not public non-repudiation and not independently immutable by itself.

The build defines the next two boundaries without claiming them complete:

- `E5_EXTERNAL_ASYMMETRIC_ATTESTED` requires a separately identified external party and verifiable asymmetric evidence.
- `E6_INDEPENDENTLY_ANCHORED` requires an independently controlled append-only/timestamp/object-lock surface plus successful readback.

The existing CrownThrive External Evidence Relay is reserved for separate provider readback and witness dispatch. No duplicate scheduler is introduced.

## Promotion state

`CONTROLLED_TEST / RUNTIME_APPLY_HELD`

Source validation does not authorize runtime mutation or production promotion. Promotion still requires disposable-database migration proof, preservation of the live legacy chain, privilege and mutation-negative tests, secret binding, a real provider delivery, independent readback, external anchor write/readback, exact-SHA cross-repository verification and a D3 human decision.
