# CIE Institutionalization — Wave 2

**Date:** August 23, 2026  
**Framework:** `ct.framework.cultural-imprint-engine`  
**Canonical name:** Cultural Imprint Engine  
**Companion repository:** `crownthrive1/CrownThrive-CIE`

## Founder directive carried forward

Wave 2 locks the following institutional rules:

1. The engine is **Cultural Imprint Engine** only.
2. `CIE` is the canonical shorthand for Cultural Imprint Engine.
3. Public and internal usage are profiles of the same engine.
4. Cultural Imprint Engine is interoperable with CHLOM.
5. Interoperability does not merge or transfer authority between CIE and CHLOM.

## Canonical name lock

`Cultural Impact Engine` remains preserved only as stale historical/public-projection drift where source history requires it. It is rejected for new engine identities, machine records, API/MCP contracts, agents and current documentation.

## Public and internal profiles

Wave 2 establishes:

- `ct.cie.profile.public.v1` — public-safe doctrine, validation, sanitized handoffs and public-safe status projection;
- `ct.cie.profile.internal.v1` — RBAC-governed internal operations, opaque evidence references and separately authorized private-runtime workflows.

Both profiles retain the same D2 ceiling, non-voting state and human-reserved D3 boundary.

## CHLOM interoperability

Wave 2 establishes `ct.contract.cie-chlom.interop.v1` as a typed bidirectional contract.

### CIE → CHLOM

CIE provides cultural/narrative state, conditions, audience/canon state, source references and correlation/digest metadata.

### CHLOM → CIE

CHLOM provides rights, license, permission, evidence and record/digest state.

Neither direction inherits the other authority's decision.

## Composed readiness

The deterministic composition layer may resolve:

- cultural denial;
- CIE HOLD;
- rights denial;
- CHLOM rights/license/permission HOLD;
- evidence HOLD;
- `COMPOSED_READY_NON_EXECUTING`.

The positive composed state remains non-mutating. It does not authorize execution, provider writes, economic activation, checkout, entitlement, D3 or sovereign action.

## Explicit non-effects

Wave 2 does not by itself:

- deploy a live public CIE API/MCP endpoint;
- create CHLOM mutations;
- change the CIE D2 ceiling;
- automate D3;
- create a sovereign vote;
- activate ThriveEvergreen economics;
- create a price, checkout, payout or entitlement;
- issue a license;
- activate provider or production writes.

Those remain separately governed states.
