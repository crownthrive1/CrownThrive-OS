## Founder architecture clarification

The earlier packet incorrectly treated a framework child as requiring its own physical GitHub repository. The corrected CrownThrive definition is:

> A framework child is an independently executable framework package with its own workflow, validator, engine, skills, tools, algorithms/decision interface, evals, API/MCP contracts, federation identity, documentation and commercialization candidate surfaces. A separate repository is optional distribution packaging.

This correction does not lower governance. Physical repository absence is no longer a framework-existence blocker, but OIDC authority binding, Agent D certification, protected-runtime integrity, IP classification, framework acceptance and public/production activation remain independently fail-closed.

## OIDC hardening

The prior child governance template granted `id-token: write` at workflow scope while also running on `pull_request`. That is corrected.

Current template policy:

- PR validation job: `contents: read` only;
- trusted non-PR federation job: `contents: read` + `id-token: write`;
- no provider/customer write;
- no direct-to-main repair;
- no auto-merge;
- no `sync_agents`;
- no child self-certification;
- no sovereign vote creation.

This closes the package-template OIDC-scope defect itself. The broader federation gate for exact workflow/ref/environment → institutional-agent/capability enforcement remains independently governed until the runtime proves it.
