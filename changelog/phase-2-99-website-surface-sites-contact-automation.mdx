# Phase 2.99 — Website Surface, Sites & Contact Automation

**Date:** August 20, 2026  
**Program namespace:** `institutional_build_phase`  
**Current subphase:** `2.99`  
**Disposition:** `read_probe_and_planning_active / external_provider_mutation_gated`

## Objective

Extend CrownThrive's governed design/API architecture into websites so Sites-backed and other API-connected public properties can consume approved Figma/Canva assets, expose reliable contact/CTA interactions, emit evidence, detect drift, and prepare autonomous remediations without giving an agent uncontrolled website authority.

## Contact and consent boundary

Operational contact is not promotional consent. Any future routing from a website contact into ThrivePush, Collab Portal, CRM, analytics, or automated email must preserve source/form version, purpose, fields, consent basis, suppression state, destination, retention, and correction/delete path.

## Claim/namespace drift

Current public CrownThrive surfaces expose multiple platform-count statements and phase language. Because CrownThrive maintains separate count universes and phase/maturity namespaces, the Website Surface Agent opens evidence-controlled reconciliation when public statements differ from institutional records. It does not pick a number/phase by arithmetic convenience and rewrite the website automatically.

## Security evidence

## Provider-write hard gate

Production mutation requires exact provider/version, project identity, auth/scopes, allowed fields/assets, rollback checkpoint, read-before-write, read-after-write, idempotency/concurrency, budgets, DAIL evidence, and provider-exit certification.
