# Phase 2.99 — Website Surface, Sites & Contact Automation

**Date:** 2026-08-20<br />**Program namespace:** `institutional_build_phase`<br />**Current subphase:** `2.99`<br />**Disposition:** `read_probe_and_planning_active / external_provider_mutation_gated`

## Objective

Extend CrownThrive's governed design/API architecture into websites so Sites-backed and other API-connected public properties can consume approved Figma/Canva assets, expose reliable contact/CTA interactions, emit evidence, detect drift and prepare autonomous remediations without giving an agent uncontrolled website authority.

## Implemented machine state

The private THIVEBASE/Supabase control boundary now records website surfaces, creative-asset routes, interaction-check definitions, append-only check evidence, remediation queues and provider-write certification state. The records are private, RLS-protected and service-role-only. Exact schemas, table names, service identifiers and deployment topology remain restricted institutional evidence.

## Governed website adapter

A dedicated authenticated adapter supports bounded surface discovery, interaction checking, asset-route inspection, queue inspection and remediation planning. Exact tool namespaces, protocol/deployment versions and central-dispatch topology remain in restricted custody. External update execution remains disabled and approval-gated.

## Seeded website surfaces

CrownThrive.com and the KJV Visualized/Sermon Toolkit property have stable internal surface records and current public hosts. Versioned provider/project and release-lineage evidence is retained privately. Public reachability or saved-project evidence does not certify a write API or authorize external mutation.

## Creative asset routing

CrownThrive design-system and brand-kit sources are registered privately by immutable reference and version. The public rule is that Figma governs approved interface contracts, Canva supplies downstream production assets, and every website route defaults to `auto_sync_allowed=false`. Exact file, kit and project identifiers remain restricted.

## Initial check outcome

The initial bounded run exercised registered public interaction checks without submitting a form. Detailed URLs, checksums, field observations, findings and remediation-queue records remain in private evidence custody. A successful public response is not provider-write certification, and a finding may be planned but not externally applied.

## Automated cadence

Daily read-only checking and internal remediation planning are active under private job identities. The jobs do not alter external websites. Exact scheduler names and live queue state remain restricted operational evidence.

## Contact-data and consent boundary

Operational contact is not marketing consent. Any future routing from a website contact into ThrivePush, Collab Portal, CRM, analytics or automated email must preserve source/form version, purpose, collected fields, consent basis, suppression state, destination, retention and correction/delete path.

## Public claim / namespace drift

Current public CrownThrive pages expose multiple platform-count statements and public phase language. The institutional system also maintains multiple legitimate count universes and phase/maturity namespaces. Therefore the Website Surface Agent opens evidence-controlled reconciliation when statements differ; it does not pick a number or phase by arithmetic convenience and rewrite the website automatically.

## Provider-write hard gate

A Sites/website provider adapter cannot execute production mutation until exact provider/version, project identity, auth/scopes, allowed fields/assets, prohibited classes, rollback checkpoint, concurrency/idempotency, read-before-write, read-after-write, cost/request limits, DAIL evidence and provider-exit are certified.

## Downstream phase propagation

- **Phase 3:** surface/contact/asset/event schemas become executable and at least one bounded provider adapter must be certified before provider-side autonomous repair.
- **Phase 4:** website surfaces federate identity, entitlements, support, consent, analytics and design patterns by cohort.
- **Phase 5:** contact/CTA conversion, form reliability, asset reuse, accessibility and update latency become measured operational evidence.
- **Phase 6:** certified site/design templates and APIs may be licensed to approved builders/developers.
- **Phase 7:** the same interaction contract extends to kiosks/TapStations/MM Suites physical interfaces.
- **Phase 8:** provider custody, site/project inventories, asset ownership and exports become portfolio controls.
- **Phase 9:** advanced provenance/interoperability remains problem-driven.
- **Phase 10:** provider mappings, interaction definitions, creative lineage, exports and restore instructions become permanent continuity artifacts.

## Gate impact

This checkpoint advances Phase 2.99 website-surface readiness but does **not** close Phase 2.99 or authorize Phase 3 entry. External site mutation and central MCP federation remain explicit open gates.
