This sprint is a versioned documentation correction pass. Git history preserves prior wording; this page records why the current projection changed and which exceptions remain intentionally exact.

## Sprint scope

Sprint 1 targeted high-confidence stale documentation in two areas:

1. **Canonical system naming:** current institutional prose must use **ThriveBase**, not the legacy all-caps rendering.
2. **Roadmap freshness:** current planning references must use the adopted **Ten-Phase Institutional Program Charter** while historical five-phase records remain preserved as dated version evidence.

## Naming correction rule

`ThriveBase` is the canonical institutional display name.

Two classes of identifiers are intentionally not rewritten by a documentation-only sprint:

- exact provider-side labels, including the pre-existing cPanel token whose literal provider name remains recorded in the API seed register;
- exact deployed legacy SQL identifiers such as `thivebase_control.*` and `thivebase_private`.

Those values are identifiers, not canonical product spelling. Renaming a deployed schema or provider object requires a separately governed migration, dependency test, rollback/readback and evidence update.

## Roadmap correction rule

The adopted roadmap generation is `ten_phase_v1`. Earlier five-phase material remains historical evidence and is not rewritten to make history appear cleaner. Current/live architecture pages and machine namespace descriptions must use the ten-phase program; historical changelog pages receive supersession/version notices where needed.

- Mintlify credential-custody and MCP-boundary documentation;

## Verification criteria

Sprint 1 passes only if:

- no current CrownThrive prose uses the legacy all-caps rendering as the system/brand name;
- any remaining exact legacy all-caps string is demonstrably an external/provider identifier or preserved quoted evidence;
- the dropped-R legacy typo is absent from current documentation prose;
- legacy `thivebase_*` SQL identifiers are explicitly distinguished from the canonical ThriveBase name;
- current phase-machine descriptions use the ten-phase roadmap;
- historical five-phase records remain recoverable and are not silently rewritten;
- Mintlify navigation and MDX validation pass;
- the branch diff is reviewed before merge.

## Non-effects

This documentation sprint does **not** rename database schemas, rotate credentials, rename provider-side tokens, change Supabase state, modify application code, activate Phase 3, or alter historical acceptance records.
