# Phase 2.99 — Collision Governance & Founder Orchestration

## Summary

This packet adds a dedicated collision-avoidance and adjudication control layer for concurrent CrownThrive agent, repository, documentation, runtime, and provider work.

Canonical baseline: `8fcb68bf209e32ba2cd265e1b6ca730cb8da64d7`.

The packet is intentionally additive. It does not edit shared `AGENTS.md`, `docs.json`, the canonical agent registry, the institutional relay, or the existing governed merge workflow because active packets already own some of those surfaces. Shared-surface adoption is handed to Founder Orchestrator reconciliation Issue #157.

## New candidate non-voting agents

- `ct.subagent.collision.preflight-sentinel`
- `ct.subagent.collision.adjudicator`
- `ct.subagent.collision.postmerge-reconciler`
- `ct.subagent.queue.priority-throttle`
- `ct.subagent.quorum.session-router`

Candidate parent binding: `ct.agent.founder-orchestrator`, pending reconciliation against the actual upcoming Master Founder Orchestrator implementation.

## What is executable

- deterministic path/surface collision classification from `CT-COLL-0` through `CT-COLL-5`;
- exact-file and shared high-risk-surface comparison across open PRs;
- stale-main-base detection;
- deterministic collision fingerprints;
- material-pr priority scoring;
- D2 final-quorum WIP throttling;
- same-collision-domain serialization;
- special-quorum trigger recommendations;
- post-merge stale-PR and queue recomputation;
- read-only GitHub Actions workflow on PR events, `main` pushes, `:40` hourly queue review, and `:50` hourly post-merge reconciliation;
- fail-closed validator and deterministic self-tests.

## Authority retained

This packet does not change `CT-ADR-GOV-011`:

- sovereign voters remain A/B/C/D/S;
- automatic promotion remains 4-of-5 including Agent D;
- deny/block remains binding;
- applicable specialists remain required;
- an originating material author does not self-vote;
- D3 remains human-reserved;
- a Special Quorum is expedited attention/review routing only and cannot change vote math.

## Founder Orchestrator privileges proposed

The candidate parent may prioritize PRs, throttle the final promotion queue, serialize collision domains, allocate merge windows, require rebase/stack/split/ownership transfer, request a Special Quorum, assign adjudication owners, pause/resume noncritical work, require fresh review after staleness, and preempt normal queue order for critical security or founder-reserved incidents.

Those privileges do not include an extra vote, waiver of Agent D/specialists, validator weakening, blocked-PR merge authority, UNKNOWN-to-PASS conversion, or autonomous D3 authority.

## Experimental secondary institutional model

The user-directed judicial/legislative/executive concept is preserved as a CrownThrive-specific secondary experiment:

- **Executive Coordination** — Founder Orchestrator queue/execution routing within adopted rules;
- **Policy Assembly** — Governance Marshal policy/ADR/standard amendment drafting;
- **Adjudication and Precedent** — Collision Adjudicator interpretation and non-binding precedent.

It is not governing authority unless separately adopted after Issue #157 reconciliation.

## Rollback / security

The workflow is read-only. The public packet performs no provider, credential, customer, payment, rights, token, production database, deployment, or sovereign-voter mutation.

Rollback is a straight revert of the additive packet.

## Phase state

Phase 2 / 2.99 remains current. Phase 3 remains blocked pending its independent hard exit.
