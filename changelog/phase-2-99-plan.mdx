# Phase 2.99 — Private Core and Machine Seed Program

## Mission

Convert the Phase 2.98 platform intelligence and all prior institutional knowledge into a protected, executable seed package so Phase 3.0 can begin without rediscovery, data leakage, vendor lock-in or ambiguous authority.

## Workstream 1 — Repository and source topology

Decide and establish:

- public CrownThrive-Support/Mintlify projection repository;
- private institutional schemas and registry repository;
- CHLOM services repository or governed monorepo;
- platform adapter/MCP/SDK repository strategy;
- infrastructure-as-code repository;
- private policy/evaluation fixtures;
- restricted source/evidence object storage;
- source mirrors/exports and release tags;
- branch protection, review, signing/provenance and AGENTS.md rules.

No production secret or restricted evidence is placed in public Git history.

## Workstream 2 — Private institutional data architecture

Implement the selected baseline for:

- tenant/organization/actor identity;
- RBAC plus relationship/attribute policy;
- central institutional registry;
- domain-partitioned operational stores;
- restricted evidence vault;
- search/retrieval isolation;
- event bus and DAIL envelope;
- workflow/queue/dead-letter;
- retention, deletion and legal hold;
- data export and off-provider recovery.

## Workstream 3 — Stable schemas and seed records

Produce validated machine files/tables for:

1. tenants/organizations;
2. actors/service identities;
3. roles/authority/delegations;
4. agents/models/providers/prompts/evaluations;
5. assets/works/products/brands/imprints/universes/rooms/characters;
6. platforms/corridors/frameworks/capability pallets;
7. CHLOM papers/components/protocol pallets/services;
8. versions/corrections/aliases/successors;
9. sources/claims/metrics/evidence;
10. policies/legal profiles/applicability/acceptance;
11. rights/provenance/DLA/license/entitlement state vocabularies;
12. prices/economic schedules/fees/splits/rewards/allocations;
13. domains/routes/SEO profiles;
14. APIs/MCPs/tools/webhooks/adapters/SDKs;
15. repositories/deployments/environments/vendors/secret references;
16. data classes/flows/events/retention;
17. SOPs/runbooks/support/incident/continuity;
18. platform capability state/risk/backlog;
19. run packets/approvals/DAIL events;
20. tests/fixtures/evaluations.

## Workstream 4 — Identity and SSO decision package

Finalize ADRs for:

- CrownThrive ID as institutional identity authority;
- CrownThrive Commons/social platform and external login providers as entry/identity providers;
- OAuth 2.1/OIDC issuer/audience/client model;
- account linking and duplicate identity resolution;
- organizations/teams/roles/consent/eligibility;
- assurance/MFA/recovery;
- service identities and short-lived credentials;
- platform adapter migration sequence;
- user-facing privacy/data portability.

## Workstream 5 — API, MCP and adapter manifests

For every Phase 3/P0/P1 interface create:

- service/server/tool ID;
- environment/base URL or proposed host;
- docs/OpenAPI/schema/source reference;
- auth/audience/scopes;
- data classes and side effects;
- idempotency/concurrency;
- webhooks/events/retry/replay/dead-letter;
- rate/cost limits;
- owner/support/incident;
- deployment/repository;
- health/version/deprecation;
- vendor export/replacement;
- current verification state.

Prepare the first central Institutional MCP, CHLOM MCP and P0 platform MCP manifests without exposing private tools publicly.

## Workstream 6 — Cloud, IaC and environments

Create:

- cloud/provider ADR and portability requirements;
- development/test/staging/production/recovery/research environments;
- network/service boundaries;
- PostgreSQL/object storage/queue/workflow/search/observability baseline where selected;
- IaC modules;
- secret manager/KMS;
- CI/CD and migration controls;
- feature flags/progressive delivery;
- backup/PITR/replication/off-provider export;
- restore/rollback tests;
- cost/renewal/capacity ownership.

## Workstream 7 — Automation control plane

Seed:

- run-packet compiler;
- agent registry/factory templates;
- work queues and priority/dependency rules;
- approval gates;
- tool/MCP broker;
- evaluation/verification services;
- watchdogs and health checks;
- incident/pause/kill switch;
- cost/token/request budgets;
- knowledge/registry/next-run updater.

First autonomous workflows should be low-risk, reversible and independently verified.

## Workstream 8 — Legal Depot and private knowledge

- import source/policy/version metadata;
- map platform/role/action/jurisdiction applicability;
- preserve historical terms and acceptance evidence;
- implement legal-status overlays;
- separate public legal pages from private strategy/agreements/evidence;
- create review/expiration/correction queues;
- decide crownthrivesupport.com public/authenticated deployment;
- build source-to-public/member/developer/operator/machine publication pipeline.

## Workstream 9 — SEO/search fleet

Prepare:

- host/route/canonical/redirect registry;
- per-platform SEO profiles;
- robots and sitemap generation/validation;
- structured-data/entity mapping;
- crawler and link/accessibility checks;
- public-claim freshness;
- private/token/environment leakage checks;
- search-console/analytics connectors where authorized;
- AIO/public API/feed/llms.txt policy;
- remediation queues and DAIL/CrownLytics events.

## Workstream 10 — Security and evaluation gate

Required tests include:

- cross-tenant and relationship isolation;
- private retrieval filtering before model generation;
- secret scanning and credential rotation;
- prompt injection/data exfiltration;
- unauthorized MCP/API calls;
- no agent self-approval;
- idempotency/replay/concurrency;
- stale/conflicting-source hold;
- correction immutability;
- rights/DLA/entitlement consistency;
- revenue arithmetic;
- webhook signature/retry/dead-letter;
- backup/restore and deployment rollback;
- public/private publication boundaries;
- historical legal claim suppression;
- SEO/environment leakage;
- incident/pause/read-only fallback.

## Required ADRs

At minimum:

- repository/monorepo strategy;
- database/tenant/isolation strategy;
- event/workflow/queue architecture;
- identity/SSO architecture;
- authorization/policy engine;
- cloud/region/provider portability;
- secret/key management;
- evidence/object storage;
- search/retrieval/embedding architecture;
- API/MCP federation;
- deployment/CI/CD;
- observability;
- backup/restore;
- public/private knowledge projection;
- initial Phase 3 pilot selection.

## Exit criteria

Phase 2.99 is complete when:

- private/public boundaries are deployed or fully implementation-ready;
- schemas and seed records validate and resolve references;
- current platform/API state imports without invented data;
- secrets/credentials have controlled ownership;
- infrastructure and recovery are reproducible;
- approval/event/correction/evaluation contracts are executable;
- first service and platform-adapter skeletons can be generated from the seed;
- Phase 3.0 run packets, backlog and acceptance tests are ready;
- PRs/commits/deployments and next-run state are exact.

## Handoff

The final handoff states: **Build Phase 3.0 from this commit, schema release, infrastructure release and source snapshot.** Phase 3 agents should not redesign settled institutional doctrine unless new evidence triggers the version/correction process.
