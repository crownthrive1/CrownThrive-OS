# Phase 2.98 Pass D9 — Portfolio Census & Exit Audit

## Purpose

D9 is the portfolio-wide closure pass for Phase 2.98. It does **not** declare Phase 2 complete. It determines whether every material CrownThrive platform/brand/framework recovered during Phase 2 has either:

- substantive Phase 2.98 coverage;
- an explicit current/historical/research/reserve/sunset/unknown disposition;
- a Phase 2.99 machine-seed requirement;
- or a governed unresolved-source/owner-validation record that cannot disappear silently.

The institutional program remains a **five top-level phase** model. Phase 2.98 and Phase 2.99 are subphases inside Phase 2.

## Current evidence basis

The Phase 2.7 exhaustiveness package identified a July 2026 registry containing 74 platforms/frameworks plus additional unresolved names and required explicit current, merge, successor, dormant, research, reserve or sunset dispositions before Phase 3. Later Holdings management planning used a separate 68-asset portfolio registry, 85 mapped engines/services and 82 domain records. These counts are different artifacts with different scope and must not be forced into equality.

## D9 census rule

Every named asset must resolve through stable identity rather than arithmetic convenience.

```yaml
asset_id:
```

A count mismatch triggers reconciliation; it never justifies deleting, duplicating or renaming records to make totals match.

## Phase 2.98 exit criteria

Phase 2.98 is ready to hand off to 2.99 when:

- no material named platform/brand/framework is omitted silently;
- P0/P1 coverage is substantive or explicitly blocked/unverified;
- alias/successor/sunset/reserve records are stable;
- current, historical and research states are distinguishable;
- public claims have dated evidence or qualification;
- every active/current candidate has legal, rights, support and API/provider state fields;
- articleization has a recoverable title/category/source mapping;
- documentation-impact/changelog ownership exists;
- unresolved records have owner/source/evidence requirements;
- navigation validator passes with no accidental orphan pages;
- Phase 2.99 can import the corpus without rediscovery.

## What D9 does not do

D9 does not:

- start Phase 3 engineering;
- mark unknown platforms active;
- merge brands solely to reduce count;
- reactivate historical vendors or storefronts;
- treat Holdings planning assumptions as production evidence;
- expose restricted/private source bodies;
- waive the Phase 2.99 hard gate.

## Phase 2.99 handoff

The immediate successor is the **Phase 2.99 Private Core and Machine Seed Program**. D9's output becomes the census against which article manifests, platform records, aliases, APIs, rights, policies, products, sources, evidence and unresolved-state queues are validated.

## Completion principle

The objective is not a cosmetically perfect portfolio count. The objective is a **lossless, versioned and machine-addressable institutional map** in which CrownThrive can tell what each asset is, what state it is in, what evidence supports that state, what remains unknown and what must happen before activation.
