## Decision

Direct CrownThrive application/API evidence now resolves **ThriveTools SEO** and **ThriveTools OPT** as distinct child applications inside the `ct.platform.thrivetools` family:

```text
ct.platform.thrivetools
├── ct.platform.thrivetools-seo
└── ct.platform.thrivetools-opt
```

The child identities do **not** merge into the root platform, and their credentials, engines, API contracts, quotas, deployment state and runtime evidence do not promote to the root by inheritance.

## Security and destructive-action controls

Upload and Delete are not activated by possession of a credential.

Future upload certification requires, as applicable:

- exact HTTP method;
- bounded file references, file types and sizes;
- compression-ratio constraints;
- source-asset rights and provenance;
- privacy/data classification;
- response/output validation;
- audit/DAIL evidence;
- read-after-write or equivalent confirmation;
- provider/object-store recovery and exit behavior.

Future deletion certification requires target validation, retention/recovery policy and explicit scoped authority. `permanent_delete=true` remains a high-scrutiny destructive operation.
