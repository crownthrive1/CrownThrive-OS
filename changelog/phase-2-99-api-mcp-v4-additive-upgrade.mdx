# API and MCP v4 additive upgrade

## Outcome

CrownThrive API/MCP Control v4 is active in the private runtime as an additive successor to v3. The v3 contract remains supported. No existing contract, registry row, tool, evidence record, or compatibility path was deleted.

The external protocol remains the current MCP specification version `2026-07-28`; this release advances the CrownThrive server contract from `3.0.0` to `4.0.0`.

## v4 controls

- Request bodies are bounded before JSON parsing.
- Provider reads have an explicit timeout.
- Provider responses are streamed through bounded readers.
- Input and output schemas remain fail-closed.
- The runtime catalog continues to expose only governed, enabled tools.
- Versioned health, catalog, and conformance contracts are registered but disabled until exact client conformance and governance pass.

## Compatibility and preservation

The upgrade is deliberately additive:

- v3 remains a supported compatibility baseline.
- No existing tool was removed or renamed.
- Existing enabled-tool state was not broadened.
- New v4 control contracts start disabled.
- No mutation, provider-write, customer-write, checkout, entitlement, voting, `sync_agents` voting, child-certification, or D3 authority was activated.

## Distribution boundary

This public packet contains safe interface and behavior facts only. Credentials, runtime locators, repo-to-agent authority mappings, private policy hooks, optimized adapters, protected algorithms and calibration, restricted tests, and private evidence remain outside the public projection.

## Remaining acceptance work

Before any new v4 contract may be enabled, the exact release needs external-client conformance, unchanged security/privacy checks, exact-artifact IP/rights disposition, and governed acceptance. Existing read-only production behavior remains contained while those gates are open.
