# Phase 2.99 — Agent Template & Pallet Institutionalization

## Purpose

This patch converts the current CrownThrive agent-building practice into durable institutional knowledge and reusable source IP. It does **not** change Phase 2.99 into Phase 3, add new sovereign voters or activate a paid product merely because a template exists.

```yaml
change_id: ct.change.phase-2-99.agent-template-pallet-institutionalization.v1
phase: "2.99"
change_class: architecture_and_documentation_control
status: candidate
source_template_generation: "1.0.1"
sovereign_voter_pool: [A, B, C, D, S]
scheduled_non_voting_specialists: [E, F, G, H]
embedded_non_voting_specialists: [I, J, K]
stripe_checkout_enabled: false
price_status: not_authorized
phase_3_entry: blocked_pending_phase_2_99_hard_exit
```

## Material changes

### Agent topology

The current topology is now explicitly versioned:

- A/B/C/D/S remain the five sovereign voters;
- E API/MCP, F Source/Articleization, G Domain/Engine/Vendor and H Webhook/Delivery are scheduled non-voting specialists;
- I Continuity/Recovery, J Phase 3 Snapshot/Entry Packet and K Roadmap Transition are embedded non-voting subagents so specialist capacity can expand without consuming independent scheduler slots or changing quorum.

The current scheduler/prompt projections are implementation details. Stable IDs and role versions are the institutional identity.

### Reusable source templates

The first reusable source-template generation now includes:

- `developers/templates/agent-role-template.v1.yaml`;
- `developers/templates/subagent-role-template.v1.yaml`;
- `developers/templates/agent-pack-manifest-template.v1.json`;
- `developers/templates/chlom-capability-pallet-template.v1.yaml`;
- `developers/templates/chlom-runtime-adapter-template.v1.yaml`;
- `developers/templates/third-party-attribution-template.v1.yaml`;
- `developers/templates/README.md`.

Generation `1.0.1` adds the separately gated runtime/decentralized-adapter family while preserving the original capability-pallet model. These templates default to fail-closed behavior: no self-approval, no phase advancement, no production writes, runtime secret references only, historical-version preservation and no commercial price until separately authorized.

### Version archive

[Agent Lineage & Version Archive](/automation/agent-lineage-version-archive) now preserves the progression from ad hoc orchestration → four-role relay → five-voter sovereign relay → scheduled specialist ring → embedded specialist generation. Machine lineage is also captured in `developers/manifests/agent-lineage-archive.v1.json`. Future material prompt/schedule/authority/tool changes must append lineage rather than silently rewriting the past.

### CHLOM capability pallets and runtime adapters

The current cloud/software definition of a **CHLOM capability pallet** is now given a reusable source template. It remains distinct from historical Substrate/runtime pallets.

A second source template now covers a future **CHLOM runtime/decentralized adapter**. That adapter defaults to `RESEARCH`, `production_deployed=false`, no token/wallet/chain requirement, no public immutable PII/restricted evidence, and an earliest activation phase of Phase 9. Threat model, legal/privacy/security review, key custody/recovery, rollback/off-chain reconstruction, third-party license review and an explicit governed activation decision are required before activation.

A capability pallet and runtime adapter therefore have independent stable IDs, versions, tests, rights/security records, recovery state and deployment evidence. A runtime-adapter template never proves a CrownThrive blockchain, token, wallet, DAO, smart contract, decentralized network, money-transmission authority or compliant offering exists.

### Open-source and third-party rights gate

Any external/open-source component intended for incorporation, redistribution or paid distribution must be registered with its exact upstream version/commit, copyright holder, SPDX license where available, attribution/NOTICE obligations, source/copyleft/modification/trademark/distribution obligations and compatibility state. Public source availability is never treated as unrestricted commercial permission.

No third-party code is imported by this patch. The new source/attribution system is the gate for future reuse.

### Changelog consolidation

The new [Institutional Changelog Index](/changelog/index) becomes the main history entry point. Existing phase/pass/patch pages are preserved at their current routes and grouped by subject rather than deleted or flattened. Major changes point into subject histories; subject histories link back to their durable operating pages.

## Commercialization path

The reusable agent, pallet and adapter templates are **commercialization candidates**, but this patch does not create or activate a Stripe Product/Price because no exact price and package license were adopted in this directive.

The preferred first commercial architecture is:

```text
sanitized agent/pallet pack
→ package/license + third-party notice gate
→ versioned artifact + checksum
→ Stripe Product/Price after explicit pricing authority
→ hosted Checkout
→ signed webhook
→ entitlement/protected download
→ support/update terms
→ refund/dispute reconciliation
```

Potential later offerings include one-time agent packs, pallet bundles, support/update subscriptions, enterprise licenses and implementation/certification services. Internal CrownThrive authority, private data, secrets and restricted trade-secret implementation are never sold merely because a generic template is licensable.

## Rights and preservation controls

- CrownThrive-authored templates remain CrownThrive-controlled IP unless a specific package license says otherwise.
- Third-party code retains upstream copyright and required notices.
- Historical versions and accepted source snapshots remain recoverable through Git/version history and controlled archives.
- A commercial derivative is separately versioned from the internal operational agent.
- No agent template, capability pallet or runtime-adapter package may contain credentials, credential fingerprints, private customer records, restricted evidence, private contracts or internal break-glass information.

## Downstream phase impact

- **Phase 3:** agent/role/tool/approval schemas can import stable role/template IDs; Phase 3 entry remains blocked until the Phase 2.99 hard exit passes.
- **Phase 4:** certified specialist/adapter packs can become repeatable onboarding units without changing institutional authority.
- **Phase 5:** commercially useful agent/pallet packs may be productized only after pricing/license/fulfillment proof.
- **Phase 6:** developer licensing, external pack distribution, certification and support become first-class licensing-economy candidates.
- **Phase 9:** capability pallets may receive runtime/cryptographic/decentralized adapters only after independent threat/legal/privacy/recovery/custody gates and explicit activation.
- **Phase 10:** source templates, version archives, third-party notices and provider-independent reconstruction become continuity assets.

## Rollback

Rollback is documentation/source-only: revert the template/docs patch while preserving the historical commit and changelog entry. No production provider, payment, rights or customer state is mutated by this patch.
