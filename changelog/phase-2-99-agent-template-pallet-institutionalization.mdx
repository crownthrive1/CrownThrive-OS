# Phase 2.99 — Agent Template & Pallet Institutionalization

## Purpose

This patch converts CrownThrive's agent-building practice into durable institutional knowledge and reusable source IP. It preserves the distinction among sovereign authority, scheduled specialists, embedded subagents, operational probes, research-and-development specialists and domain agents.

It does **not** advance Phase 3, add sovereign voters, authorize D3 activity, activate provider writes or create a paid product merely because a template exists.

```yaml
change_id: ct.change.phase-2-99.agent-template-pallet-institutionalization.v1-1
phase: "2.99"
change_class: D2_architecture_documentation_governance_preparation
status: candidate_draft
source_template_generation: "1.1.0"
sovereign_voter_pool: [A, B, C, D, S]
scheduled_non_voting_specialists: [E, F, G, H]
embedded_non_voting_specialists: [I, J, K, L, M, N, O]
rnd_default_state: RESEARCH_CANDIDATE
children_add_votes: false
same_family_creates_independence: false
stripe_checkout_enabled: false
price_status: not_authorized
phase_3_entry: blocked_pending_phase_2_99_hard_exit
```

## Material changes

### Agent topology

The agent estate is explicitly separated into:

```text
authority layer
→ specialist layer
→ embedded subagent layer
→ operational probes
→ R&D fabric
→ domain-specific agent factory
```

A/B/C/D/S remain the only sovereign voter pool. E/F/G/H remain scheduled non-voting specialists. I/J/K and reconciliation L/M/N/O remain embedded/non-voting. Operational heartbeat/credential/vendor watchers remain probes rather than new authority classes.

### Agent Factory Delegation

A new machine policy, `developers/manifests/agent-factory-delegation-policy.v1.json`, governs parent/child delegation.

Every delegated child now resolves through a contract including:

- child run ID;
- parent and root agent IDs;
- delegation path;
- independence family;
- role/scope/source snapshot;
- allowed tools and data classes;
- inherited authority ceiling;
- budget and TTL;
- output class;
- promotion route;
- termination state.

The spawn matrix deliberately differs by role:

- **A** can dispatch the broadest bounded registered/ephemeral specialist set but cannot expand authority;
- **B** can delegate retrieval/audit subchecks, but its descendants are not independent verification of B-originated material;
- **C** can instantiate builder cells, which remain one implementation family and cannot self-approve;
- **D** is checks-only and is never converted into a builder host;
- **S** may invoke scanners/TEVV/security subchecks, but child count does not add security votes;
- **E/F/G/H** may fan out narrowly inside specialist scope;
- **M** may fan out by source family;
- **N** may use deterministic subchecks but cannot manufacture an independent N through descendants;
- **J** is intentionally minimal/late-gated;
- operational probes have no child-spawn role.

No child, sibling group or model-confidence score changes the A/B/C/D/S denominator.

### Same-family independence

The factory now machine-records an `independence_family` and parent/root lineage. **Same-family descendants do not become independent reviewers because they used different prompts, models, tools or runtime IDs.**

This closes the risk that one parent could spawn multiple children and then treat the resulting agreement as sovereign quorum or independent verification.

### Persistent versus ephemeral agents

A runtime may create a bounded ephemeral specialization when the registered factory allows it. Ephemeral children require TTL, budget, authority ceiling, source snapshot, lineage and termination state.

A persistent CrownThrive agent requires a stable ID, owner, versioned role contract, tools/data scope, evaluation suite, lifecycle, escalation and archive record. An agent cannot invent a new permanent institutional authority simply by naming it during a run.

### Permanent R&D fabric

A new public-safe machine registry, `developers/manifests/agent-rnd-specialist-fabric.v1.json`, records six non-voting research roles:

- legal/regulatory;
- IP/rights/licensing;
- finance/tax/treasury;
- blockchain/cryptographic protocol;
- accessibility/consumer protection;
- regional/global localization.

All default to **`RESEARCH_CANDIDATE`** and have no direct PASS, phase-advance or production-write authority.

Their function is:

```text
research → model → challenge → discover → propose → identify risk → create candidate work
```

not `research → PASS`.

### R&D promotion boundary

The reconciliation-tag system now includes:

- `CT:RND`;
- `CT:RESEARCH-CANDIDATE`;
- `CT:PROMOTION-PENDING`;
- `CT:CERTIFICATION-SCOPE`.

R&D registry growth is explicitly expected and **does not create a formal proof-coverage gap by count alone**. L/M/N may scan exploratory scopes without converting them into hard-exit obligations.

A research scope enters formal certification only after promotion or material contact with governed scope, including when it touches a Phase 2.99 hard-exit predicate, changes an existing governed disposition, becomes canonical/production-relevant or enters authoritative phase-entry evidence.

The standard promotion path is:

```text
R&D
→ M source reconciliation
→ N proof verification
→ applicable domain specialist
→ B evidence audit
→ C implementation if needed
→ S security
→ D independent gate
→ sovereign acceptance or reserved human/professional authority
```

### Reconciliation validator hardening

`scripts/scan_reconciliation_tags.py` now validates tag-declared `requires` and `prohibits` fields generically and adds fail-closed R&D rules:

- `CT:RESEARCH-CANDIDATE` cannot coexist with PASS;
- `CT:PROMOTION-PENDING` cannot coexist with PASS;
- R&D-lineage PASS requires `CT:CERTIFICATION-SCOPE`;
- research-only registry expansion cannot be treated as formal coverage drift by count alone.

### Agent-template validator hardening

`scripts/validate_agent_template_library.py` now verifies:

- fixed A/B/C/D/S sovereign voter set;
- child vote prohibition;
- role-specific spawn modes/depths;
- D checks-only behavior;
- N deterministic-subcheck-only behavior;
- J late-gated minimal collection;
- M source-family fan-out;
- same-family non-independence;
- six exact R&D stable IDs;
- R&D direct-PASS prohibition;
- R&D growth accounting;
- template-generation 1.1.0 lineage;
- documentation/changelog synchronization.

### Template generation 1.1.0

The agent and subagent source templates now encode:

- parent/root identity;
- independence family;
- persistent versus ephemeral runtime lifecycle;
- spawn mode and allowed child classes;
- maximum delegation depth;
- child authority ceiling;
- required budget/TTL;
- child vote and production-write defaults `false`;
- termination state;
- same-family independence prohibition;
- persistent child registration;
- R&D candidate → PASS prohibition without promotion.

The previous 1.0.0 and 1.0.1 generations remain preserved in the lineage archive.

### Runtime topology and scheduler discipline

The architecture review identified duplicate same-minute reads among several scheduled specialists and operational probes. Live runtime scheduler offsets are being staggered so probes remain cheap telemetry and specialists can consume their outputs rather than repeatedly hitting the same source at the same instant.

A scheduler change is operational cadence, not a new institutional identity. Stable agent IDs and governance contracts remain unchanged.

Agent A is also directed to delegate domain cognition through registered/bounded specialists instead of accumulating every specialty into the orchestrator context. A stays fluid in coordination and rigid in authority.

### CHLOM capability pallets and runtime adapters

The cloud/software **CHLOM capability pallet** remains distinct from any historical protocol/runtime pallet. Existing candidate pallets now gain two additional institutional patterns:

- **Agent Delegation Pallet** — parent/root lineage, authority ceilings, TTL/budget, termination and independence controls;
- **R&D Promotion Pallet** — research → certification transition without count-driven hard-gate churn.

The future `chlom-runtime-adapter-template.v1.yaml` remains `RESEARCH`, `production_deployed=false`, Phase-9-or-later gated and cannot imply a token, chain, wallet, DAO or production decentralized runtime exists.

### Open-source and third-party rights gate

External components still require exact upstream version/commit, copyright/license/SPDX where available, attribution/NOTICE, source/copyleft/modification/trademark/distribution obligations and compatibility review before incorporation or distribution.

No third-party code is imported merely by this agent-factory hardening patch.

## Why this change was required

The hard pass identified six concrete architecture weaknesses:

1. runtime topology was moving faster than canonical agent documentation;
2. the factory lacked an explicit machine spawn matrix;
3. same-family independence was not sufficiently machine-enforced;
4. some live scheduler slots caused duplicate same-minute provider reads;
5. Agent A was accumulating too much domain cognition instead of delegating it;
6. R&D-to-certification promotion was not machine-readable, allowing intentional research growth to be misreported as formal proof-coverage deterioration.

This patch addresses all six without increasing sovereign authority.

## Commercialization path

The reusable agent, pallet and adapter templates remain commercialization candidates only. No Stripe Product/Price is activated because exact package price/license authority remains unadopted.

```text
sanitized agent/pallet pack
→ package/license + third-party notice gate
→ versioned artifact + checksum
→ Stripe Product/Price after explicit authority
→ hosted Checkout
→ signed webhook
→ entitlement/protected delivery
→ support/update terms
→ refund/dispute reconciliation
```

Internal CrownThrive authority, credentials, private data, restricted evidence and trade-secret implementation are never sold merely because a generic template can be licensed.

## Downstream phase impact

- **Phase 3:** stable role/delegation IDs and research-promotion semantics become inputs to executable role/approval/event schemas; Phase 3 remains blocked pending the hard exit.
- **Phase 4:** certified domain/adapter packs can become repeatable onboarding units without altering authority.
- **Phase 5:** agent/pallet packages may be productized only after pricing/license/fulfillment proof.
- **Phase 6:** external developer licensing/certification can reuse sanitized factory contracts.
- **Phase 9:** protocol/cryptographic runtime adapters remain independently gated.
- **Phase 10:** lineage, parent/root delegation records and provider-independent reconstruction become continuity assets.

## Rollback

Rollback is bounded to this draft architecture/documentation/template patch and live scheduler/prompt configuration. Revert the affected commits/configuration while preserving the historical record. No customer, payment, rights, provider credential or production data mutation is required by this change.
