# Phase 2.99 — Governed Site Auto-Publish

**Date:** 2026-08-20

## Added

- `ct.site.autopublish.v1` release policy.
- Exact version/SHA-256 governed release records.
- Independent specialist certification records.
- Eligible-voter enforcement and self-vote rejection.
- Automatic vote-request routing to active vote-eligible relay agents.
- Surface-specific provider adapter registry.
- Surface-specific publication routes.
- Quarantined/idempotent publication jobs.
- Append-only publication attempts.
- Surface-scoped published catalog projection.
- Public read-only `site-catalog-feed` Edge Function.
- Non-voting `ct.subagent.governed-release-publisher` execution contract.
- Automatic rollback/withdrawal when authorization is removed.
- Automatic supersession lineage when a newer accepted exact release publishes.
- Developer Marketplace asset-release → governed-release trigger.
- Developer Library membership catalog-digest → governed-release trigger.
- Generic governed-release registration contract for other platform agents.

## Proven canaries

A synthetic preview release demonstrated:

1. six applicable certification dimensions PASS;
2. three eligible YES votes including `ct.relay.agent-d`;
3. automatic quarantine before adapter certification;
4. committed dynamic-feed write and public readback;
5. rollback and public absence readback;
6. automatic job promotion after adapter certification;
7. autonomous publish;
8. automatic withdrawal when one certification changed to HOLD; and
9. autonomous republish after the same exact release returned to PASS.

Publication and rollback attempts remained append-only.

The first feed-adapter certification attempt intentionally failed because same-transaction state was not externally visible. The certification design was corrected to use committed operations before the adapter was marked certified.

## Scheduled automation

- `governed_site_autopublish_dispatcher` — every two minutes.
- `governed_release_vote_router` — every five minutes.
- `governed_dynamic_feed_adapter_canary` — hourly.
- `governed_site_feed_bootstrap_verifier` — hourly.

## Production Sites status

Developer Marketplace, KJV Visualized / Sermon Toolkit and Virality Music each have:

- exact Sites project mapping;
- dynamic-feed destination route;
- one-time feed-bootstrap contract;
- separate project-bound provider-mutation adapter candidate;
- current rollback/version reference where available; and
- hourly bootstrap verification.

All three remain `observe_only` with `auto_update_enabled=false` because the feed bootstrap marker and feed URL are not yet present in current public HTML. No public Sites source-write adapter was fabricated.

## Existing product state

Six current downloadable Developer Marketplace releases plus the Developer Library membership were automatically projected into governed release records. All seven remain quarantined because the current specialist/legal/commerce certification set is HOLD, not release PASS.

No current product was published by this implementation.

## Governance impact

- A built ZIP is not release authority.
- A provider project ID is not write certification.
- A payment-provider event is not a CrownThrive license.
- A dynamic-feed adapter is not a provider source-write adapter.
- HOLD/UNKNOWN/pending/fail remain non-publishable.
- D3 human-reserved authority is unchanged.
- Phase 3 remains blocked.

Virality continues to preserve `REMOVED_BY_FOUNDER_OVERRIDE` for SoundCloud API use.
