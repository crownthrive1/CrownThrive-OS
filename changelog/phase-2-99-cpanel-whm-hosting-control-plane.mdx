## What changed

Founder-supplied WHM administrator evidence and a newly created provider token were converted into a governed infrastructure integration instead of remaining chat-only credential material.

The credential is now stored only as restricted Vault material with a CHLOM-managed recovery reference and version-custody record. An authenticated WHM API 1 read confirmed **44 cPanel accounts**, including **8 suspended** at the certification snapshot. Independent read calls also verified current system-load telemetry and resolved the provider hostname. The raw credential is not reproduced in documentation, source control, logs or evidence summaries.

A JWT-protected `cpanel-whm-api-control` Edge Function was deployed as the institutional adapter. It exposes an allowlisted D0 read surface and keeps provider mutations disabled.

## THIVEBASE and evidence state

THIVEBASE now treats cPanel/WHM as an active infrastructure provider. Capacity records include the current account-count/suspension-count observations and current load samples. The hosting-control data model also adds private snapshot/observation structures and evidence hashes so later agents can reconcile hosting state without copying security-sensitive provider payloads into public knowledge.

The current suspension count is a **WATCH/reconciliation signal**, not an automatic remediation order. Several suspended accounts may correspond to intentional reserve/sunset assets. Asset lifecycle evidence controls whether a suspension is expected, stale or an incident.

## Explicit boundaries

- provider token existence does not grant blanket CrownThrive mutation authority;
- provider-native ACL/privilege detail remains unverified;
- cPanel account presence does not prove registrar custody, DNS/TLS, application health or canonical deployment;
- current load averages are not classified as overload until CPU/core and resource capacity are verified;
- exact account rows, contact information, IP assignments, raw provider responses and credentials remain restricted;
- no account/package/DNS/service/token/server mutation was performed in this run.

## Remaining gates

1. verify provider-native token ACL/expiry/revocation state without disclosing the token;
2. certify bounded disk-usage read and establish CPU/core, memory and storage capacity baselines;
3. reconcile the eight suspended accounts against canonical asset lifecycle state;
4. certify backup/restore/export/provider-exit procedures;
5. map hosting evidence to domain/DNS/TLS/mail/application deployments as separate authorities;
6. define monitoring cadence, thresholds, alert routing and rollback before any autonomous remediation;
7. preserve the provider-write gate until an explicit governed action class authorizes a specific mutation.

- **Phase 4:** platform deployment certification can consume WHM account evidence but must independently prove DNS/TLS and application/runtime health.
- **Phase 8:** portfolio infrastructure and capacity management gains provider-backed account/dependency evidence without inflating platform counts.
- **Phase 10:** continuity inherits credential rotation/revocation, backup/export, DNS/mail dependencies and provider-exit requirements.
