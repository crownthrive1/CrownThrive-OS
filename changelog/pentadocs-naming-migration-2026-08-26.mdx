## PentaDocs Naming Migration — 2026-08-26

## Decision

Effective **2026-08-26**, **PentaDocs** is the canonical CrownThrive institutional name for the documentation, knowledge, developer-docs, support-article, registry, changelog, recovery and public-safe institutional-memory system previously referred to internally as “Mintlify.”

This is a **product/system identity change**, not a claim that CrownThrive owns or has renamed the Mintlify vendor.

## Canonical naming boundary

| Context | Required name |
| --- | --- |
| CrownThrive institutional documentation/knowledge system | **PentaDocs** |
| Public-safe institutional corpus | **PentaDocs** |
| Documentation source-of-truth rules | **PentaDocs** |
| Documentation automation, articleization, changelogs, route graph and knowledge coverage | **PentaDocs** |
| Current third-party docs rendering/search/hosting provider | **Mintlify** |
| Mintlify API, Admin MCP, editor, provider workflows, plan, deployment version or provider-domain configuration | **Mintlify** |
| Mintlify credentials and provider-specific stable credential families | **Mintlify** / `ct.cred.mintlify.*` |
| Historical source text that originally said Mintlify | preserve original wording and annotate current PentaDocs successor meaning where needed |

## Unchanged infrastructure

The rename does **not** rotate or invalidate Mintlify credentials, change the source repository, change the deploy branch, alter provider API/MCP identifiers, or automatically activate a custom domain. Provider-specific facts remain provider-specific.

Current source and continuity remain centered on `crownthrive1/CrownThrive-OS`, Git history, machine-readable manifests, exports and registered recovery paths. PentaDocs must remain recoverable if Mintlify or any future rendering provider becomes unavailable.

## Relationship to ThriveSupport

- **PentaDocs** is the governed documentation and institutional-knowledge plane.
- **ThriveSupport / CrownThrive Support** is the support-facing service and knowledge-delivery function.
- **Mintlify** is the current PentaDocs provider implementation.
- Git/source, private registries, CHLOM evidence and ThriveBase remain separate authorities for the data classes they own.

## Migration rule

Living/current CrownThrive documentation, architecture, navigation, standards, automation contracts and roadmap language must use **PentaDocs** wherever the sentence refers to CrownThrive's own documentation or knowledge system.

Do **not** blindly replace `Mintlify` where the statement describes the actual vendor, provider API/MCP, credentials, deployment/readback, editor, plan, hosted checks, custom-domain configuration, outage scenario or preserved historical event.

## Governance effect

All future documentation-impact events, agent contracts, support workflows, changelogs, recovery tests, developer documentation and institutional-release records should emit **PentaDocs** as the product/system name. Provider-specific evidence should name Mintlify explicitly as the implementation provider.

This naming rule is additive and source-preserving: immutable historical evidence is not rewritten merely to make old wording look current.
