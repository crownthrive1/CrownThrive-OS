# Agent Generation 6 — priority, delegation, and throughput control

**State:** DRAFT / CONTROLLED_TEST / GOVERNED_HOLD  
**Phase effect:** none; Phase 2 / 2.99 remains current and Phase 3 remains blocked by the existing hard-exit contract.  
**Baseline:** `c70d48e768e1a0094fe6ddcdd3cc416ebc914091`.

This packet addresses a measured throughput bottleneck: the CrownThrive estate is creating bounded candidate work faster than the governed review, reconciliation, collision, and evidence queues are closing it. The private runtime currently has 32 construction work items and all 32 are blocked; the authoritative reconciliation estate includes 126 OPEN and 39 BLOCKED scopes. The scheduled control plane already uses all available active task slots, so Generation 6 does not add independent clocks merely to increase apparent agent count.

Generation 6 therefore uses a priority/delegation layer above the durable execution queues. It upgrades Agent A's orchestration contract from one-packet-at-a-time selection to bounded multi-packet dispatch with work-in-progress limits, dependency/collision checks, separation of originator and verifier, and exact handoffs. Existing durable queues remain the execution substrate.

- specify continuous skill-factory behavior: repeated bounded procedures may become fingerprinted skill candidates, but skills create no sovereign, legal, financial, rights, credential, merge, or D3 authority.

## Throughput doctrine

Agent A may dispatch multiple independent bounded packets in one cycle only when they have disjoint write sets or an explicit sequencing relationship, assigned owners and independent verifiers, bounded authority, rollback, and no unresolved collision. The control plane uses WIP caps rather than unlimited parallelism. Work that is blocked on the same upstream predicate is grouped and reconciled once instead of repeatedly retried by several agents.

Agent L owns intake/tag normalization and queue routing. Agent M owns permissioned multi-source reconciliation. Agent N owns independent proof/drift verification. Agent O owns current-main, branch, documentation, and homepage reconciliation. Agent P owns timing/backpressure analysis and schedule-change proposals. All five are non-voting D0–D2 support agents and cannot manufacture quorum or certify originating work.
