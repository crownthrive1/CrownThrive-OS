# Phase 2.99 — commercialized asset Sites storefront

## Why this exists

CrownThrive is converting reusable institutional operating knowledge into governed commercial digital products. A new **Sites-based storefront** is being built as the customer-facing distribution surface for approved runbooks, eBooks, templates, CHLOM capability pallets, institutional agent packs, training products and later licensed implementation/support offerings.

This storefront is a distribution and commerce surface. It does not become governance authority, framework certification authority or evidence authority merely because it renders a product page or accepts payment.

## Current evidence boundary

## Product loop

```text
institutional operation
  -> reusable pattern
  -> IP / security / rights classification
  -> public-safe or licensed product
  -> Sites storefront listing
  -> governed checkout
  -> protected fulfillment / entitlement
  -> customer + support evidence
  -> CrownLytics / THIVEBASE measurement
  -> product improvement
  -> updated institutional asset
```

The loop recycles learning into product improvement without recycling private customer data, credentials, restricted evidence or trade-secret implementation detail into public assets.

## Initial commercial families

- Quick Runbooks
- Developer Runbooks
- eBook Volumes
- Team Packs / worksheets / checklists
- Training Labs with synthetic fixtures
- CHLOM Capability Pallets
- Institutional Agent Packs
- Governed Reference Architecture packages
- Licensed Implementation Packs after rights/security review
- Support & Update subscriptions after recurring fulfillment is certified

The first compiled candidate is **Governed Agentic Operations Runbooks for Developers — Volume 1** and remains `packaged_candidate` rather than live commerce.

## Commercial lifecycle

Every storefront item inherits:

`concept -> candidate -> packaged -> rights_cleared -> pricing_authorized -> fulfillment_certified -> checkout_staged -> live`

A page, PDF, Stripe object or Sites deployment cannot skip those stages.

## Required before live

- provider-confirmed Sites project ID, saved version and production URL/access;
- exact product/master/storefront identity linkage;
- responsive, mobile, accessibility and interaction QA;
- public/private/IP disclosure scan;
- exact license authorization;
- exact price authorization;
- governed Stripe payment surface;
- payment/webhook reconciliation where applicable;
- protected delivery or entitlement certification;
- refund/dispute/revocation behavior;
- least-data analytics and support telemetry;
- rollback and saved-version continuity.

## Roadmap propagation

### Phase 2 / 2.99

Package, classify, archive and prepare product/storefront candidates. Keep sales fail-closed by default.

### Phase 3

Build executable product identity, rights, evidence, license and entitlement contracts plus controlled storefront pilots.

### Phase 4

Federate the storefront with CrownThrive ID, CHLOM, THIVEBASE/CrownLytics, CrownThrive Support, Crown Affiliates/Ambassadors, CrownRewards and approved API/MCP adapters.

### Phase 5

First general governed revenue activation for approved runbooks, eBooks, agent packs, capability pallets, training and support offers.

### Phase 6+

Developer licensing, implementation marketplace, conformance/certification, enterprise/OEM and recurring support scale.

## Protection boundary

Never publish or deliver credentials, credential fingerprints, Vault bodies, private runtime locators, protected master-agent instructions, trade-secret calibration, private eval/security corpora, private customer/partner evidence, undispositioned patent-candidate detail or third-party content without distribution rights.

Sell reusable capability, education, implementation rights, conformance, service access and support. Do not sell CrownThrive sovereign authority or its trade-secret kernel.
