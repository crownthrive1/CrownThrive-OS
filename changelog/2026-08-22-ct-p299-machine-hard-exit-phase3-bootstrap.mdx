# CT-P299 Machine Hard Exit and Perpetual Commerce Gate

**Date:** August 22, 2026  
**Program state at implementation:** Phase 2 / 2.99  
**Phase 3 state:** machine-evaluated, fail-closed; no transition is claimed by this change.

This packet resolves the roadmap namespace to the canonical ten-phase institutional program, preserves earlier five-phase material as historical planning evidence, and implements a deterministic `GO | HOLD | NO-GO` Phase 2.99 hard-exit evaluator.

The evaluator freezes exact source, Git, THIVEBASE and documentation baselines, requires exact-head authority/quorum and recovery receipts, and gives live provider/security evidence precedence over stale static snapshots. `GO` is bootstrap eligibility only. Phase 3 activation requires exact readback of the DAIL event, THIVEBASE baseline, Git release/tag, Mintlify changelog and rollback snapshot.

The Commercial Release Factory is also defined as perpetual candidate-processing capacity with no terminal product count. Every new or materially changed product/version re-enters all applicable gates and cannot inherit a prior version's PASS. ECAC remains mandatory before economic activation, automatic publication remains default-off, and authorized pause/quarantine/decommission remains available.

The THIVEBASE SQL/migration control channel was unavailable during this implementation because database connections timed out. No database PASS or phase-transition record was fabricated. The read-only OIDC snapshot lane is separately deployable and does not widen production authority.
