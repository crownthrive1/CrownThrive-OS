# Phase 2.98 — Platform Extraction Program

## Mission

Inspect every material CrownThrive platform, brand, imprint, universe, room, engine, domain and vendor implementation against the Platform Extraction Standard and create a complete evidence-backed institutional package. Phase 2.98 verifies what exists; it does not rebuild every platform.

## Entry baseline

- Phase 1–2.95 institutional recovery;
- Phase 2.97 release `2.7.9.0`;
- deep governance patch `2.7.9.1`, merged to `main` as the institutional checkpoint established by PR #8;
- Founder adjudications;
- continuation work must fork from that merged checkpoint rather than mutate its historical branch;
- current repositories, Drive/source files and live properties;
- standards for IDs, evidence, rights, versioning, legal status, APIs/MCPs, SEO, private knowledge and run packets.

## API and vendor discovery method

Use official docs, repository contracts, admin integration settings, source configurations, current authorized tests and provider records. Record planned/source-defined endpoints separately from deployed/verified interfaces. No secret or private base URL enters public docs.

## Platform-state verification

Verify capability by capability:

- public reachability;
- auth/account;
- core read experience;
- mutation/action;
- checkout/payment;
- webhook;
- entitlement/fulfillment;
- admin/ops;
- API/MCP;
- support;
- analytics/monitoring;
- backup/recovery.

A site cannot receive one blanket “production” status.

## Cleanup outputs

Identify stale routes, dead links, obsolete webhooks, duplicated source files, old vendors, dormant credentials, unsupported plugins, abandoned branches, conflicting products, retired names and prior-run bridges. Do not delete; create dependency-checked migration/sunset records for Phase 2.99/Phase 3 execution.

## Execution model

Each platform extraction runs as a governed packet with parallel source, product, technology, API, legal, SEO, security and registry workstreams. An independent reviewer verifies the resulting package. High-risk conclusions remain held for Founder/counsel/technical authority.

## Acceptance criteria

- every selected platform is populated or explicitly marked unknown by domain;
- no invented API, legal status, metric, rights or production claim;
- all public claims have source/as-of/method;
- restricted source content remains private;
- stable IDs and relationships resolve;
- current/historical/planned states are distinct;
- cleanup candidates preserve dependency and rollback;
- each packet ends with exact Phase 2.99/Phase 3 handoff.

## Exit artifact

A versioned platform intelligence corpus plus machine-ready imports for the Phase 2.99 private core and Phase 3.0 registries.
