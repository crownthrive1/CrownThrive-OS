## Machine trigger asset fabric bindings

CrownThrive now treats the machine-led Phase 2.99, Phase 3 bootstrap, commerce and continuity triggers as governed institutional candidate assets rather than informal workflow logic.

The controlled-test fabric `ct.fabric.machine-trigger-assets.v1` contains **32 trigger bundles**. Each bundle deterministically derives one algorithm, one governed skill, one machine prompt and one automation-script candidate, for **128 derivative candidates**. These assets are registered for intake by `ct.fleet.chlom-proprietary-asset-factory.100k-plus` but do not alter the completed authoritative estate: the current **100,800 authoritative generation assets remain unchanged** and the trigger-asset authoritative delta is zero until governed factory admission.

The fabric includes five D2-ceiling, non-voting plugins: `ct.plugin.machine-trigger-router`, `ct.plugin.p299-phase-gate`, `ct.plugin.phase3-bootstrap`, `ct.plugin.commerce-factory` and `ct.plugin.vault-dail-continuity`.

The Vault binding contract `ct.binding.machine-trigger-vault.v1` defines **32 opaque Vault binding candidates** across control, bootstrap, commerce and continuity evidence classes. Raw secrets and public Vault locators are prohibited. Live binding is `PENDING_RUNTIME_BINDING` because the governed THIVEBASE SQL/control path remains connection-timeout constrained; no binding receipt is manufactured.

The Machine Trigger Asset Fabric workflow runs hourly and on relevant repository events. Its deterministic builder and cross-binding validator prove the trigger, derivative, plugin, Vault and factory-intake topology while preserving read-only scheduled permissions. Negative tests reject D3 expansion, provider-write defaults, ECAC bypass and public Vault locator disclosure.

CT-P299 now includes the machine-trigger fabric, plugin suite, Vault binding contract, factory intake and cross-binding validator in its canonical source freeze. The GitHub OIDC THIVEBASE snapshot service exact-pins the corresponding controlled-test source artifacts. Technical validation does not change the Phase 3 verdict; `GO`, authority/recovery receipts and bootstrap readback remain separate gates.

The Commercial Release Factory candidate path is separately bound to the trigger fabric for candidate discovery, material-change reopening, package build, release-gate evaluation, ThriveEvergreen ECAC decisions, bounded publication, entitlement/fulfillment, drift reconciliation, remedies, Vault custody, DAIL and supersession.
