# Commercial Release Factory — August 22, 2026

CrownThrive established a bounded **Commercial Release Factory** for CrownThrive Launch, CrownThrive Ready and CrownThrive Procure.

## Exact initial cohort

The factory binds the existing 30 packaged `1.0.0-candidate.4` digital products: ten products per platform. Existing deterministic package rebuild and independent integrity evidence is preserved; the release factory does not reclassify package QA as commercial acceptance.

The three registered ChatGPT Sites provider surfaces remain healthy and provider-connected. Their preferred custom hostnames remain separate DNS/TLS certification targets and are not represented as active merely because a target name is known.

## Agent and machine contract

The existing non-voting `ct.agent.commercial-release-packager` is now projected as the canonical release-package orchestrator. The public machine contract adds:

- nine hard release dimensions;
- 18 reusable release skills;
- eight protected algorithm contracts whose bodies remain private;
- three Sites surface bindings;
- all 30 initial SKU bindings;
- credit-only commerce invariants;
- provider-independent feed/readback rules;
- explicit replication rules for non-voting child workers.

The originating agent remains A2/D2 and cannot self-approve or activate production.

## Commerce decision

Launch, Ready and Procure product checkout is standardized as **Crown Credits-only**. Per-SKU Stripe Product/Price creation is prohibited for these three surfaces. A separately governed Stripe funding rail may fund Crown Credits where authorized, but funding evidence does not independently grant a product license or entitlement.

The required sequence remains:

```text
credit redemption evidence
→ license / entitlement policy decision
→ entitlement
→ protected fulfillment
→ append-only remedy / reversal if needed
```

## Automated package dimensions

For each product the factory prepares independent packets for:

1. rights and provenance;
2. pricing and tax;
3. private fulfillment;
4. Crown Credits checkout and event/replay handling;
5. entitlement and license;
6. refund, dispute and rollback;
7. accessibility and device evidence;
8. DNS, TLS and canonical routing;
9. governed acceptance and publication.

Unknown or stale hard-gate evidence resolves to HOLD.

## Publication architecture

The default Sites publication path is a **governed dynamic feed** followed by provider readback rather than unrestricted direct editing by the release originator. Automatic publication is possible only where the accepted release policy, certified destination adapter, route, read-after-write proof and rollback controls all permit it.

## Controlled-test evidence

A repository validator and dedicated CI workflow were added. The controlled test checks the 30-product binding, exact gate order, credit-only semantics, disabled MCP candidates, non-voting/no-self-approval constraints and protected-IP boundary. It also runs negative authorization cases that must fail when unsafe policy mutations are introduced.

This controlled test creates no rights grant, live price, tax conclusion, credit movement, Stripe object, DNS change, provider write or production publication.

## Next acceptance work

The factory may now compile and route the missing product evidence without inventing PASS. Initial promotion remains gated by the same substantive work that previously blocked canonical release: rights, pricing/tax, private fulfillment, entitlement/remedies, full accessibility/device evidence, DNS/TLS where custom domains are desired, and independent governed acceptance.
