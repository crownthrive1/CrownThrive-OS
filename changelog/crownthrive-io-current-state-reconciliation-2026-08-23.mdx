## Corrections

### Provider/version state

Previous public-safe documentation left the CrownThrive IO application engine/vendor as `not-yet-forensically-verified`. The current admin evidence now supports `66biolinks / AltumCode / v66.0.1` as the dated implementation lineage.

That correction does **not** prove:

- editable source-repository custody;
- exact deployment revision;
- backup/restore health;
- database migration readiness;
- compatibility with `v70.0.0`;
- authenticated API runtime behavior.

### Metrics state

The dashboard's `Users` value is now explicitly classified as a registered-account counter. It is not a member, verified-user, monthly-active-user, customer or ecosystem-member count.

The supplied users/logs also create a registration-quality review obligation because many recent records are unconfirmed Free accounts and exhibit low-trust registration patterns. The documentation does not label every such account as malicious; it prevents those raw counters from becoming unsupported growth claims.

### Commerce state

The local dashboard shows zero application payments and zero application-local earnings at the snapshot. This is not a CrownThrive-wide revenue claim and does not negate downstream economic value from links, QR routes, advertising or other ecosystem handoffs.
