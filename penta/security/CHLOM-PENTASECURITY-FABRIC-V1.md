# CHLOM + PentaCHLOM + PentaSecurity Fabric v1

Status: **source candidate / independent certification required**

## Canonical boundary

CHLOM remains CrownThrive's rights, rules, roles, revenue, records and remedies authority layer. PentaCHLOM is the proposed governed Web2/interoperability engineering adapter; it does not manufacture CHLOM authority. PentaSecurity is the existing Security, Identity & Trust family security orchestrator and cannot certify its own work.

Current CHLOM runtime baseline is `ct.chlom.protocol.v1`, active, API/event-first, append-only and DAIL-backed. Current health readback reports canonical DAIL enabled, direct DAIL writes revoked, sequencer enabled, tamper-evident chaining enabled and runtime health healthy. CHLOM Wallet remains an internal non-economic accounting kernel with D3 human-reserved for live/public economic activation. A public CHLOM token economy is **not** current production authority. Token semantics remain HOLD until exact current machine/runtime evidence establishes them.

CHLOM 2.1 construction overlays and other proposal rows are research/proposal evidence only. They do not supersede the current canonical protocol.

## DAIL topology correction

The verified CrownThrive runtime has three canonical DAIL systems:

1. `ct.dail.human.v1` — explainable, founder/approval-facing continuity.
2. `ct.dail.hybrid.v1` — joint human/autonomous crossover relay.
3. `ct.dail.machine.v1` — machine execution and evidence lineage.

`evidence`, `decision`, and `execution` are semantic stages projected across those systems. They are not replacement ledgers and must never be represented as three separate canonical DAIL systems unless a later governed migration explicitly changes the topology.

The v1 assurance kernel does not trust a caller-supplied DAIL lane label. It appends each material assurance action through canonical CHLOM DAIL, calls the canonical DAIL classifier, then records the exact DAIL event ID/hash and classification only after readback succeeds. A failed append/readback aborts the assurance mutation.

## Security assurance state machine

The v1 kernel enforces:

```text
candidate
  -> scanned
  -> threat_modeled
  -> tested
  -> security_pass
  -> chlom_pass
  -> cie_pass (when required)
  -> certification_pending
  -> certified
  -> released
```

The kernel pre-binds originator, independent security decider, CHLOM authority path and independent certifier; when CIE is applicable it also pre-binds an independent CIE decider. Required separation-of-duties combinations are rejected. Security, CHLOM and certification stages must be performed by their bound actors. The originator cannot certify or release its own work, and the certifier cannot also execute release.

Every material action is DAIL-first and transactional. Local assurance chronology is append-only. Runtime service roles may read projections and invoke governed functions but are denied direct state mutation and direct chronology insertion.
