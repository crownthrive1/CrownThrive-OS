# Agentic \+ Intelligence Pentas

This lane governs machine intelligence and agentic execution as institutional capabilities rather than unbounded personalities.

## PentaAgentic™

**Mission:** canonical specialist-agent family operating under bounded authority. **Portal:** `/io/pentas/agentic`. Defines agent identity, contracts, leases, authority ceilings, evidence, evaluation and handoffs.

## PentaEdge™

**Mission:** identity, least-data, authority and side-effect guard at execution boundaries. **Portal:** `/io/pentas/edge`. It is the execution-edge control that prevents a valid tool from becoming an invalid action.

## PentaFlex™

**Mission:** adaptable MCP/API framework and interface layer. **Portal:** `/io/pentas/flex`. Standardizes adaptable interfaces while preserving provider-specific certification.

## PentaMCP™

**Mission:** MCP runtime and tool-service interface. **Portal:** `/io/pentas/mcp`. Registers, exposes and governs MCP capabilities and their evidence/permission contracts.

## PentaAgents™

**Mission:** governed agent registry, execution and lifecycle. **Portal:** `/io/pentas/agents`. Maintains agent state, leases, versions, tools, responsibilities and terminal disposition.

## PentaLLM™

**Mission:** LLM provider/model governance and runtime bindings. **Portal:** `/io/pentas/llm`. Tracks model/provider identity, allowed uses, evaluation, routing and fallback without treating model access as institutional authority.

## PentaMCL™

**Mission:** machine-learning capability and lifecycle layer. **Portal:** `/io/pentas/mcl`. Covers non-LLM ML lifecycle, model evidence, evaluation and controlled deployment.

## PentaBoxes™

**Mission:** plugin/component packaging and runtime extension system. **Portal:** `/io/pentas/boxes`.

## PentaSkills™

**Mission:** governed skill/capability registry and lifecycle. **Portal:** `/io/pentas/skills`.

## PentaTools™

**Mission:** governed tool registry and execution bindings. **Portal:** `/io/pentas/tools`.

## PentaStars™

**Mission:** governed capability/authority agreements and contracts. **Portal:** `/io/pentas/stars`.

## PentaRithms™

**Mission:** algorithms and governed decision/execution logic. **Portal:** `/io/pentas/rithms`.

## PentaSets™

**Mission:** asset-set registry, packaging, ownership and lifecycle. **Portal:** `/io/pentas/sets`.

## PentaScripts™

**Mission:** governed script registry, execution, provenance and versioning. **Portal:** `/io/pentas/scripts`.

## PentaMaps™

**Mission:** system, relationship and status visualizations plus operational maps. **Portal:** `/io/pentas/maps`.

## Operating requirements

Every independently executable intelligence component requires a defined owner, approved purpose, authority ceiling, tool/data scope, evaluation, provenance, security policy, status adapter, audit receipt, lifecycle state, rollback/disable path and current provider/model readback where applicable.
