# Binding \+ Provider Control Pentas

This lane turns potential integrations into governed, supportable production paths. Possessing a credential or API endpoint is not the same as having certified authority to execute.

## PentaBound™

**Mission:** authority/resource boundary definitions. **Portal:** `/io/pentas/bound`. Defines what an identity, subsystem, provider path or asset is permitted to touch and under what conditions.

## PentaBind™

**Mission:** governed binding of identities, providers, assets and capabilities. **Portal:** `/io/pentas/bind`. Creates inspectable associations without broadening underlying rights.

## PentaWire™

**Mission:** governed wiring/integration into the operating mesh. **Portal:** `/io/pentas/wire`. Materializes approved integration paths and their dependency/readback contracts.

## PentaCredentials™

**Mission:** credential references, lifecycle, readiness, binding and health without secret exposure. **Portal:** `/io/pentas/credentials`. Owns references and readiness semantics; secrets stay in governed vault/provider custody.

## PentaBuild™

**Mission:** build, package, version and maintain software assets, adapters, plugins and provider bindings. **Portal:** `/io/pentas/build`. A successful build is a build result, not certification.

## PentaCertify™

**Mission:** certify adapters, plugins, integrations and execution paths using governed tests and evidence. **Portal:** `/io/pentas/certify`. Certification must identify exact version, provider path, permissions, tests, evidence and expiry/revalidation conditions.

## PentaNurture™

**Mission:** maintain provider/software lifecycle health after build and certification. **Portal:** `/io/pentas/nurture`. Tracks drift, expiring credentials/certificates, provider changes, regressions, maintenance and remediation.

## Canonical chain

```text
BOUNDARY → BIND → WIRE → CREDENTIAL READINESS → BUILD → CERTIFY → OPERATE → NURTURE → RE-CERTIFY / RETIRE
```

## Required evidence

Provider identity, exact adapter/version, credential reference, permission scope, test evidence, provider readback, failure modes, retry/rollback behavior, status adapter, audit events, owner/escalation and lifecycle state are mandatory for production classification.
