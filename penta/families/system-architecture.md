# Penta System Architecture Family

**Family ID:** `system-architecture`  
**Portal:** `/io/pentas/families/system-architecture`  
**Parent:** Penta Family™

## Story

This is the body plan of CrownThrive's Penta operating system. It answers where a system belongs, which plane it occupies, how dependencies connect, what the canonical substrate is, and how the whole institutional system models itself without confusing observation with authority.

PentaOS establishes the technical namespace. PentaTechture captures architecture and ADRs. PentaPology maintains topology and reachability. PentaPlanes keeps control/data/execution/governance planes distinct. PentaBase binds the institutional runtime/data substrate. PentaMesh and PentaFabric describe interoperable runtime fabric. PentaControl coordinates already-governed intent. PentaVergence reconciles drift and supersession. PentaSELF provides bounded self-observation.

## Operating flow

```text
institutional intent / topology change
→ PentaControl + PentaTechture
→ PentaPology / PentaPlanes validation
→ PentaRoute / Federation handoff
→ child system execution gates
→ PentaStatus / organic-system readback
→ PentaVergence reconciliation
→ PentaSerialized / Generation preservation
```

## Cross-family handoffs

- **Routing & Interoperability:** turns topology into certified addressable paths.
- **Governance & Legal:** resolves authority/policy that architecture cannot manufacture.
- **Observability & Organic Systems:** supplies current body/health evidence.
- **Resilience & Continuity:** preserves versions, snapshots and recovery paths.

## Authority boundary

Architecture describes and coordinates capabilities; it does not create credentials, provider writes, rights, legal sufficiency, financial authority, D3 authority or production maturity. A reachable node is not an authorized node.

## Status and evidence

Family status is derived dynamically from member registries. Technical `active`, machine `production`, PentaOD `HOT`, or portal `contracted` are independent state dimensions.

## Incidents and recovery

Topology or substrate incidents route through PentaStatus/PentaTriage, the Security/Trust family and Resilience/Continuity. Recovery must preserve current authority, exact configuration/evidence lineage and rollback.

## Releases and roadmap

Architecture changes are versioned topology changes. New planes, meshes, substrates or control components must receive stable identity, family classification, child contract, evidence and portal coverage before family verification returns PASS.
