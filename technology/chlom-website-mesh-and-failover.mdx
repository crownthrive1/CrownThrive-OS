# CHLOM Website Mesh and Failover

CHLOM must remain discoverable and explainable even when an individual site, provider, or runtime is unavailable. The website mesh therefore separates **public discovery**, **institutional documentation**, **developer orientation**, **source visibility**, and **runtime execution**.

## Public mesh

| Priority | Surface | Role |
| --- | --- | --- |
| 1 | `crownthrive.com` | corporate, partnership, commercial funnel |
| 2 | `crownthrivesupport.com` | institutional documentation and support |
| 3 | `crownthrive.io` | developer ecosystem and integration discovery |
| 4 | `crownthrive/chlom-protocol` | public CHLOM commercial source and registries |
| 5 | `crownthrive1/CrownThrive-Support` | canonical public-safe governance parent |

These are routing roles, not claims that every planned CHLOM API, MCP tool, portal, checkout, or service is currently deployed on each surface.

## Degraded-mode behavior

When one surface is unavailable:

- corporate discovery falls back to institutional docs and GitHub;
- documentation discovery falls back to the public CHLOM child repository;
- developer discovery falls back to machine contracts and architecture in the child repository;
- runtime API/MCP failures fail closed for rights, economic, or other high-consequence mutations;
- provider failures may create an operational HOLD but must not erase DAIL evidence or silently rewrite institutional truth.

## Redundancy layers

Public URL redundancy is only one layer. Production resilience should separately address:

1. DNS and domain control;
2. CDN/edge delivery;
3. application/runtime health;
4. API/MCP gateway routing;
5. database and ledger durability;
6. queue and scheduler durability;
7. provider adapters;
8. object/archive storage;
9. observability and incident routing;
10. documented human recovery paths.

## Agent binding

`ct.agent.chlom-mesh-reliability` observes public discovery routes, repository projection, documentation reachability, and machine-contract availability. It may generate repair candidates but cannot modify DNS, credentials, production routing, payment rails, or restricted infrastructure without separate accepted authority.

## Continuous checks

Repository automation may perform scheduled reachability and projection checks. A successful public HTTP response is availability evidence only. It does not establish that every downstream feature is healthy, licensed, or production-certified.

## Website convergence rule

Every public CHLOM page should resolve to at least one of the following actions:

- understand CHLOM;
- inspect public architecture or registries;
- evaluate developer integration;
- request support or report a correction;
- begin a licensing or enterprise conversation;
- voluntarily support the build;
- navigate back into the CrownThrive ecosystem.

This keeps the mesh useful as both an institutional reference and an acquisition/education funnel without exposing protected implementation material.
