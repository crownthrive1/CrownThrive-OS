# CrownThrive IO and MCP

**CrownThrive IO** is the interoperability corridor. Its existing public role includes links, QR codes, biolinks, static sites, and lightweight digital-presence infrastructure. The institutional architecture expands that role into a governed **IO/MCP integration layer** that connects CrownThrive platforms, services, data contracts, and approved AI tools.

## Core responsibilities

The institutional layer should provide:

- platform and service adapters;
- stable API contracts;
- webhook intake and delivery;
- tool registration and capability discovery;
- identity and authorization propagation;
- event normalization;
- metering and usage records;
- rate limits and throttling;
- health/status reporting;
- secrets isolation;
- agent-facing MCP tools;
- public link, QR, vCard, event-link, and static-site services where applicable.

## MCP security model

Agents should never receive unrestricted vendor credentials or blanket database access. The gateway exposes narrowly scoped tools with explicit inputs, outputs, actor identity, permission checks, logging, and approval requirements.

```text
Agent / Platform
      ↓
CrownThrive ID
      ↓
IO / MCP Gateway
      ↓
CHLOM + Approval checks
      ↓
Scoped adapter / tool
      ↓
External or internal system
      ↓
DAIL event + CrownLytics signal
```

## Governed design/creative connector lane

The IO/MCP registry includes bounded service identities for Figma design control, Canva creative production, Mintlify documentation control, GitHub repository control and Google Drive artifact mirroring.

Current managed connectors are not equivalent to unattended server-side adapters. The machine registry keeps these dimensions separate:

- provider authentication/credential state;
- provider read/write verification;
- central MCP tool registration;
- central adapter/dispatch certification;
- production write-gate state.

Managed OAuth remains with the provider connector and is recorded as `provider_managed_only`. A future CrownThrive-owned direct adapter must use a Vault-backed secret reference rather than embedding credentials in design files, docs, code or tool definitions.

The design lane routes through the same CHLOM, approval, DAIL, budget and recovery controls as other tools. Figma Code Connect remains disabled until exact code paths/exports are proven, and Canva remains downstream from the canonical design contract.

See [Design Control Plane and Creative Production Governance](/technology/design-control-plane-and-creative-production).

## Adapter doctrine

A third-party vendor can be replaced without changing institutional identity. For example, a link engine, ad server, community platform, publishing engine, design tool, creative-production tool or booking system may change while the CrownThrive service ID and business contract remain stable.

## Phase 3 requirement

The gateway should initially focus on a small set of high-value integrations rather than attempting to connect the entire portfolio at once. Each integration requires an owner, data contract, permissions, event taxonomy, failure behavior, backup/export route, and support runbook.
