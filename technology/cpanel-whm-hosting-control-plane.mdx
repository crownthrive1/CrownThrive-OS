## Hosting-account evidence rules

A cPanel account is **hosting evidence**, not a universal platform-state assertion:

- account present ≠ domain registered or controlled at the registrar;
- account unsuspended ≠ application healthy, reachable or production-certified;
- account suspended ≠ asset legally sunset or abandoned;
- account package/quota ≠ current application demand or commercial entitlement;
- hosting IP ≠ canonical DNS or TLS correctness;
- filesystem presence ≠ authoritative editable source repository;
- an API token ≠ blanket mutation authority.

The eight suspended accounts therefore enter lifecycle reconciliation. Some may correspond to intentional sunset/reserve assets; no automated unsuspension is authorized solely from the suspension flag.

## THIVEBASE integration

THIVEBASE now records the hosting provider as an infrastructure dependency with current account-count, suspension-count and load observations. Load averages are retained privately as time-stamped operational evidence. They are not interpreted as overload without an independently verified CPU/core and resource-capacity baseline.

This makes WHM evidence available to future capacity, continuity, deployment and platform-certification workflows while preventing provider telemetry from becoming a platform-status shortcut.

## Security and continuity controls

Current controls include:

- encrypted Vault storage and managed recovery reference;
- opaque credential version handle and rollback-capable custody history;
- JWT-required Edge Function adapter;
- read-only operation allowlist;
- response SHA-256 evidence rather than public raw payload replication;
- restricted hosting-control schema;
- provider-write gate closed;
- source/evidence separation between WHM, registrar, DNS/TLS, repositories and application runtime.

A post-migration security-advisor review produced no new finding specific to the private hosting-control schema. Existing unrelated informational RLS notices elsewhere in the CrownThrive database remain separate remediation work.

## Remaining certification gates

- rotate the broad conversation-exposed WHM token to a least-privilege managed credential; provider ACL inspection shows the current token exceeds the read adapter's needs;
- review the separate pre-existing full-access cPanel token named `THRIVEBASE` for unknown external consumers before revoke/retire;
- verify the ThriveBase SSH passphrase and provider-side authorization state before any live SSH test or shell execution;
- certify disk-usage read and establish server CPU/core, memory and storage capacity baselines before thresholding load;
- reconcile the eight suspended hosting accounts against the canonical asset lifecycle/disposition register;
- verify backup, restore, retention, account export and provider-exit procedures;
- treat the `crownthrive.io` account's 12-host local cPanel inventory as established by `S115`, while separately mapping registrar/registrant state, DNS/DNSSEC authority, TLS, mail, canonical redirects, application health and source/deployment state without conflating those systems of record;
- define monitoring cadence and alert thresholds before autonomous remediation;
- keep WHM/cPanel mutations and SSH shell execution fail-closed until an explicit action class, approval rule, rollback plan and independent verification exist.

## Downstream phase impact

- **Phase 3:** import the WHM provider, credential, endpoint, hosting-account and observation records into the executable infrastructure seed; keep provider mutation authority separate.
- **Phase 4:** platform certification may consume WHM hosting evidence but must still verify DNS/TLS, source/deployment and application health independently.
- **Phase 5:** customer-facing commerce or acquisition paths cannot rely on a hosting-account flag as availability evidence.
- **Phase 8:** Holdings/infrastructure reporting may use governed capacity and dependency evidence without treating cPanel accounts as additional portfolio assets.
- **Phase 10:** continuity requires credential rotation/revocation, off-provider backups/exports, hosting-account reconstruction, DNS/mail dependency mapping and a tested provider-exit path.

No Phase 2.99 or Phase 3 hard gate is relaxed by this integration.
