# Private Knowledge, RBAC and Automated Publication Architecture

CrownThrive needs one coherent knowledge system without making all institutional knowledge public.

## Knowledge tiers

**Public:** support, approved policies, public platform documentation, approved developer docs, public claims, public-safe institutional frameworks.

**Authenticated/gated:** member, customer, creator, affiliate, partner, developer, operator or staff guidance appropriate to an authenticated role.

**Restricted:** internal strategy, private ADRs, contracts, security procedures, confidential IP, private source material, nonpublic economics, evidence, investigations, sensitive identity and operational details.

**Machine-only:** secrets references, raw authorization state, internal identifiers where exposure creates risk, automated evaluation artifacts, private event payloads and system-control records.

## Support-domain strategy

`crownthrivesupport.com` may become the branded knowledge entry layer, but it must not expose restricted material merely because public and private documentation share a domain. If used for both public and private knowledge, private content requires real authentication/authorization at the application/data layer, separate indexing rules, audit logs and safe search/retrieval boundaries.

A safer long-term pattern is one knowledge control plane with multiple projections: public Mintlify/Help Center, authenticated portal views, restricted internal knowledge service, and machine APIs.

## Automated publishing

Source changes should be classified, linted, checked for secrets/PII, validated against audience/role, reviewed according to autonomy class, versioned, then projected to the correct destination. Public search indexes and sitemaps must receive only public-safe material.

## Retrieval

Agent retrieval must include caller role, data class, purpose and platform context. Search results must not cross visibility boundaries because two documents are semantically similar.

## Redaction and transformation

Restricted source material may produce public-safe summaries only through an explicit transformation path that removes private details and records the source relationship.

## Automation goal

The desired operating state is nearly hands-off synchronization: governed source → validation → audience classification → approved projection → search/index refresh → link and metadata validation → DAIL event → monitoring. Human review remains where policy requires judgment.
