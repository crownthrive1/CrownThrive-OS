# Phase 3 Readiness Gate

Phase 2.9 closes the documentation-only preparation cycle. Phase 3 may begin only from a controlled baseline that distinguishes fact, history, target architecture, unresolved decisions and production evidence.

## Required before Sprint 0 closes

### Identity and versioning

- stable IDs for organizations, actors, assets, platforms, CHLOM components and knowledge sources;
- version namespaces and lifecycle state vocabulary;
- alias/successor relationships;
- current platform-state records for P0/P1 assets.

### Governance and authority

- founder/reserved decision list;
- delegated role matrix;
- approval thresholds;
- break-glass/recovery authority;
- legal/accounting/counsel gates.

### Data and evidence

- source authority levels;
- DAIL event envelope;
- correction model;
- restricted/public data classes;
- evidence references and checksums where appropriate.

### Security and continuity

- secret manager decision;
- repository/deployment map;
- domain/DNS ownership map;
- backup/restore policy;
- vendor exit records for critical dependencies;
- incident and credential-rotation paths.

### Commerce and rights

- payment/webhook/entitlement state by active commerce platform;
- rights-hold procedure;
- product/license state vocabulary;
- economic schedules versioned separately from ownership/equity.

### Testing and evaluation

- synthetic fixtures;
- unauthorized-action tests;
- stale/conflicting-source tests;
- idempotency/retry tests;
- backup/restore test;
- rollback test;
- agent eval baseline.

## Explicitly permitted unresolved items

Phase 3 may start with some records still `research`, `proposed`, `legal-review`, `unverified` or `implementation-gated` so long as services cannot silently promote them to a stronger state.

Examples: future Holdings formation, MM Suites legal franchise activation, patent strategy, token deployment and universal SSO do not need to be completed before Sprint 0; their state and gates must be explicit.

## Phase 2.95 additions to the gate

Before Sprint 0 closes, Phase 3 must also seed or explicitly backlog:

- CHLOM paper/IP records, including confidentiality and authority classes;
- full component/pallet records and namespace distinction between runtime pallets and cloud/API capability pallets;
- developer API/client registry;
- platform API/adapter profiles;
- CrownThrive ID/social-platform SSO account-link model;
- SDK/webhook/event version policy;
- developer/sandbox credential classes;
- role-to-surface and widget registry;
- Crown Affiliates attribution/economic-schedule event model;
- sustainability/impact evidence schema;
- framework/engine registry;
- recovery targets for paper families or source records that have not yet been located.

Purple, Silver, Orange and Yellow CHLOM paper families are currently recovery targets only; their absence does not block Sprint 0 because the system now knows they are missing and must not invent their contents.

## Go / no-go principle

Phase 3 is a **go** for controlled engineering when the institution can identify what it knows, what it does not know, who can decide, how records are versioned, how failures are recovered, and how consequential actions are prevented when those prerequisites are missing.

Broad autonomous execution remains **no-go** until the individual service acceptance tests and approval controls are proven.
