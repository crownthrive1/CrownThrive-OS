## Current institutional documentation control plane

PentaDocs is CrownThrive's cross-surface documentation control plane. It converts governed source truth into human-readable and machine-readable records while keeping documentation, runtime, authority, deployment and public-readback states separate.

The current institutional implementation spans:

- the governed Drive folder **05 — PentaDocs Source & Publication Records**;
- the CrownThrive OS repository's Mintlify-compatible source named **PentaDocs**;
- `integration_control.penta_docs_change_ledger_v1`;
- `integration_control.penta_docs_delta_registry_v1`;
- `integration_control.penta_docs_reconciliation_ledger_v1`;
- recurring delta projection, bounded reconciliation, observation, configuration-watchdog and site-enrichment schedules;
- CHLOM and DAIL release evidence;
- phase, evidence, IP/asset and publication ledgers.

Repository source, Drive custody, DAIL evidence and public deployment are cooperating surfaces, not interchangeable copies. A repository branch does not prove merge. A merge does not prove provider deployment. A deployment does not prove exact public readback. Documentation confidence does not certify runtime or institutional authority.

## Current DAIL documentation profile

The current DAIL generation is the **Cursor-Controlled DAIL Capacity Mesh**:

```text
One canonical CHLOM DAIL chain
→ Machine / Human / Hybrid / Cursor projections
→ DAIL Cursor coordination
→ 500K Continuity Lock
→ Head / Continuity / Archive routing
→ PentaBalancer admission
→ PentaGas capacity accounting
→ MeshAssist and approved bounded capacity donors
→ one canonical writer and terminal readback
```

The documentation profile preserves these distinctions:

- Machine, Human, Hybrid and Cursor are projections over one canonical event identity, not four ledgers.
- Cursor coordinates manifests, high-water marks, routes, deferred work, verification and terminal receipts.
- The Continuity Lock activates at 500,000 exact pending routes and releases at 450,000 or fewer.
- While locked, route selection remains 70 percent Head, 30 percent Continuity and 0 percent Archive.
- Archive work is preserved and deferred, not deleted or counted as complete.
- PentaBalancer controls admission and pressure behavior; it does not grant authority.
- PentaGas accounts for execution capacity; available gas does not grant archive bypass, rights, payment, publication, token or D3 authority.
- MeshAssist and approved donors add bounded capacity without creating another DAIL chain, writer or institutional principal.
- Retired compact-catchup and serial-lane clocks remain historical lineage and must not be automatically restored.

The governed Drive source includes the DAIL Phase Library Master Ledger, complete Cursor-Controlled Capacity Mesh compendium, evidence and publication workbook, phase books, diagrams and release records. Current runtime truth remains in ThriveBase and canonical DAIL receipts.

| Support | Current guide, runbook, escalation path and accountable owner |
| Master records | CHLOM, phase, DAIL, IP/asset and product ledgers as applicable |

Use explicit documentation states instead of one ambiguous done flag:

```text
DISCOVERED
→ SOURCE_PRESENT
→ EXTRACTED
→ RECONCILED
→ DOCUMENTED
→ REVIEWED
→ MERGED
→ DEPLOYED
→ PROVIDER_READBACK
→ PUBLIC_CURRENT
```

`CONFLICT`, `SUPERSEDED`, `RETIRED` and named `HOLD_*` states remain available at the appropriate boundary.

The current source authority hierarchy is:

1. Current provider or runtime readback.
2. Canonical DAIL event and terminal receipt.
3. Governed database ledger or registry.
4. Accepted repository source and exact commit.
5. Governed Drive source and phase record.
6. Public documentation after provider readback.
7. Historical documents as lineage unless explicitly reaffirmed.

No lower source silently overrides a higher current source. Contradictions are preserved and reconciled rather than erased.

## Reliability, failure modes & recovery

Treat timeout, dependency degradation, stale evidence, invalid authority, unavailable provider bindings, provider refusal, partial write, duplicate delivery and inconsistent readback as explicit failure states. Fail closed for high-consequence ambiguity. Bounded retry is appropriate only when the underlying operation is retry-safe/idempotent; otherwise reconcile/read back before another write.

## Observability, SLOs & PentaStatus

At minimum expose or resolve: lifecycle/readiness state, last successful readback, dependency health, error/incident state, evidence freshness, release/version identity and accountable owner. Numeric SLO/SLA targets must come from the Penta-specific contract; documentation must not invent them.
