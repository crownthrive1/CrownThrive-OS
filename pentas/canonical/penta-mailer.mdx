# PentaMailer

PentaMailer is the bounded execution layer inside PentaMail. It owns provider route selection, queue claims, rate reservations, bounded retries, delivery attempts, provider outcome normalization, receipt-chain continuity, and terminal projection.

## Identity rule

PentaMailer is **not** a second sovereign Penta and may not duplicate PentaMail's institutional identity. The runtime aliases `penta.mailer`, `pentamailer`, and `ct.penta.mailer.v1` resolve to `penta.mail` as subcomponent aliases.

## Current transport policy

| Field | Assignment |
| --- | --- |
| Parent identity | `penta.mail` |
| Pool contract | `ct.pentamailer.pool.40k.v1` |
| Universal-copy policy | `ct.pentamailer.policy.universal-copy.v1` |
| Provider route state | `HOT_REDUNDANT` |
| Raw secret return | prohibited |
| Direct Gmail/Outlook send fallback | prohibited |
| D3 | human-reserved |

## Deterministic responsibilities

- claim only eligible, unclaimed work;
- enforce idempotency and recipient-policy state;
- preserve class priority without starving support/transactional traffic;
- reserve and release rate/campaign capacity safely;
- dispatch only through a verified provider route;
- normalize provider acceptance, rejection, bounce, complaint, retry, and terminal state;
- reconcile incomplete/ambiguous attempts before retry;
- append/read back applicable institutional evidence;
- recover stale claims without duplicate delivery.

## Non-authorities

PentaMailer cannot create campaign intent, invent a persona, approve recipient eligibility, waive suppression, bypass provider limits, originate a contract, move money, grant rights, rotate credentials, or certify itself.

## Contract

The machine contract is `contracts/communications/penta-mailer-transport.v1.json`. Operational use follows [PentaMail and Persona Operations](/runbooks/penta-mail-and-persona-operations).
