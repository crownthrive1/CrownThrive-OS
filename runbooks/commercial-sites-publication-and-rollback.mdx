# Commercial Sites Publication and Rollback Runbook

## Preconditions

- exact product package digest accepted;
- rights, pricing, tax, accessibility, security, fulfillment, credit commerce, webhook and entitlement gates accepted;
- target ChatGPT Site and source version identified;
- provider credential obtained through approved Vault alias only;
- custom-domain DNS/TLS evidence current;
- rollback version and expected route behavior bound;
- governed execution receipt authorizes the bounded provider write.

## Execute

1. confirm the provider candidate still matches the accepted digest;
2. publish only the accepted site/product delta;
3. read back the provider version and public route with cache-busting;
4. verify product record, credit price, license/terms reference, accessibility path, support path and entitlement route;
5. run synthetic credit redemption and exact replay only in the authorized test environment;
6. record sanitized provider/public receipts and hashes;
7. mark live only through the release activation function after all predicates pass.

## Rollback

Rollback immediately on digest drift, route mismatch, broken entitlement, public private-data leakage, inaccessible critical flow, invalid tax/license presentation, failed webhook replay control, DNS/TLS regression or governance revocation.

The rollback must restore the bound prior version, prove public readback, revoke any candidate activation receipt and open a correction packet. Never delete evidence or rewrite the prior release.
