# Governed agent orchestration

Use this runbook when a workflow is distributed across orchestrators, builders, auditors, security reviewers, integration specialists, and gatekeepers.

## Outcome

A work packet moves from objective to evidence-backed completion without allowing an agent to manufacture authority, self-certify its own work, silently broaden capabilities, or convert missing evidence into success.

## Preconditions

- canonical repository/record is identified;
- current baseline and exact candidate head are known;
- task has a risk class and authority ceiling;
- source and evidence requirements are explicit;
- independent reviewer requirements are known;
- rollback/reopen behavior is defined;
- credentials remain outside prompts and repository artifacts.

## Execution sequence

1. **Resolve current truth.** Read canonical state before inheriting any prior handoff.
2. **Bound the packet.** Define deliverables, non-goals, risk class, files/systems touched, and maximum authority.
3. **Route specialists.** Separate build, evidence, security, integration, and final-gate responsibilities.
4. **Preserve independence.** A builder does not count as its own independent verifier.
5. **Execute least privilege.** Prefer read-first/D0-D1 operations; keep higher-risk writes fail-closed until predicates pass.
6. **Produce evidence.** Capture source references, test results, negative cases, changed-state records, and rollback target.
7. **Reconcile drafts.** Compare candidate work to the latest canonical head before review evidence is reused.
8. **Independent review.** Validate claims, rights, security, and scope from current evidence.
9. **Gate promotion.** Promotion occurs only under the governing quorum/approval model; CI alone is not authority.
10. **Close or hold.** Record PASS, NOT-PASS, governed deferral, or UNKNOWN without semantic inflation.

## Required handoff envelope

```yaml
packet_id: example.packet.001
baseline: canonical-ref
candidate_head: exact-ref
risk_class: D1
sources_read: []
sources_unavailable: []
claims_changed: []
tests_run: []
security_state: reviewed
rights_state: reviewed
rollback: documented
unknowns: []
next_owner: verifier
promotion_authority: external_to_builder
```

## Failure modes

- **stale-head review**: candidate changed after approval;
- **authority laundering**: transport identity is treated as a voter/approver;
- **self-certification**: originator approves its own high-risk work as independent proof;
- **scope creep**: task silently expands into unrelated production writes;
- **evidence substitution**: CI/synthetic success replaces required provider/runtime evidence;
- **secret leakage**: prompts, logs, examples, or docs carry restricted values;
- **unknown collapse**: missing evidence is represented as PASS.

## Verification checklist

- [ ] Canonical baseline was refreshed.
- [ ] Candidate exact head is recorded.
- [ ] Authority ceiling is explicit.
- [ ] Originator and verifier are independent where required.
- [ ] Secrets and private evidence are absent from distributable artifacts.
- [ ] All assertions have current evidence or remain UNKNOWN.
- [ ] Rollback/reopen behavior is usable.
- [ ] Promotion used the governing approval path.

## Commercialization state

This is a public-safe developer pattern candidate. CrownThrive-specific sovereign identities, production prompts, private authority mappings, evidence bodies, and protected algorithms are excluded from the commercial edition.
