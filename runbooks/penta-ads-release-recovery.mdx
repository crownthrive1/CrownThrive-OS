# PentaAds Release and Recovery

## Preflight

1. Pin the exact private PentaAds source SHA.
2. Re-read ThriveBase site/zone inventory and provider configuration.
3. Resolve exact site, surface, provider site ID, zone ID, format, consent and exclusion policy.
4. Confirm no existing equivalent installation/binding.
5. Confirm connector write/readback/rollback authority for the exact provider or site.
6. Resolve pricing, campaign/ad state, rights, privacy, accessibility and editorial separation.
7. Acquire exact-resource ownership/lease when required.

## Release pipeline

`scan -> classify -> select zone -> build manifest -> validate -> stage/canary -> connector write -> publish -> provider and public readback -> independent verification -> settle`

## Required evidence

- exact source and manifest digests;
- inventory/provider IDs and observed timestamps;
- consent/exclusion behavior;
- installation target and source pre-state;
- rollback artifact/fingerprint;
- connector write receipt;
- public DOM/network/readback evidence;
- provider observation where available;
- no duplicate placement/billing;
- DAIL events and release/certification refs.

## Current Locticians hold

The source and public compatibility package is certified, but live Brilliant Directories installation remains `HOLD_BD_TEMPLATE_WRITE_AUTHORITY`. Do not write templates/widgets until the exact BD write/readback/rollback chain is independently certified.

## VAST and intrusive formats

VAST, interstitial, popunder, autoplay, or other intrusive formats require exact format validation and explicit opt-in/consent policy. Invalid or ambiguous provider payloads remain held. Publisher content must fail open when advertising is unavailable.

## Rollback

Rollback restores the exact prior site/template/configuration state and verifies:

- placement removed or prior version restored;
- canonical page continues to render;
- no orphan provider requests;
- no duplicate binding remains;
- state/evidence supersession is appended;
- affected campaign/finance interpretation is reconciled.

## Finance boundary

Impression, click, fill, transaction, payout, settlement and anomaly records are separate evidence classes. A tag render cannot prove revenue. D3 spend, payout, settlement and irreversible economic changes remain human-reserved unless separately authorized.
