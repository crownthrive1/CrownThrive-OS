## Channel inclusion and loading

The build configuration includes all 66 channel IDs recovered from the existing Viloud-hosted website, plus the separately recovered Bless the Mic and Bless this House scheduled channels: 68 distinct channel feeds. A separate, previously registered Bless the Mic live input is retained as a visible entry; its previous HTTP 404 is recorded as availability evidence, not a retirement instruction.

Every directory card is created from the bundled registry before remote feed responses arrive. Four flagship feeds may load initially; other channels load on selection. Network concurrency is capped at three, and the loaded-provider cache is bounded. Empty, not-yet-loaded, and temporarily unavailable channels remain discoverable.

Live/scheduled channels use the provider's `GET /channel/{channel_id}?format=roku_json` response. On-demand catalogs use the ordinary channel response. Scheduled programs are not automatically reclassified as on-demand assets. Web-page URLs are not treated as native HLS streams. Provider domain, authentication, and entitlement restrictions remain enforced.

## Release procedure

1. Verify the release cursor, archive inventory, and source ZIP checksum. Never upload the original backup as though it were the new build.
2. Run the source/reference tests and a BrightScript-aware compiler. Structural and Python reference checks are not substitutes for Roku compilation.
3. Sideload the ZIP on a linked development Roku, capture startup/player logs, and test navigation, empty states, valid playback, remote controls, deep links, memory behavior, and advertising transitions where applicable.
4. Use the existing listing and original signing identity. Rekey the development device with the original package and matching signing password when necessary; do not generate a replacement identity silently. Confirm the candidate version exceeds the published version.
5. Generate the new encrypted `.pkg` on the development Roku, inspect its developer ID, hash the generated file, and store it separately from the unsigned ZIP and original backup.
6. Upload the newly signed `.pkg` to the existing Roku app's publishing dashboard and run the required submission tests. Record actual provider responses rather than inferring acceptance from an upload.
