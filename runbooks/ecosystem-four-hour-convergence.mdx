## Purpose

Move qualified CrownThrive assets through governed production, commercialization, distribution, and measurement using the existing Penta owners and factories. The four-hour coordinator is a bounded convergence pass, not a claim that every platform is already integrated or commercially certified.

Contract: `ct.crownthrive.ecosystem-loop.4h.v1`.

## Verified deployment

On September 5, 2026, the coordinator was installed in ThriveBase through migration `20260906001228` (`crownthrive_ecosystem_4h_loop_v1`). The existing `ct-commercial-gap-certification-4h` job was reused. No new sovereign activation clock or Edge Function was created.

The cron schedule is `17 */4 * * *` in UTC. During Eastern Daylight Time this corresponds to 12:17 AM, 4:17 AM, 8:17 AM, 12:17 PM, 4:17 PM, and 8:17 PM. UTC scheduling preserves the elapsed four-hour cadence; local wall-clock labels change with the UTC offset.

The existing commercial-gap certification invocation remains a coordinator stage. Faster manufacturing, custody, commerce, publication, and evidence workers remain unchanged. The hourly Penta Activation Continuity clock remains separate and unchanged.

## Execution contract

Each distinct four-hour window uses a deterministic window identity and an advisory overlap lock. Reinvoking an already recorded window returns `ALREADY_RECORDED` without repeating provider work.

The coordinator reads the current system and exact `cron_job` DND gates before execution, captures a baseline, runs a bounded Drive custody batch and bounded PentaGreen evidence pass, preserves commercial-gap certification dispatch, captures a second snapshot, emits a signed PentaPlanner convergence handoff, and appends or queues DAIL evidence. It then records the Markdown report and its SHA-256 digest.

The initial configured custody batch is ten records. This is a supplemental coordinator batch, not a ten-product limit on the existing manufacturing estate.

## Evidence and completion boundaries

A built-product row is not a sale. Verified Drive custody is not publication. A provider request is not a completed action. A scheduler success is not commercial certification. A DAIL append is not independent verification of all three DAILs.

The seven release-evidence dimensions remain rights, price, tax, fulfillment, entitlement, destination, and provider readback. Existing workers retain their own authorization and provider gates. Missing evidence remains visible; this coordinator does not manufacture rights, credentials, reserved decisions, ad-spend authority, or payment authority.

The first execution verified ten additional product rows in Drive with an HTTP 200 provider readback, appended its DAIL receipt, and passed the repeated-window test. Its overall result was `RECORDED_WITH_OPEN_ITEMS`. The commercial-gap agent later recorded a pass for its own run; fresh seven-dimension release readiness still had open items. These findings do not imply ten new publications, ten sales, or whole-estate certification.

Before-and-after inventory changes may include concurrent worker activity. Attribute a result to this coordinator only when its specific stage receipt supports that attribution.

## Documentation and readback

The authoritative cycle ledger is `integration_control.crownthrive_ecosystem_4h_runs_v1`. It is append-only, protected by row-level security, and inaccessible to anonymous and ordinary authenticated roles. The service role has the intended read and execution access.

Authorized operators can retrieve the latest receipts with:

```sql
select window_start, run_id, run_state, completed_at,
       report_sha256, drive_mirror_state
from integration_control.crownthrive_ecosystem_4h_runs_v1
order by window_start desc
limit 6;
```

The full Markdown report is stored in `report_markdown`. Verify its digest against the stored `report_sha256`; do not replace actual provider readback with a documentation claim.

The detailed installation record and first-run evidence are in the [Drive operating contract and execution log](https://docs.google.com/document/d/1z8ATsz7l5OTTYMapS5TbSRtPEonO5hKAQyLwpEl-zDo/edit). The canonical Penta Activation Continuity cursor also contains an append-only installation record.

Runtime cycle documentation is automatic. Automatic mirroring of every future receipt into Drive and PentaDocs is separately tracked as `PENDING_VERIFIED_MIRROR` until the mirror writer and readback are implemented and proven. This page is an operating contract, not a live replica of the cycle ledger.

## Scoped rollback

The scheduler's desired-state metadata retains its prior command and generation. A rollback must first confirm that the actual job and its desired generation still match this installation, honor the exact DND gate, and use a strictly newer generation to restore only the previous certification command.

Do not remove receipt history, products, source custody, evidence, or unrelated workers. Do not run a stale rollback over changes made by another owner. A rollback of this coordinator does not erase already completed external provider actions.
