# IP Disclosure & Commercialization Gate

CrownThrive does not publish first and classify later. Before a materially detailed CrownThrive technical, agentic, CHLOM, policy, software, research, security, economic or operating artifact is published, distributed, licensed, open-sourced, supplied to a partner, disclosed externally or placed into an external model workflow, the artifact must receive an IP-disclosure disposition.

This is a **permanent institutional rule**. It protects the difference between explaining CrownThrive publicly and giving away implementation know-how that derives value from controlled access.

The machine policy is `developers/manifests/ip-disclosure-commercialization-policy.v1.json`; the reusable review packet is `developers/templates/ip-disclosure-review-template.v1.yaml`.

## Four-layer projection model

CrownThrive separates the same institutional capability into different disclosure projections:

1. **Public specification / public doctrine** — explains what CrownThrive does, the problem solved, public interfaces, interoperable standards and sanitized architecture.
2. **Licensed implementation** — explains how an authorized licensee implements an approved capability, subject to a package license, rights terms, support boundaries and conformance requirements.
3. **Restricted institutional implementation** — CrownThrive-specific authority mappings, private configuration, internal operational evidence and controlled implementation detail.
4. **Trade-secret kernel** — high-value confidential policy logic, private economic calibration, proprietary evaluation corpora, orchestration heuristics, internal security architecture, protected runbooks and other know-how CrownThrive does not generally distribute.

A public specification does not imply the right to copy a licensed implementation. A license to an implementation does not transfer CrownThrive's sovereign authority, trademarks, private production identities, restricted evidence or trade-secret kernel.

## Classification classes

Every material disclosure can carry more than one class when different portions of the asset require different treatment.

| Class | Default treatment | Typical examples |
| --- | --- | --- |
| `PUBLIC_STANDARD` | public-safe after rights/IP review | public interface specifications, interoperability profiles, conformance requirements |
| `PUBLIC_DOCTRINE` | public-safe after claim review | architecture principles, mission, high-level diagrams, governance concepts |
| `COPYRIGHT_LICENSED` | distribute under a defined license | manuals, templates, source examples, schemas, curriculum, SDK materials |
| `TRADE_SECRET_CANDIDATE` | hold/restrict pending secrecy controls | new internal mechanisms with potential confidential economic value |
| `TRADE_SECRET_CONTROLLED` | restricted, need-to-know | private policy/economic/eval/orchestration/security implementation |
| `PATENT_CANDIDATE` | hold from material public disclosure pending disposition | potentially novel technical mechanisms or combinations |
| `TRADEMARK_CANDIDATE` | brand-strategy controlled | product names, marks, badges and source identifiers |
| `CERTIFICATION_MARK_CANDIDATE` | standards/legal controlled | future conformance marks indicating independent standards satisfaction |
| `RESTRICTED_INSTITUTIONAL` | internal/restricted | production authority maps, private DAIL/evidence, private runbooks |
| `THIRD_PARTY_LICENSED` | exact-license dependent | external code, templates, media, standards text or dependencies |
| `RIGHTS_REVIEW` | fail closed | uncertain chain of title, contributor, license or distribution rights |

A classification is not a legal registration claim. For example, `PATENT_CANDIDATE` means a mechanism requires invention/prior-art/filing disposition; it does not mean a patent application exists. `CERTIFICATION_MARK_CANDIDATE` does not mean a mark is registered.

## Mandatory gate triggers

The gate runs before:

- a public GitHub or Mintlify publication containing material technical detail;
- open-source release or external source-code distribution;
- a licensed digital package, SDK, agent pack or pallet release;
- partner, vendor, investor, conference, media or customer disclosure of protected implementation detail;
- a new API/MCP/A2A example that exposes implementation beyond the approved public interface;
- external-model ingestion of restricted CrownThrive material when provider/workspace policy does not already authorize that data class;
- an invention disclosure, standards submission or technical paper that may affect patent/trade-secret strategy.

Routine public-safe updates do not require a ceremonial new legal review when an existing classification clearly covers the change, but the agent must prove the artifact remains inside that approved boundary.

## Fail-closed conditions

The default disposition is `HOLD` when any of these remain unresolved:

- patent-candidate mechanism before a filing/public-disclosure decision;
- trade-secret candidate before secrecy/control disposition;
- unknown or conflicting chain of title;
- third-party license uncertainty;
- production credentials or credential fingerprints;
- restricted rights, customer, partner, payment, personal or privileged evidence;
- proprietary policy/economic calibration that is not approved for licensing;
- internal security findings or exploit-enabling detail;
- proprietary adversarial/evaluation corpora that provide material defensive advantage;
- private DAIL/evidence bodies;
- break-glass or privileged-access implementation detail.

No agent may repair an IP gate by deleting the classification label while leaving the sensitive content intact.

## AI-assisted authorship and invention records

AI assistance is recorded as provenance, not used as a shortcut to ownership conclusions. For valuable copyrighted or patent-candidate work, the record should preserve:

- founder/human objectives and substantive decisions;
- human selection, arrangement, modification, editing and accepted expression where material;
- human inventive contribution for a technical mechanism;
- source evidence and prior work;
- AI/model/provider involvement where material;
- the exact accepted version and date.

A model output by itself does not prove copyright ownership, chain of title, patent inventorship or technical novelty.

## Commercialization gate

CrownThrive strongly prefers **licensing and service access** over transferring ownership of core institutional IP.

Every offer uses the state model:

```text
concept
→ candidate
→ packaged
→ rights_cleared
→ pricing_authorized
→ fulfillment_certified
→ checkout_staged
→ live
```

A product manifest, proposal, Stripe Product, draft price, documentation page or working demo does not skip those states.

Before `live`, the offer must have:

- exact rights/chain-of-title disposition;
- adopted package/license terms;
- exact price authority;
- tax/accounting review where applicable;
- fulfillment/provisioning/entitlement proof;
- support/update/refund/dispute terms;
- checkout/webhook/entitlement certification where commerce uses them;
- IP-disclosure gate PASS for the exact distributed artifact;
- required legal, rights, security, accessibility/consumer and financial specialists.

## What CrownThrive sells

CrownThrive can monetize approved **interfaces, implementation rights, capability packages, software/service access, conformance, education, support and professional services**.

CrownThrive does not sell sovereign institutional authority merely because a generic template is licensed. It also does not generally distribute raw private authority maps, production credential details, private economic calibration, internal security findings, restricted evidence or the trade-secret kernel.

The machine offer catalog is `developers/manifests/chlom-agentic-commercial-offer-catalog.v1.json`. The reusable offer contract is `developers/templates/commercial-offer-manifest-template.v1.yaml`.

## Agent responsibilities

- **Agent A / Orchestrator:** route IP classification and commercialization dependencies before public distribution or packaging.
- **Agent B / Evidence Auditor:** verify chain of title, source authority, human contribution, third-party rights and classification evidence.
- **Agent C / Builder:** generate only the approved projection — public, licensed or restricted — and do not copy protected kernel material into a customer/public package.
- **Agent D / Gatekeeper:** block publication, licensing or live-sale promotion when the gate is incomplete.
- **Agent S / Security Sentinel:** block credential, sensitive implementation, exploit or defensive-corpus leakage.
- **Agent F / Source & Articleization:** classify reconstructed/public documentation before articleization or publication; a recovered source does not automatically become publishable.
- **Agent N / Proof Verifier:** verify that evidence actually supports the claimed IP/disclosure disposition.
- **R&D fabric:** default potentially high-value new mechanisms to `RESEARCH_CANDIDATE` plus IP review; R&D cannot publish a patent/trade-secret candidate merely because research is complete.
- **Rights/Governance/IP specialists:** classify rights, licensing, provenance and external-distribution implications; agent output is not a substitute for counsel when professional legal review is required.

## R&D promotion boundary

Research and commercialization are related but distinct state machines.

```text
R&D discovery
→ evidence/source reconciliation
→ proof verification
→ IP classification
→ domain/specialist review
→ implementation if needed
→ security/governance acceptance
→ package candidate
→ commercial release gates
```

A research discovery may remain valuable internal IP forever without becoming a product. Conversely, a public standard may be deliberately published while its optimized implementation remains licensed or trade-secret controlled.
