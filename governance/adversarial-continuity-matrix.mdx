# Adversarial Continuity Matrix

Phase 2.9 asks whether CrownThrive can continue operating when critical people, vendors, systems, credentials, evidence or money rails fail.

## Threat matrix

| Scenario | Required institutional answer | Phase 3 control |
| --- | --- | --- |
| Founder temporarily unavailable | Who can read, operate, approve routine work, and what remains founder-gated? | authority registry, break-glass policy, delegated approvals with ceilings |
| GitHub unavailable | Where are canonical exports/backups and how is source reconstructed? | independent repository backup, release artifacts, signed manifests |
| Mintlify unavailable | Can institutional knowledge be rebuilt from source without losing authority? | Git/source remains canonical, docs export, navigation manifest |
| Google Drive/SaaS unavailable | Are critical source masters duplicated and indexed independently? | source register, checksum inventory, controlled backup copies |
| Domain/DNS failure | Who owns domains, where is DNS managed, what are recovery steps and expiry dates? | domain/vendor registry, renewal alerts, recovery runbook |
| Payment processor outage | Can orders be paused safely and entitlements reconciled later? | payment incident state, idempotent webhook/event ledger, fail-closed checkout |
| Webhook failure | Can payment and fulfillment be reconciled without duplicate delivery? | durable event log, replay, entitlement reconciliation |
| Credential compromise | Can affected credentials be revoked without losing the institution? | secret manager, least privilege, rotation, break-glass recovery |
| Database loss/corruption | Are backups restorable and evidence/rights records recoverable? | tested restore, point-in-time recovery where appropriate, immutable evidence export |
| Agent makes bad change | Can execution be stopped, traced, rolled back and attributed? | approval gates, sandboxing, DAIL, change diff, rollback |
| Rights dispute | Can affected uses be frozen while preserving evidence and unrelated operations? | rights hold, case service, evidence linkage, scoped suspension |
| Platform sold/spun out | Can identity, rights, data, domains, code and obligations be separated cleanly? | stable asset IDs, dependency map, assignment/transition package |
| Vendor shuts down | Is business logic portable away from the vendor? | adapter pattern, exports, vendor exit record, replacement plan |
| Successor takes control | Can a qualified steward understand CrownThrive without oral history? | doctrine, registries, ADRs, credentials process, succession package |
| Legal structure changes | Can services continue while ownership/entities are updated? | entity IDs separated from platform IDs; effective-date governance |
| Public metric is wrong | Can claims be corrected without erasing history? | public claim registry, versioning, correction event |

## Severity classes

- **C0 — existential:** loss could prevent control of CrownThrive or destroy irreplaceable rights/evidence.
- **C1 — critical:** revenue, production, identity, security or major customer impact.
- **C2 — material:** a corridor/platform can degrade but institution remains controllable.
- **C3 — recoverable:** localized failure with documented workaround.

## Mandatory continuity objects before broad Phase 3 autonomy

- owner/authority map;
- domain and DNS inventory;
- repository/deployment map;
- credential/secret ownership map without exposing secrets;
- backup and restore policy;
- vendor exit map;
- payment/entitlement reconciliation procedure;
- rights-hold procedure;
- emergency communications path;
- succession/stewardship package;
- recovery verification schedule.

## Fail-closed rule

When a consequential action depends on missing authority, disputed rights, uncertain money state, compromised credentials or unverified production state, automation must fail closed and create a case/event rather than improvise.
