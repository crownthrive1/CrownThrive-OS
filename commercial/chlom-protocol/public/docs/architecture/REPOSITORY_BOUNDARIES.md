# CHLOM repository boundaries and commercial projection model

## Canonical parent

`crownthrive1/CrownThrive-Support` is the CrownThrive-controlled private parent for CHLOM institutional product policy, protected implementation knowledge, release authority, factory controls and the public/private projection boundary.

The parent is the source of authority for the factory-managed commercial overlay.

## Public commercial child

`crownthrive/chlom-protocol` is the public and monetized commercial child repository.

Its job is to expose public-safe CHLOM material for:

- product discovery and technical evaluation;
- machine-readable public registries and schemas;
- developer and integration contracts;
- research and formal verification artifacts;
- commercial licensing and enterprise integration surfaces;
- approved public documentation.

The child does not become authoritative over private parent policy merely because it is public, contains executable examples or receives independent contributions.

## Safe synchronization contract

1. Canonical commercial policy and managed public source are changed in the parent.
2. The parent branch is validated under the CHLOM commercial projection workflow.
3. The factory builds the exact managed overlay from an exact parent commit.
4. Secret/IP boundary checks run before export.
5. The output receives `.crownthrive/upstream.json` with exact parent provenance.
6. If cross-repository write authority is configured, the factory opens a candidate branch and pull request against the public child.
7. The public child runs its own validation before merge.
8. A build receipt or pull request is not itself a production, economic or legal activation claim.

## Public/private boundary

Never project production secrets, webhook signing secrets, raw evidence, customer records, protected-person data, private contracts, confidential unit economics, Fingerprint implementation details, private policy logic or unreleased proprietary source assets.

The factory is allowlist-only and does not delete unmanaged public-child content.

## Authority conflicts

If a historical child document says that the public repository is the parent source of authority, the current factory-managed boundary document supersedes that relationship for the commercial projection layer pursuant to the recorded 2026-08-24 Founder-direct bootstrap.

Historical source documents remain retained as lineage and must not be silently rewritten to erase their original context.

Historical DAL and historical “Decentralized Licensing Authority” wording are lineage, not current canonical product definitions.
