## Custody and provenance

The factory uses a split-custody model:

- **ThriveVault / Supabase Vault** stores runtime-only encryption material and restricted secret aliases.
- **THIVEBASE / CHLOM** stores identities, versions, registry digests, fingerprints, DAIL references, run receipts, agent receipts, queue state, commercialization candidates, and governance metadata.
- **Google Drive Institutional Continuity** stores encrypted recovery material and public-safe recovery/control-plane documentation with exact ciphertext readback verification.
- **Private GitHub** stores governed source, schemas, tests, derivation proofs, interface contracts, and public-safe digests. Protected bodies are not committed.
- **Mintlify** receives only approved contract/interface/documentation projections.

DAIL remains append-only. Reconciliation errors are corrected through explicit superseding/projection events rather than destructive history rewrites.

## Independent agent fleet

The canonical fleet separates planning, building, validation, security, custody, provenance, commercialization, documentation, and continuity responsibilities. Builder output cannot self-certify.

Core roles include orchestration, domain architecture, algorithm synthesis, skill compilation, prompt systems, script engineering, test/evaluation, security red-team, independent verification, archive custody, DAIL lineage, rights/IP, commercialization, documentation projection, and continuity.

## Governance invariants

<CardGroup cols={2}>
  <Card title="Human sovereignty">
    D3 remains human-reserved. Generated agents are non-voting and cannot grant themselves greater authority.
  </Card>

  <Card title="No self-certification">
    Builders may generate evidence but independent verifier and security roles determine PASS/HOLD/FAIL status.
  </Card>

  <Card title="Candidate-only automation">
    Automatic generation does not imply automatic publication, pricing activation, checkout, Stripe object creation, production deployment, or rights clearance.
  </Card>

  <Card title="Reversible execution">
    Material external writes require exact capability bindings, readback evidence, and rollback paths.
  </Card>
</CardGroup>

UNKNOWN is never promoted to PASS. No silent deletion or overwrite is permitted. Protected implementations never enter a public projection.

## Commercialization model

Capabilities may mature into enterprise licenses, metered APIs/MCPs, managed agents, skill/workflow packs, prompt/runtime bundles, conformance services, implementation packages, and per-execution automation services.

Commercialization is evidence-gated. Candidate pricing and value hypotheses are not public market-value claims. Rights, security, pricing, tax, fulfillment, entitlements, refund/dispute, accessibility, domain/TLS, and final certification must independently pass before activation.
