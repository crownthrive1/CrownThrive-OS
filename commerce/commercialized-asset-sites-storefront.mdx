# Commercialized asset Sites storefront

CrownThrive is building a new **Sites-based storefront** to distribute approved reusable institutional knowledge products. The storefront is a customer-facing commerce surface, not a governance authority or source of truth.

## What the storefront will sell

Initial governed product families include:

- Quick Runbooks
- Developer Runbooks
- eBook Volumes
- Team Packs, worksheets and checklists
- Training Labs with synthetic fixtures
- CHLOM Capability Pallets
- Institutional Agent Packs
- Governed Reference Architecture packages
- Licensed Implementation Packs after rights/security review
- Support & Update subscriptions after recurring fulfillment is certified

The first compiled candidate is **Governed Agentic Operations Runbooks for Developers — Volume 1**. It is a packaged candidate, not a live offer.

## Product lifecycle

Every storefront item inherits the commercial state model:

`concept -> candidate -> packaged -> rights_cleared -> pricing_authorized -> fulfillment_certified -> checkout_staged -> live`

A Sites page, PDF, Stripe Product/Price, Payment Link, Checkout Session, or machine manifest cannot skip those stages.

## Institutional recycling loop

```text
institutional operation
  -> reusable pattern
  -> IP / security / rights classification
  -> public-safe or licensed product
  -> Sites storefront listing
  -> governed checkout
  -> protected fulfillment / entitlement
  -> customer + support evidence
  -> CrownLytics / THIVEBASE measurement
  -> product improvement
  -> updated institutional asset
```

Customer and support signals may improve products, but private customer data, credentials, restricted evidence, and trade-secret implementation detail must never be recycled into public masters.

## Required before live

A storefront item cannot become `live` until its applicable gates pass, including:

- provider-confirmed Sites project ID, saved version and production URL/access;
- exact source/master/version/storefront-item linkage;
- responsive, mobile, accessibility and interaction QA;
- public/private/IP disclosure classification;
- exact license authorization;
- exact price authorization;
- governed Stripe payment surface;
- payment/webhook reconciliation where applicable;
- protected entitlement or delivery certification;
- refund, dispute and revocation behavior;
- least-data analytics and support telemetry;
- rollback and saved-version continuity.

## Protection boundary

Never publish or deliver through the storefront:

- raw credentials or API keys;
- credential fingerprints;
- Vault secret bodies or private runtime locators;
- unrestricted master-agent instructions when they encode protected operational know-how;
- trade-secret calibration or private eval/security corpora;
- private customer, partner or personal evidence;
- patent-candidate technical detail before IP disposition;
- third-party material without distribution rights;
- CrownThrive sovereign authority.

Sell reusable capability, education, implementation rights, conformance, service access and support instead.

## Roadmap placement

**Phase 5:** first general governed revenue activation for approved digital assets.

**Phase 6\+:** developer licensing, implementation marketplace, conformance/certification, enterprise/OEM and recurring support scale.
