## Custody model

The wallet is CrownThrive server-managed through ThriveBase Vault. The control plane generated a fresh EVM wallet inside the trusted runtime, encrypted it as an Ethereum V3 keystore, stored the encrypted keystore and its decryption secret under separate Vault aliases, and discarded the raw private key and mnemonic.

Public-safe readback currently asserts:

- wallet creation performed: true
- durable runtime binding: true
- encrypted private material vaulted: true
- raw private key persisted: false
- mnemonic persisted: false
- private material returned: false

No private wallet material is permitted in GitHub, Google Drive documentation, DAIL payloads, MCP responses, logs, public APIs, or ordinary model output.

## Certification canaries

The managed wallet passed:

- Base `eth_chainId` readback for chain ID 8453;
- native Base USDC contract-code readback;
- no-value local message signature;
- independent signature recovery to the bound public address;
- Vault replay/idempotency: the second bootstrap reused the same encrypted wallet rather than creating another address.

The Base public RPC is used only as a chain/contract canary because Base documents its public endpoint as rate-limited and not suitable as a production application RPC. Production broadcasts require a governed production-grade RPC/provider path or an independently certified execution provider.

## Trust Wallet Agent Kit relationship

Trust Wallet Agent Kit remains the preferred multichain intelligence, market-data, quote, route-construction and cross-chain provider. Its hosted HMAC plane is production active. The managed Agent Wallet is the signing/custody lane CrownThrive controls directly.

A Trust Wallet quote or transaction build is provider evidence and never authorizes a transaction by itself.

## Execution boundary

`money_movement_authorized=true` means the production economic capability exists. It does not mean a transaction has occurred.

For autonomous execution, the current unattended ceiling remains zero. A positive unattended transfer therefore remains blocked until a later governed policy explicitly raises that ceiling and passes exact ECAC, amount/asset/address allowlists, simulation, readback and incident/rollback controls.

Human-approved WalletConnect and MetaMask Embedded Wallet flows remain separate user-sovereignty lanes.
