# Trust Wallet Agent Kit production runner

Trust Wallet Agent Kit is integrated into CrownThrive as two related but distinct execution planes:

1. a **production hosted HMAC gateway** for market and routing intelligence; and
2. a **persistent local TWAK CLI/MCP runner** for wallet holdings, portfolio, signing, and autonomous Agent Wallet execution.

The hosted plane is active. CrownThrive has selected a dual execution model for wallet actions: **user-approved WalletConnect plus a dedicated bounded Agent Wallet**. Each lane has an independent activation gate.

## Official installation

On a persistent macOS, Linux, WSL, Codex CLI, Claude Code, Cursor, or compatible MCP runner, use Trust Wallet's official installer:

```bash
curl -fsSL https://agent-kit.trustwallet.com/install.sh | bash
```

The installer:

- installs the `twak` CLI;
- prompts for the Trust Wallet Access ID and HMAC secret;
- verifies and stores them locally;
- wires supported agent harnesses;
- offers an Agent Wallet, WalletConnect, or read-only path;
- exposes the tool surface through `twak serve` for MCP clients.

CrownThrive credentials are already vaulted in ThriveBase. Do not publish them in source control, documentation, screenshots, issue bodies, logs, or MCP responses.

## Verify a local installation

After installation:

```bash
twak auth status --json
```

Market-data smoke test:

```bash
twak price BNB --json
```

Quote-only smoke test:

```bash
twak swap 100 USDC ETH --quote-only --json
```

The exact asset/network arguments must match the intended route. Quote success does not authorize execution.

## Holdings and portfolio

Trust Wallet's Agent Kit wallet skill defines holdings through the local CLI/MCP wallet plane.

Own-wallet balance:

```bash
twak wallet balance --chain ethereum --json
twak wallet balance --chain solana --json
twak wallet balance --all --json
```

Full portfolio:

```bash
twak wallet portfolio --json
twak wallet portfolio --chains ethereum,base,bsc,solana --json
```

Any-address read:

```bash
twak balance --address <address> --coin 60 --json
twak balance --address <address> --chain bsc --json
```

A canary against an assumed hosted `/v1/balance` path returned HTTP 404. CrownThrive therefore does **not** expose a fabricated hosted balance API. Wallet holdings remain attached to the official local TWAK CLI/MCP contract.

## Dual wallet trust model selected

CrownThrive uses both wallet modes because they solve different authority problems.

### WalletConnect — user-approved lane

Stable ID:

```text
ct.wallet-mode.walletconnect.user-approved.v1
```

Use this lane when a human-controlled wallet should retain per-transaction sovereignty.

Characteristics:

- user self-custody;
- transaction proposed by CrownThrive/CHLOM;
- explicit modal wallet approval required;
- autonomous execution disabled;
- unattended value ceiling `0`;
- D2 maximum policy ceiling;
- suitable for consumer, founder, treasury-approval, or other human-signature flows.

For the Virality Music implementation, MetaMask Embedded Wallets Wallet Services supplies the user-facing WalletConnect/funding corridor. Its frontend request tool remains staged until the Mainnet origin is allowlisted and the VM Sites binding passes readback.

### Dedicated Agent Wallet — bounded autonomous lane

Stable ID:

```text
ct.wallet-mode.agent-wallet.autonomous.v1
```

Use this lane for machine-executable operations that have already passed exact CHLOM and ThriveEvergreen policy.

Characteristics:

- dedicated institutional Agent Wallet;
- encrypted wallet material stays on a persistent trusted runner;
- policy can define asset allowlists, address allowlists, value limits, and automation boundaries;
- current unattended value ceiling is `0`, so architecture does not equal permission to move funds;
- D3 remains human-reserved;
- suitable for future DCA, limit strategies, x402, agent commerce, or other bounded workflows only after separate execution certification.

Current state:

```text
runtime contract: production
activation: configured_pending_runner
wallet creation performed: false
durable runner bound: false
money movement: deny-by-default
```

An Agent Wallet is not created inside a transient Supabase Edge Function or ordinary ChatGPT response runtime.

## ThriveEvergreen boundary

A Trust Wallet route, quote, signed transaction, or on-chain confirmation is provider evidence. It cannot create CrownThrive economic authority by itself.

Any CrownThrive commerce effect remains subject to ThriveEvergreen's exact `ECAC | HOLD | DENY` decision and the relevant CHLOM policy/rights/settlement gates.

## WalletConnect completion gate

The user-approved lane becomes transaction-active only after:

1. the required production wallet frontend is injected through a certified site write;
2. the provider origin/allowlist gate passes;
3. wallet connection and identity readback pass;
4. a no-value signature canary passes;
5. a negative unauthorized-sign canary passes;
6. modal approval remains mandatory;
7. provider and ThriveEvergreen readback are reconciled.

## Agent Wallet completion gate

The autonomous lane becomes transaction-active only after:

1. persistent TWAK CLI/MCP runner installed;
2. credentials verified without secret leakage;
3. dedicated Agent Wallet created on that persistent runner;
4. only public addresses/account IDs registered in CHLOM Wallet;
5. holdings canary passes on the bound wallet;
6. transaction build canary passes;
7. unauthorized-sign test proves denial;
8. asset/address allowlists, unattended-value ceiling, rollback/compensation, and incident controls are certified;
9. exact ThriveEvergreen ECAC authorization is enforced immediately before each economic effect;
10. signing/broadcast MCP exposure is promoted only after readback.

Until those lane-specific gates pass, the hosted intelligence/quote plane remains production while transaction execution remains fail-closed.
