# Trust Wallet Agent Kit & CHLOM Managed Agent Wallet

Trust Wallet Agent Kit and the CrownThrive-managed Agent Wallet serve **different but complementary production roles**.

1. **Trust Wallet hosted HMAC plane** supplies multichain price, market, provider, route and swap-quote intelligence.
2. **CHLOM Managed Agent Wallet** is CrownThrive's governed signing/custody lane for machine-executable wallet actions.
3. **WalletConnect / MetaMask Embedded Wallets** remain separate human-approved wallet lanes.

A provider quote, transaction build, signature or chain receipt is evidence. It never manufactures CrownThrive economic authority by itself.

## Managed custody model

The Agent Wallet was generated inside the governed CrownThrive control runtime, encrypted as an Ethereum V3 keystore and bound to ThriveBase Vault.

The encrypted keystore and its decryption credential are stored under **separate Vault aliases**. Public-safe machine readback asserts:

```text
wallet_creation_performed        true
durable_runner_bound             true
private_material_vaulted         true
raw_private_key_persisted        false
mnemonic_persisted               false
private_material_returned        false
```

The bootstrap is idempotent. Replaying initialization reuses the existing encrypted wallet rather than creating a second institutional address.

No wallet secret, mnemonic, raw private key, keystore password or bootstrap secret may appear in source control, Mintlify, Drive documentation, DAIL payloads, logs, MCP responses or ordinary model output.

## Authority vs. execution

The current commerce acceptance state is intentionally:

```text
snapshot_state                    AUTHORIZED_CONFIGURED_NOT_EXECUTED
money_movement_authorized         true
money_movement_execution_count    0
max_unattended_value_minor        0
candidate_decision                HOLD
checkout_state                    HOLD
agent_wallet_state                active
```

**Authorized configuration is not a performed transaction.**

An hourly acceptance snapshot preserves this distinction so later agents cannot flatten capability authorization into a false transaction claim.

## ThriveEvergreen boundary

ThriveEvergreen v2 is the economic-execution authority. The engine is `production_write`, production effects are enabled, and economic execution may occur only after the exact action clears the applicable `ECAC | HOLD | DENY` gate.

For the Agent Wallet:

- `money_movement_authorized=true` means the production capability exists;
- action-specific execution still requires exact ECAC and all execution controls;
- the current unattended ceiling of `0` blocks positive autonomous transfers even though the capability itself is production-authorized;
- D3 remains human-reserved;
- provider success cannot manufacture entitlement, rights, payout truth, settlement truth or economic authority.

## Production broadcast boundary

Base's public RPC was used only for chain and contract canaries. Production chain broadcast requires a governed production-grade RPC/provider path or another independently certified broadcast provider.

Before positive autonomous value can move, CrownThrive must preserve:

1. exact ECAC immediately before execution;
2. asset and destination allowlists;
3. bounded amount/value policy;
4. simulation/preflight;
5. idempotency/replay protection;
6. production RPC/provider certification;
7. post-broadcast receipt/readback;
8. rollback or compensation path;
9. incident/quarantine controls;
10. append-only acceptance and DAIL evidence.

## WalletConnect and MetaMask relationship

WalletConnect and MetaMask Embedded Wallets are the **human-sovereignty lanes**. They require user confirmation and do not become autonomous merely because the CHLOM Agent Wallet exists.

The managed Agent Wallet is the bounded machine-execution lane; WalletConnect/MetaMask are user-approved lanes. All remain subordinate to CHLOM rights/policy and ThriveEvergreen economic authority.

## Trust Wallet local CLI / failover path

Trust Wallet's local TWAK CLI/MCP remains useful for holdings, portfolio, testing, portability, local tooling and a future failover custody path. Typical local operations include:

```bash
twak auth status --json
twak wallet balance --chain base --json
twak wallet portfolio --chains ethereum,base,bsc,solana --json
twak swap 100 USDC ETH --quote-only --json
```

The hosted market HMAC plane does not expose a fabricated `/v1/balance` endpoint; a prior canary against that assumed route returned HTTP 404.

## Superseded local-runner plan

Earlier CrownThrive documentation described a persistent local TWAK Agent Wallet runner as the planned primary signing path. That architecture is retained as historical design and portability/failover guidance, but it is **superseded as the primary production custody path** by the CrownThrive-managed encrypted-keystore wallet documented here.

It is no longer accurate to describe the institutional Agent Wallet as `configured_pending_runner`, `wallet creation performed: false`, `wallet account bound: false`, or `money movement: deny-by-default`.
