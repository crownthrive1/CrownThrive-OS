## What you should get from this page

After reading this page, you should be able to:

- identify PentaGreen as the current commerce/economic-authority name;
- distinguish PentaGreen authority from provider capability or a provider's successful response;
- locate the Penta component responsible for a SKU, price, credit, checkout, receipt, entitlement, payout, settlement, or correction;
- understand when an exact action may proceed, must remain on hold, or requires escalation;
- resolve legacy `ThriveEvergreen` identifiers without rewriting historical evidence.

## What PentaGreen governs

PentaGreen progressively governs CrownThrive economic state across products, offers, SKUs, pricing, checkout, credits, payments, advertising, marketplace activity, licensing handoffs, entitlements, fulfillment, invoicing, earnings, royalties, commissions, payouts, settlement, refunds, disputes, reconciliation, rollback, and compensating actions.

A provider can execute work; a provider cannot manufacture CrownThrive economic truth. Payment success, fulfillment success, ad delivery, marketplace state, API success, webhook success, or provider readback remains **evidence** until reconciled against the applicable institutional authority and state.

## Economic activation contract

```text
candidate
  → rights / authority / evidence checks
  → PentaGreen
  → ECAC | HOLD | DENY
  → bounded provider execution when authorized
  → provider readback
  → PentaReceipt
  → PentaReconcile
  → PentaLedger
  → entitlement / invoice / payout / settlement as applicable
  → PASS | CORRECT | ROLLBACK | COMPENSATE | ESCALATE
```

`ECAC` is the exact economic-activation certificate/envelope. It is not a blanket permission. Material changes in asset, rights, SKU, offer, price, tax, fulfillment, entitlement, territory, channel, provider, risk, advertising, or policy can require re-evaluation.

## PentaSKU authority

PentaGreen is the exclusive CrownThrive SKU issuer through PentaSKU. Provider IDs—including store IDs, Stripe Product/Price IDs, marketplace IDs, ad-server IDs, and fulfillment IDs—are aliases. Retired CrownThrive SKUs are never reused.

## PentaCredits

[PentaCredits](/commerce/pentacredits) is the canonical credits/economic-value subsystem inside PentaGreen. It governs programs, balances, top-ups, purchases, promotional credits, reversals, refund-to-credit, usage restrictions, expiration where authorized, fraud controls, and reconciliation. A credit rail must not silently become cash, a deposit, a security, or unrestricted transferable value merely because a provider technically permits transfer.

## Provider boundary

PentaGreen treats Stripe, storefronts, marketplaces, AdLuxe execution providers, fulfillment services, booking systems, wallet infrastructure, APIs, MCPs, plugins, agents, and future providers as **replaceable execution systems**. Provider success does not by itself create an invoice, earning, payout, entitlement, public performance claim, or settlement.

## Runtime migration and compatibility

The naming migration is non-destructive. Existing `thriveevergreen_*` tables, functions, event identifiers, receipts, prior releases, and signed evidence remain valid where exact identity is required. Canonical `pentagreen_*` compatibility surfaces resolve into the documented compatibility runtime rather than rewriting history.

New documentation, code, APIs, MCPs, workflows, registries, agents, and releases should use PentaGreen/Penta subsystem names. Historical material may retain ThriveEvergreen verbatim when that is necessary for provenance.

<Note>
  For the decision, compatibility-wrapper lineage, and unchanged governance boundary, see [PentaGreen Naming & Runtime Migration — 2026-08-26](/changelog/pentagreen-naming-runtime-migration-2026-08-26). For older identifiers, use the [ThriveEvergreen legacy runtime and lineage record](/commerce/thriveevergreen); do not use that compatibility page as the current commerce-authority entry.
</Note>

## Agent boundary

`ct.penta.agent.green` is the bounded PentaGreen Agent. It can assess economic state, resolve compatibility names, route gates, and supervise reconciliation within its assigned authority. It cannot self-approve, self-vote, grant itself new authority, create D3 authority, bypass CHLOM, or manufacture money-movement, licensing, settlement, or provider-write authority.

## Current-state rule

A canonical rename does not promote a held provider route. Exact execution remains independently gated. If authority, evidence, credentials, provider certification, reconciliation, or required approvals are missing, PentaGreen remains fail-closed.

<Warning>
  PentaGreen reduces economic, financial, rights, legal, security, customer, and operational risk through bounded execution and reconciliation. It does not claim that residual risk can be reduced to literal zero.
</Warning>
