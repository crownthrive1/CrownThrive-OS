# Developer runbooks and eBooks

CrownThrive is packaging repeatable automation and institutional operating methods as developer-facing digital products. The product line is designed to monetize the reusable **method** while keeping CrownThrive-specific credentials, private evidence, trade-secret kernels, personal information, and sovereign authority isolated.

## Product families

Initial packaged-candidate titles include:

- Governed Agent Orchestration
- Evidence Reconciliation and Gate Audit
- Integration Heartbeat and SRE Watch
- API and MCP Integration Certification
- Credential Continuity and Secret Boundaries
- Webhook Delivery Integrity and Idempotency
- Vendor, Engine, Version, and Dependency Watch
- Security Sentinel and Resilience Watch
- Documentation Source Reconciliation and Articleization
- Recurring Intelligence Brief and Attention Triage
- Scheduled Follow-Up and Deadline Watch
- Production Deployment and Rollback

These may be sold later as individual runbooks, thematic bundles, team packs, training labs, or compiled eBook volumes after the commercial lifecycle gates pass.

## Volume 1

**Governed Agentic Operations Runbooks for Developers - Volume 1** is the first compiled eBook candidate. It combines the public-safe operating patterns into one developer-oriented reference with checklists, evidence envelopes, fail-closed rules, and packaging guidance.

## What customers can receive

Depending on the governed package:

- PDF/eBook edition;
- editable DOCX/Markdown source where licensed;
- checklists and worksheets;
- machine-readable manifest examples;
- synthetic test fixtures;
- architecture diagrams or reference flows;
- version/update notes;
- optional training or implementation support after separate authorization.

## What is never included by default

- production API keys, tokens, signing/webhook secrets, private keys, Vault bodies, or credential fingerprints;
- customer/partner records or personal case information;
- private incident evidence, DAIL/evidence bodies, or production request payloads;
- unrestricted CrownThrive master-agent prompts or sovereign authority mappings;
- trade-secret scoring/calibration, defensive logic, private eval/adversarial corpora, or sensitive security findings;
- patent-candidate mechanism detail before IP review;
- third-party content CrownThrive lacks redistribution rights to license.

## Commercial lifecycle

```text
concept
  -> candidate
  -> packaged
  -> rights_cleared
  -> pricing_authorized
  -> fulfillment_certified
  -> checkout_staged
  -> live
```

The current catalog is at **packaged candidate**. Exact pricing is not yet authorized, checkout remains disabled, and no customer entitlement is created by this documentation.

## Fulfillment design

The intended digital fulfillment package should be reproducible from the governed source and contain:

1. immutable release/version identifier;
2. customer-facing PDF;
3. editable source only when the package license allows it;
4. license/terms file once governed;
5. checksum/manifest where useful;
6. support/version statement;
7. delivery receipt or entitlement record;
8. revocation/refund handling appropriate to the selected commerce model.

Google Drive stores the institutional master/archive. The governed repository stores the versioned public-safe source and machine catalog. Customer fulfillment should use a dedicated protected delivery path rather than exposing private Drive masters.

## Stripe architecture

For one-time digital runbooks and bundles, the simplest future payment surface is Stripe-hosted Checkout or Payment Links. A recurring support/update subscription may be added for packages that include continuing compatibility/support.

This page does not authorize a Stripe Product, Price, Payment Link, checkout session, exact price, or live fulfillment. Those actions require pricing, license, tax/accounting, refund, support, fulfillment, and entitlement approval.
