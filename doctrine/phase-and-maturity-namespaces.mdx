# Phase and Maturity Namespaces

CrownThrive has used the word **phase** in multiple systems. Phase 2.8 makes those namespaces explicit.

## 1. Ecosystem rollout phase

Public CrownThrive material has used **Phase 0** to describe integration, internal testing, rollout preparation and future MM Suites/partner activation. This is a portfolio-level maturity label.

It does **not** mean that no CrownThrive platform is live.

Canonical namespace: `ecosystem_phase`.

## 2. Institutional recovery / CrownThrive OS phase

The current knowledge and infrastructure reconstruction uses:

- Phase 1 — operating-map foundation;
- Phase 2 — CHLOM/Help Center recovery;
- Phase 2.5 — institutional consolidation;
- Phase 2.7 — exhaustiveness recovery;
- Phase 2.8 — contradiction hunting;
- Phase 2.9 — adversarial continuity;
- Phase 3 — executable institutional core.

Canonical namespace: `institutional_build_phase`.

These numbers do not supersede the public ecosystem rollout phase.

## 3. Platform lifecycle

Individual platforms should use states such as:

`concept → validate → build → pilot → beta → active → growth → reserve → merge → sunset`.

Canonical namespace: `asset_lifecycle_state`.

## 4. Product/release state

Products, books, music, licenses and services have their own governed release states. They should not inherit a platform or ecosystem phase number.

Canonical namespace: `release_state`.

## 5. Technical migration stage

Infrastructure programs may require migration stages or sprints. These should use names such as `sprint`, `migration_stage`, or an ADR-defined program identifier rather than unqualified `Phase N`.

## Public wording rule

Never write "CrownThrive is in Phase 3" without specifying the namespace.

Correct examples:

- "The CrownThrive institutional-core build is entering Phase 3."
- "The public ecosystem roadmap still labels its integration program Phase 0."
- "Virality Music is active while its institutional integration work continues."

<Warning>
  Phase numbers are labels, not evidence of product availability, legal status, integration completeness, or commercial readiness.
</Warning>
