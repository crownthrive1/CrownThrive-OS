# Master Narrative Ledger

CrownThrive has accumulated years of evolving names, phases, vendors, technical designs, brand descriptions, and public claims. The **Master Narrative Ledger** prevents institutional memory from being overwritten every time the implementation changes.

## Record model

Each material concept should preserve:

- stable institutional ID;
- canonical current name;
- historical names and aliases;
- current description;
- prior descriptions with dates;
- current lifecycle/status;
- predecessor and successor relationships;
- source documents;
- governing decision or ADR;
- public claim class;
- last review date.

## Why this matters

The public website currently contains descriptions from multiple eras—for example, more than 60 platforms in some FAQs, 80\+ platforms elsewhere, Phase 0 language on older pages, and Phase 1 CHLOM language on newer pages. Those differences are evidence of evolution, not a reason to erase the record.

The institutional system should instead state which description is current for a given context and preserve the earlier version as historical evidence.

## Correction doctrine

Corrections append. They do not silently rewrite history. When an identity, ownership statement, metric, vendor, phase, product capability, or operating role changes, the ledger should retain the previous value, correction reason, source, actor, and effective date.

## Phase 3 implication

The narrative ledger should be addressable by stable IDs and exposed through CrownThrive IO/MCP so websites, agents, support systems, and public docs can retrieve current approved language instead of inventing descriptions independently.
