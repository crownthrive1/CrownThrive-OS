# Framework and Engine Registry

CrownThrive's institutional IP includes frameworks and engines that are neither ordinary brands nor standalone software platforms. Phase 2.95 keeps those concepts explicit so Phase 3 can implement them as policies, schemas, workflows, services or reusable operating patterns without forcing each into a public app.

## Institutional frameworks

- **Convergent Ecosystem** — the field connecting corridors, platforms, brands, people, rights, data and value.
- **Thrive Flywheel** — the compounding movement from discovery and activation through engagement, monetization, proof, retention, contribution and expansion.
- **Hybrid Incubator** — shared-infrastructure venture/person/product development model.
- **Cultural Imprint Engine (CIE)** — cultural alignment, canon, representation, context and responsible reuse governance.
- **CHLOM** — Compliance Hybrid Licensing and Ownership Model; rights, rules, roles, revenue, records and remedies.
- **One Seat, Multiple Industries** — target unified member/operator experience across heterogeneous systems.
- **Core Operating Spine** — identity, IO/MCP, CHLOM, operations, support, analytics/signals, retention/distribution.
- **Master Narrative Ledger** — versioned canon, naming, claims and lineage control.
- **Corridor Architecture** — separates industry lanes while preserving governed handoffs.
- **MM Suites** — beauty/wellness/place-based operator and regional-license/franchise architecture, with legal activation separated from technical design.
- **ThrivePaths** — progression/playbook lineage across roles and ecosystem pathways.
- **dS-CaaS / CaaS lineage** — compliance-service architecture; exact terminology remains source/ADR controlled.
- **Succession \+ Generational Continuity** — stewardship, recovery and long-horizon institutional transfer.
- **CII / ThriveFund** — for-profit impact governance and internal reinvestment architecture.

## Registry fields

Each framework should carry stable ID, canonical name, aliases, owner, source family, version, current status, IP class, purpose, inputs, outputs, affected corridors, implementation components, policy relationships, evidence, public claim wording and successor/predecessor links.

## Phase 3 rule

Platforms **perform** work. Corridors **organize** work. Frameworks **govern or shape** work. Engines/services **execute reusable capability**. Phase 3 schemas must preserve those distinctions.
