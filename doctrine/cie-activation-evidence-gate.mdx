## CIE Activation Evidence Gate

The **Cultural Imprint Engine (CIE)** uses a separate activation-evidence gate before protected scoring source can be integrated or activated.

Wave 4 institutionalizes:

```yaml
gate_id: ct.gate.cie.activation-evidence.v1
framework_id: ct.framework.cultural-imprint-engine
canonical_engine_name: Cultural Imprint Engine
current_source_integration_state: HOLD_CONTRACT_DIGEST_MISMATCH
current_activation_state: HOLD_SOURCE_INTEGRATION
activation_authorized: false
```

The gate exists to prevent a technically valid but stale or semantically mismatched candidate from inheriting authority from newer CIE infrastructure.

## Two separate gates

Wave 4 separates **source integration** from **activation readiness**.

### Stage 1 — source integration

Protected-score source may be reconciled onto current CIE `main` only when all of the following are true:

1. the Wave 3B durable CIE ↔ CHLOM runtime is live and fail-closed;
2. the current CIE ↔ CrownThrive-OS technical parent-link receipt matches the intended exact repository heads;
3. Guardian, repository-family, and interoperability predicates are verified;
4. the candidate protected-score public-contract digest matches the live institutional algorithm registry;
5. the CIE package remains `controlled_test`, D2, non-voting, and D3-human-reserved;
6. no provider, economic, licensing, entitlement, D3, or sovereign authority is inferred.

The current Stage 1 result is:

`HOLD_CONTRACT_DIGEST_MISMATCH`

### Stage 2 — activation readiness

Even after Stage 1 becomes `SOURCE_INTEGRATION_READY`, protected scoring remains non-activated until separate evidence exists for:

- Agent D parent certification;
- independent semantic verification;
- independent security review;
- exact current head and contract-digest agreement;
- Founder first-activation ratification.

The highest Wave 4 machine result is:

`READY_FOR_INDEPENDENT_REVIEW_AND_FOUNDER_RATIFICATION`

That is a handoff state, **not execution authority**.
