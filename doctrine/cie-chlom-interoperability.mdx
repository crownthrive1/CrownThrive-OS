## CIE ↔ CHLOM Interoperability

**Cultural Imprint Engine and CHLOM are interoperable, not interchangeable.**

The purpose of the contract is to let each authority consume the other's resolved state without duplicating or overriding it.

## Authority split

| Authority | Governs |
| --- | --- |
| Cultural Imprint Engine | cultural meaning, narrative continuity, imprint identity, representation, aesthetics, audience/canon constraints, responsible reuse |
| CHLOM | ownership, rights, licensing, permissions, roles, evidence, records, remedies |

CIE does not manufacture rights. CHLOM does not manufacture cultural alignment.

## Contract identity

```yaml
contract_id: ct.contract.cie-chlom.interop.v1
version: 1.0.0
cie_framework_id: ct.framework.cultural-imprint-engine
cie_canonical_name: Cultural Imprint Engine
chlom_authority_id: ct.framework.chlom
mode: bidirectional_typed_fail_closed
mutation_authority: false
authority_inheritance: false
```

## CIE → CHLOM envelope

A handoff carries:

- contract ID and version;
- canonical CIE identity;
- public-safe or internal-governed usage profile;
- correlation ID;
- object and use IDs;
- CIE decision state;
- CIE conditions;
- audience class;
- canon state;
- source references;
- envelope digest;
- explicit zero authority effect.

The envelope requests CHLOM resolution. It does not issue a license, ownership determination, entitlement or economic approval.

## CHLOM → CIE receipt

A receipt carries:

- contract ID and version;
- correlation ID;
- CHLOM record ID;
- rights state;
- license state;
- permission state;
- evidence state;
- CHLOM digest.

The receipt informs CIE and the composition layer of rights state. It does not create or rewrite CIE cultural state.

## Composition states

CrownThrive uses explicit composition rather than collapsing two decisions into one opaque approval.

| Composed state | Meaning |
| --- | --- |
| `DENY_CULTURAL` | CIE denied the proposed use. |
| `HOLD_CIE` | CIE requires correction/evidence. |
| `DENY_RIGHTS` | CHLOM denied permission. |
| `HOLD_CHLOM` | CHLOM permission is held or unknown. |
| `HOLD_CHLOM_RIGHTS` | rights are disputed or unknown. |
| `HOLD_CHLOM_LICENSE` | required/current license state is unresolved. |
| `HOLD_EVIDENCE` | CHLOM evidence state is below the v1 verified threshold. |
| `COMPOSED_READY_NON_EXECUTING` | CIE and CHLOM are sufficiently resolved for the evaluated use, but no execution/economic/D3 authority is created. |

`COMPOSED_READY_NON_EXECUTING` is intentionally bounded. It does not authorize:

- provider or database writes;
- production deployment;
- PentaGreen ECAC;
- pricing or checkout;
- license issuance beyond CHLOM's separately recorded rights state;
- customer entitlement;
- D3 action;
- sovereign approval.

## Public-safe interoperability

Public-safe CIE callers may send only sanitized public fields. Private evidence references, raw evidence, secrets, protected calibration and private reasoning are forbidden.

## Internal-governed interoperability

Internal-governed callers may use approved opaque restricted-evidence references under RBAC. Raw credentials and raw private evidence do not cross this interoperability contract.

See [CIE Public & Internal Usage](/doctrine/cie-public-internal-usage).

## Version and digest discipline

A contract-version or required digest mismatch is HOLD.

Any future networked/mutating adapter must also provide:

- correlation ID preservation;
- replay/duplicate idempotency;
- authenticated caller identity;
- RBAC for internal payloads;
- evidence/receipt lineage;
- rollback/compensation appropriate to the downstream mutation;
- explicit provider/economic authority separate from this contract.

## Non-collapse invariants

The following statements are always false:

```text
CIE PASS == CHLOM ALLOW
CHLOM ALLOW == CIE PASS
CIE == CHLOM
CHLOM == Cultural Imprint Engine
COMPOSED_READY_NON_EXECUTING == production authority
```

Interoperability depends on preserving the separation.

## Wave 3B durable runtime state

The Wave 2 contract now has a **durable internal controlled-test** evidence/runtime substrate in ThriveBase.

```yaml
runtime_id: ct.runtime.cie-chlom.durable.v1
cie_system_id: ct.system.cie.runtime
chlom_system_id: ct.system.chlom.runtime
persistence_contract: ct.contract.cie-chlom.persistence.v1
route_id: ct.route.cie-chlom.interop.v1
contract_state: controlled_test
route_state: controlled_test
route_certification_state: candidate
public_network_endpoint: not_deployed_by_wave_3b
composition_ceiling: COMPOSED_READY_NON_EXECUTING
```

The durable path records one canonical payload for each `(correlation_id, direction)` and binds newly persisted exchange receipts to restricted DAIL evidence.

Its runtime results include:

- `RECORDED` for the first valid payload;
- `IDEMPOTENT_DUPLICATE` for an exact replay;
- `HOLD_REPLAY_CONFLICT` for the same key with a different payload;
- `HOLD_ORPHAN_CHLOM_RECEIPT` when a CHLOM response has no prior CIE request.

A replay conflict does not rewrite the original receipt. The runtime is forced-RLS and append-only, and the governed writer is service-role-only. Direct service-role insert/update/delete is not granted.

The persistence contract has a bounded `write_effect=true` because it writes **internal evidence**. That write effect is not provider, customer, deployment, commerce, entitlement, scoring, D3 or sovereign authority.

Current certification readback showed two durable receipts, one complete correlation, zero pending correlations, forced RLS, no anonymous/authenticated writer execution, and a positive composed result of `COMPOSED_READY_NON_EXECUTING` for the controlled synthetic test.

No public network endpoint is claimed by this state. Declared API/MCP contracts, internal persistence and a live database function do not prove a public CIE service deployment.

See [CIE Durable Runtime & Evidence](/doctrine/cie-durable-runtime-and-evidence) for the persistence, DAIL, replay, access and observability model.
