# ThriveTools SEO Certification Queue

## Resolved identity

```yaml
parent_platform: ct.platform.thrivetools
capability_id: ct.capability.thrivetools.seo
name: ThriveTools SEO
relationship: capability_of
public_host: https://seo.thrivetools.io
identity_state: resolved
host_lineage_state: source_backed
```

The parent/child identity and host relationship are resolved from founder adjudication plus recovered platform/domain manifests. This does **not** certify the current application runtime.

## Current verification queue

The following remain evidence-gated:

1. application/version identity;
2. current provider/engine and license lineage;
3. current deployment/runtime health;
4. admin and end-user role model;
5. API documentation and base URL, if any;
6. authentication, scopes and credential custody;
7. webhooks, batch exports and MCP exposure;
8. robots, sitemap, canonical and structured-data behavior;
9. data collection, retention and customer-site permissions;
10. write/action capabilities and rollback;
11. CrownLytics event contract;
12. monetization, plan and entitlement state;
13. source repository, backup and vendor-exit path;
14. legal/privacy/addendum coverage.

## Non-inference rule

`seo.thrivetools.io` appearing in a master-link/domain manifest proves a governed host relationship. It does not prove that an API exists, that a provider account is entitled, that writes are safe, or that any current feature set is operational.

The queue should close through current operational evidence rather than historical product descriptions.
