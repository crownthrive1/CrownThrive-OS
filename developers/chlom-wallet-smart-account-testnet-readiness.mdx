**State:** `HOLD_PREDEPLOYMENT`  
**Target chain:** Sepolia / `eip155:11155111`  
**EntryPoint chain code:** unverified  
**Simulation:** not run

## Read-only chain-code contract

The preflight implementation permits exactly two JSON-RPC methods:

```text
eth_chainId
eth_getCode
```

It rejects:

- non-HTTPS external RPC URLs;
- embedded URL credentials;
- transaction, wallet, personal, miner, admin or debug methods;
- chain-ID mismatch;
- missing runtime code;
- absent approved runtime codehash;
- runtime-codehash mismatch.

The contract test runs against an isolated local mock RPC and passes:

```yaml
result: PASS_READ_ONLY_CHAIN_CODE_PREFLIGHT_CONTRACT
chain_id_bound: true
runtime_codehash_bound: true
missing_codehash_holds: true
mismatch_holds: true
rpc_write_methods_sent: false
external_rpc_used: false
testnet_broadcast: false
money_movement: false
```

That PASS validates the preflight behavior. It is not Sepolia chain evidence.

## Manual Sepolia readback workflow

A manual workflow exists at:

`.github/workflows/chlom-wallet-sepolia-readonly-codehash.yml`

It requires:

- the restricted `CHLOM_SEPOLIA_RPC_URL` environment secret;
- a governed expected runtime codehash supplied at dispatch;
- exact Sepolia chain ID `0xaa36a7`;
- exact candidate EntryPoint address.

The workflow contains no signer, private key, UserOperation, paymaster, account deployment or broadcast step. A successful run would establish read-only chain/address/codehash compatibility only. It would not authorize testnet deployment.

## Hard predeployment gates

The machine gate contract is:

`developers/reference/chlom-wallet/smart-account/testnet-predeployment-gates.v1.json`

It requires all of the following before a separate broadcast workflow may exist:

1. External read-only chain ID and runtime-code receipt.
2. Independently approved EntryPoint runtime codehash.
3. Reviewed account implementation.
4. Reviewed factory or deterministic deployment pattern.
5. Reviewed passkey validator.
6. Certified recovery policy.
7. Reviewed call data and init code.
8. Bundler compatibility and UserOperation simulation.
9. Independent security review.
10. Testnet signer and recovery authority receipt.
11. Rollback and recovery drill.
12. Separate governed testnet broadcast authorization.

Every required gate is snapshot-bound. Source drift, chain mismatch, stale evidence, codehash drift, recovery defects or authority withdrawal returns the profile to `HOLD_PREDEPLOYMENT`.
