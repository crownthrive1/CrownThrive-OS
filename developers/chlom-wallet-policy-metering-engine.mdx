# CHLOM Wallet policy, metering and assurance engine

**Subsystem:** `ct.subsystem.chlom-wallet.policy-metering-assurance.v1`  
**Algorithm suite:** `ct.algorithm-suite.chlom-wallet-policy-metering.v1`  
**State:** `CONTROLLED_TEST`  
**Institutional phase:** 2.99  
**Effective policy, billing, prices and checkout:** disabled

The Policy, Metering & Assurance Engine converts CHLOM Wallet governance into deterministic, testable machine contracts. It is the control layer that allows WalletKit capabilities to be packaged, measured, simulated and independently reviewed without turning controlled-test evidence into a live product, charge, entitlement, credential, transaction or chain action.

The engine is proprietary CrownThrive orchestration built above public standards and replaceable providers. It does not relabel WebAuthn, Stripe, ERC-4337, ERC-7579, CAIP or other third-party technology as CrownThrive intellectual property.

## Five algorithm families

### CWPX — CHLOM Wallet Policy Compiler & eXecutor

CWPX normalizes policy packages, detects contradictory same-priority rules, produces deterministic compiled artifacts and returns explainable `ALLOW | HOLD | DENY` receipts.

Core rules:

- `DENY` outranks `HOLD`, which outranks `ALLOW`;
- missing consequential inputs fail closed to `HOLD`;
- policy source and compiled artifacts receive separate SHA-256 commitments;
- compilation never activates a policy;
- evaluation never writes to a provider, grants a production right, activates a credential, moves money or broadcasts to a chain.

### MARC — Metered Activity Reconciliation Compiler

MARC records append-only usage evidence and separates provider or application event time from append order.

It enforces:

- one tenant/idempotency key per semantic event;
- exact duplicate replay returns `DUPLICATE`;
- the same idempotency key with a different payload digest fails closed;
- monthly UTC rollups sort by occurrence time and stable event ID;
- rollups are evidence, not bills;
- no price, charge or Stripe object is inferred from usage.

### QERA — Quota Enforcement & Reconciliation Algorithm

QERA implements the founder-overridden CrownThrive-local limit semantics exactly:

```yaml
-1: unlimited CrownThrive-local limit
0: exactly zero permitted
positive_integer: exact permitted quantity
null: unresolved or unknown; HOLD fail-closed
less_than_-1: invalid; DENY
```

Provider throttles, plan entitlements, billing limits, contractual limits and platform safety controls remain separately authoritative. `-1` does not mean an external provider has no limit.

### SAGE — Scenario Assurance & Governance Evaluator

SAGE executes deterministic policy matrices and produces:

- decision distributions;
- reason-code distributions;
- per-rule true/false/unknown coverage;
- unreachable-rule candidates;
- deterministic simulation digests.

A passing simulation proves only the tested policy behavior. It does not activate the policy or authorize a live action.

### AURA — Algorithmic Usage & Risk Advisor

AURA ranks suggestion-only proposals from simulation summaries, meter snapshots and bounded risk signals. The first version is deterministic and makes no external model call.

Candidate recommendations include:

- resolve missing policy inputs;
- investigate usage that conflicts with a zero limit;
- review a bounded limit above 80 percent utilization;
- add an explicit deny or hold rule for an unmapped consequential action;
- add scenario coverage for an untested rule path.

AURA has no auto-apply path. It cannot change policy, pricing, rights, provider state, credentials, chain state or institutional phase.

Every evaluation returns:

```yaml
contract: ct.wallet.policy-decision-receipt.v1
policy_id: ct.policy.chlom-wallet.walletkit-controlled.v1
policy_version: 1.0.0
compiled_digest_sha256: <digest>
input_digest_sha256: <digest>
decision: ALLOW | HOLD | DENY
reason_code: <stable reason>
decisive_rule_ids: []
rule_evaluations: []
decision_digest_sha256: <digest>
```

The receipt is evidence of a policy evaluation. It is not a payment, license, credential, transaction, fulfillment event or release authorization.
