# CHLOM Wallet Execution Envelope v1

The execution-envelope layer closes the gap between a skill existing in the Wallet Agent catalog and that skill being eligible to run a bounded controlled-test action. A skill name, pallet mapping, handoff label, provider event, or AI recommendation is never sufficient by itself.

Each request is bound to:

```text
skill
  + pallet
  + action type
  + value class
  + environment
  + A/D authority
  + exact source head
  + source / rollback evidence
  + required independent handoffs
  + deterministic Policy Assurance v2
        ↓
ECAC | HOLD | DENY
```

`ECAC` means only **eligible controlled-action candidate**. It is not a production approval, capability grant, reviewer vote, money instruction, rights grant, chain transaction, pricing authorization, checkout authorization, merge authorization, or phase transition.

## Handoff Evidence Router

`ct.contract.chlom-wallet.handoff-evidence-router.v1` validates existing independent evidence. It does **not** mint a heartbeat, create a review receipt, or grant a capability.

For each required handoff it checks:

1. exact stable agent ID exists in the verified handoff crosswalk;
2. registry binding is active;
3. reviewer is independent of the originator;
4. receipt role matches the registered role;
5. receipt is bound to the same source head;
6. reviewer heartbeat is fresh;
7. receipt decision is `PASS`, not `HOLD` or `DENY`;
8. receipt hash has a valid digest shape.

Missing or stale evidence returns `HOLD`. Explicit independent denial, self-review, role mismatch, an unverified reviewer, or an attempted pending-alias receipt returns `DENY`.

## Policy composition

The execution envelope cannot weaken Policy Assurance v2. Final disposition is the strictest of:

- per-skill profile validation;
- handoff-evidence routing;
- deterministic Policy Assurance v2.

Therefore a `DENY` from any layer remains `DENY`; a `HOLD` cannot be upgraded to `ECAC` by another layer; and AI remains advisory-only behind the AI Counsel Firewall.

## Hard boundaries

This tranche creates no production authority. The following remain false:

```yaml
authority_granted: false
capability_grant_created: false
provider_write: false
custody: false
token_issuance: false
money_movement: false
rights_grant: false
chain_broadcast: false
effective_price_publication: false
checkout_activation: false
merge_authorized: false
phase_advancement: false
ai_final_authority: false
```

Independent review evidence must be produced by the independent reviewer lane itself. The Wallet Agent may validate and route that evidence; it may not fabricate it.
