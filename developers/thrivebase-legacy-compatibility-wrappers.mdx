# ThriveBase legacy compatibility wrappers

**Contract:** `ct.manifest.thrivebase-legacy-compatibility-wrappers.v1`  
**Institutional phase:** 2.99  
**State:** `CONTROLLED_TEST_SOURCE_READY_RUNTIME_PENDING`  
**Production authority:** none

This controlled tranche introduces canonical `thrivebase` function names without destructively renaming the pre-existing missing-r runtime estate.

<Warning>
  The wrappers do not rename schemas, queues, triggers, consumers, Vault secrets, Edge functions, or legacy routines. They do not broaden public access, create provider-write authority, move money, grant rights, broadcast a chain transaction, advance the institutional phase, or authorize merge.
</Warning>

## Why wrappers come first

A direct rename would risk breaking queue consumers, trigger functions, scheduler bindings, Vault lookups, Edge code, and historical evidence. The safer migration sequence is:

```text
Inventory legacy dependencies
        ↓
Create canonical service-only wrappers
        ↓
Verify signatures and privilege parity
        ↓
Run safe read-only behavior canaries
        ↓
Bind new source to canonical names
        ↓
Rebind consumers and triggers in controlled tranches
        ↓
Verify rollback and exact readback
        ↓
Retire legacy aliases only under explicit approval
```

This page covers the wrapper stage only.

## Canonical wrapper surface

| Canonical function | Access | Current purpose |
| --- | --- | --- |
| `thrivebase_async_queue_complete_v1(...)` | no new service-role grant | Preserve the original restricted completion surface without widening authority |
| `thrivebase_async_queue_complete_v2(...)` | service role | Canonical completion alias |
| `thrivebase_async_queue_read_v1(...)` | service role | Canonical bounded queue-read alias |
| `thrivebase_async_queue_status_v1()` | service role | Canonical read-only queue status |
| `thrivebase_async_webhook_authorize_v1(...)` | service role | Canonical authorization alias; existing Vault secret unchanged |
| `thrivebase_health_snapshot()` | service role | Canonical health alias; existing heartbeat sink unchanged |
| `thrivebase_self_diagnostic_run_v1()` | service role | Canonical diagnostic-run alias; existing agent binding unchanged |
| `thrivebase_self_diagnostic_status_v1()` | service role | Canonical read-only diagnostic status |

All wrappers are `SECURITY INVOKER`. `PUBLIC`, `anon`, and `authenticated` execution remain revoked.

## Safe readback canaries

Only two behavior-equivalence checks are authorized in this tranche:

1. queue-status parity; and
2. self-diagnostic-status parity.

The following surfaces are not invoked during compatibility readback because they may consume, archive, authorize, write, lock, or create operational evidence:

- queue read;
- queue completion;
- webhook authorization;
- health snapshot;
- diagnostic run.
