# API Base URL and Endpoint Seed Register

This is a starting inventory for Phase 2.98. A source-defined host or endpoint is not a production claim. Every item requires environment, authentication, ownership and live-response verification before state advances beyond `source_defined` or `prepared`.

## State vocabulary

- `source_defined` — found in an approved specification or directive;
- `prepared` — route/configuration was designed or reportedly created, but current deployment is not reverified here;
- `public_host_verified` — public website host responds, not necessarily an API;
- `docs_verified` — official documentation is reachable/current;
- `auth_verified` — authentication flow tested;
- `sandbox_verified` — authorized test succeeds;
- `production_verified` — authorized production behavior and owner confirmed;
- `deprecated` — replacement exists;
- `blocked` — cannot currently validate/use;
- `unverified` — known reference, current state unknown.

## Required verification packet

For every seed item record:

1. DNS/TLS/host owner;
2. environment;
3. service/provider/account;
4. official docs/schema;
5. auth and scopes;
6. authorized request/response test;
7. health/version;
8. webhook signature/retry where applicable;
9. data classification;
10. support/incident path;
11. source repository/deployment;
12. last verified timestamp;
13. deprecation/replacement;
14. DAIL event or evidence reference.

## Security rule

Do not publish private admin/internal base URLs, client secrets, webhook secrets, tokens, database hosts or debug endpoints in public documentation. Public API references must be intentionally approved.
