# ThriveLedger™ Private API & MCP

ThriveLedger's network interface is a **restricted CrownThrive operations surface**. It is not a public financial API and does not expose bank records, transaction bodies, credentials, Vault material or private provider identifiers.

| Field | Current state |

| Service version | `1.0.0` |

The runtime also requires CrownThrive service authorization after platform JWT validation. A deployed function is not considered an enabled MCP merely because the code exists.

## API routes

The controlled-test contract defines:

- `GET /health`
- `GET /api/status`
- `POST /api/evidence`
- `POST /api/balance-observation`
- `POST /api/reconcile`
- `POST /api/audit`
- `GET /api/chlom-evidence`
- `POST /mcp`

The MCP endpoint supports `initialize`, `tools/list` and `tools/call` under the adopted target protocol profile.

## Data minimization

Evidence ingestion is digest-first. The interface rejects or avoids raw secret material and is designed to store provider references as hashes or governed references rather than copying sensitive identifiers into the institutional ledger.

Permitted evidence metadata is limited to what is needed to establish source class, occurrence time, shape, confidence, reconciliation state, correlation and integrity. Raw financial bodies remain in the applicable protected source system.

## Internal writes are not provider writes

Some ThriveLedger tools write append-only internal evidence, audit or reconciliation records. These are classified as internal mutations because they strengthen CrownThrive's evidence trail. They do **not** authorize:

- charging or refunding a customer;
- transferring funds;
- changing a bank record;
- modifying a Stripe object;
- changing CHLOM Wallet economic state;
- filing taxes;
- granting a license or entitlement;
- executing a D3 action.

## Request-budget semantics

ThriveLedger is governed by Founder Directive V4 with a CrownThrive-local monthly ceiling of `-1`, meaning unlimited local requests. `0` would mean zero permitted requests and `null` would fail closed. Provider and connector limits remain independently authoritative.

## Audit and reconciliation behavior

`reconcile` does not invent missing entries. It detects unmatched evidence, stale sources, conflicts, cross-entity contamination and unbalanced journals, then returns PASS/HOLD/FAIL evidence.

`audit` independently verifies evidence-chain continuity, double-entry conservation, legal-entity boundaries and reversal integrity. Corrections use reversals or superseding records rather than historical deletion.

## CHLOM export

The CHLOM export surface is proof-oriented. It returns bounded assertion receipts and source-chain heads, not bank statements or payment-provider payloads. `economic_truth_authority=false` is part of the v1 export contract.

## Release gate

The v1 API/MCP remains a controlled-test private surface until the exact authenticated HTTP canary is recorded. Public exposure, customer access and provider-write expansion are not implied by this documentation.
