# Virality SoundCloud and Catalog Optimization Adapter

## Status

**Service state:** documented<br />**Public SoundCloud embed standard:** passed for supported oEmbed/HTML5 Widget use<br />**Public embed credential requirement:** none<br />**SoundCloud authenticated credential state:** unverified<br />**Authenticated provider-read certification:** blocked<br />**Provider write gate:** closed<br />**Promotion execution:** not implemented<br />**Public-document posture:** contracts and safeguards only; no secrets or private object references

This adapter separates two different jobs that must not be collapsed:

1. **public presentation/playback** through SoundCloud-supported public widgets; and
2. **authenticated measurement/evidence** through a separately governed provider API/export lane.

A missing analytics credential does not block an official public SoundCloud embed. Conversely, a functioning public embed never proves authenticated Artist Studio/API evidence.

## Service boundaries

- Supabase holds the private operational registry and dated evidence rows.
- Virality supplies stable work identity and approved public projection.
- SoundCloud supplies a supported public playback/embed surface and, separately, an external measurement source.
- CrownLytics supplies definitions and recommendation evaluation.
- the Website Surface & Interaction Agent plus its Virality visual-QA child govern public presentation evidence;
- GSO and CHLOM remain outside the adapter's authority but provide mandatory readiness gates.

## Public embed contract

For public Virality Music listening pages, the default is the supported SoundCloud embed stack:

- **simple public playback:** use SoundCloud oEmbed / the standard iframe widget;
- **custom parent-page playback controls or player events:** use the official HTML5 Widget API around the standard iframe;
- **authenticated analytics:** do not use the public widget as a substitute; route through the separately certified read/export contract.

SoundCloud's oEmbed response is designed for responsive embedding and returns widget markup at width `100%`; `auto_play` defaults to `false`. The HTML5 Widget API is the supported JavaScript control surface for playback methods and events.

CrownThrive requirements:

- responsive width within the governed page container;
- autoplay off by default;
- descriptive iframe/player title;
- preserve canonical SoundCloud attribution/source route where appropriate;
- surrounding controls remain keyboard operable with visible focus;
- preserve click-to-load/consent behavior when the current privacy model requires user-initiated third-party media;
- reserve player space to reduce avoidable layout shift;
- lazy-load below-fold embeds where the supported implementation permits;
- no SoundCloud API token, client secret or provider credential in page source, iframe parameters, public JS, GitHub or Mintlify;
- a player failure must not destroy the page's core copy, rights route or business CTA.

Official provider references:

- [SoundCloud oEmbed](https://developers.soundcloud.com/docs/oembed)
- [SoundCloud HTML5 Widget API](https://developers.soundcloud.com/docs/api/html5-widget)

Implementation across every applicable Virality route remains a separate Sites/public-surface verification task. The standard itself does not claim that every current route has already been migrated.

## Read contract

Every read tool must enforce:

- stable identifiers;
- explicit allowed fields;
- service or user scope;
- bounded page size and cursor pagination;
- request budget and timeout;
- evidence date and evidence state;
- deterministic ordering;
- no private file identifiers, credentials, raw provider payloads or customer records;
- audit receipt with request class, actor, tool version and result count.

## Daily authenticated-sync contract

`soundcloud.sync.daily` is idempotent on provider, scheduled date and attempt. One run records request count, response count, raw digest, evidence state, completion state and error code. A snapshot is unique by date, entity type and provider entity ID.

The authenticated metric adapter must not treat HTML, an iframe, oEmbed output or a public profile observation as equivalent to authenticated Artist Studio/API evidence. Public observations are recorded as `observed_unverified`; an unavailable or unauthorized read is `blocked`.

Before the authenticated tool can be enabled, the certification packet must prove:

1. a least-privilege read credential or repeatable signed export;
2. token storage outside code and docs;
3. pagination and field mapping;
4. rate, timeout, retry and backoff behavior;
5. stale and partial response handling;
6. idempotent replay;
7. raw-evidence retention and deletion policy;
8. a bounded read in production with no provider mutation.

None of those prerequisites is necessary merely to display an official public SoundCloud widget.

## Recommendation write contract

A recommendation request includes asset ID, target surface, action type, score, evidence window, evidence digest, reasons, safeguards, expiry and algorithm version. It must fail closed when rights, release, canon, audience, commerce, freshness, cooldown, balance or rollback evidence is absent.

Approval creates an append-only decision event. It does not execute a placement. Execution requires a separate tool, separate scope, separate approval, target-specific preflight and target-specific rollback.

## Public-surface and visual QA handoff

Any proposed change to public SoundCloud presentation is handed to `ct.subagent.virality-public-surface-visual-qa` under the Website Surface & Interaction Agent. The child checks responsive fit, player overlap, keyboard/focus behavior, visual hierarchy, third-party loading, accessibility, layout stability and Virality brand coherence.

A successful API/read test cannot substitute for visual QA. A successful visual QA cannot substitute for provider-read certification.

## Security and rollback

- No anonymous or authenticated end-user role can access the private control schema.
- Operational tables use RLS and service-role-only policies.
- The private storage bucket has no public listing or object-read policy.
- Credentials belong in a managed secret store, not GitHub, Mintlify, logs, prompts or database metadata.
- Public SoundCloud embeds never contain CrownThrive provider credentials.
- Rollback first disables the affected schedule/tool or restores the last accepted Sites/public-surface version as applicable. Evidence rows are preserved for audit.
