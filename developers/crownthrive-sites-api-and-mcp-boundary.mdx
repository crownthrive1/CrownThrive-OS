# CrownThrive Sites™ API and MCP boundary

## Stable identities and versions

| Field | Value |
| --- | --- |
| Platform | `ct.platform.crownthrive-sites` |
| Public API | `ct.api.crownthrive-sites.public` |
| API version | `v1` |
| MCP contract | `ct.mcp.crownthrive-sites` |
| MCP protocol target | `2026-07-28` when production work is authorized |
| Current MCP state | `specified-not-production` |

## Public API

Base URL: `https://crownthrive-sites.crownthrive.chatgpt.site`

| Method | Route | Purpose | Auth | Data class | Side effects |
| --- | --- | --- | --- | --- | --- |
| GET | `/api/health` | Returns service availability metadata. | None | Public | None |
| GET | `/api/v1/catalog` | Returns the current public catalog candidates and declared lifecycle states. | None | Public | None |
| GET | `/api/v1/integration-status` | Returns public-safe state for documentation, GitHub, and MCP boundaries. | None | Public | None |

Responses may change only through versioned source releases. Consumers must not treat a catalog candidate as a purchasable product, price, rights clearance, or fulfillment promise.

## Explicit non-capabilities

This public API does **not** provide:

- customer, lead, account, payment, identity, or entitlement data;
- checkout, billing, refund, order, product-activation, or rights-grant operations;
- access to credentials, source repositories, private governance records, or CHLOM restricted evidence;
- automatic execution of ecosystem upgrades;
- a remote MCP endpoint, OAuth authority, tool grant, or write capability.

## MCP contract candidate

The future MCP surface is intentionally separated from the public API. If approved for production, it must begin with read-only discovery tools:

| Candidate tool | Purpose | Authority | Data class | Approval | Rollback |
| --- | --- | --- | --- | --- | --- |
| `sites_catalog_list` | Read publicly released catalog records. | A0 observe | Public | None | Remove tool registration |
| `sites_integration_status` | Read declared integration states and gates. | A0 observe | Public | None | Remove tool registration |
| `sites_release_readiness` | Read a governed release-readiness projection after source authorization. | A0 observe | Public / summary only | None | Disable tool or revert record |

Write-capable tools—including lead intake, product activation, template release, checkout, customer support, deployment, provider connection, or data export—are blocked until they each have:

1. a documented tool contract and stable tool ID;
2. data classification, authentication, authorization, scope, rate, logging, retention, and export rules;
3. side-effect disclosure, approval class, and rollback or compensation behavior;
4. verified CHLOM, privacy, security, commerce, and accessibility review where applicable;
5. test, incident, deprecation, and replacement records; and
6. independent release verification.

## Agent and release coupling

The API and future MCP contract are governed by the [Institutional Hourly Agent Relay](/automation/institutional-hourly-agent-relay) and the [Website Patch Workflow](/workflows/website-patch). Agents may prepare records and validate public read-only routes within their authority. They may not self-approve a material integration, broaden access, activate customer-data handling, or deploy a write-capable MCP tool.
