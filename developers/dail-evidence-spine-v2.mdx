## DAIL Evidence Spine v2

DAIL v2 makes the existing institutional event chain the evidence spine for material CrownThrive OS transitions. It does not turn the ledger into a copy of every database, message, file or telemetry sample. Bodies remain in their authorized systems of record; DAIL receives a classified envelope, content digest, provenance, authority, verification and correction references.

The source implementation is intentionally additive. Existing DAIL 1.0 and 1.1 rows retain their historical preimages, sequence and documented correction. New v2 rows extend that same chain with an unambiguous full-envelope hash, provider/source identity, trust domain, evidence class, idempotency key and verification lineage.

## Evidence path

For the first non-CHLOM input, the ingress adapter verifies the exact Stripe request bytes before parsing, accepts any valid `v1` signature from an active versioned secret within a 300-second window, records only safe digests and references, and queues business processing. The shared-secret HMAC is strong provider-origin evidence, but it is not public non-repudiation. A separate workload must reconcile the provider event and a separately controlled witness must write and read back a checkpoint before the evidence can be classified as independently anchored.

The existing CrownThrive External Evidence Relay is the only external recurrence used for provider readback and witness dispatch. This capability pack adds no scheduler, framework, vote or quorum participant.

## OS binding

The machine manifest maps all five Pentafabric layers and all twelve capability pallets to DAIL event families. Rights, authority, economic, entitlement and deployment transitions fail closed unless the domain write and DAIL append share a transaction or a transactional outbox blocks certification until sealing succeeds. Low-risk telemetry may queue temporarily only as explicitly `unsealed`; it cannot support certification.

PentaSerialized remains a local recovery/WAL mechanism. Domain receipt tables remain useful projections. Neither becomes a competing institutional authority.

## Factory continuation and contour

PentaContour is specified here as the deterministic boundary stage before planning and compilation: it freezes the file, dependency, interface, classification, test, rollback and DAIL-event contours. The source migration implements append-only continuation checkpoints, deterministic content digests, monotonic fencing, assurance-receipt separation, terminal DAIL binding and an outbox receipt. The `FOR UPDATE SKIP LOCKED` acquisition/reclaim worker remains specified but not implemented or crash-certified. A missing executable-test, security, provider-readback, rollback, independent-verification or DAIL receipt can never authorize a later human promotion.

The old maintenance records are preserved. For current work, the most restrictive applicable gate wins: branch-scoped source work is allowed, while automatic child projection, runtime apply and production promotion remain held pending independent review and a D3 human decision.

## Native chain boundary

The twelve modern pallets are cloud/API capability packages. Native Substrate anchoring remains deferred target architecture. A future native implementation may accept signed checkpoint roots and expose inclusion proof metadata; it must not store raw evidence, personal data, rights bodies or economic logic. No native-chain or metaverse production claim is made by this build.

## Promotion proof

Promotion requires disposable-database migration proof, preservation of the legacy chain, RLS/privilege and mutation-negative tests, complete webhook/replay fixtures, distinct verifier identity, deterministic factory crash/recovery proof, external checkpoint write/readback, exact-SHA cross-repository verification and an explicit D3 decision.
