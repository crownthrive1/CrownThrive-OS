## Authentication

Requests use an API key in the `Authorization` header. The actual value is restricted runtime credential material and must never be copied into public examples or browser-side code.

Authentication success must be evaluated against the expected API success schema rather than inferred from HTTP status alone. Detailed negative-test behavior is retained as restricted institutional evidence, not published here.

## Request contracts

### Get optimized images

The provider documentation identifies `/get-images`, but its HTTP method is not yet independently certified. The documented source shape shows no request parameters. The documented response includes overall optimized-image counts, current-day counts and size information, plus image records containing an image identifier, name, dimensions, optimized URL, byte size and creation timestamp.

### Get media images

The provider documentation identifies `/get-media`, but its HTTP method is not yet independently certified. The documented source shape shows no request parameters. The documented response includes overall media-image counts, current-day counts and image records with identifier, name, dimensions, URL, byte size and creation timestamp.

### Upload images

The provider documentation identifies `/upload` with a form-data request shape, but its HTTP method is not yet independently certified. The documented parameters are:

- `images[]` — image-file array
- `compression_ratio` — integer compression ratio
- `media_upload` — string boolean flag

The documented response returns an array of optimized download URLs. This mutation surface is not enabled through the CrownThrive control plane.

### Delete images

The provider documentation identifies `/delete` with a JSON request shape, but its HTTP method is not yet independently certified. The documented parameters are:

- `image_id` — array of image identifiers
- `permanent_delete` — boolean

This destructive surface is not enabled through the CrownThrive control plane.

### Get single image

The provider documentation identifies `/get-single-image` with a JSON request shape requiring `image_id`, but its HTTP method is not yet independently certified. The documented response returns one image record including its identifier, name, dimensions, URL, byte size and creation timestamp.

### Check status

`GET /check-status` has no documented request parameters. A live authenticated CrownThrive certification returned the expected success schema. Account-specific capacity and usage values are intentionally not published on this public page.
