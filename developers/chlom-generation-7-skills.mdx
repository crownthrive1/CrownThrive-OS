# CHLOM Generation 7 Skills

Generation 7 packages repeated evidence-processing work into reusable capability contracts. Skills do not create authority.

| Install name | Owner | Public purpose | State |
| --- | --- | --- | --- |
| `crownthrive-gen7-evidence-governor` | Agent Q | evidence sufficiency, decision sufficiency and capacity-utilization receipts | controlled test |
| `crownthrive-gen7-remediation-optimizer` | Agent R | blocker burn-down, SEO remediation ranking and bounded remediation planning | controlled test |
| `crownthrive-gen7-value-licensing` | Agent T | licensing-value analysis, benchmark reconciliation and candidate commercial packaging | controlled test |

## Skill invariants

Every execution must bind to an exact skill version, exact algorithm version where applicable, input/evidence digest, caller authority, reason codes and an immutable receipt. Protected implementation and calibration stay behind the CHLOM Vault/capability boundary.

A child execution identity inherits the least of parent, template, task and current-policy authority. Vote eligibility is never inherited. D3 remains human-reserved.

## Evidence-governor skill

Consumes sanitized evidence features and returns immutable scoring/decision candidates. It can recommend internal resolution, independent verification, governed review or human adjudication, but cannot execute the underlying operation merely because a score is high.

## Remediation-optimizer skill

Consumes bounded work/website evidence and generates ranked remediation packets. It distinguishes crawlability failures from content/accessibility defects, preserves the dated baseline and requires recrawl/readback before claiming improvement.

## Value/licensing skill

Reconciles current public market evidence with a protected CrownThrive value model. It may generate candidate tier/price recommendations and license-scope candidates, but it cannot activate checkout, Stripe objects, operative terms, redistribution rights or white-label authority.

## MCP contracts

The controlled-test logical surface includes:

- `gen7.score.evaluate`
- `gen7.governance.decision_candidate`
- `gen7.status`
- `gen7.license.candidates`
- `gen7.seo.queue`

All protected weights, thresholds, secret values and private identity mappings remain unavailable to the public/tool caller.
