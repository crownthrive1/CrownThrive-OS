# CHLOM Generation 7 Skills

Generation 7 packages repeated evidence-processing work into reusable capability contracts. Skills do not create authority, sovereign votes or D3 automation.

| Install name | Owner | Public purpose | State |
| --- | --- | --- | --- |
| `crownthrive-gen7-evidence-governor` | Agent Q | evidence sufficiency, decision sufficiency and capacity-utilization receipts | controlled test |
| `crownthrive-gen7-remediation-optimizer` | Agent R | blocker burn-down, SEO remediation ranking and bounded remediation planning | controlled test |
| `crownthrive-gen7-value-licensing` | Agent T | licensing-value analysis, benchmark reconciliation and candidate commercial packaging | controlled test |
| `crownthrive-gen7-provider-finops` | Agent U | provider usage, spend/balance evidence, allowance/overage watch and stale-evidence detection | controlled test |

| `crownthrive-gen7-purple-verifier` | Purple Team | independent reproduction and patch-efficacy verification | controlled test |

## Skill invariants

Every execution must bind to an exact skill version, exact algorithm version where applicable, input/evidence digest, caller authority, reason codes and an immutable receipt. Protected implementation and calibration stay behind the CHLOM Vault/capability boundary.

A child execution identity inherits the least of parent, template, task and current-policy authority. Vote eligibility is never inherited. D3 remains human-reserved.

## Evidence-governor skill

Consumes sanitized evidence features and returns immutable scoring/decision candidates. It can recommend internal resolution, independent verification, governed review or human adjudication, but cannot execute the underlying operation merely because a score is high.

## Remediation-optimizer skill

Consumes bounded work/website evidence and generates ranked remediation packets. It distinguishes crawlability failures from content/accessibility defects, preserves the dated baseline and requires recrawl/readback before claiming improvement.

## Value/licensing skill

Reconciles current public market evidence with a protected CrownThrive value model. It may generate candidate tier/price recommendations and license-scope candidates, but it cannot activate checkout, Stripe objects, operative terms, redistribution rights or white-label authority.

## Provider FinOps skill

Tracks provider billing periods, included units, provider-reported spend, account-balance observations and evidence freshness. `-1` means no CrownThrive local monthly ceiling; it never means a provider cannot throttle, bill or enforce account terms. Adserver.Online overage does not trigger an automatic CrownThrive delivery stop under the current founder policy.

## CrownLytics JSON ingest skill

Stages JSON in a restricted, forced-RLS intake plane before any provider dispatch. Each batch receives a payload SHA-256, schema fingerprint, duplicate check, secret-signal scan, privacy-signal scan and immutable receipt. Secret-shaped inputs fail closed to quarantine. Provider dispatch is off by default. Evidence Quality and Data Protection scoring may be composed for internal readiness, but the score cannot waive privacy/credential/provider gates.

## Quarantined adversarial security skills

Red, Blue and Purple operate only inside `synthetic_fixture`, `isolated_replica`, `policy_model` and `sanitized_config_snapshot` targets. The lab has no external-network authority and no production-write authority. Findings and patch candidates are restricted; public documentation may state only sanitized remediation status.

Red attempts bounded control failures. Blue proposes containment/patches. Purple independently reproduces and verifies. Originators cannot self-verify. A six-hour invariant heartbeat verifies the quarantine contract itself without touching production or external networks.
