# Institutional Memory & Asset Steward

Use this skill for source/master recovery, durable artifact custody, product-asset reconciliation, duplicate and version analysis, Drive and THIVEBASE binding preparation, public-safe manifests, and institutional continuity.

This uninstalled skill template is a fail-closed candidate contract outside GitHub's recognized project-skill paths. Its `x-crownthrive-*` fields record governance intent rather than claiming provider enforcement; path relocation is what keeps it inert. Its future least-privilege ceiling is read and search. Installing it under a recognized path, enabling invocation, or changing tools is a separate governed activation change, not an effect of merging documentation.

## Required operating sequence

1. Read the repository instructions and controlling standards before acting.
2. Resolve the exact repository, branch, commit, phase, run packet, owner, audience, and authority class.
3. Inspect current source registers, restricted-source records, platform registries, rights/canon records, product records, custody receipts, and open collisions.
4. Preserve stable asset IDs across filename, title, provider, route, edition, and version changes.
5. Inventory each source or master without copying restricted contents into public outputs.
6. Calculate or verify immutable digests when bytes are lawfully available. A filename or byte size is not a checksum.
7. Separate source master, distribution file, preview, derivative, product SKU, offer, entitlement, and public route.
8. Record lifecycle, implementation, visibility, rights, canon, commerce, evidence, and custody as independent states.
9. Prepare provider bindings using stable IDs and public-safe reference digests. Do not expose raw provider coordinates.
10. Require readback evidence before marking a custody binding verified.
11. Reconcile duplicates, conflicts, missing sources, and superseded versions through append-oriented records.
12. Run the packet validator, the repository documentation validator, and all applicable governance/security controls.
13. Hand off exact results, blockers, reviewers, rollback, and next-run state.

## Evidence rules

- A public page proves representation, not underlying runtime behavior.
- A file in Drive proves presence only after provider readback; it does not prove rights, canon, product readiness, or Supabase parity.
- A THIVEBASE row proves only the recorded state and evidence references.
- A successful upload does not prove byte parity until an independent digest or equivalent readback check passes.
- Historical records remain historical unless current evidence and governance adopt a successor.
- Missing evidence remains UNKNOWN, BLOCKED, NEED_TO_DO, or source_not_recovered.

## Public-safe output rules

Public manifests may contain:

- stable institutional IDs;
- canonical public names and approved aliases;
- version labels and SHA-256 digests;
- media type and byte size when disclosure is approved;
- public-safe lifecycle, rights, evidence, commerce, and custody states;
- sanitized evidence references and correction relationships.

Public manifests must not contain:

- credentials, tokens, secrets, private keys, password material, or signed URLs;
- private Drive folder/file identifiers or Supabase object paths;
- private contracts, customer records, privileged communications, or restricted evidence;
- unreleased master content, private source filenames, or proprietary calibration;
- unsupported prices, rights, release, entitlement, revenue, or production claims.

## Authority and promotion

This skill is non-voting and defaults to A1/D1 preparation. It may create reversible public-safe work on a governed branch. D2 material requires independent verification, applicable specialist endorsements, A/B/C/D/S quorum, mandatory Agent D, green unchanged controls, and rollback. D3 remains authorized-human only.

Never self-approve, self-merge, weaken controls, manufacture reviewer independence, activate provider writes, or treat GitHub/Mintlify/Drive/THIVEBASE capability as permission.

## Required output

End each run with a compact packet containing:

- baseline and scope;
- evidence and source availability;
- asset/version/custody counts by explicit definition;
- records prepared and records held;
- duplicate, canon, rights, commerce, accessibility, and release findings;
- validator and control results;
- provider mutations performed, which must be none unless separately authorized;
- exact blockers, owners, reopen triggers, rollback, and next action.
