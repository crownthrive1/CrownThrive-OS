## Supplied Admin API operations

- **Users:** retrieve all/one, create, update, delete, generate one-time login code.
- **Plans:** retrieve all/one.
- **Payments:** retrieve all/one.
- **Domains:** retrieve all/one, update, delete.

Other Admin UI modules are UI observations only unless an API operation is separately evidenced.

## Risk boundary

User reads are D1; plans/domains reads are D0; payment reads are D1. User/domain mutations are D2. One-time login generation is D3. All are disabled; D2/D3 actions require explicit governed approval.

The `v61.0.0` notice is an available-update observation, not installed-version proof. Under the standing highest-known-version rule, `v61.0.0` is nevertheless the **documented and staged upgrade target now**. CrownThrive intends to update CrownPulse to that highest known version. Production mutation remains fail-closed until the current installed version, migrations/customizations, runtime requirements, license/support prerequisites, backup checkpoint, compatibility validation and rollback path are verified.

## Credential blocker

The founder supplied the current key, but the connected secure-write layer rejected direct Vault insertion before persistence. Planned aliases are `crownpulse_admin_api_key` and `crownpulse_admin_api_key_recovery`. Do not bypass this control by encoding or committing the key.
