## Canonical scheduler architecture

CrownThrive no longer requires a separate external ChatGPT clock for each logical agent.

```text
external clocks
├─ CrownThrive External Evidence Relay
├─ CrownThrive Communications Watch
├─ CrownThrive Daily Backup & Continuity
└─ CrownThrive Maintenance Coordinator   # temporary while maintenance remains open

internal execution fabric
├─ ThriveBase / CHLOM agent identities
├─ governed owner/verifier work packets
├─ pg_cron for database-native recurrence
├─ Mintlify workflows for documentation recurrence
└─ bounded internal subroutes / specialist identities
```

After maintenance closes, the normal external-clock target is **three**: external evidence relay, communications, and backup/continuity. The maintenance coordinator is a temporary separate failure domain and is not part of the normal post-maintenance target.

### External Evidence Relay

The previous Vendor Engine Watch dispatcher identity is retained for lineage but its scheduler role is now **CrownThrive External Evidence Relay**.

Canonical schedule:

```text
ct.schedule.external-evidence-relay.hourly.v1
hourly at minute 17
```

The relay is a connector-capable dispatcher only. It queries the governed schedule registry and executes compatible due subroutes under their own agent identities, authority ceilings and evidence contracts. A shared clock does not combine agent authority, votes or certification roles.

### Communications failure domain

**CrownThrive Communications Watch** is the single external communications clock. It folds founder attention, inbound sales/lead triage and nurture, and—after the commercial/outbound reactivation wave—eligible Locticians outreach. During targeted maintenance it is read-only for founder-attention and urgent inbound alerts.

### Database-native work

Database-native recurring work belongs to `pg_cron`; a new external ChatGPT task is not created merely to wake a database function.

### Documentation recurrence

Documentation drift, link integrity and founder-context reconciliation are already scheduled through Mintlify workflows and do not consume external ChatGPT task slots.

## Retired scheduling scaffolding

The execution identities remain institutional assets. Agent A, B, C, D, E, F, G, H, S and other specialist roles were not deleted or collapsed. Their old external clocks remain disabled while their work is routed through the canonical execution fabric.

## Security boundary

The new topology and receipt tables use RLS + FORCE RLS and have no direct `anon`, `authenticated`, or `service_role` read grants. The public-name status wrapper is also not executable by those roles. Runtime inspection is intentionally through governed internal control paths.
