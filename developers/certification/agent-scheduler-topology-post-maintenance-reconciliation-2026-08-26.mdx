## Agent Scheduler Topology Post-Maintenance Reconciliation — 2026-08-26

## Current decision

The production scheduler remains `ct.scheduler-topology.production.v1`. ThriveBase is runtime-authoritative. This reconciliation updates source-controlled projection to the **post-maintenance** topology rather than rewriting the original August 24 certification.

```text
runtime topology semantic version   1.2.0
maintenance                         CLOSED
external clock target               2
external failure domain #1          CrownThrive External Evidence Relay
external failure domain #2          CrownThrive Communications Watch
backup clock                        internal pg_cron
backup connector work               subroute of External Evidence Relay
maintenance coordinator             RETIRED_SCHEDULING_SCAFFOLDING
legacy one-agent-one-clock model     RETIRED_SCHEDULING_SCAFFOLDING
```

The scheduler clock creates no authority. D3 remains human-reserved. No topology change authorizes provider writes, money movement, rights, entitlements, checkout, credential export, sovereign voting, or phase advancement.

## Why this reconciliation exists

The August 24 source projection still described the maintenance-era topology and a normal three-clock target. ThriveBase subsequently closed targeted maintenance and converged backup continuity so that midnight due generation and dedupe are owned by `pg_cron`, while the connector-only Google Drive portion is serviced by the canonical External Evidence Relay. The dedicated backup ChatGPT clock remains retired.

The current external topology therefore has two clocks, not three:

```text
External Evidence Relay
└─ due connector-only logical subroutes
   ├─ midnight backup Drive evidence/readback/restore when a ThriveBase job is due
   ├─ vendor/provider evidence that cannot run internally
   └─ other explicitly bound connector-only duties

Communications Watch
└─ email/communications connector failure domain
```

Everything compatible with ThriveBase, pg_cron, queues, PentaFactory/PentaBuild, framework software, GitHub Actions, Mintlify workflows, Edge Functions, or another production-native executor stays internal.
