# Gen-6 Skill Factory, Telemetry & MCP Contract

Generation 6 treats repeated agent procedures as versioned institutional assets. A skill is a capability package, not an authority grant.

## Candidate lifecycle

`observed_repeat -> extracted -> sanitized -> tested -> independently_verified -> fingerprinted -> registered -> mcp_candidate -> governed_active`

A candidate cannot skip independent verification, fingerprint, classification or authority binding.

## Skill manifest minimum

Every skill version must carry:

- stable skill ID and install name;
- semantic version and supported agent generation(s);
- owner and a distinct verifier;
- parent/template/task authority ceilings;
- allowed and forbidden capabilities;
- public/restricted classification;
- exact source/evidence references;
- positive and negative tests;
- deterministic manifest digest;
- CHLOM subject and version fingerprint;
- DAIL creation/supersession lineage;
- rollback/revocation behavior;
- API/MCP exposure state;
- commercial state separated from runtime state.

## First-class telemetry contract

Every live Gen-6 packet uses the lifecycle:

`planned -> running -> verifying -> done | blocked`

with `cancelled` and `superseded` as explicit terminal alternatives.

The restricted telemetry layer records cycle ID, packet, agent, role, state, progress, work units, owner/verifier heartbeat, exact PR/head where applicable, blocker baseline/current values, blocker codes, unlock condition, retries, collisions, no-op suppressions and timing.

Cycle roll-up records WIP utilization, packets started/verifying/done/blocked, packets closed per hour, blocker burn-down, review wait, verification time, total cycle time and throughput by agent.

Canary/replay records are segregated from live throughput. The initial telemetry canary passed `planned -> running -> verifying -> done` with Agent L as owner and Agent N as the different verifier.

## MCP surface

Generation 6 prepares these public-safe logical operations. Provider transport and production exposure remain separately certified.

- `gen6.priority.evaluate` — priority band, dispatch eligibility and reason codes; no protected weights.
- `gen6.portfolio.plan` — bounded non-colliding packet set plus owner/verifier assignments.
- `gen6.homepage.reconcile` — material-delta/no-change decision and affected public-safe surfaces.
- `gen6.cadence.propose` — WIP/cadence/schedule-change candidate; does not mutate a task.
- `gen6.skill.evaluate` — determines whether a repeated procedure is a skill candidate.
- `gen6.skill.register_candidate` — registers a fingerprinted candidate only; cannot activate it.
- `gen6.skill.instantiate` — creates an ephemeral scoped execution identity from an accepted template; no vote inheritance.
- `gen6.cie.advisory` — eligible artifact/use/context advisory; cannot score people or override a hard block.
- `gen6.schedule.election.prepare` — future Schedule Governor election preparation only.
- `gen6.schedule.apply_authorized` — future receipt-bound schedule mutation; remains disabled until constitutional acceptance.

All ten remain disabled/specification-only MCP contracts unless separately certified. The new controlled-test runtime functions are internal THIVEBASE capabilities and are not equivalent to production MCP exposure.

## CHLOM adjudication API contract

The restricted runtime supports bounded adjudication functions for:

- opening a typed disagreement;
- submitting independently attributable agent/oracle positions;
- calculating confidence and disagreement;
- returning a disposition candidate;
- automatically resolving only eligible low-risk D0/D1 consensus;
- routing D2 to independent governed resolution;
- routing D3 or qualified-professional scopes to humans;
- escalating unresolved disagreement after a bounded round limit.

The adjudication oracle is non-sovereign. It cannot create votes, legal truth, rights, certification or D3 authority.

## Authority inheritance

For an instantiated skill agent:

`effective_authority = min(parent_authority, template_authority, task_authority, current_policy_ceiling)`

Vote eligibility is independently governed and never inherited. D3 is human-reserved. Skills cannot merge, pay, sign, grant rights, rotate credentials, publish protected data, certify their own work or mutate external schedules merely by being installed.

## Fingerprint and supersession

A changed skill body creates a new version and new fingerprint. The previous version remains queryable and may be marked superseded or revoked; it is never silently rewritten. Fingerprints establish byte/version integrity only and do not establish authorship, ownership, legality, accessibility, security certification or commercial approval.

## Commercialization boundary

Reusable public-safe skills may later become licensed support packs, MCP capability packs, training, implementation services or managed-governance offers. That is a separate commerce lifecycle. No price, checkout, entitlement or customer license becomes active from skill registration alone.
