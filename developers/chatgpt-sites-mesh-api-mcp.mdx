A site loader requests its manifest using a stable `surface_id` and validates:

```json
{
  "contract": "ct.site-mesh-loader.v1",

```

The manifest supplies the current public-safe binding, peer, communication, catalog, and ThriveEvergreen projections. Site source must not hard-code the fleet size, peer inventory, products, prices, entitlements, or protected module implementations.

## Public telemetry

Public telemetry is schema-limited, origin-checked, idempotent, rate-controlled, and non-authoritative. It must not include credentials, access tokens, customer content, payment data, private rights evidence, or restricted operational evidence.

A telemetry receipt is evidence of an observation only. It cannot approve a release, activate an offer, create entitlement, move money, or manufacture authority.

## ThriveEvergreen boundary

Every price, SKU, checkout, paid CTA, booking, entitlement, settlement, payout, or public economic-performance claim must resolve through ThriveEvergreen:

```text
ECAC | HOLD | DENY
```

A feed row, provider response, storefront appearance, Stripe object, or successful API call is not an ECAC decision.

ThriveEvergreen may optimize within authority. It may never manufacture authority.

## Security and authority boundaries

- Never embed a Supabase service-role credential or provider secret in browser code.
- Public manifests expose capability projections, not restricted implementation bodies.
- Existing site publicity and sign-in settings remain unchanged unless separately authorized.
- Native source changes require exact pre-state, rollback reference, write, readback, rollback verification, and exact reapply.
- D3 remains human-reserved.
- Agents cannot self-approve.
- Native Site or project deletion is not granted.
- Provider success is not institutional authority.
