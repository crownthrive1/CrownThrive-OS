# ChatGPT Sites Mesh API & MCP

CrownThrive operates a governed mesh for registered ChatGPT Sites surfaces. The mesh centralizes site identity, peer discovery, module/pallet/agent bindings, governed catalog feeds, non-authoritative telemetry, and privileged planning/control without treating provider access as institutional authority.

<Warning>
  The mesh does not create native ChatGPT Sites provider-write authority. Native source or layout changes remain project-scoped, exact-version, rollback, and read-after-write gated. Destructive provider deletes are not granted by this contract.
</Warning>

## Privileged MCP/API control

Privileged requests require a legitimate founder/super-admin session, a governed server-side scoped principal, or another accepted backend identity. Browser code must never contain service-role credentials or provider secrets.

Current MCP target protocol: `2026-07-28`.

Available tools:

- `sites.list`
- `sites.get`
- `sites.mesh.get`
- `sites.bindings.list`
- `sites.peers.list`
- `sites.routes.list`
- `sites.install.plan`
- `sites.update.queue`
- `sites.binding.set`

`sites.update.queue` creates an internal D0-D2 work request only. It does not itself mutate ChatGPT Sites. Deletion, money movement, payout/transfer, credential revocation, rights grants, and D3 actions cannot be queued through this tool.

## Routine automation after bootstrap

The intended source architecture is a one-time generic loader plus durable remote control:

```text
ChatGPT Site
  -> Sites Mesh manifest
  -> governed module/pallet/agent bindings
  -> governed catalog feed
  -> peer-site links
  -> CrownThrive Services Stack / CHLOM APIs
  -> ThriveEvergreen economic gate where economic state is involved
  -> non-authoritative telemetry
```

After the generic loader is installed and read back on a site, routine governed product/catalog and compatible module-state updates can be delivered centrally without editing that site's source for every change. Native visual/layout/source changes still require a certified native provider-write route.

## Security and authority boundary

The mesh is preservation-first and non-sovereign:

- no browser/service-role secret embedding;
- no self-approval;
- no silent deletion of evidence or source history;
- no direct money movement or final rights grant;
- no D3 automation;
- no native Sites project/source deletion authority;
- no direct-main write authority;
- service/agent principals do not impersonate the founder;
- independent readback is required after consequential writes; and
- public telemetry cannot manufacture authority.
