## Use this matrix

<Steps>
  <Step title="Find the stable platform or capability ID">
    Match the intended integration to the institutional identity, including parent/child and framework/implementation relationships.
  </Step>
  <Step title="Read the verified present state">
    Distinguish public reachability, source lineage, provider documentation, authenticated reads, controlled tests, and production monitoring. They are not interchangeable.
  </Step>
  <Step title="Apply the API or adapter state">
    Use the vocabulary below as the current ceiling. A direction column describes intended integration, not available operations.
  </Step>
  <Step title="Collect the missing evidence">
    Follow the row's evidence requirement through authorized discovery. Record exact environment, contract, auth, data, side effects, failures, tests, owner, and timestamp.
  </Step>
  <Step title="Update by exact scope">
    Promote only the interface and operation that passed. Keep unrelated reads, writes, webhooks, providers, and environments at their prior state.
  </Step>
</Steps>

## Status vocabulary

- `none_known` — no interface has been identified;
- `uninspected` — platform/engine exists but interfaces have not been inspected;
- `public_routes_only` — public web routes are verified; no API contract is verified;
- `vendor_api_candidate` — underlying vendor appears to offer an API, but CrownThrive account/version/scopes are not verified;
- `native_api_discovered` — interface/docs located but not authenticated or tested;
- `adapter_specified` — CrownThrive adapter contract is defined but not implemented;
- `sandbox_tested` — authorized non-production integration passed tests;
- `certified` — contract, auth, security, data, events and failure tests passed;
- `production_monitored` — live integration has health, version, incident and recovery evidence;
- `blocked` — legal, security, vendor or technical constraint prevents current integration;
- `deprecated` — replacement/migration exists.

## Interface ownership rule

The platform owning the user experience does not automatically own every institutional record. For example:

- Stripe remains authoritative for processor payment objects; CrownThrive owns the order, entitlement and rights relationship.
- A hosted reader may own reader-session state; CrownThrive owns the edition, license and customer entitlement.
- A social/community engine may own its local profile; CrownThrive ID owns the durable institutional account-link and role context.
- An analytics provider may calculate traffic; CrownThrive's claim registry controls approved public wording and effective period.

## Certification gates

A platform moves to `certified` only when all of the following are true:

- owner/provider and exact version are known;
- documentation and base URLs are recorded by environment;
- authentication, scopes and tenant/relationship checks work;
- data classification, purpose and retention are approved;
- endpoints/events/webhooks are versioned;
- idempotency, retries, replay and partial-failure behavior are tested;
- security, privacy, rights and legal dependencies pass;
- synthetic/sandbox tests pass;
- monitoring, incident, export and vendor-exit paths exist; and
- DAIL records the certification and expiry/review date.

<Info>
  Certification belongs to an exact interface, operation set, environment, contract version, evidence packet, and review period. It does not automatically promote the whole platform or its provider account.
</Info>
