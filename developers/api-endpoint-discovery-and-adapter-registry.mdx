# API Endpoint Discovery and Adapter Registry

Phase 2.98 and Phase 3 require a verified integration inventory. A marketing page that says “API available” is not sufficient; each interface must be inspected, tested where authorized and classified.

## Discovery sources

For each platform inspect, as applicable:

- official vendor/product documentation;
- repository routes/controllers/OpenAPI/GraphQL schemas;
- network/service configuration;
- admin integration settings;
- existing webhooks and callback URLs;
- Postman/Insomnia collections;
- SDK/package manifests;
- WordPress REST routes and custom plugins;
- database/export capabilities;
- feeds, CSV/SFTP, RSS/Atom, webhooks and email ingestion;
- current CrownThrive source files and prior build records;
- live health/version endpoints.

Do not probe private systems without authorization. Unknown stays `unverified`.

## Endpoint record

Every endpoint/tool should identify:

- method and templated path;
- purpose;
- audience;
- auth/scopes;
- input/output schema versions;
- data classes;
- side effects;
- idempotency behavior;
- rate limits;
- error states;
- webhook/event emissions;
- approval/autonomy class;
- environment availability;
- deprecation date;
- test evidence.

## Canonical CHLOM baseline endpoints

The technical build pack includes baseline families such as:

- entitlement verification;
- provider webhook intake;
- dispute creation and evidence submission;
- governance proposal submission;
- scoped audit-event querying;
- webhook endpoint registration.

These source specifications are baselines for implementation, not proof that the endpoints are live.

## Adapter classes

- **native** — supported first-party platform API;
- **vendor** — supported SaaS/vendor API;
- **webhook** — event-driven callback integration;
- **database** — controlled direct access, generally internal only;
- **feed/export** — file/feed integration;
- **browser-assisted** — temporary authorized automation when no supported API exists;
- **manual** — documented human process pending automation;
- **deprecated** — replacement exists;
- **blocked** — technical/legal/security constraint prevents integration.

## Support levels

`uninspected → discovered → documented → authenticated → sandbox_tested → integration_tested → certified → production_monitored`

## Base URL rules

- separate environment URLs;
- never publish private/internal base URLs publicly without purpose;
- canonicalize trailing slash/version behavior;
- record DNS/TLS ownership;
- use major URI versions for public contracts where adopted;
- do not encode secret keys in URLs;
- maintain health and deprecation metadata.

## Webhook registry

Collect endpoint owner, signing secret reference, event types, provider account, replay behavior, idempotency, retry/dead-letter policy, ordering assumptions, payload version, data class and last successful delivery. Old webhook endpoints must be disabled only after dependency checks.

## Generated developer docs

Where OpenAPI/GraphQL/schema sources exist, generate docs and SDKs from authoritative contracts. Handwritten guides should explain workflows and policy; they must not diverge from schemas.
