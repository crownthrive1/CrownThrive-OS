## Platform outcome

The Developer Platform is the governed engineering surface for CrownThrive's convergent ecosystem. It exists so each new platform can integrate through stable identity, events, APIs, rights, permissions, commerce and observability contracts instead of inventing a new integration model.

## Contract and current-state matrix

| Layer | What this page establishes | What remains interface-specific |
| --- | --- | --- |
| Identity | CrownThrive ID is the target durable identity and role broker | Issuer, client registration, claims, scopes, token lifetime, MFA and recovery |
| API/MCP | CrownThrive IO routes governed APIs, tools and adapters | Exact base URL, protocol/version, operations, schemas, authentication and limits |
| CHLOM | Rights, rules, roles, revenue, records and remedies are required touchpoints | Executable service contract, deployment, authorization and acceptance evidence |
| Commerce | Economic operations require the current commerce authority and entitlement controls | Approved SKU, price, checkout, provider, tax, license, settlement and ECAC state |
| Platform interface | Every platform receives a capability profile | Whether its current interface is native, vendor, adapter, webhook, batch, internal MCP, or unavailable |
| Events | Consequential changes require versioned events and delivery evidence | Exact topics, payloads, signing, retry, replay, ordering and retention |
| SDK and sandbox | Contract-first clients and safe fixtures are the target | Published packages, supported versions, test credentials, quotas and compatibility |

<Info>
  **Environment rule:** production, staging, sandbox, provider test mode, and local fixtures must remain separate records. No environment is implied by a brand name or route family.
</Info>

## Source-backed baseline

Recovered CrownThrive Help Center material explicitly included **Developer Toolkits**, **REST/GraphQL APIs**, **Rate Limits & Throttling**, **SDK Quick-starts**, **Sandbox & Test Keys**, and **Webhooks & Events**. CHLOM research also envisioned JavaScript, Python, Solidity and REST developer tooling. The current 2026 build posture modernizes that foundation into an API-first, modular and human-governed system.

## Core developer layers

1. **CrownThrive ID** — canonical identity brokerage, roles, consent, eligibility and profile links.
2. **CrownThrive IO / MCP** — API gateway, tool routing, adapters, metering and AI-agent connectivity.
3. **CHLOM** — rights, rules, roles, revenue, records and remedies.
4. **PentaGreen** — mandatory commerce/economic activation contract for assets, SKUs, offers, pricing, AdLuxe, payments, licenses, entitlements, fulfillment, settlement and reconciliation.
5. **Platform APIs** — first-party or vendor-backed interfaces for each platform.
6. **Event layer** — canonical event contracts and webhook delivery.
7. **Developer Portal** — applications, credentials, docs, environments, usage and support.
8. **SDK layer** — typed clients and reference examples generated from canonical API contracts.
9. **Sandbox** — non-production credentials, fixtures, mock providers and safe integration testing.
10. **Observability** — request IDs, audit events, rate usage, errors, status and change history.

## Integration rule

A platform does not need a custom public API on day one. Each platform receives an **API capability profile**:

- native API available;
- vendor API available;
- first-party adapter available;
- webhook-only integration;
- batch/import-export integration;
- internal MCP tool only;
- no integration yet.

As a platform matures, its profile can move forward without changing its stable platform ID.

## Authentication and permissions

There is no ecosystem-wide credential described by this page. Each interface record must name its own authentication mechanism, service identity, scopes, tenant boundary, token/credential storage, rotation path, and re-authentication requirements. Browser code must not contain provider secrets or server-side credentials.

For identity integrations, use [SSO, CrownThrive ID and Social Identity Bridge](/developers/sso-identity-bridge). For agent-facing operations, apply the [MCP topology and tool-boundary architecture](/technology/mcp-topology-and-tool-boundaries). Technical reachability does not grant institutional authority.

## Minimum platform integration contract

Every integrated platform should eventually identify:

- stable platform ID;
- current lifecycle and deployment state;
- auth/SSO method;
- API base/version or adapter;
- scopes and roles;
- event topics;
- webhook contract;
- rate limits;
- data classification;
- rights/CHLOM touchpoints;
- PentaGreen commerce/ECAC/SKU/entitlement/AdLuxe touchpoints;
- support owner;
- sandbox/test method;
- deprecation policy;
- current schema and API version.

## Phase 3 relationship

Phase 3 Sprint 0 establishes IDs, schemas, authority, events and environment rules. The Developer Platform then becomes the controlled external/internal surface over those services. It should expose governed capability—not unrestricted database access.

## Errors, testing, and support boundary

No shared error envelope, retry schedule, pagination contract, idempotency header, webhook signature, or service-level commitment is established here. Builders must take those details from the exact interface contract and stop when they are absent.

| Situation | Required action |
| --- | --- |
| Base URL, auth, schema, or environment is missing | Keep the interface `unverified`; do not construct a request from naming conventions |
| A request has an unknown mutation outcome | Do not replay blindly; preserve evidence and open an integration delta |
| Provider documentation conflicts with observed behavior | Record both sources and keep certification or write promotion on hold |
| Customer, rights, payment, identity, or restricted data is involved | Require the applicable security, privacy, rights, and authority review |
| A page claims more than its cited contract proves | Use the [support request workflow](/workflows/support-request) and documentation correction path |
