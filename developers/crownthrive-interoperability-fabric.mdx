# CrownThrive Interoperability Fabric

**State:** CONTROLLED TEST / GOVERNED HOLD  
**Plugin ID:** `ct.plugin.crownthrive-interoperability-fabric`  
**MCP server ID:** `ct.mcp.crownthrive-interoperability`  
**Archetype:** tool-only  
**Public submission:** not submitted  
**Provider writes:** disabled  
**Checkout and entitlements:** disabled

The CrownThrive Interoperability Fabric is the governed contract, plugin, adapter, and route-planning layer that allows CrownThrive platforms, services, websites, repositories, agents, and future customer installations to exchange public-safe structured data without transferring credentials or protected implementation.

The first release is deliberately **tool-first**. A widget is optional future work after the MCP/tool contract is stable. This follows the current OpenAI plugin architecture: an MCP server supplies live data, authentication, and controlled tools; focused tools use explicit schemas and accurate annotations; interface work remains separable from the server contract.

## Operating model

The controlled path is:

`stable identity -> canonical contract -> exact-version binding -> compatibility check -> route plan -> negative/privacy/idempotency/rollback tests -> independent verification -> controlled-test route -> separately governed activation`

A compatibility score or route plan does not activate an integration. It does not create a provider write, credential, entitlement, price, sovereign vote, D3 authority, or direct-main merge.

## Root tools

| Tool | Purpose | Authority |
| --- | --- | --- |
| `search` | Search plugins, contracts, routes, and services | read-only D0 |
| `fetch` | Fetch one stable resource by exact ID | read-only D0 |
| `interop.status` | Read sanitized fabric status | read-only D0 |
| `interop.compatibility.check` | Determine whether two packages can exchange one contract | read-only D1 |
| `interop.route.plan` | Produce a non-executing route plan and reliability score | read-only D1 |
| `plugins.list` | List truthful package lifecycle states | read-only D0 |
| `plugins.get` | Read one package manifest, bindings, and pricing candidates | read-only D0 |
| `plugins.install.plan` | Generate a non-executing installation plan | read-only D1 |
| `plugins.package.validate` | Validate package identity, tests, and governance boundaries | read-only D1 |

The root tools are intentionally non-destructive and idempotent. They do not expose private identity mappings, raw credentials, service-role keys, protected algorithm weights, private field maps, or protected source.

## Protected scoring

Two public-contract/restricted-implementation algorithms support the fabric:

- `ct.alg.gen7.icrs` — Interoperability Contract Readiness Score;
- `ct.alg.gen7.arrs` — Adapter Route Reliability Score.

Their exact weights, bands, calibration, and private features remain in Supabase Vault. Public callers receive only sanitized scores, bands, reason/blocker classes, and immutable digests. Scores are evidence aids, not authority.

The first Squarespace-to-CrownLytics product-contract assessment produced:

- ICRS: 90.6 / Band A / compatibility PASS;
- ARRS: 86.5 / Band A / verified route candidate;
- provider write performed: false.

The AdLuxe-to-CrownLytics campaign route correctly remained HOLD while its provider authentication and source binding are not certified.

## Security and governance

The Edge Function requires JWT/admin authorization. Database operations execute through restricted service-role RPCs behind the server. The public tool layer is read-only.

Hard invariants:

- no raw credentials or private keys;
- no protected implementation or scoring weights;
- no private identity mapping;
- no D3 automation;
- no sovereign-vote effect;
- no direct-main merge;
- no provider write from a route plan;
- no live checkout or entitlement;
- no silent deletion;
- provider rate limits, billing, quotas, and account plans remain authoritative.

The canonical local request-budget sentinel is `-1` for no CrownThrive local monthly ceiling and `0` for disabled. This never overrides a provider's own limits or charges.
