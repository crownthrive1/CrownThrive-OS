# CHLOM Agentic Foundry Production Activation

This runbook is executed by the existing `ct.maintenance.coordinator.sol` lane after the targeted-maintenance release evaluator permits the applicable reactivation wave. It does not authorize early activation.

## Preconditions

Require all of the following before mutation:

- maintenance release permits the foundry's execution wave;
- exact current `crownthrive1/CrownThrive-CIE` main contains the accepted `chlom_agentic_foundry_production_v1.sql` migration or its governed successor;
- exact-head CHLOM Agentic Foundry Governance CI is green;
- Framework Child Governance and applicable interoperability/security governance are green on that exact head;
- current Support/Mintlify public-safe contract is not contradictory;
- DAIL integrity is current;
- no newer source supersedes the accepted package;
- no duplicate external scheduler is required or created.

If any predicate is missing, stale or contradictory, remain HOLD.

## Apply

Apply the exact source-controlled migration through the governed Supabase migration path. Do not reconstruct SQL from this public runbook and do not copy a protected migration body into ordinary documentation or Drive.

Immediately second-read the runtime before any downstream foundry operation.

## Required positive readback

Confirm:

- `public.chlom_agentic_foundry_status_v1()` resolves the expected system/version;
- exactly seven active foundry planes exist;
- at least thirteen active reusable sidecar classes exist;
- the foundry suite is active, non-voting, non-quorum and D3-reserved;
- the foundry steward agents exist at D2 maximum;
- Vault alias `chlom_agentic_foundry_control_v1` exists without returning its value;
- protected control asset `ct.package.chlom-agentic-foundry.control.v1` exists with body exposure disabled;
- the eight foundry skill packages are registered;
- plugin `ct.plugin.chlom-agentic-foundry.v1` is internal and non-commercial;
- six foundry MCP tools are enabled on the intended internal MCP surface;
- `ct-chlom-agentic-foundry-30m` is active at minutes 11 and 41;
- connector-heavy foundry work reuses the existing CrownThrive External Evidence Relay;
- no additional ChatGPT recurring scheduler was created.

## Negative tests

The activation is not certified until the following fail closed:

1. request a D3 patch candidate -> `HOLD/DENY`, no candidate authorized for apply;
2. request recursive sidecar spawning -> `DENY`, no child-of-sidecar depth expansion;
3. set parent/originator equal to independent verifier -> `HOLD`, no self-certification;
4. use inactive execution host for an independent sidecar -> `HOLD`;
5. request protected asset candidate with invalid digest -> `HOLD`;
6. inspect public/MCP status -> no raw secret, mnemonic, private key, Vault body or protected implementation body;
7. verify sidecar classes -> vote false, quorum false, authority inheritance false, external scheduler false;
8. verify patch candidates -> default `apply_authorized=false`;
9. verify provider-write/money/rights/credential effect flags -> no automatic authorization;
10. verify RLS/FORCE-RLS and client-role denial on internal foundry tables/functions.

## Stress test

Run `chlom_runtime.agentic_foundry_stress_test_v1()` at least twice without state mutation. Require `PASS` and an identical deterministic evidence digest for unchanged state.

After a controlled state change, rerun and require the new digest to reflect the changed state while all invariants remain PASS.

## PatchPilot apply boundary

A patch candidate is not permission to apply it. Application may proceed only when the candidate's exact snapshot, tests, security review, rollback probe, independent verification and ordinary target-specific authority all pass.

D3 is always human-reserved. Provider writes, money movement, rights/entitlements and credential changes remain governed by their own narrower contracts even when the foundry produced the patch.

## AssetForge boundary

AssetForge may create and route protected candidates. It may not manufacture ownership, rights provenance, patent status, final publication authority, public pricing, checkout, entitlement or settlement.

Protected implementations remain Vault/restricted-custody material. Public documentation may expose stable identity, version, public-safe contract and hashes where approved.

## Final certification

Append exact runtime evidence to the foundry receipt ledger and DAIL. Reconcile the public-safe certification from:

`PASS_PACKAGE / HOLD_MAINTENANCE_RUNTIME`

to:

`PASS_PRODUCTION_RUNTIME`

only when every positive and negative predicate above is proven on the exact activated version.

Do not close or otherwise alter the broader maintenance event merely because this foundry activation passes; the maintenance event has its own institution-wide release contract.
