# CHLOM Wallet independent review contract

**State:** `HOLD_REVIEWER_HEARTBEATS_AND_RECEIPTS`  
**Phase:** 2.99  
**Originator:** `ct.agent.chlom-wallet-settlement`  
**Originator final approval:** prohibited  
**Deployment and broadcast authority:** none

CHLOM Wallet separates evidence construction from independent review. The Wallet Agent may build and freeze the technical packet, but it cannot refresh reviewers on their behalf, impersonate them, submit their decisions, approve its own runtime codehash, promote the EntryPoint profile, or authorize deployment.

## Receipt acceptance rules

A review receipt is accepted only when:

1. the work ID maps to the exact canonical reviewer and role;
2. the reviewer is not the Wallet Agent or work owner;
3. the agent template exists and prohibits self-approval;
4. the repository binding is active;
5. the DID and public identity digest resolve;
6. the reviewer heartbeat is fresh at recording time;
7. the queue scope matches the registered review lane;
8. the receipt binds to the frozen head and evidence digest;
9. the decision is `PASS_REVIEW`, `HOLD`, or `DENY`;
10. every no-live and no-authority boundary remains false.

The private write contract is:

```text
chlom_wallet.record_independent_review_receipt_v1(...)
```

Receipts are append-only, RLS-protected, and service-role mediated.

## Scheduler hardening

The quarter-hourly construction scheduler evaluates dependencies but does not execute reviewers.

```yaml
job: chlom-construction-queue-quarter-hourly
schedule: '7,22,37,52 * * * *'
fresh_reviewer_heartbeat_required: true
stale_reviewer_forces_waiting: true
scheduler_executes_reviewers: false
reviewer_impersonation_allowed: false
```

This prevents a dependency refresh from moving an independent-review item to `ready` while its designated reviewer is stale.

## Synthesis boundary

The synthesis function can return only:

```text
HOLD_MISSING_INDEPENDENT_RECEIPTS
HOLD_REVIEWER_IDENTITY_OR_HEARTBEAT
HOLD_REVIEW_CONDITIONS
DENY_INDEPENDENT_REVIEW
PASS_INDEPENDENT_REVIEW_RECEIPTS_READY_FOR_PHASE_GATE
```

Even five PASS receipts produce only `PASS_INDEPENDENT_REVIEW_RECEIPTS_READY_FOR_PHASE_GATE`. They do not promote the EntryPoint profile, choose an account implementation or factory, authorize a signer, deploy a contract, broadcast a UserOperation, move funds, grant rights, merge the PR, or enter Phase 3.
