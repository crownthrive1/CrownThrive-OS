# One institution. One governed spine. Many execution lanes.

**CrownThrive Operating System** is the phased institutional knowledge and implementation map for CrownThrive's convergent ecosystem. It connects the portfolio, doctrine, intellectual property, technology, commerce, media, education, community, support, governance, impact, and automation systems into one operating model while preserving distinct brands and specialized platforms.

<Info>
  **Current maturity:** Phase 2.97.1 / machine release `2.7.9.1` accepted and merged into `main` as `52762bd4bd629ea8012fac6ceb3790d0955b0499`. This Mintlify deployment remains a working public-safe review projection. It is not yet the final CrownThrive public Help Center, authenticated institutional portal, private evidence vault or Phase 3 runtime.
</Info>

This knowledge base is built for founders, operators, collaborators, developers, rights managers, publishing teams, support teams, partners, reviewers, and approved automation systems that need to answer five questions consistently:

1. **What exists?**
2. **Who owns, operates, or governs it?**
3. **What state is it actually in?**
4. **What may happen next, under which rights/rules/approvals?**
5. **What evidence proves the decision or outcome?**

<Note>
  This is a **public-safe working projection**. Production credentials, customer records, private contracts, raw evidence, confidential methods, unreleased masters, protected identities, and other restricted material belong in controlled private systems—not in public Mintlify or public repositories. Custom-domain and public/private projection decisions are intentionally deferred to the applicable release gate.
</Note>

## The institutional model

CrownThrive is organized around a shared operating spine rather than a collection of unrelated websites.

```text
Doctrine + Portfolio Stewardship
          ↓
CrownThrive ID
          ↓
CrownThrive IO / MCP
          ↓
CHLOM
          ↓
OpsOasis + Collab Portal
          ↓
CrownThrive Support + Institutional Knowledge
          ↓
CrownLytics + CrownPulse + ThrivePush
          ↓
CrownRewards + Affiliates + Ambassadors + Distribution
          ↓
Operating Corridors and Portfolio Assets
```

The diagram expresses institutional responsibility. It does **not** claim every integration is already complete in production.

## Commerce and execution

CrownThrive uses multiple commerce rails because a personal-use digital download, a subscription, a hosted reader, a creator payout, a service engagement, and a governed commercial license are not the same transaction.

## Source authority

Institutional truth is versioned. When sources disagree, do not pick the newest-looking document or the most confident wording. Use the CrownThrive-wide source authority hierarchy and preserve correction history.

<Card title="Institutional Source Authority Hierarchy" icon="ranking-star" href="/knowledge/source-authority-hierarchy">
  See how current ADRs/registries, verified production evidence, adopted policies, platform state, public statements, historical plans, experimental research, and conversational context are ranked and reconciled.
</Card>

<Warning>
  A product card is not proof of availability. A website sentence is not proof of production functionality. A success redirect is not proof of payment. A purchased script is not automatically a deployable CrownThrive service. A public claim is not automatically audited evidence. A generated file is not automatically a protected right. Every material state must answer to its governing record.
</Warning>
