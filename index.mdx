# CrownThrive OS // Institutional Control Plane

**One institution. One governed spine. Many execution lanes.**

CrownThrive Operating System is not a static help center and not a brochure. It is the public-safe institutional control plane for the convergent ecosystem: a governed projection of what CrownThrive knows, what has been verified, what remains blocked, what changed, who has authority, and what the next execution lane is allowed to do.

## How truth moves

```text
SOURCE PULL / PR / LIVE EVIDENCE / AUTHORIZED DECISION
                         ↓
                 ingest + classify
                         ↓
          authority + freshness + scope
                         ↓
            conflict / drift detection
                         ↓
       macro → corridor → platform → object
                         ↓
      registry + article + policy + changelog
                         ↓
             validation + approval gates
                         ↓
                  governed merge
                         ↓
             post-merge revalidation
                         ↓
       monitoring / correction / self-healing
```

<Warning>
  **No silent promotion.** `unverified`, `not_connected`, `source_not_recovered`, `historical`, `research`, `blocked`, `reserve`, `provider_capability` and similar states do not become `current`, `active`, `deployed`, `licensed`, `integrated` or `production_verified` because a page, vendor document, domain, purchased script, screenshot, redirect, payment or old plan exists.
</Warning>

          ↓
CrownThrive ID
          ↓
CrownThrive IO / MCP
          ↓
CHLOM
          ↓
OpsOasis + Collab Portal

          ↓
CrownRewards + Affiliates + Ambassadors + Distribution

## Every pull updates the institution

A material pull request, connected-source refresh, provider-state verification, domain/API change, pricing change, rights decision, platform release, policy update or revived-source discovery can affect more than the files directly touched. CrownThrive therefore treats propagation as part of the change itself.

For every material change, the workflow determines:

- which stable records changed;
- what source/evidence class supports the change;
- whether current, historical, target, research or unresolved state changed;
- which platform, corridor, framework, rights, economic, legal, security, API/MCP and support records inherit the change;
- which articles and platform changelogs must update;
- whether the homepage control state changed;
- which Phase 2.99 hard-exit criterion or downstream roadmap gate changed;
- whether a migration note, correction, rollback or incident record is required;
- whether the result is `docs_updated`, `docs_no_change` or `docs_delta_opened`.

<Note>
  The homepage is not a decorative exception. When a merged PR or verified source pull changes the current institutional phase, hard-gate posture, major source census, operating-spine claim, repository/ruleset state, accepted roadmap namespace, authoritative platform state or primary navigation path, the homepage becomes a required documentation-impact target.
</Note>

## Evidence over appearance

Institutional truth is versioned. A polished UI does not outrank source authority. A confident model output does not outrank a verified record. A recent timestamp does not automatically outrank an older governing source.

<Card title="Institutional Source Authority Hierarchy" icon="ranking-star" href="/knowledge/source-authority-hierarchy">
  Use current ADRs/registries, verified production evidence, adopted policy, platform state, public statements, historical plans, research and conversational context according to their actual authority and scope.
</Card>

<Warning>
  A product card is not proof of availability. A website sentence is not proof of production functionality. A success redirect is not proof of payment. A purchased script is not proof of deployment. A vendor API page is not proof of CrownThrive account entitlement. A generated artifact is not proof of protected rights. A historical plan is not a current operating fact.
</Warning>
