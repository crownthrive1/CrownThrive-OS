# PENTA Institutional Phase Model

CrownThrive now uses one five-phase institutional lifecycle aligned to the PENTA doctrine:

> **Phase 1 — Discover → Phase 2 — Govern → Phase 3 — Execute → Phase 4 — Verify → Phase 5 — Preserve**

The current institutional generation is **Phase 3 — Execute**.

## Why the phase model changed

Earlier CrownThrive work used increasingly granular transition labels such as Phase 2.5, 2.7, 2.8, 2.9, 2.95, 2.97, 2.98, 2.99, pre-entry convergence, waves, sprints, and workstream-specific phase language. Those labels were useful while CrownThrive was recovering sources, defining governance, rebuilding CHLOM, developing CIE, establishing ThriveBase, reconciling providers, and discovering the eventual autonomous operating architecture.

They are no longer useful as an institution-wide roadmap. A decimal phase can make a transitional implementation detail look like a permanent institutional generation. Different workstreams can invent competing timelines. Historical pages can appear current merely because their numbers look advanced. The result is unnecessary cognitive and operational fragmentation.

PENTA replaces that complexity with a model simple enough to survive new providers, new platforms, new participants, acquisitions, technology replacement, and generational transition.

## Phase 1 — Discover

**Institutional question:** What exists, what matters, and what is actually true?

Phase 1 establishes identity, inventory, source lineage, platforms, providers, assets, participants, risks, dependencies, historical records, contracts, APIs, MCP surfaces, opportunities, and gaps. Discovery separates observed evidence from assumption and desired state from verified state.

Phase 1 is historical as the dominant CrownThrive generation, but discovery remains a permanent PENTA function through PentaDiscover, PentaSearch, PentaQuery, PentaFetch, PentaRead, PentaObserve, CrownLytics, provider scans, repository reconciliation, and PentaDocs.

## Phase 2 — Govern

**Institutional question:** What may happen, under whose authority, and under what conditions?

Phase 2 consolidated rights, rules, roles, evidence, vault custody, CHLOM, CIE boundaries, source-of-truth rules, provider certification, licensing, capability ceilings, D0–D3 risk, security, interoperability, archives, versions, and controlled execution authority.

All earlier decimal Phase 2 institutional labels are now historical aliases of this broader governance generation. They remain evidence, not current roadmap layers.

## Phase 3 — Execute

**Institutional question:** Can CrownThrive perform its work through durable governed software rather than depending on a person or chat to push every action?

Phase 3 is the current generation. It is the operationalization of CrownThrive through PentaRoute, PentaTun, PentaBeata, the wider Penta primitive family, PentaFramework Factory, CrownThrive Software Factory, Penta Federation, PentaMedia, PentaBooks, PentaGeneration, PentaStudios, ThriveBase, CHLOM, CIE, CrownThrive IO, schedulers, queues, provider-native adapters, bounded writes, proof surfaces, publishing, media, commerce, and autonomous self-discovery/certification.

Phase 3 completion requires more than software existence. Priority institutional functions must execute durably; critical capabilities need known ownership; provider mutations need bounded certification; failures must create evidence and recovery work; and execution must generate enough proof for CrownThrive to refactor into an assurance-first Phase 4.

## Phase 4 — Verify

**Institutional question:** Can CrownThrive independently prove that its systems, claims, effects, and authority are correct?

Phase 4 is the future assurance/refactoring generation. It expands independent provider readback, cross-system proofs, conformance, reproducibility, fault injection, red-team testing, resilience drills, rollback verification, economic reconciliation, rights integrity, security attestations, release provenance, certification renewal, and continuous drift detection.

Phase 4 changes the institutional standard from “the operation ran” to “the result, authority, effect, and recovery state are continuously provable.”

## Phase 5 — Preserve

**Institutional question:** Can CrownThrive survive change without losing itself?

Phase 5 is the future continuity and inheritance generation. It treats preservation as more than backups: PentaGeneration, seven-generation stewardship, succession, executable institutional memory, provider exit, repository portability, durable identity, rights custody, archive lineage, knowledge inheritance, data migration, dependency replacement, recovery packages, and long-horizon Cultural Imprint continuity.

## Decimal phase retirement

CrownThrive will not create new institution-wide decimal phases such as Phase 3.1, 3.9, 3.99, or 4.5.

Historical Phase 2.5/2.7/2.8/2.9/2.95/2.97/2.98/2.99 and pre-entry labels remain preserved in releases, archive pages, filenames, branches, migrations, evidence, and changelogs where historically accurate. They are retired only as **current roadmap taxonomy**.

Precision now belongs in the appropriate dimension: OS release, component version, maturity state, certification state, authority class, wave, sprint, cohort, or milestone.

## PENTA is both a lifecycle and a loop

The institution progresses through five dominant generations, but each asset, provider, product, workflow, and participant may continuously run the five PENTA functions inside any phase.

A provider integrated during Phase 3 can still be discovered, governed, executed, verified, and preserved while CrownThrive remains institutionally in Phase 3. The phase identifies the dominant institutional objective; it does not disable the other four functions.

## Forward baseline

**Discover what is real. Govern what is allowed. Execute what is authorized. Verify what happened. Preserve what must outlive us.**

That is the CrownThrive institutional roadmap through Phase 5.
