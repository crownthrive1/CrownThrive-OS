# Commercial Product Release Certification Workflow

```text
packaged product
→ exact inventory and digest
→ rights/license package
→ comparable pricing and tax package
→ accessibility/security package
→ protected fulfillment canary
→ credit checkout + webhook replay canary
→ entitlement/remedy canary
→ DNS/TLS/canonical-route proof
→ ChatGPT Sites publish/readback/rollback/reapply proof
→ exact-digest independent review
→ governed acceptance
→ provider publication receipt
→ monitoring and rollback readiness
```

## State machine

`packaged -> rights_cleared -> pricing_authorized -> fulfillment_certified -> checkout_staged -> publication_staged -> accepted -> live`

A package cannot skip a state. A public preview, ZIP, hash, database row, payment-provider object, CI run or agent score is evidence only.

## Credit-only commerce

The initial cohort redeems Crown Credits. Direct cash checkout for the products remains disabled. Stripe may fund approved closed-loop credits through a separately governed top-up rail, but the product release package does not create Stripe Products, Prices, Checkout Sessions, charges, payouts or transfers.

## Publication transaction

The publication transaction is accepted only when the same exact product and site version completes:

1. write or save provider candidate;
2. provider readback;
3. public route readback;
4. rollback to the bound prior version;
5. proof of rollback/absence;
6. exact reapply; and
7. second provider and public readback.

A transport-level success without application-level readback remains HOLD.

## Independent acceptance

The originating package agent casts no vote. Required specialist reviews are assigned by gate. Sovereign acceptance uses the existing A/B/C/D/S contract: at least four approvals, Agent D mandatory, any current block holds publication.
