# Commercial Product Release Certification Workflow

```text
packaged product
→ exact inventory and digest
→ rights/license package
→ comparable pricing and tax package
→ protected fulfillment canary
→ credit checkout + webhook replay canary
→ entitlement/license canary
→ refund/dispute/rollback canary
→ accessibility/device review
→ DNS/TLS/canonical-route proof
→ exact-digest governance + ChatGPT Sites publication proof
→ accepted release
→ monitoring and rollback readiness
```

## Canonical gate topology

Launch and Procure require these 10 canonical dimensions:

1. `package_integrity`
2. `rights_provenance`
3. `pricing_tax`
4. `private_fulfillment`
5. `credit_checkout_webhook`
6. `entitlement_license`
7. `refund_dispute_rollback`
8. `accessibility_device`
9. `dns_tls_route`
10. `governed_acceptance_publication`

Ready requires those same 10 plus `qualified_professional_review`.

Historical labels including `rights_licensing`, `fulfillment`, `checkout_webhook`, `entitlement`, `accessibility`, `dns_tls`, and `destination_readiness` are compatibility aliases only. They do not create additional gate rows or additional authority.

## State machine

`packaged -> rights_cleared -> pricing_authorized -> fulfillment_certified -> checkout_staged -> publication_staged -> accepted -> live`

A package cannot skip a state. A public preview, ZIP, hash, database row, provider object, CI run or agent score is evidence only.

## Credit-only commerce

The initial cohort redeems Crown Credits. Direct cash checkout for the products remains disabled. Stripe may fund approved closed-loop credits through a separately governed top-up rail, but the product release package does not create per-SKU Stripe Products, Prices, Checkout Sessions, charges, payouts or transfers.

Synthetic refund/dispute canaries may prove credit-ledger idempotency, reversal and rollback behavior without activating customer balances or live checkout. They do not independently prove operative customer license acceptance or private fulfillment.

## Publication transaction

The publication transaction is accepted only when the same exact product and site version completes:

1. write or save the governed provider/feed candidate;
2. provider or consumer readback;
3. anonymous public application readback;
4. rollback to the bound prior version;
5. proof of rollback/absence;
6. exact reapply; and
7. second provider/consumer and public readback.

Current provider readback is fail-closed: all three ChatGPT Sites roots return HTTP 401 to anonymous requests, while the preferred custom domains do not resolve in DNS. Those states are blockers, not deployment success.

## Independent acceptance

The originating package agent casts no vote. Required specialist reviews are assigned by gate. Sovereign acceptance uses the existing A/B/C/D/S contract: at least four approvals, Agent D mandatory, any current block holds publication.
