# PentaSELF Hard Repairs

PentaSELF’s hard-repair lane is the governed production path for repairs that are too important for a shallow retry but remain inside bounded D0–D2 authority.

The lane is operated by the **Penta Surgical Care Family**:

- **PentaSurgeon** executes an exact, registered repair procedure.
- **PentaChart** records triage, pre-operation truth, procedure, response, rollback, retry, certification, discharge, and follow-up.
- **PentaRounds** performs post-operation readback and causal regression analysis.
- **PentaDnD** independently isolates and tests the exact repair generation.
- **PentaCertify** independently certifies the same immutable case digest.
- **PentaScribe** preserves the institutional narrative and structured chart lineage.
- **PentaDocs** publishes internal records and a redacted public record for significant cases.
- **PentaPR**, **PentaMerge**, and **PentaCloser** govern exact-head source closure when a repair requires code changes.

## Safety contract

| Control | Production rule |
| --- | --- |
| Authority | D0–D2 only; D3 stays human-reserved |
| Repair execution | Exact allowlisted handler; arbitrary SQL is not accepted |
| Direct main writes | Forbidden |
| Self-certification | Forbidden |
| Rollback | Only when post-operation evidence proves the surgery caused a new regression |
| Immediate retry | One bounded retry after transactional rollback or verified compensation |
| Provider writes | Require an independently certified provider-write contract |
| Money movement | Forbidden |
| Secret mutation or manufacture | Forbidden |
| Stale rollback | Forbidden; newer generations supersede older ones |

## Operational charting

PentaChart uses a disciplined chart structure modeled on high-quality operational recordkeeping: observations, assessment, procedure, response, plan, evidence, author identity, case generation, and cryptographic digest. It is an operations record, not medical care or medical documentation.

Routine noise is not published publicly. Significant, critical, held, or failed cases receive a redacted public report. Full internal evidence remains in the governed PentaDocs repair ledger.

## Release closure

A successful repair that changes source code is not written directly to `main`. PentaSELF creates or links an exact-head pull request. The merge gate requires:

1. A healthy post-operation state.
2. Two independent exact-generation certifications: PentaDnD and PentaCertify.
3. Green checks, a mergeable non-draft PR, no unresolved high findings, and complete documentation.
4. Exact head SHA continuity.
5. Provider merge readback through PentaPR/PentaMerge.

PentaSELF supplies the certified repair snapshot. It does not count its own vote and does not perform an ungoverned direct merge.

## Public reports

Public reports expose only the information needed to understand the repair class, disposition, rollback/retry use, independent verification, and safety boundaries. Credentials, secrets, contact data, internal stack details, and sensitive provider responses are removed.
