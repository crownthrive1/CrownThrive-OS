## Governance Observability and Archive Continuity

CrownThrive operates this capability in **Phase 3: Production + Convergence**. Governance observability is not a new authority body. It is a bounded evidence and reliability capability owned operationally by **PentaNurture™** and **PentaStatus™**, with outputs consumed by PentaMerge™, PentaCloser™, PentaCertify™, CHLOM governance, and authorized human reviewers.

The controlling rule is unchanged: the capability observes and classifies evidence; it **does not manufacture authority**.

## CI state is not policy state

**A red CI job is not automatically a CHLOM or Penta HOLD or DENY.** CI can fail because exact Git evidence was not hydrated, a runner was unavailable, a deterministic contract rejected input, a dependency review blocked a change, or an authoritative policy validator actually emitted a disposition. Those states must remain distinct.

The classifier uses these machine categories:

- `PASS`
- `POLICY_HOLD`
- `POLICY_DENY`
- `CI_EVIDENCE_HYDRATION_FAILURE`
- `STALE_EXACT_HEAD`
- `CONTRACT_ASSERTION_FAILURE`
- `SUPPLY_CHAIN_DENY`
- `RUNTIME_UNAVAILABLE`

`POLICY_HOLD` and `POLICY_DENY` require an explicit authoritative policy marker. Generic process exit codes, cancelled duplicate workflows, queued jobs, stale PR prose, or unavailable Git objects do not create a policy disposition.

## Exact-head truth

For current transport/source identity, machine readback uses GitHub's current PR API and immutable base/head SHAs. Historical PR body snapshots remain historical evidence but do not override current API state.

The privileged observability workflow executes canonical default-branch code, not contributor-controlled workflow code. Credentials are not persisted by checkout. Current governed merge logic must continue to bind immutable PR SHAs and verify exact Git objects before material trusted-diff evaluation.

## Penta operating relationship

| System | Relationship |
| --- | --- |
| PentaNurture™ | Owns drift, health, evidence-quality, and remediation routing for the capability. |
| PentaStatus™ | Projects current machine state without converting transport state into authority. |
| PentaMerge™ | May consume exact-head evidence but applies its own merge contract and authority. |
| PentaCloser™ | May use supersession/staleness evidence when closing obsolete work, without deleting history. |
| PentaCertify™ | May certify the exact observability implementation and tests; certification does not broaden governance authority. |
| CHLOM | Remains the governing policy/evidence metaprotocol. |

The prior standalone `ct.agent.governance-observability` framing is superseded as a current authority model. Any historical agent record remains lineage only. The capability is non-voting, cannot self-approve, cannot merge, and cannot emit institutional HOLD/DENY unless an authoritative policy source already did so.

## Machine-owned PR readback

The readback process may maintain one machine-owned PR comment containing:

- exact head and base SHA;
- transport/draft state;
- GitHub mergeability readback;
- observed workflow status;
- a CI evidence summary; and
- an explicit `NOT_DERIVED_FROM_CI` institutional-disposition firewall.

It must not rewrite human-authored PR prose, fabricate approval, manufacture reviewer evidence, or convert a green workflow into permission to merge.

## Resumable encrypted archive continuity

The archive-continuity design preserves the durable properties of the August 23 controlled test:

- chunked processing instead of a monolithic retry loop;
- plaintext is not persisted as an archive checkpoint;
- ciphertext chunks are checkpointed durably;
- members, cipher chunks, and manifest records are append-oriented;
- restart resumes from the last committed chunk;
- caught errors fail closed as `HOLD_NO_AUTOMATIC_RETRY`;
- no new top-level scheduler slot is created merely to retry archive work; and
- public/authenticated direct table access remains prohibited for protected archive state.

### Historical v21 evidence boundary

The v21 values recorded on **August 23, 2026**—including the frozen source counts, expected 154 chunks, eight canary chunks, and the historical CrownThrive Services Stack hourly subroute—are dated evidence. They are **not a claim about today's archive progress or today's scheduler binding**.

Before archive continuation resumes, the current runtime must be read back and the present governed scheduler/subroute must be identified. If current binding cannot be verified, the correct state is `READBACK_REQUIRED`/HOLD, not an inferred continuation from the historical CSS cadence.

## Authority boundaries

This capability does not authorize:

- direct-main merge or branch deletion;
- a vote or quorum effect;
- D3 automation;
- policy-disposition manufacture;
- provider writes;
- credential disclosure;
- plaintext archive export;
- money movement, settlement, pricing, or checkout;
- rights grants or license mutation;
- archive runtime activation merely because source is canonical; or
- AI final authority.

Penta systems may exercise authority already present in a current instrument. Observability cannot create the instrument it is observing.
