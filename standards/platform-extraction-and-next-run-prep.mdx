# Platform Extraction and Next-Run Preparation Standard

Every platform review must leave a complete institutional package rather than a loose summary.

## Platform package

For each platform capture: stable ID, canonical name, aliases, ownership/control, corridor, imprint/framework relationships, current phase/state, public URLs, domains/subdomains, repository/deployment, vendor/engine, audiences, roles, portals/dashboards, products/services, universes/rooms/collections, content models, commerce, payments, entitlements, rights/licensing, Legal Depot dependencies, APIs/webhooks/MCPs, SSO/auth, data classes, analytics, notifications, SEO/metadata/robots/sitemap, support, dependencies, recovery/export, security risks, current blockers, and next milestone.

## Creative/IP package

For music/media/story platforms capture universes, worlds, characters, canon, works, masters, editions, series, imprints, rights/provenance, participatory rights, licensing, distribution state and related products.

For ministry/education platforms capture rooms, study areas, curricula, scripture/content boundaries, courses, studies, products, memberships, teacher/pastor/church roles, licenses, privacy-sensitive journals/reflections, and content-review rules.

## Interface package

Capture all user-role surfaces: public, member, customer, creator, affiliate, developer, partner, operator, moderator, admin, super-admin, founder/governance and machine interfaces. Identify which screens can share components and which must remain platform-specific.

## Integration package

Collect supported API docs, base URLs, endpoints, auth, scopes, webhook events, SDKs, feeds, exports, vendor APIs and MCP opportunities. Unsupported interfaces remain `unverified` until inspected.

## Cleanup rule

Legacy bridges, duplicate routes, abandoned adapters, stale credentials, dead webhooks, old vendor references and previous-run scaffolding must be inventoried before removal. Cleanup requires evidence that no active workflow, user, inbound link, entitlement, license, source record or rollback path depends on the artifact.

## Next-run rule

Every run ends with: changed records, unresolved items, tests/evidence, affected dependencies, migration notes, rollback information, recommended next action and the exact phase/state inherited by the next run.
