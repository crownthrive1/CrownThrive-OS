# Architecture Self-Awareness & Reconciliation Standard v1.0

## Purpose

CrownThrive system self-awareness means a machine-readable, continuously refreshed model of canonical identity, parent/child relationships, dependencies, authority ceilings, lifecycle state, interoperability contracts, runtime components, safety controls and evidence state. It does not mean sentience, consciousness or autonomous authority.

## Scope

The self-model covers the operating-system layer, governance and authority, all registered agents, Framework Factory packages, repository federation, interoperability systems/contracts/mappings/routes, CSS services/contracts, identity, custody, DAIL evidence, commerce, documentation, optimization, scheduling and canonical data state.

Every registered agent receives an `architecture_self_awareness` projection containing the current snapshot ID, architecture root SHA-256, macro/micro awareness flags and the canonical refactor-optimizer agent ID. That projection never grants authority.

## Macro vs. micro

A **micro change** modifies a bounded component without changing its authority ceiling, autonomy class, parent, voting state or lifecycle authority boundary. Examples include canonical labels, bounded schemas, non-authoritative metadata and compatible contract detail.

A **macro change** adds/removes a component or changes authority, parentage, autonomy, lifecycle, privilege/guardian/kill state, framework/repository governance, or other structural control-plane state.

Micro changes may receive automated D0-D1 self-model/metadata reconciliation when reversible. Macro changes are HOLD by default and require a governed D2 exact-scope path or higher human/sovereign review as applicable.

## Refactor and optimization agent

`ct.agent.architecture-refactor-optimizer` is A2/D2, non-voting, non-sovereign and no-self-approval. It may build snapshots, classify drift, synchronize agent self-models, reconcile safe metadata/bindings, prepare macro reconciliation packets, and perform tested rollback/readback.

It may never delete, drop, truncate, purge, merge directly to main, create D3 authority, vote, self-certify, expand its own authority, export credentials/secrets, move money, grant rights, inherit provider authority, or perform provider writes without an explicit governing contract.

## Authority firewall

Awareness is evidence, not authority. A self-model, dependency graph, architecture score, optimizer recommendation, green CI result or successful canary cannot create institutional authority.

D2 actions require exact scope or governed handoff. D3 remains human-reserved. Emergency containment remains available through the existing agent kill-switch framework.

## Runtime

The architecture subroute is bound into the existing CSS hourly control cycle. No new top-level scheduler slot is created.

The cycle is:

1. Read canonical registries.
2. Build a fingerprinted architecture snapshot.
3. Compare with the prior snapshot.
4. Classify changed components as macro or micro.
5. Write reconciliation actions.
6. Synchronize all agent self-models.
7. Apply only bounded safe micro awareness/metadata reconciliation.
8. HOLD macro changes for governed review.
9. Append DAIL evidence and update agent health.

## Interoperability

The interoperability fabric must consume the architecture self-model through `ct.system.crownthrive.architecture-self-model` and its controlled-test contracts. Interoperability agents must never infer provider, merge, sovereign or D3 authority from architecture awareness.

## Canonical spelling and compatibility

Human-readable CrownThrive platform labels use **ThriveBase**. Legacy opaque identifiers containing `thivebase` may remain for compatibility until deliberately migrated; they must be treated as aliases rather than canonical presentation names.

## Certification

Framework Factory compilation and runtime PASS are technical evidence only. Canonical activation remains pending independent Agent D parent certification and ordinary governed source acceptance.
