## Agent-to-Build Execution Standard

CrownThrive separates **requesting/planning authority**, **materialization**, and **independent verification**.

`requesting agent → ct.agent.execution-builder → independent verifier → governed acceptance`

The Execution Builder exists because specialist and framework agents may correctly identify missing software, documentation, tests, schemas, adapters or migration candidates without themselves being the correct general-purpose materialization worker.

## Execution Builder

`ct.agent.execution-builder` is a non-voting A3/D2 child of `ct.relay.agent-c`. Its sole job is to turn a bounded build intent into deterministic candidate artifacts. It may reuse specialist builders such as deterministic-build, script-engineering, skill-compiler, API/MCP packaging and integration-adapter as internal capabilities, but it owns completion of the requested artifact bundle.

## Separation of duties

The requesting agent specifies the needed outcome and evidence. The Execution Builder builds it. A different verifier recomputes or reviews the evidence. Agent C and its child cannot independently certify C-originated work. Agent D remains mandatory wherever the surrounding governance requires D.

## Fail closed

Missing exact base head, D3 scope, requester/verifier collision, secret-shaped public input, protected-body publication, target-main drift or unavailable rollback produces HOLD. A build receipt is never a PASS lifecycle receipt, sovereign vote, merge authorization or production activation.
