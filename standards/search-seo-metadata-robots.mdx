# Search, SEO, AIO, Metadata, Robots and Sitemap Standard

Search is ecosystem infrastructure. Every CrownThrive platform should expose accurate, crawlable, canonical, role-safe information without leaking restricted content.

## Required public-page metadata

Where applicable: unique title, description, canonical URL, indexability state, robots directive, Open Graph/Twitter metadata, content type, published/modified timestamp, author/organization, language, image metadata, breadcrumb context, and appropriate structured data.

## Canonical rules

One canonical URL per public resource. Aliases, legacy routes, edition routes, and platform migrations should use documented redirects/canonicals rather than competing indexable copies. Public titles should optimize for human meaning and discovery; internal version codes stay in structured records unless needed publicly.

## Robots rules

Each public host must have a deliberate `robots.txt`. Do not use robots rules as a security mechanism. Private/admin/account/API/testing routes require authentication and appropriate noindex behavior in addition to any crawler directives.

Robots policy should be generated from environment and route classification, versioned, tested, and monitored for accidental site-wide blocks.

## Sitemap rules

Each public host should publish valid XML sitemap coverage appropriate to its scale. Large properties may use sitemap indexes separated by content type. Sitemaps must exclude private, duplicate, error, expired-token, admin, checkout-session, and restricted routes.

Every deploy should be capable of detecting orphaned canonical pages, broken sitemap URLs, redirect chains, invalid last-modified data, and unexpected indexability changes.

## AIO / machine discovery

Public institutional facts should be consistent across websites, knowledge pages, structured data, API/docs surfaces, feeds, and approved machine-readable records. Agents should retrieve current claim records rather than copy stale prose.

## Programmatic SEO safety

Automation may create scalable landing pages only from governed data with real user value. No thin doorway pages, fabricated locations, fake reviews, duplicated city pages, or unsupported claims.

## Media and universe metadata

Works, characters, universes, rooms, studies, books, music, videos, products, events, courses, and licensing assets should carry stable IDs and relation metadata so search systems can understand parent/child relationships rather than treating every page as isolated.

## Automation target

CrownThrive should eventually run centralized search governance through CrownThrive IO/MCP plus per-platform adapters: crawl, validate metadata, compare canonical claims, regenerate sitemaps, check robots, inspect structured data, identify broken links, watch indexability, route fixes, and log results to DAIL/CrownLytics.
