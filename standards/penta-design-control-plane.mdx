# Penta Design Control Plane

This standard carries forward the valid design-governance work from the older Figma control-plane packet onto the current Penta architecture.

## Tool roles

- **Figma** is the product/UI/design-system control plane for governed interface source, components, tokens, layouts and design-to-code mappings when connected evidence supports the exact artifact.
- **Canva** is a downstream creative-production surface for approved brand/social/marketing derivatives and does not redefine canonical product UI or design-system source.

## Penta ownership

- **PentaBuild** — build/package design-to-code and implementation assets.
- **PentaCertify** — certify exact design-source mappings, adapters, Code Connect-style mappings and delivery paths.
- **PentaCredentials** — manage provider-managed OAuth/credential references; provider-managed OAuth is not copied into public source or treated as a raw Vault value.
- **PentaQuality / PentaAssure** — visual, responsive, accessibility, component and evidence-quality gates.
- **PentaNurture / PentaStatus** — maintain bindings and surface drift/broken mappings.
- **PentaDocs / PentaScribe** — preserve design-system documentation, terms, decisions and change lineage.

## Canonical-source rule

A screenshot, generated code fragment, provider connection or named component does not prove canonical design-system source. Canonical tokens, components and design-to-code mappings remain held until exact authoritative file/node/source-path evidence and current readback exist.

## Specialist functions

The functional roles preserved from the original design packet are:

- Design System Architecture;
- Design-to-Code / component mapping;
- Brand Content Production;
- Design Quality & Accessibility.

These are functions inside the Penta operating model, not new sovereign authorities or independent execution identities.

## Authority boundary

No design tool or Penta member may invent brand rights, approve inaccessible output by lowering criteria, publish a provider mutation without authority, or convert a visual match into production certification. Provider authentication, institutional authority, source provenance, accessibility, implementation tests and deployment readback remain separate gates.
