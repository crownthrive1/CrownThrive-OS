# Penta API/MCP Current Control State

This page supersedes old Phase-2.99 checkpoint language without replacing the stable MCP/API governance standard.

## Current routing and ownership

- **PentaMCP** — institutional MCP capability/control surface.
- **PentaRoute** — governed cross-system routing.
- **PentaFederation** — cross-platform federation and interoperable topology.
- **PentaMation** — bounded automation/execution orchestration.
- **PentaCredentials** — credential references, health and lifecycle without public secret exposure.
- **PentaCertify** — adapter/provider execution-path certification.
- **PentaStatus / PentaNurture** — health, continuity, drift and remediation support.

All identities must resolve through the current Penta Family registry. An unknown or ambiguous Penta reference fails closed.

## Execution invariant

An API endpoint, MCP tool, provider feature, working credential, HTTP success, connector availability or registered Penta member is **not** authority.

A consequential provider action requires, as applicable:

1. a registered Penta member whose maturity is execution-eligible under the current family contract;
2. CHLOM/DAIL or other governing authority trace for the requested action;
3. PentaCredentials-ready credential binding;
4. PentaCertify-certified provider/adapter path;
5. required security/privacy/rights/economic controls;
6. required PentaHybrid or other human gate where policy demands it;
7. bounded execution through PentaRoute/PentaMation;
8. provider readback/receipt and preserved evidence.

No layer may manufacture a missing upstream permission.

## Protocol and compatibility

The stable CrownThrive MCP/API standards continue to govern versioning, discovery, side effects, error contracts, idempotency, authentication and tool metadata. Protocol-version claims must be tied to current executable evidence; old control-plane checkpoints remain historical evidence rather than current runtime truth.

## Collab Portal and legacy adapters

Old Collab Portal/OpenAPI/webhook records remain source lineage. A documented contract or UI event family does not establish a currently certified provider-write path. Current execution eligibility must be resolved through the Penta controls above and the exact provider evidence in force at execution time.

## Fail-closed provider writes

Provider writes remain operation-specific. Read certification does not widen into write certification, one write does not imply provider-wide authority, and browser/provider UI access does not substitute for an institutional contract.

## Projection rule

Public API/MCP documentation can lag current source state. Projection lag opens a PentaDocs/PentaScribe delta; it does not overwrite the current family registry, CHLOM/DAIL authority or exact provider evidence.
