# Dynamic Homepage Projection Standard

The CrownThrive homepage is a governed summary of accepted institutional meaning. It is generated from public-safe records, validated with the same change, and reconciled hourly for drift. It is not a marketing page that agents may rewrite from memory and it is not a live window into restricted systems.

## Standard identity

| Field | Value |
| --- | --- |
| Standard ID | `ct.standard.homepage-projection.v1` |
| Projection ID | `ct.projection.mintlify.homepage` |
| Manifest | `developers/manifests/homepage-projection.v1.json` |
| Renderer | `scripts/render_homepage_projection.py` |
| Target | `index.mdx` marker-bounded region |
| Cadence | hourly at minute 17, plus manual dispatch |
| Mutation boundary | dedicated automation branch and draft pull request only |
| Direct `main` write | prohibited |

Registered public-safe source packets include the dated ecosystem placement manifest, the monetizable-tooling coordination manifest, the AI/ML/CHLOM protected capability map, the Phase 2.99 hard-exit ledger, the readiness gate, the documentation host registry and the related governance standards. Adding an input requires review of its authority, classification, freshness and public projection boundary.

## Canonical projection fields

The generated homepage region may expose only public-safe, source-bound fields:

- current program phase/subphase and hard-entry decision;
- default documentation URL and dated public-readback disposition;
- recovery corpus generation, record count and body-provenance boundary;
- typed public-card census with count semantics;
- AI/ML/CHLOM capability-catalog posture;
- monetizable-tool candidate posture and commercial gate;
- exact projection-input digest;
- refresh, review and rollback behavior.

Private evidence bodies, credentials, vault locators, salts, private fingerprints, protected algorithms, customer records, restricted evaluation data and internal economic schedules never enter the public projection.

## Deterministic rendering

The renderer hashes the declared canonical inputs and replaces only the bounded region between `HOMEPAGE_PROJECTION:START` and `HOMEPAGE_PROJECTION:END`. The same inputs must produce the same bytes.

The renderer deliberately excludes the wall clock. An hourly run with no semantic input change emits a GitHub Actions heartbeat and leaves `index.mdx` unchanged. A current timestamp alone is not institutional change evidence and must not create a commit.

## Same-change propagation

A pull request that changes a tracked phase, gate, recovery, platform-placement, capability, commerce or navigation source must regenerate the homepage in the same change. CI fails when the generated region is stale.

If a source cannot safely or authoritatively update the homepage, the pull records:

```yaml
homepage_impact:
  outcome: no_change | delta_opened
  reason: <evidence-backed reason>
  source_refs: []
  affected_claims: []
```

`delta_opened` cannot preserve a materially false security, phase, rights, commerce, deployment or public-claim statement.

## Hourly reconciliation cycle

Each scheduled run:

1. checks out the current default branch with bounded workflow permissions;
2. renders the marker-bounded region from registered inputs;
3. runs homepage, documentation, security and supply-chain validations;
4. exits without a content commit when no canonical input changed;
5. otherwise updates only the dedicated `automation/hourly-homepage-projection` branch by non-force push;
6. opens or updates one draft pull request;
7. leaves merge, publication and phase authority to the governed review path.

The run binds itself to the exact `main` SHA that triggered it and fails closed if `main` moves before mutation. When the automation branch already exists, the workflow first proves that its complete lineage delta contains only `index.mdx` and that every branch commit belongs to the registered GitHub Actions bot identity. It then merges the exact current `main`, rerenders, proves that the complete candidate PR diff contains exactly `index.mdx`, and refuses any update that would require a non-fast-forward push.

Before mutation, the workflow also requires GitHub's current branch readback to report `main` as protected. That boolean is useful provider evidence but does not replace separate required-check/ruleset proof. After the push, the workflow reads the remote branch and pull request back from GitHub. The exact head and complete changed-file set must match the candidate. Its evidence receipt records the triggering actor, canonical-main SHA, prior automation head, candidate head, homepage digest and rollback target. The rollback drill retrieves the prior canonical `index.mdx` and records its digest; it does not rewrite history or exercise a production deployment.

The workflow may not force-push, write directly to `main`, self-merge, mint OIDC tokens, access production credentials, call live commerce mutations or reinterpret a failed validation as success.

The repository workflow deliberately does not invent or directly mutate external observations. Public/provider changes enter through an authorized source-pull or evidence-reconciliation task that updates a registered input by pull request. The hourly renderer then proves whether the homepage matches that canonical input. If the external-source connector is unavailable, the run reports the visibility gap and leaves the last known good source state intact.

## Public readback and acceptance

Four states remain separate:

| State | Evidence |
| --- | --- |
| source rendered | deterministic local output |
| repository accepted | exact commit and required CI evidence |
| Mintlify deployed | provider deployment evidence |
| publicly accepted | independent homepage, sitemap, robots and machine-output readback |

As observed on August 21, 2026, the active default Mintlify URL redirects to authentication. This creates `PUBLIC_READBACK_BLOCKED`; it does not invalidate the repository renderer, but repository CI must not be represented as public deployment acceptance.

## Claim and count rules

The public CrownThrive.com card census includes platforms, brands, programs, frameworks, governance artifacts, support/status surfaces and architecture concepts. The homepage therefore uses a typed mixed-card count and never relabels that census as a pure platform count.

Historical, archived, reserve, target, research and unresolved rows remain explicit. A card, domain, vendor entitlement, description or redirect is not production proof.

## Failure and recovery

On missing input, duplicate marker, invalid manifest, unexpected branch author, non-homepage branch/PR delta, stale canonical SHA, read-after-write mismatch, authentication failure, merge conflict, validation error or unsafe public content, the workflow stops and preserves the last known good homepage. Recovery is a normal reviewed pull request or a revert of the bounded packet. It may not erase source history or weaken the failing check.

## Ownership and review

- Documentation Steward owns deterministic rendering and D1 repair.
- Platform Registry Agent owns source-backed placement deltas.
- Phase Gate Agent owns phase/gate consistency.
- Security/Privacy, AI/ML/LLM TEVV, IP/Rights/Licensing, Finance/Tax/Treasury and Accessibility/Consumer Protection review their applicable portions.
- D3 controlled claims, access changes, prices, legal terms, rights, privileged security and live commerce remain human-reserved.
