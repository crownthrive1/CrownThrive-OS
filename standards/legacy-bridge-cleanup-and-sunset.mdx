# Legacy Bridge Cleanup, Migration and Sunset Standard

CrownThrive has accumulated platforms, domains, adapters, integrations, branches, source copies, prior vendor configurations and experimental bridges across multiple build eras. Cleanup must reduce operational confusion without destroying provenance, users, entitlements, inbound links or recovery options.

## Cleanup inventory

Before removal, register:

- asset or artifact ID;
- platform/owner;
- type: route, domain, repository, branch, adapter, webhook, API key, database, cron, workflow, provider, plugin, page, duplicate source, deployment or account;
- current status and last observed use;
- dependencies and downstream consumers;
- data/evidence contained;
- credentials/secrets involved;
- inbound links and search traffic;
- active users/orders/licenses/entitlements;
- replacement/successor;
- backup/export;
- rollback window;
- decision authority.

## Decommission states

`discovered → dependency_checked → migration_planned → shadowed → read_only → disabled → archived → destroyed_if_permitted`

Destruction is optional and must respect legal holds, retention, rights, evidence and recovery requirements.

## No-delete-without-proof rule

Do not remove an old integration merely because it appears unused. Confirm:

1. no production traffic or scheduled job depends on it;
2. no user/account/payment/license/entitlement depends on it;
3. no inbound link or canonical route requires redirect;
4. no private evidence or unique source exists only there;
5. replacement has passed verification;
6. rollback is documented;
7. credentials are rotated/revoked;
8. owner approves the applicable state.

## Duplicate sources

Duplicate files should be grouped into a source family with:

- canonical working master;
- original copies preserved where meaningful;
- hashes and dates;
- supersession relationships;
- content differences;
- restricted/public classification.

Never infer that the newest upload is the newest content.

## Vendor migration

Every critical vendor exit plan should address:

- data export and format;
- identity/account migration;
- DNS/domain changes;
- API and webhook replacement;
- historical logs/evidence;
- customer communications;
- contract/renewal timing;
- billing cutoff;
- feature gaps;
- dual-run/shadow period;
- rollback;
- deletion confirmation.

## Search and public continuity

Retired public pages require appropriate redirects, canonicals, sitemap removal, archive/noindex decisions, updated internal links and preserved institutional history. A platform may be retired without erasing its contribution to CrownThrive.

## Repository hygiene

Old branches, generated artifacts and previous-run scaffolding should be classified before pruning. Protect release tags, migration points, source masters, architecture decisions and evidence. Automated cleanup may remove known generated/cache artifacts under policy; source or history deletion remains controlled.

## DAIL events

Emit events for migration approval, shadow start, disablement, credential revocation, archive completion, data deletion and rollback. The final record must identify what replaced the artifact and where its history can be found.
