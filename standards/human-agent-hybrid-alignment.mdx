# Human, Agent and Hybrid Alignment Rules

CrownThrive automation should minimize unnecessary human intervention while preserving explicit human authority where consequences justify it.

## Autonomy classes

**A0 — Observe:** read, classify, summarize, monitor, index, compare, test.

**A1 — Prepare:** draft, stage, create branches, assemble migrations, generate previews, prepare transactions without committing consequential actions.

**A2 — Execute reversible:** publish low-risk content, update non-sensitive records, run approved workflows, synchronize indexes, refresh sitemaps, perform reversible configuration within policy.

**A3 — Execute controlled:** make consequential changes only when a machine-readable approval rule is satisfied and evidence/rollback exists.

**A4 — Reserved:** founder/governance/legal/security/finance authority required; agents may prepare but may not independently authorize.

## Mandatory behavior

Agents must read current institutional state before acting; preserve IDs and lineage; obey audience and visibility; avoid inventing missing rights/status; emit traceable events; test before release where feasible; stop on conflicting authority; and leave a next-run-ready state.

## Human roles

Human review should focus on judgment, exceptions, legal/economic commitments, cultural stewardship, security, irreversible actions, and ambiguous source conflicts—not repetitive clerical steps that can be policy-driven.

## Hybrid model rules

AI/ML/LLM systems may assist with classification, retrieval, anomaly detection, forecasting, recommendations, content, support triage, rights checks, metadata, SEO, and routing. Model output is evidence of a computation, not automatically institutional truth.

## Model governance

Record model/provider where material, prompt/policy version, source context class, confidence or uncertainty where meaningful, output destination, human-review requirement, and evaluation results. Sensitive prompts, private evidence, credentials, and restricted data must follow the same access rules as the underlying records.

## Failure rules

When a workflow encounters missing authority, stale evidence, contradictory source state, failed idempotency, broken dependency, or unverified rights, the safe action is hold/escalate—not infer permission.

## Audience orientation

A run must optimize for its intended audience. Public help text, developer docs, internal runbooks, executive dashboards, creator portals, and machine contracts may describe the same object differently, but they must resolve to the same stable institutional record.
