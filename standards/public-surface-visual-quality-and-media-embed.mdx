# Public Surface Visual Quality & Media Embed Standard

A CrownThrive public page is not healthy merely because it returns HTTP 200. Public surfaces must also remain legible, usable, responsive, visually coherent, accessible, rights-safe, privacy-aware and faithful to the current platform identity.

This standard applies to Sites-backed properties and any other registered public website surface. It is evaluated separately from backend evidence certification: a public player may work while measurement evidence remains missing or unverified, and a technically healthy backend may coexist with a broken public layout.

## Independent state dimensions

Every material public-surface change keeps these states separate:

- functional/runtime health;
- visual and responsive quality;
- accessibility quality;
- public-claim/evidence alignment;
- media/embed integrity;
- privacy/consent behavior;
- performance/regression posture;
- rights/canon/brand approval where applicable;
- commerce/entitlement state;
- provider-write and rollback authority.

One PASS never manufactures another.

## SoundCloud public playback rule

For public Virality Music listening surfaces, use SoundCloud's supported embed stack rather than a CrownThrive API credential when the job is simply to present public SoundCloud audio.

1. **Default simple embed:** SoundCloud oEmbed / the standard SoundCloud iframe widget.
2. **Custom playback controls or player events:** the official HTML5 Widget API may wrap/control the standard iframe.
3. **SoundCloud measurement evidence:** SoundCloud API access is `NOT_APPLICABLE / REMOVED_BY_FOUNDER_OVERRIDE` under the August 20, 2026 directive signed by Kavonte Jones Sr. Accept only provenance-backed non-API reports, permitted exports supplied without API integration, or public observations classified `observed_unverified`.
4. **No SoundCloud API credentials:** never request, store, configure, certify, invoke or expose SoundCloud API tokens, OAuth credentials, client secrets, authenticated API reads/writes, webhooks or API-dependent adapters/jobs in CrownThrive systems or public surfaces.

SoundCloud documents oEmbed as the supported way to obtain widget embed code for SoundCloud URLs; its returned widget is width `100%` and `auto_play` defaults to `false`. The HTML5 Widget API is the supported JavaScript control surface when a site needs playback methods or player events.

Official references:

- [SoundCloud oEmbed](https://developers.soundcloud.com/docs/oembed)
- [SoundCloud HTML5 Widget API](https://developers.soundcloud.com/docs/api/html5-widget)

### CrownThrive embed profile

- width must remain responsive to its containing layout;
- autoplay is off by default;
- use a descriptive iframe/player title;
- preserve a canonical SoundCloud attribution or source link where appropriate;
- surrounding controls must remain keyboard operable with visible focus;
- player/artwork cannot obscure page copy, navigation or primary calls to action;
- reserve player space so loading does not create avoidable layout shift;
- below-fold players should lazy-load where the active provider/browser implementation permits;
- preserve click-to-load/consent behavior when the current privacy model requires deliberate third-party media loading;
- an embed may not be represented as authenticated Artist Studio/API evidence;
- the site must still work meaningfully when a third-party player cannot load.

## Responsive visual QA

A material public change requires an evidence-backed responsive review at representative narrow-mobile, mobile, tablet, laptop and wide-desktop widths. Exact viewport sizes may vary by surface and current traffic, but the test must exercise the smallest supported public layout and at least one desktop layout.

Check for:

- horizontal overflow and clipped content;
- navigation collapse and sticky-header behavior;
- touch-target usability and spacing;
- typography size, line length, hierarchy and truncation;
- artwork crop, aspect ratio, caption and alt-text behavior;
- cards, grids, carousels and collection shelves at wrap points;
- persistent audio/player overlays covering content or controls;
- dialogs, drawers and menus with correct focus/scroll behavior;
- form labels, errors and consent copy;
- embedded media fit and loading states;
- CTA hierarchy and route clarity;
- safe-area behavior where applicable;
- reduced-motion behavior;
- contrast/focus visibility;
- layout stability before and after third-party media loads.

If the executing environment cannot inspect a required visual breakpoint, record that breakpoint as `unverified` and open a remediation/review delta. Do not infer visual PASS from markup, a screenshot at one width, or a successful HTTP check.

## Virality Music visual profile

Virality should remain premium, cinematic, culturally grounded, editorial, modern, emotionally rich and credible to both public listeners and enterprise licensing buyers.

Prefer:

- strong artwork and character/universe imagery;
- clear listening and business funnels;
- readable editorial rhythm;
- intentional negative space;
- concise statistic/evidence cards;
- audio embeds, diagrams, timelines and visual breaks where they improve comprehension;
- responsive album/release/world grids;
- content density appropriate to the user's current task.

Avoid:

- generic AI imagery;
- stock neon/headphone clichés;
- walls of text without hierarchy;
- tiny typography;
- cluttered competing CTAs;
- unnecessary animation;
- autoplay audio;
- fake awards, testimonials, ratings, streams or revenue claims;
- decorative visual effects that materially degrade mobile performance or accessibility.

The site may remain deep as an archive. Depth is not permission to make the first-action path ambiguous.

## Performance and third-party media

The public-surface agent treats performance as a user-experience control, not merely a hosting metric.

- core copy and primary CTA should not wait for third-party media scripts;
- avoid nonessential third-party requests before the user's current consent/interaction model permits them;
- use responsive image dimensions and modern delivery formats where supported;
- lazy-load below-fold images and media where appropriate;
- avoid unnecessary duplicate players/scripts;
- explicitly inspect layout shift around players, ads, artwork and consent-controlled embeds;
- persistent players must not trap focus or create unusable mobile viewport space.

A performance target is a target until measured; do not claim a Lighthouse/Core Web Vitals grade from architecture alone.

## Agent and subagent behavior

The Agent Router may instantiate a bounded non-voting `public_surface_visual_qa` child under the Website Surface & Interaction Agent for a registered route, release, breakpoint set or embed family.

The child may inspect public/read-only evidence, compare current output to a governed baseline, classify visual defects and create D0/D1 remediation plans. It cannot mutate a live site, replace brand masters, publish protected media, grant rights, change pricing, submit customer forms or self-approve a material release.

Same-family visual-QA children do not count as independent sovereign verification.

## Release and self-healing rule

Automated self-healing may repair internal metadata, regenerate a deterministic audit plan, retry read-only checks, or prepare a bounded site-update queue item. A live Sites/provider mutation requires the separately certified website-provider adapter, read-before-write state, rollback checkpoint, read-after-write verification and applicable governance.

When a public-facing change alters layout, media, navigation, CTA hierarchy or a major visual component, Agent D must treat missing visual/responsive evidence as a release HOLD rather than assuming CI proves appearance.
