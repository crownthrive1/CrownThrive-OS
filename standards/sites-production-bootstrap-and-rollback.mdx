# Production Sites Bootstrap and Rollback

Production rendering is not publication authority. Each CrownThrive Sites surface must expose the registered governed-feed marker, exact surface identity, a read-only catalog proxy, a public site-consumer DID document and a deterministic public fingerprint certificate before it can consume a governed release projection.

## Acceptance cycle

A surface reaches `full_cycle_pass` only after one exact source state completes:

1. provider write and successful deployment;
2. independent public readback of the marker, exact surface and feed reference;
3. HTTP 200 readback of the proxy, DID document and certificate;
4. equality between the proxy response body SHA-256 and its digest header;
5. deliberate rollback;
6. public proof that the marker is absent and all three bootstrap endpoints are absent;
7. exact reapplication;
8. a second independent public readback.

Build success, preview success, a provider version, source history or a rendered home page cannot substitute for the cycle.

## Fail-closed policy

Production auto-update remains disabled while any surface is incomplete, the current-policy canary is not passing at application level, or scheduler transport status can mask an inner governed failure. Legal, rights, pricing, tax, checkout, entitlement, delivery, refund, dispute and live-commerce gates are independent and unchanged.

## DID and fingerprint boundary

The public `did:web` document identifies a site consumer and its public service endpoints. The fingerprint is a deterministic SHA-256 commitment under the versioned `ct-json-c14n-v1` profile.

These records are public digest evidence. They are not a signed verifiable credential, proof of a controlled private key, sovereign agent acceptance or institutional certification. A cryptographic certification claim requires a versioned resolver profile, public verification key, protected signing key, signed credential/status record, proof anchor, rotation and independent verification.

## Phase boundary

This packet does not activate Phase 3. Phase 3 remains blocked until all production surfaces complete the cycle, the current-policy automation canary passes without masked inner failures, and all independent governance gates accept the resulting exact head.
