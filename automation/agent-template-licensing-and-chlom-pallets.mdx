# Agent template licensing and CHLOM pallets

CrownThrive may productize its **agent-definition architecture, governance logic, evaluation patterns, run-packet structure, orchestration templates and CHLOM capability mappings**. Commercialization must preserve the distinction between CrownThrive-owned IP and third-party/open-source dependencies.

## CrownThrive-owned template layer

Potentially licensable CrownThrive-authored components include:

- agent and subagent definition schemas;
- non-secret orchestration prompts and run-packet structures;
- role/authority/evidence/stop-condition patterns;
- topology manifests and validation logic authored by CrownThrive;
- generic evaluation and negative-test structures;
- THIVEBASE heartbeat/control-plane templates stripped of private provider state;
- CHLOM pallet mappings and institutional workflow blueprints;
- implementation guides, training and certification materials.

Private CrownThrive data, provider credentials, restricted evidence, proprietary production configuration, customer records and confidential calibration are never part of a public template license by default.

## Third-party and open-source rule

External code may be incorporated only after the exact license is captured and its obligations are compatible with the intended use.

For every incorporated dependency or excerpt record:

```yaml
component_id: thirdparty.example
source_repository: null
upstream_version_or_commit: null
license_spdx: null
copyright_holder: null
notice_required: false
source_offer_required: false
modification_notice_required: false
redistribution_permitted: unknown
commercial_use_permitted: unknown
patent_terms_reviewed: false
copyleft_scope: null
approved_use: reference_only | dependency | modified_distribution | prohibited
```

If license terms are unknown, the code is **reference-only** until reviewed. CrownThrive does not remove attribution, copyright notices or license files to make a package look proprietary.

## License compatibility tiers

- **Permissive-compatible:** may generally support commercial use/redistribution when attribution/notice obligations are satisfied; verify the actual license/version.
- **Weak-copyleft/relinking obligations:** isolate and review distribution boundaries before bundling.
- **Strong/network copyleft:** requires legal/technical review before inclusion in a proprietary hosted or distributed CrownThrive product.
- **Source-available/proprietary/vendor marketplace:** use only within the purchased/license scope; do not redistribute source merely because CrownThrive owns a license.
- **Unknown/no license:** do not copy or redistribute.

This page is an operating rule, not legal advice; consequential redistribution/licensing decisions remain subject to the appropriate D3/IP/legal gate.

## CHLOM agent-pallet model

The reusable agent system can be represented as CHLOM capability pallets without claiming those pallets are already deployed as decentralized protocol modules.

| Pallet | Purpose | Example current role |
| --- | --- | --- |
| `AgentIdentityPallet` | stable agent/subagent identity, aliases, versions | registry/template layer |
| `AuthorityPallet` | D0–D3 ceiling, voting status, approvals, break-glass | permissions/governance |
| `EvidencePallet` | source refs, checksums, claims, UNKNOWN state | Evidence Auditor/factory |
| `ExecutionPallet` | scheduled/embedded invocation and run packets | A/E/F/G/H \+ subagents |
| `EvaluationPallet` | test suites, negative cases, provider/model regression | QA/Security |
| `ContinuityPallet` | archive, export, rollback, recovery, succession | Agent I |
| `TransitionPallet` | phase/gate/downstream dependency propagation | Agent J/K \+ Phase Gate |
| `CommercePallet` | SKU/license/entitlement for external template packages | future governed commerce |

These are current **institutional capability abstractions** and future CHLOM implementation inputs, not evidence of a live blockchain/runtime pallet deployment.

## Commercial package model

A future commercial offering should separate deliverables:

1. **Template Pack** — YAML/JSON definitions, generic run-packet/eval templates, public documentation.
2. **Operator Pack** — setup guides, governance checklists, deployment patterns and upgrade notes.
3. **Developer Pack** — scaffold/validation code and SDK examples that CrownThrive has the right to distribute.
4. **Enterprise Blueprint** — implementation architecture, mapping workshop and governed customization under a separate agreement.
5. **Managed THIVEBASE/CHLOM Service** — future hosted/managed capability only after the applicable later-phase service, privacy, security and support gates.

## Stripe and entitlement boundary

Stripe may be used for the product/price/order layer, but **payment is not the license grant**. A sale must resolve to a versioned CrownThrive license/entitlement record that states the permitted use, support/update scope, redistribution restrictions and version/effective date.

Any live template SKU should therefore map:

```text
Stripe Product/Price
→ CrownThrive offer/SKU
→ CHLOM license class/version
→ order/payment evidence
→ entitlement
→ protected delivery
→ update/support policy
→ revocation/refund/dispute state
```

No third-party component may be placed behind a CrownThrive paid download unless its license permits that distribution and required notices/source obligations are included.

## Monetization readiness

The agent-template family is **commercialization-ready as an IP/product architecture**, but live checkout should open only after the public license text, deliverable package, third-party notice inventory, version manifest, support/update policy and fulfillment path all pass. Price creation alone does not satisfy those gates.
