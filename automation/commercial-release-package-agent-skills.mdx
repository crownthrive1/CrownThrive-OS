# Commercial Release Agent Skill Suite

The canonical suite `ct.agent-suite.commercial-release-factory.v1` contains one non-sovereign originator and seventeen scoped workers. All **18 reusable skill packages are now registered in THIVEBASE** and share the same fail-closed authority contract. The worker count is intentionally larger than the release-gate count: multiple workers may prepare evidence for one canonical gate, while historical gate aliases do not create new approval gates.

| Canonical skill | Worker lane | Hard boundary |
| --- | --- | --- |
| `ct.skill.commercial-release-packager` | Package orchestration | Cannot self-approve |
| `ct.skill.commercial-release-rights` | Rights, provenance, license and assent | Cannot clear rights |
| `ct.skill.commercial-release-pricing-tax` | Credit pricing comparables and tax package | Cannot authorize price or tax conclusion |
| `ct.skill.commercial-release-fulfillment` | Protected fulfillment and delivery canary | Cannot expose private masters |
| `ct.skill.commercial-release-checkout-webhook` | Credit redemption, webhook signature, replay and ordering | No cash checkout or live provider mutation |
| `ct.skill.commercial-release-entitlement` | License, entitlement, revocation and delivery chain | Payment is not entitlement |
| `ct.skill.commercial-release-accessibility` | Accessibility, mobile, keyboard and assistive-tech evidence | Automated tests are not conformance certification |
| `ct.skill.commercial-release-dns-tls` | DNS, TLS, HTTPS and canonical route | Cannot mutate DNS |
| `ct.skill.commercial-release-site-publisher` | Governed dynamic-feed publication candidate | No direct Sites provider write |
| `ct.skill.commercial-release-governance` | Exact-digest review and quorum packet | Cannot manufacture votes |
| `ct.skill.commercial-release-credential-alias` | Primary/recovery Vault alias request | Raw secret return prohibited |
| `ct.skill.commercial-release-source-normalization` | Source, product and asset normalization | Cannot invent missing evidence |
| `ct.skill.commercial-release-provider-capability` | Provider capability and least-privilege boundary | Cannot broaden provider authority |
| `ct.skill.commercial-release-site-readback` | Public/provider readback, rollback and reapply proof | Transport success is not application success |
| `ct.skill.commercial-release-remedy-rollback` | Refund, dispute, reversal and rollback package | Cannot move money or erase evidence |
| `ct.skill.commercial-release-drift-reconciliation` | Exact-head and release drift reconciliation | Cannot silently rewrite accepted state |
| `ct.skill.commercial-release-evidence-hashchain` | Package and evidence digest continuity | Hashes do not create authority |
| `ct.skill.commercial-release-agent-replication` | Non-voting worker replication | Authority and credentials never inherit |

The canonical release topology is **10 all-product gates plus one Ready-only professional-review gate**. Historical labels such as `fulfillment`, `checkout_webhook`, `entitlement`, `accessibility`, `dns_tls` and `destination_readiness` are aliases for current canonical gates and are never double-counted.

Every skill is A0–A2 / D0–D2, non-voting, no-self-approval and evidence-producing. D3/A4, final rights, tax/legal conclusions, money movement, credential recovery and external signatures remain human-reserved.
