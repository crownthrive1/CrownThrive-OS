# Framework Child Package Factory

The **Framework Child Package Factory** is the execution-packaging layer beneath the CrownThrive Framework Factory. An independently executable framework package may exist and run bounded non-voting controlled tests without a separate GitHub repository. That package state is distinct from a **linked_governed child repository**. Agent-D parent certification, operational activation and any later sovereign-voter proposal require a physical child repository with immutable GitHub repository ID, backlink, OIDC binding, exact parent/child digests, bidirectional message/ACK/reference/heartbeat proof, inherited governance/security, passing CI/evals and rollback/recovery evidence.

Program authority remains issue `#148`. This packet is stacked on the active CIE parent packet, PR `#145`.

## Corrected child definition

A framework package exists when its accepted packet provides the required package surfaces and the package validator can reproduce the public-safe execution contract. A standalone repository remains optional for package existence, bounded R&D and controlled-test execution. It is **not optional** for the separate `linked_governed` child-certification state: until the physical repository and its certification evidence exist, the package remains non-operational, non-voting and cannot advance the framework sequence.

The canonical source host for the current Factory is `crownthrive1/CrownThrive-Support`.

## Engine and protected algorithms

The public package engine is real executable code for health, contract validation, deterministic public logic and governed dispatch. It intentionally does not duplicate CrownThrive trade-secret or restricted decision material.

Public-safe package material may contain safe dimensions, thresholds, schemas, hard-block interfaces, deterministic validation logic and public digests. Proprietary calibration, weights, private evaluation corpora, defensive rules, restricted evidence and private policy/economic implementation remain in approved Vault/private runtime and are invoked through the governed federation/API/MCP path.

If a material decision requires private runtime or a registered digest and that state is unavailable, the engine returns HOLD rather than substituting public approximations.

## GitHub automation and OIDC

Each package receives dedicated GitHub workflow material. Pull-request validation is read-only and receives **no GitHub OIDC token authority**. OIDC is isolated to trusted non-PR runtime jobs used for state/bootstrap/heartbeat after the package validator passes.

Before any material federation mutation, CrownThrive still requires exact workflow/ref/environment → institutional-agent/capability binding. Repository-level OIDC alone is not sufficient institutional-agent authority.

The self-sustain layer may:

- validate package structure and public-safe executable surfaces;
- run local engine health checks;
- run hourly governed state/heartbeat lanes after acceptance to the default branch;
- create/update one idempotent drift issue;
- close the drift record after deterministic recovery;
- receive Dependabot GitHub Actions proposals.

It may not direct-write repairs to `main`, auto-merge, certify itself, manufacture votes, enable provider/customer writes, create exact prices, grant licenses or activate checkout.

The private control plane uses `institutional_federation.framework_package_registry` as the authoritative package registry. It separately tracks:

- package and framework identity;

- Agent D certification state;
- public/operational activation state;

Historical `repository_registry` rows may remain optional distribution projections for package-only R&D. Their missing GitHub repository IDs do not erase the corresponding package, but they do keep `linked_governed` child certification, operational activation and sovereign activation unavailable.

## Public distribution and monetization

Framework packages are designed to become sellable/useful public products where the applicable IP/right/governance gates permit it. Candidate forms include:

- licensed reference framework packages;
- managed framework runtime/services;
- API/MCP access;
- implementation/migration services;
- training/operator enablement;
- conformance assessment.

Issue `#131` remains the permanent disclosure and commercialization gate. The Factory may build packaging, manifests, validators, templates, training/service scopes and fulfillment designs. It does not invent prices, create Stripe Products/Prices, enable checkout, grant a package license, assert certification status or create customer entitlement without separate authority.

## Rollback and reopen

Rollback is a straight revert of the package-factory packet plus disablement of any package runtime binding. Historical package evidence remains preserved.

Reopen when package identity, workflow permissions, runtime/digest state, Agent D certification, API/MCP schema, IP classification, distribution rights, predecessor acceptance or constitutional authority changes.

Phase 2 / 2.99 remains current. Framework-package buildout does not itself open Phase 3.
