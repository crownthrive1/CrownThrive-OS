# Scheduled Task Agent Architecture

## Purpose

A scheduler is an execution trigger, not a source of institutional authority. Every durable scheduled or conditional workflow must resolve to a stable governed agent identity, skill contract, authority ceiling, evidence contract, escalation path, and retirement or supersession state.

```text
governed objective
→ CHLOM orchestration
→ stable agent + skill contract
→ private schedule or condition binding
→ permission and evidence gates
→ provider execution
→ readback and DAIL evidence
→ reconciliation
```

## Public authority boundary

The accepted sovereign voter set remains A/B/C/D/S. Eligible D0-D2 promotion requires four of five approvals, Agent D approval, no deny or block, applicable specialist evidence, rollback, and exact-head validation. D3 remains human-reserved.

Specialists, operational watches, sales agents, content agents, framework agents, subagents, provider tasks, repositories, OIDC identities, MCP tools and transport messages are non-voting unless separately accepted through the sovereign governance process. Scheduling or synchronizing an identity never creates a vote.

## Private binding registry

The restricted runtime stores provider task identifiers, precise schedules, current enabled state, routing, evidence and heartbeat details. Those operational values are intentionally omitted from this public projection.

The public contract may expose only:

- stable agent and capability identifiers already approved for publication;
- role and authority class;
- voting or non-voting status;
- required evidence and escalation interfaces;
- lifecycle and supersession semantics;
- non-secret contract digests after disclosure review.

Operational counts, exact cadence, provider task identifiers, recipients, credentials, private evidence and routing remain restricted and must be resolved from the governed private registry.

## Task lifecycle

```text
REQUESTED
→ AGENT_BOUND
→ SKILL_BOUND
→ SCHEDULED / CONDITION_WATCH
→ ACTIVE
→ HEARTBEAT / RUN EVIDENCE
→ VERIFIED / WATCH / HOLD / ACTION_REQUIRED
→ PAUSED / SUPERSEDED / RETIRED
```

A valid heartbeat does not prove authority. A candidate DID does not prove certification. A provider success response does not prove the intended outcome.

## Sales boundary

Sales and email agents may research, prepare and reconcile records within their individual authority ceilings. They must resolve current offers from the restricted governed registry at execution time. Public documentation must not duplicate unaccepted admin configuration, private price calibration, customer records or unsupported recurring-payment claims.

Cold outbound remains fail-closed unless the current private compliance record proves enablement, a verified physical postal address, lawful contact sourcing, suppression clearance and all other applicable gates.

## Completion standard

A scheduled workflow is complete only when its current private task is bound to the approved agent and skill, its authority and public/private classification are known, outcome evidence is recoverable, failures have an escalation and rollback route, and exact current state can be inherited without relying on chat or a public schedule snapshot.
