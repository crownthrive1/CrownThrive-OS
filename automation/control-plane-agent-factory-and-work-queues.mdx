# Automation Control Plane, Agent Factory and Work Queues

The automation control plane coordinates work across CrownThrive without giving one model, connector or vendor universal authority.

## Core services

1. **Objective intake** — founder directives, scheduled events, incidents, support cases, platform events and system health signals.
2. **Run-packet compiler** — converts the objective into scoped workstreams, sources, roles, tools, approvals, tests and rollback.
3. **Institutional retrieval** — resolves current records, source authority, audience, visibility and unresolved conflicts.
4. **Policy/authority evaluator** — CHLOM Rights, Rules, Roles, Risk and approval checks.
5. **Agent router/factory** — selects or instantiates registered specialist agents.
6. **Work queues** — priority, dependency, retry, dead-letter, hold and scheduled queues.
7. **Tool/MCP broker** — issues scoped credentials and routes tools to approved services.
8. **Approval service** — machine and human approvals with expiration and conditions.
9. **Verification/evaluation** — tests outputs, claims, rights, security, accessibility and audience fit.
10. **Execution gateway** — performs changes through versioned APIs/MCPs/adapters.
11. **DAIL recorder** — append-only event, evidence, correction and decision trail.
12. **Knowledge updater** — updates registries, docs, search, runbooks and next-run baseline.
13. **Watchdog/recovery** — detects failure, retries safely, rolls back or escalates.

### Agent factory template system

The factory does not generate unrestricted prompts. It instantiates stable, versioned contracts from:

- `developers/templates/agent-role-template.v1.yaml`;
- `developers/templates/subagent-role-template.v1.yaml`;
- `developers/templates/agent-pack-manifest-template.v1.json`;
- `developers/templates/chlom-capability-pallet-template.v1.yaml`;
- `developers/templates/third-party-attribution-template.v1.yaml`.

Every generated role must inherit its phase/gates, vote eligibility, allowed/prohibited actions, evidence policy, tests, rollback, documentation impact, archive lineage and commercial/IP restrictions. Scheduler runtime IDs and prompt text are projections of that stable contract, not the identity itself.

## Tool credentials

Agents receive task-scoped capabilities, not standing universal credentials. Credentials should be short-lived where feasible and reference a secret manager. Tool access is bound to:

- actor/agent;
- role;
- run ID;
- platform/tenant;
- environment;
- scopes;
- expiration;
- maximum actions/cost;
- approval state.

## Work isolation

Parallel agents may work from the same source snapshot but must not concurrently mutate the same record/file without a merge/lock strategy. Shared writes use optimistic concurrency, ETags/version preconditions or workflow locks.

## Quality gates

Every run selects applicable gates:

- source authority;
- factual/claim evidence;
- rights/provenance;
- legal-policy applicability;
- privacy/security;
- content/cultural alignment;
- accessibility;
- SEO/metadata;
- API/schema compatibility;
- tests/build/lint;
- commerce/entitlement;
- documentation-impact/article/changelog consistency;
- provider capability/account entitlement/deployment-state separation;
- phase-gate reconciliation;
- rollback/continuity.

## Minimal-human-input target

The control plane should auto-approve only actions explicitly covered by policy. Humans receive concise exception packets, not entire raw workflows. An exception packet states the decision, evidence, alternatives, risk, recommended action and consequence of delay.

## Observability

Track run success, latency, queue age, retries, cost, model/tool usage, approval delay, failure class, rollback, correction rate, human intervention rate and business outcome. Automation is successful when it reduces work without hiding risk or degrading institutional truth.

## Phase 3 implementation

Phase 3.0 seeds run, agent, role, tool, approval and event schemas. Phase 3A implements DAIL/approvals. Phase 3D connects MCPs/APIs. Phase 4 activates cross-platform work queues. Phase 5 allows certified external builders and partners to participate under CHLOM.
