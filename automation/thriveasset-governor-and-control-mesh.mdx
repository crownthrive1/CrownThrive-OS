# ThriveAssetGovernor and Asset Control Mesh

**State:** controlled test / non-voting.  
**Primary controller:** `ct.asset.agent-governor`.  
**Independent verifier:** `ct.asset.agent-scrutinizer`.  
**Authority ceiling:** D2.  
**External scheduler slots added:** zero.

`ThriveAssetGovernor` is the primary institutional controller for CrownThrive's complete asset estate. It coordinates the existing Proprietary Asset Factory rather than replacing or duplicating the 64-agent production fleet.

Its control loop is:

`inventory -> fingerprint -> classify -> deduplicate -> assign -> build -> test -> scrutinize -> custody -> package -> version -> release candidate -> monitor -> supersede`

## Agent mesh

| Agent | Function |
| --- | --- |
| `ct.asset.agent-governor` | Estate inventory, stable identity, lifecycle, assignments, dependency graphs, duplicate suppression, gap routing, and controlled promotion planning |
| `ct.asset.agent-scrutinizer` | Independent integrity, security, privacy, rights, dependency, test, custody, and commercial-truth verification |
| `ct.asset.agent-custodian` | Vault, encrypted archive, fingerprint, restore-test, and custody continuity |
| `ct.asset.agent-kernel-builder` | Kernels, executable profiles, scripts, launchers, and runtime candidates |
| `ct.asset.agent-contract-steward` | Schema, MCP, API, event, and public/private contracts |
| `ct.asset.agent-plugin-productizer` | Root plugins, pallet plugins, skills, customer packages, and non-live commercial candidates |
| `ct.asset.agent-release-sentinel` | Lifecycle-transition, release, rollback, drift, and supersession safeguards |

All seven agents are non-voting A2/D2 subroutes. They cannot create D3 authority, sovereign votes, direct-main merges, provider writes, operative rights, live prices, checkout, or entitlements.

## Governor authority

The Governor may inventory and classify assets, assign stable IDs and versions, detect duplicates, build dependency graphs, route bounded work, generate deterministic package candidates, open controlled-test and verification work, plan versioned supersession, record DAIL/custody receipts, and suppress false completion claims.

The Governor may not verify its own originating work, expose Vault secrets or private identity mappings, publish protected bodies, activate provider writes from a package definition, declare untested assets production, create live commerce, or delete historical custody/predecessor records.

## Scrutiny matrix

The independent Scrutinizer evaluates:

1. stable identity and version integrity;
2. owner/verifier separation;
3. rights and source provenance;
4. dependency completeness and cycles;
5. secret/private-identity leakage;
6. authority ceiling and tool annotations;
7. schema and semantic compatibility;
8. test, negative-test, and rollback coverage;
9. Vault and archive custody;
10. commercialization and public-claim truthfulness.

Structural validation may PASS while each asset remains on HOLD for rights, security, testing, custody, runtime, or commercialization evidence.

## Scheduling and scaling

The mesh uses the existing Vendor Engine Watch as an internal parent-task dispatcher at minute `:53`. It consumes no additional external scheduler slot.

Work-in-progress remains bounded. The Governor selects the smallest dependency-unlocking tranche, and the Scrutinizer verifies a different tranche identity. Thousands of candidates do not become thousands of simultaneous jobs.

## Counting integrity

The 5,760 records are derived package candidates:

`12 pallets × 10 capability families × 12 asset types × 4 deployment profiles`

They bind and productize the existing proprietary estate. They do not silently increase the authoritative 100,800 source-asset generation count.
