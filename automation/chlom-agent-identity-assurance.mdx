# CHLOM agent and framework-package identity assurance

CrownThrive agents, subagents and framework packages are bound to machine identity records in THIVEBASE/Supabase. The control proves **which governed identity acted, which framework package it belongs to, which repository transport hosted the execution when applicable, and whether authoritative transport heartbeats are current** without exposing private CHLOM Fingerprint material.

## Public/private rule

- public-facing DID may be public;
- stable agent UUID may be public;
- stable framework/package IDs may be public;
- exact observed source SHA/heartbeat may be public when their disclosure is classified public-safe;
- the CHLOM Fingerprint ID remains private;
- salts, private Fingerprint commitments, keys, credentials and private telemetry remain private;
- public verification uses safe identifiers and cryptographic digests.

A public page, manifest or API that exposes the private Fingerprint ID or private verification material fails governance review.

## Framework package identity is not repository identity

A framework child is an executable framework package, not a required standalone repository. Therefore:

- `package_id` + `framework_id` + `framework_agent_id` establish the package identity;
- `canonical_host_repo_id` identifies the current governed source/execution host;
- GitHub repository ID, full name, SHA and heartbeat are transport-host evidence where a physical GitHub context exists;
- an optional standalone repository may later become a distribution projection;
- absence of a standalone repository does **not** mean a framework package is missing, unbuilt or invalid.

The current package registry is `institutional_federation.framework_package_registry`.

## Public verification record

The public-safe agent identity directory is machine-readable at the governed public identity endpoint. Each agent record may expose:

- agent UUID;
- stable `agent_id`;
- framework ID where applicable;
- public DID and DID state;
- public identity digest;
- assurance/governance state;
- public authority ceiling and governed voting classification;
- repository transport fields when a physical repository context is applicable.

Package identity is additionally governed by the package manifest and the restricted Supabase framework-package registry. A future public package directory may expose only the #131-approved safe subset.

The public directory deliberately excludes private Fingerprint record UUIDs, salts, Fingerprint commitments, verification keys, credentials and secrets.

## Runtime auto-assignment

Supabase binds:

`framework_package_registry + repository_agent_bindings → CHLOM agent identity → DID binding → optional repository transport/SHA → heartbeat → SHA-256 public digest`

New governed agent/package bindings receive stable identity state without creating authority. The current `did:chlom:*` method remains an **internal candidate method**, not a claim that an externally resolvable DID method is already deployed. External resolution stays `UNKNOWN` until an accepted resolver implementation is proved.

## Framework package lifecycle behavior

A source-discovery or scaffold-preview package requires DID/UUID/public-digest identity for its framework agent but does not require a GitHub repository ID, child SHA or child heartbeat.

A controlled-test package may execute from the canonical parent repository. GitHub OIDC authenticates the trusted host workflow; package identity remains separate. Public/production operational status remains blocked until the required trusted-runtime authority binding, Agent D parent certification and governed framework acceptance pass.

The ordered Framework Factory sequence remains:

Package identity, repository transport identity, DID assignment, CI, heartbeat, MCP registration and Fingerprint registration create **no sovereign vote**.

## OIDC isolation

Pull-request validation receives no `id-token: write` permission. GitHub OIDC is isolated to trusted non-PR/default-branch runtime jobs. Before material federation mutation, the runtime must enforce exact workflow/ref/environment → institutional-agent/capability binding.

Repository-level OIDC identity alone does not prove the institutional agent has permission for a specific action.

## Documentation hard gate

`Documentation Governance` executes `scripts/chlom_identity_assurance.py`.

The review fails when:

- public DID/UUID/digest fields are missing;
- an active canonical repository transport lacks required repository ID, SHA or heartbeat evidence;
- a framework package is incorrectly made dependent on a standalone repository;
- a framework package claims operational/public state before required certification/acceptance;
- a framework agent becomes vote-eligible merely through identity assignment;
- a Fingerprint ID/commitment, key reference, credential or secret leaks into public output;
- PR validation receives OIDC authority;
- the public/private identity contract is weakened.

On the default branch, the scheduled CHLOM identity workflow may emit the authoritative parent heartbeat from an isolated OIDC-enabled job after validation passes. Pull-request review performs read-only identity validation.

## Cryptographic boundary

A SHA-256 public identity digest is an integrity digest of public-safe identity state. It is not the private CHLOM Fingerprint ID and is not automatically a digital signature. Signature/verifiable-credential claims require separately proved key custody, verification and governance.

## Rollback and recovery

The package-registry migration is additive. Code rollback can revert workflow/validator/docs changes without deleting identity evidence. Destructive identity-data rollback requires separate governed authority.

If package or transport state drifts, preserve last-known evidence, mark stale/HOLD as appropriate and repair through governed readback. Never manufacture a heartbeat, SHA, repository ID, package ID, DID resolution claim or Fingerprint proof.
