# Agent factory and template library

CrownThrive treats an agent as a **versioned institutional component**, not merely a prompt. The factory preserves role intent, authority, evidence rules, tools, schedules, evaluations, source code, lineage and retirement history so the operating model survives model/provider changes.

## Current topology

The current Phase 2.99 execution topology has three distinct classes:

| Class | Current members | Authority effect |
| --- | --- | --- |
| Sovereign voters | A, B, C, D, S | fixed five-agent voter pool; eligible D0–D2 promotion requires 4/5 plus D |
| Scheduled non-voting specialists | E, F, G, H | execution/evidence capacity only; no sovereign vote |
| Embedded non-voting subagents | integration-heartbeat, credential-continuity, vendor-engine-watch, I continuity-recovery, J phase3-snapshot-packet, K roadmap-transition | invoked inside scheduled roles; no scheduler slot and no vote |

Scheduler capacity never changes quorum. Adding a specialist does not create authority.

## Factory lifecycle

```text
institutional need
→ define stable agent ID and mission
→ map phase/gate responsibility
→ assign D0–D3 authority ceiling
→ define tools/data/environment boundaries
→ define evidence + source precedence
→ define stop/escalation rules
→ define evaluations + negative tests
→ choose scheduled or embedded execution form
→ register version and source template
→ controlled test
→ limited production
→ monitor and self-heal within authority
→ version, supersede or retire
→ archive every prior version
```

## Canonical source assets

The factory is backed by repository-controlled machine files:

- `developers/templates/agent-definition.template.yaml` — reusable scheduled-agent definition;
- `developers/templates/subagent-definition.template.yaml` — embedded helper definition;
- `developers/manifests/institutional-agent-topology.v1.json` — current topology and phase/gate assignments;
- `developers/manifests/thivebase-operational-automation.v1.json` — current THIVEBASE operational delegation overlay;
- `scripts/scaffold_crownthrive_agent.py` — deterministic scaffold generator;
- `scripts/validate_agent_topology.py` — topology/quorum/authority validator;
- `scripts/validate_thivebase_operational_automation.py` — THIVEBASE-specific invariant validator.

The templates contain no production secrets, provider keys, customer data or restricted evidence.

## Scheduled versus embedded agents

Use a **scheduled specialist** when a role benefits from independent recurring observation, separate cadence, collision-aware ownership and a distinct handoff. Use an **embedded subagent** when the role is narrow, event/gate triggered, would otherwise consume scarce scheduler capacity, or must execute only under a parent agent's current run packet.

Embedded does not mean hidden or informal. Every embedded subagent still requires a stable ID, version, scope, prohibited actions, expected evidence, parent routing and evaluation criteria.

## Audience projections

The same institutional record supports multiple audiences without duplicating authority:

- **Founder/executive:** role, current phase, blocker, risk, decision required.
- **Operator:** allowed tools, run packet, stop conditions, rollback and handoff.
- **Developer:** source template, schemas, validation commands, version and interface contract.
- **Security/legal/rights:** data classes, prohibited actions, third-party dependencies, evidence and human gates.
- **Machine/ML retrieval:** stable IDs, version, state, source references, authority ceiling, parent/child relationships and effective dates.
- **External/licensee:** public-safe template capabilities and license terms only; no CrownThrive private rules, secrets or restricted fixtures.

## Continuity rule

Every accepted agent version remains reconstructable from its source template, machine manifest, changelog, tests and referenced institutional standards. A new version supersedes; it does not erase. Provider/model changes are implementation changes unless the role's institutional meaning changes.
