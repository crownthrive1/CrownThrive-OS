# Agent registry

Every CrownThrive agent receives a canonical ID, role, owner, scope, tool permissions, data classifications, approval limits, evaluation suite, and escalation path.

## Required registry fields

```yaml
agent_id: commerce-agent
name: Commerce Agent
owner: CrownThrive Operations
status: controlled-test
mission: Reconcile products, prices, payments, entitlements, credits, refunds, and commerce rails.
allowed_data_classes:
  - PUBLIC
  - INTERNAL
allowed_tools:
  - stripe-read
  - product-registry-read
  - entitlement-reconciliation
approval_limits:
  live_price_change: false
  high_value_refund: false
escalation_owner: founder-or-commerce-manager
```

## Four-agent institutional relay

The Phase 2.99 continuation program currently uses the [Institutional Hourly Agent Relay](/automation/institutional-hourly-agent-relay): Agent A Orchestrator at `:00`, Agent B Evidence Auditor at `:15`, Agent C Builder at `:30`, and Agent D Gatekeeper at `:45` each hour. These are **coordination roles**, not new authority classes; every relay role inherits the registry, D0–D3, phase-gate, evidence and separation-of-duties rules below.

## Virality daily scheduled lane

The existing scheduled institutional agents carry the Virality SoundCloud daily lane without adding another active automation:

| Scheduled role | Daily responsibility | Authority boundary |
| --- | --- | --- |
| Agent G | permitted non-API SoundCloud/public evidence packet | read-only; public observation remains `observed_unverified`; no SoundCloud API credential/read/write |
| Agent E | private Supabase reconciliation and disabled internal MCP contract state | idempotent writes to the control registry; enforce `REMOVED_BY_FOUNDER_OVERRIDE` for SoundCloud API paths; no provider write |
| Agent C | material GitHub/Mintlify change and durable-file custody | no routine numeric commit; no self-merge |
| Agent D | exact-head review, check enforcement, and A/B/C/D/S quorum stewardship | D is mandatory; blocked gaps cannot become PASS |
| Integration Heartbeat subagent | verify daily row/blocker and G → E → C handoff coherence | non-voting; alert and reconcile only |

Each scheduled role runs its lane at most once per America/New\_York calendar day, even though the parent agents execute hourly. SoundCloud API tooling is permanently removed from this lane under the August 20, 2026 founder override; no agent may request, store, configure, certify, invoke, or reintroduce SoundCloud API credentials, reads, writes, adapters, or API-dependent schedules. Live recommendation execution remains separately gated.

### Durable artifact custody rule

Every document, report, manifest, migration, source page, or other durable file created by an agent must also be copied to connected Google Drive using `CrownThrive_[Platform-or-Workstream]_[Document-Type]_[Short-Title]_[YYYY-MM-DD]_v#`, placed in the appropriate private folder, and verified by readback. If Drive is unavailable or verification fails, the agent records `ACTION NEEDED` and may not call the file workflow complete.

## Chief-of-Staff / Orchestrator Agent

**Owns:** task decomposition, routing, dependency management, workflow state, completion reconciliation, and founder briefs.

**Produces:** structured plans, assigned tasks, status reports, decision briefs, escalation notices, and final reconciliation reports.

**May not:** grant rights, publish protected material, approve its own high-risk outputs, or represent partial completion as complete.

## Documentation Sentinel

- **Agent ID:** `ct.agent.documentation-sentinel`
- **Authority:** A0 / D0, read-only
- **Owns:** drift detection across CrownThrive Support, registered public properties, connected repositories, provider documentation, routes, links, versions, claims and phase gates.
- **Produces:** evidence packets, stale-source notices, broken-link findings, contradiction records and `docs_delta_opened` tasks.
- **May not:** edit, approve, merge, publish or promote unverified state.

## Documentation Steward

- **Agent ID:** `ct.agent.documentation-steward`
- **Authority:** A1 / D1 and policy-eligible bounded D2
- **Owns:** stable article IDs, frontmatter, navigation, redirects, version/correction records, source references, low-risk link repair and per-platform changelogs.
- **May approve:** deterministic D1 fixes after validators pass; bounded D2 only with independent verifier and no legal, rights, privacy, security, economic, canon or contractual materiality.
- **May return:** `approve`, `approve_after_mechanical_fixes`, `deny_with_required_changes`, `escalate_for_domain_review`, `block_due_to_missing_evidence`.
- **May not:** approve its own material originating change or erase prior versions.

## Evaluation requirements

Every production-facing agent should have evaluations for:

- task classification
- source and evidence use
- permission boundaries
- refusal and escalation
- tool selection
- output completeness
- public-claim discipline
- secret and protected-data handling
- duplicate and retry behavior
- correction after failure

## Agent lifecycle

Recommended states:

- `DESIGN`
- `SANDBOX`
- `CONTROLLED_TEST`
- `PRODUCTION_LIMITED`
- `PRODUCTION`
- `SUSPENDED`
- `RETIRED`

Promotion requires evaluation evidence, scoped tool access, monitoring, documented failure paths, and an accountable human owner.

<Warning>
  An agent title does not create authority. Authority comes from the registry, current permissions, task scope, and recorded approvals.
</Warning>
