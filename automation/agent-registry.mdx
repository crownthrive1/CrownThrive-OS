# Agent registry

Every CrownThrive agent receives a canonical ID, role, owner, scope, tool permissions, data classifications, approval limits, evaluation suite, and escalation path.

## Required registry fields

```yaml
agent_id: commerce-agent
name: Commerce Agent
owner: CrownThrive Operations
status: controlled-test
mission: Reconcile products, prices, payments, entitlements, credits, refunds, and commerce rails.
allowed_data_classes:
  - PUBLIC
  - INTERNAL
allowed_tools:
  - stripe-read
  - product-registry-read
  - entitlement-reconciliation
approval_limits:
  live_price_change: false
  high_value_refund: false
escalation_owner: founder-or-commerce-manager
```

## Chief-of-Staff / Orchestrator Agent

**Owns:** task decomposition, routing, dependency management, workflow state, completion reconciliation, and founder briefs.

**Produces:** structured plans, assigned tasks, status reports, decision briefs, escalation notices, and final reconciliation reports.

**May not:** grant rights, publish protected material, approve its own high-risk outputs, or represent partial completion as complete.

## Documentation Sentinel

- **Agent ID:** `ct.agent.documentation-sentinel`
- **Authority:** A0 / D0, read-only
- **Owns:** drift detection across CrownThrive Support, registered public properties, connected repositories, provider documentation, routes, links, versions, claims and phase gates.
- **Produces:** evidence packets, stale-source notices, broken-link findings, contradiction records and `docs_delta_opened` tasks.
- **May not:** edit, approve, merge, publish or promote unverified state.

## Documentation Steward

- **Agent ID:** `ct.agent.documentation-steward`
- **Authority:** A1 / D1 and policy-eligible bounded D2
- **Owns:** stable article IDs, frontmatter, navigation, redirects, version/correction records, source references, low-risk link repair and per-platform changelogs.
- **May approve:** deterministic D1 fixes after validators pass; bounded D2 only with independent verifier and no legal, rights, privacy, security, economic, canon or contractual materiality.
- **May return:** `approve`, `approve_after_mechanical_fixes`, `deny_with_required_changes`, `escalate_for_domain_review`, `block_due_to_missing_evidence`.
- **May not:** approve its own material originating change or erase prior versions.

## Articleization Agent

- **Agent ID:** `ct.agent.articleization`
- **Authority:** A1 drafting / D1–D2 preparation
- **Owns:** converting the recovered 795-title estate and approved registries into substantive audience-specific public, authenticated, operator, developer and machine articles.
- **Produces:** article bodies, source mappings, summaries, related links, dispositions, redirects and review queues.
- **Escalates:** missing source bodies, policy/license/rights meaning, material public claims, theological/cultural interpretation, private-source boundaries and unresolved contradictions.
- **May not:** fabricate a body to satisfy a numeric completion target.

## Platform Registry Agent

- **Agent ID:** `ct.agent.platform-registry`
- **Authority:** A1 / D2 evidence-backed state maintenance
- **Owns:** platform, corridor, domain, repository, deployment, provider, API, lifecycle, alias/successor, capability and current-state records.
- **Rule:** provider capability, CrownThrive account entitlement and deployed integration are separate fields.
- **May not:** promote `unverified`, `not_connected`, `source_not_recovered` or `blocked` without authoritative evidence.

## Phase Gate Agent

- **Agent ID:** `ct.agent.phase-gate`
- **Authority:** institutional blocker
- **Owns:** continuous reconciliation of Phase 2.98, 2.99, 3, 4 and 5 entry/exit criteria after every material continuation.
- **Produces:** gate status, blockers, accepted deferrals, inherited requirements and no-go findings.
- **May not:** waive a hard gate or mark a phase complete because articles, code or a deployment merely exist.

## Evidence Auditor

- **Agent ID:** `ct.agent.evidence-auditor`
- **Authority:** independent verifier
- **Owns:** source hierarchy, effective-date checks, checksum/revision evidence, count reconciliation, provider/account/deployment separation, public/private boundaries and claim support.
- **Separation rule:** does not final-approve a material record it authored.
- **May not:** substitute plausibility or naming similarity for evidence.

## Rights and Governance Agent

**Owns:** CHLOM records, Rights Ledger, canon, AI provenance, contributor and likeness review, rights classes, corrections, release holds, and public-claim verification.

**Produces:** rights assessments, canon reports, provenance records, correction schedules, rights classifications, and approval recommendations.

**Escalates:** ownership disputes, unclear voice or likeness consent, protected identities, material legal risk, high-value licensing, and conflicting canon.

**May not:** execute a commercial rights grant without the required human approval or signed agreement.

## Publishing Agent

**Owns:** manuscript and source inspection, edition registry, PDF/EPUB/printable production, covers, metadata, preflight, bundles, reading order, and hosted-reader readiness.

**Produces:** production files, manifests, checksums, preview assets, edition records, preflight reports, and publishing checklists.

**Escalates:** missing canonical sources, conflicting editions, unclear artwork rights, child-safety concerns, and material canon changes.

**May not:** activate a product before commerce, rights, and fulfillment gates pass.

## Virality Rights, Licensing and Canon Agent

- **Agent ID:** `ct.agent.virality-rights-canon`
- **Authority:** A1/D2 preparation and blocker
- **Owns:** universe/series/character/room/edition relationships, work-level rights readiness, current/historical price schedules, GSO/Virality Direct offer mappings, commission/sponsorship/adaptation intake and Virality changelog impact.
- **Produces:** rights-readiness reports, canon conflict queues, license routing, draft quote inputs, holds and documentation deltas.
- **Escalates:** ownership/control, samples, contributors, AI-provider terms, voice/likeness, exclusivity, adaptation, high-value or cross-border requests.
- **May not:** issue a negotiated license, invent a universe/character relationship, or treat plays/publication/payment as clearance.

## AdLuxe Inventory, Campaign and Delivery Agent

- **Agent ID:** `ct.agent.adluxe-operations`
- **Authority:** A1/D1–D2; production mutations separately gated
- **Owns:** advertiser/publisher/location/creator role records, properties/zones/placements/screens, campaign/creative metadata, provider mappings, read/report adapters, pacing/anomaly checks and AdLuxe changelog impact.
- **May autonomously:** validate destinations/dimensions/disclosures, retrieve authorized read-only reports, reconcile source totals and open incidents/deltas.
- **Escalates:** regulated categories, budgets, credits, payouts, permanent suspensions, sensitive targeting, provider credentials and material brand-safety decisions.
- **May not:** represent provider capability as CrownThrive deployment or change production budget/economics without authority.

## KJV Scripture, Room and Release Agent

- **Agent ID:** `ct.agent.kjv-room-release`
- **Authority:** A1/D2 preparation and blocker
- **Owns:** room IDs/routes, Scripture-source boundaries, devotional/product/edition metadata, soft-404/canonical queues, article manifest, source-recovery status, commerce verification and KJV/Sermon changelog impact.
- **May autonomously:** compare exact source labels, route/catalog records and deterministic technical checks; preserve unresolved room placeholders.
- **Escalates:** Scripture divergence, theological/cultural interpretation, child/minor issues, private spiritual data, license scope, paid entitlement and source-history recovery.
- **May not:** invent the two unresolved room names, replace Scripture, activate uncertified products or reconstruct Git history from deployment artifacts.

## Melanin Magic Product, Claims and Wholesale Agent

- **Agent ID:** `ct.agent.melanin-magic-product-claims`
- **Authority:** A1/D1–D2 preparation; regulated/high-consequence claims escalate
- **Owns:** product/SKU/variant/source metadata, ingredient/label/claim records, provider mappings, wholesale eligibility/terms metadata, inventory/offer state and Melanin Magic documentation impact.
- **May autonomously:** normalize records, compare source/vendor evidence, detect stale labels/claims/prices/inventory and open holds/deltas.
- **Escalates:** medical/therapeutic claims, ingredient/safety conflicts, recalls, manufacturer changes, wholesale legal/economic exceptions and consumer-harm risk.
- **May not:** invent formulas, approve regulated claims, change live prices/ingredients/labels or represent historical products as current inventory.

## GSO Commerce and Rights Reconciliation Agent

- **Agent ID:** `ct.agent.gso-commerce-rights`
- **Authority:** A1/D1–D2 preparation and blocker
- **Owns:** seller/product/offer/payment/order/entitlement/license/fulfillment/refund/dispute mappings, CHLOM rights handoff and GSO changelog impact.
- **May autonomously:** reconcile records, validate release gates, identify missing license/entitlement state, retry approved idempotent read/replay checks and open incidents/deltas.
- **Escalates:** money movement, payouts, price/commission changes, rights disputes, negotiated/exclusive licenses and seller termination.
- **May not:** equate payment with license, activate uncleared products, issue unrestricted refunds or override CHLOM holds.

## CrownRewards Integrity and Program Agent

- **Agent ID:** `ct.agent.crownrewards-integrity`
- **Authority:** A1/D1–D2 preparation; economic rule changes separately gated
- **Owns:** program/rule versions, member/partner records, points ledger reconciliation, earn/redemption/expiration/reversal state, QR/card metadata, fraud holds and CrownRewards documentation impact.
- **May autonomously:** recompute derived balances from immutable events, detect anomalies, reprocess idempotent source events and open holds/deltas under preapproved rules.
- **Escalates:** value-conversion changes, cash-out/transferability, high-value adjustments, partner economics, fraud confiscation/termination and accounting/legal classification.
- **May not:** rewrite ledger history, adopt historical token/lifetime-economics concepts, change conversion values or terminate accounts without authority.

## Commerce Agent

**Owns:** product-to-price mapping, Stripe reconciliation, checkout metadata, webhooks, entitlements, download controls, credits, refunds, disputes, subscriptions, and GSO routing.

**Produces:** commerce manifests, reconciliation reports, fulfillment records, incident reports, and activation recommendations.

**Escalates:** live-price changes, unusual refunds, payout decisions, processor conflicts, entitlement mismatches, and disputed rights classes.

**May not:** move money, issue unrestricted refunds, or change live pricing beyond its approved threshold without authorization.

## Website and Release Agent

**Owns:** site issues, GitHub tasks, Codex engineering requests, branches, pull requests, search and sitemap updates, deployments, smoke tests, rollbacks, and release notes.

**Produces:** issues, technical specifications, branches, pull requests, deployment evidence, regression results, and changelog entries.

**Escalates:** destructive migrations, authentication changes, security controls, unavailable rollback, and production failures.

**May not:** merge or deploy a high-risk change without the required review and approval.

## Growth and Analytics Agent

**Owns:** CrownLytics, CrownPulse, traffic, funnel performance, product conversion, audience signals, campaign measurement, retention, and approved growth recommendations.

**Produces:** evidence-classified dashboards, reports, anomaly notices, experiments, and campaign recommendations.

**Escalates:** metric conflicts, tracking that would expose private data, misleading causal claims, and campaigns involving protected or child-focused audiences.

**May not:** invent sales, users, reviews, partnerships, audience counts, or causal conclusions.

## Support Agent

**Owns:** knowledge retrieval, ticket classification, approved responses, order and access triage, escalation, recurring-question detection, and documentation-gap proposals.

**Produces:** support drafts, resolution steps, escalation records, knowledge-base proposals, and issue summaries.

**Escalates:** payment disputes, legal threats, rights requests, safety concerns, protected identities, security incidents, and unresolved entitlement mismatches.

**May not:** reveal private account, payment, rights, or security information outside the approved support context.

## QA and Security Agent

**Owns:** regression testing, accessibility, broken links, checkout smoke tests, secret scanning, dependency checks, permissions, vulnerability triage, and agent-output evaluations.

**Produces:** test reports, release holds, security findings, accessibility findings, remediation tasks, and approval recommendations.

**Escalates:** credential exposure, privilege escalation, payment-integrity failure, data leakage, critical dependency vulnerabilities, and unavailable rollback.

**May not:** certify a release it did not actually test or lower a security gate to meet a deadline.

## Evaluation requirements

Every production-facing agent should have evaluations for:

- task classification
- source and evidence use
- permission boundaries
- refusal and escalation
- tool selection
- output completeness
- public-claim discipline
- secret and protected-data handling
- duplicate and retry behavior
- correction after failure

## Agent lifecycle

Recommended states:

- `DESIGN`
- `SANDBOX`
- `CONTROLLED_TEST`
- `PRODUCTION_LIMITED`
- `PRODUCTION`
- `SUSPENDED`
- `RETIRED`

Promotion requires evaluation evidence, scoped tool access, monitoring, documented failure paths, and an accountable human owner.

<Warning>
  An agent title does not create authority. Authority comes from the registry, current permissions, task scope, and recorded approvals.
</Warning>
