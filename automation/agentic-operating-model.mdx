# Agentic Operating Model

CrownThrive's automated team should be designed as a **supervised institutional workforce**, not a collection of chatbots with unrestricted credentials.

## Architecture

```text
Objective / Event
      ↓
Chief-of-Staff Orchestrator
      ↓
Institutional registries + approved knowledge
      ↓
Rights / Rules / Role / Risk checks
      ↓
Specialist agent
      ↓
Approval Service when required
      ↓
Codex / MCP / scoped application tool
      ↓
Validation / QA / Evals
      ↓
Production mutation
      ↓
DAIL event + evidence
```

## Agent classes

- Chief-of-Staff / Orchestrator
- Rights & Governance
- Publishing / Content Operations
- Commerce / Entitlements
- Website / Release Engineering
- Growth / Analytics
- Support / Knowledge
- Security / SRE / QA
- Finance / Reconciliation assistants as permitted
- Corridor-specific agents with inherited governance

## Sandbox and credential model

Long-running agents should execute code and untrusted work inside controlled sandboxes. Credentials remain outside model-generated execution environments where possible. MCP and application tools expose narrowly scoped capabilities, short-lived authorization where supported, explicit resource boundaries and audited actions.

## External control baselines

CrownThrive's internal control profile should map relevant practices to **NIST Cybersecurity Framework 2.0** and **NIST AI Risk Management Framework / Generative AI Profile**. These are voluntary risk-management frameworks, not certifications. Agent systems should use testing, evaluation, verification, validation, incident monitoring and documented human accountability.

## Codex role

Codex is the engineering workforce. Repositories should define `AGENTS.md`, reliable tests, environment setup, scoped tasks, branch isolation and review requirements. Parallel agents may work independently, but production changes still flow through repository controls and approval gates.

## Agents SDK role

The Agents SDK is a candidate orchestration harness for long-running file/tool work, memory, controlled sandbox execution and MCP/skills integration. CrownThrive should wrap it in its own institutional registries, approvals and event model rather than letting the framework define business authority.

## Phase 3 minimum

Do not turn on broad autonomous workflows until DAIL, Approval Service, Rights Registry, Role/Authority, secrets boundaries, test/eval harnesses and rollback behavior exist.
