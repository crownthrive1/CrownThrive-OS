## PentaFabric™ Generation 61

PentaFabric is CrownThrive's controlled-test orchestration fabric for coordinating CHLOM, the Cultural Imprint Engine, the Convergent Ecosystem, ThriveBase, DAIL, CrownLytics, maintenance, security, proprietary custody, software-factory execution, release packaging, and wave continuity.

<Warning>
  PentaFabric is not a grant of D3 authority. D3 remains human-reserved. The Penta family does not inherit money-movement, rights-grant, provider-write, legal, economic, or self-approval authority.
</Warning>

## PentaSpecter maintenance contract

PentaSpecter uses a strict 2:00 AM to 5:00 AM `America/New_York` maintenance window. PentaCrons uses DST-safe UTC candidate schedules plus a local-time gate, so only the actual Eastern-time window can create maintenance work.

Within the window the software may inspect actual recent failures, create bounded bug-squash jobs, require reproduction and regression evidence, send valid jobs to the CrownThrive Autonomous Software Factory, require the governed compiler/assurance lanes, and preserve rollback plus parent-child repository targets.

At and after 5:00 AM Eastern, PentaFabric creates no new maintenance work for that window. Pending Penta work is expired or held according to state, and associated unfinished factory requests are placed on hold rather than silently extending the maintenance period.

## PentaSecure package rule

Every active security finding is treated as a separate package candidate. The default release-impact mapping is:

- critical security issue: `security_hotfix`, with patch plus security-appendix policy;
- high severity: `security_patch`;
- medium, low, or informational security update: `security_update`;
- breaking or deliberately major change: `major_fix_candidate`, requiring separate governed release authority;
- ordinary reproducible defect: `bugfix_patch`.

The runtime does not infer a major release merely because a fix is important.

## Wave continuity

PentaWave stores each wave as a versioned write packet with predecessor, objective, source reference, bounded authority, DAIL evidence, and the next software-factory compile request. This prevents later waves from rediscovering or silently replacing prior decisions.
