## Proprietary Capability Factory

The Proprietary Capability Factory is the independent agent fleet responsible for continuing CrownThrive's protected algorithm, skill, prompt, and script estate after **48 completed governed generations**.

<Warning>
  This page publishes roles, counts, schedules, and control boundaries only. It does not expose protected implementations, prompt or script bodies, weights, thresholds, private identities, recovery material, Vault locations, or per-asset raw fingerprints.
</Warning>

## Current fleet

The factory contains **64 active, non-voting, no-self-approval candidate agents** with private identity pins. Their functional lanes include:

- orchestration and queue control;
- source and market intelligence;
- domain architecture and capability graphs;
- algorithm, skill, prompt, and script synthesis;
- testing, benchmarking, red teaming, and failure injection;
- security, privacy, rights, licensing, and supply-chain review;
- Vault, encryption, Drive, recovery, and continuity;
- DAIL, evidence, correction, and supersession;
- documentation and public-safe projection;
- productization, pricing, unit economics, fulfillment, support, and entitlement design;
- API/MCP packaging and cross-platform interoperability;
- portfolio monetization and customer-value evidence; and
- independent verification and release-governance support.

Every agent is `vote_eligible=false` and `no_self_approval=true`. No factory agent may exercise D3, sign for a human, grant rights, move money, publish protected bodies, enable checkout, create Stripe objects, issue customer entitlements, or create unrestricted provider-write authority.

The two current Cohort A Product/Price pairs were created under explicit founder authority and exact offer contracts. Their existence does not widen agent authority.

## Schedule model

The verified topology includes continuous orchestration, daily build and validation, daily DAIL and integrity review, daily documentation reconciliation, recurring security and rights review, weekly commercialization review, and monthly encrypted custody work.

The Machine Trigger Asset Fabric adds a separate **hourly, read-only reconciliation workflow**. It can deterministically materialize and validate the 32 current trigger bundles, 128 derivative candidates, five plugin records, and 32 Vault-binding candidates. It cannot mutate the authoritative generation count or activate a trigger into production on schedule.

The active policy is:

```text
ct.policy.chlom-proprietary-factory-100k-plus
```

It records 48 completed generations and allows only one candidate generation at a time. The next range is G49-G60 under a minimum 30-day cadence and prior-generation dependency controls.

```text

→ G49-G60 candidate-only continuation
→ independent verification
→ bounded cohort evaluation

```

The orchestrator may enqueue a candidate only when:

- exact ciphertext readback is verified;
- DAIL integrity is clean or explicitly held;
- security and rights preflight is complete;

- production, self-serve checkout, automatic Stripe, and entitlement activation remain false.
