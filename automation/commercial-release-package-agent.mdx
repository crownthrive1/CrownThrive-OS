# Commercial Release Package Agent

The **CrownThrive Commercial Release Package Agent** converts each exact product build into a machine-addressed release package. It is the implementation originator, not the approver. It cannot vote, satisfy quorum, grant rights, authorize a price, move money, activate checkout, expose credentials, or publish directly to a provider.

## Current scope

The first exact cohort is the 30 packaged products for CrownThrive Launch, CrownThrive Ready, and CrownThrive Procure. Each package binds the product SKU, version, asset SHA-256, ChatGPT Sites surface, candidate credit band, tax-profile candidate, required gate set, rollback requirements, and governed release record.

The customer-facing transaction model is **credit-only**. Stripe is not a per-product checkout rail. Any future Stripe use is limited to separately governed Crown Credit funding. A provider payment cannot independently create a license, entitlement, or delivery instruction.

## Worker federation

The parent agent delegates bounded evidence work to nonvoting workers for:

- rights and license lineage;
- credit pricing and tax evidence;
- private fulfillment and delivery canaries;
- credit checkout, webhook replay, and idempotency;
- entitlement, license acceptance, and protected delivery;
- accessibility and assistive-technology evidence;
- DNS, TLS, canonical-route, and application readback;
- governed Sites feed publication; and
- exact-version certification and vote-packet routing.

Every worker is A1/A2 and D1/D2, inherits no sovereign authority, and requires an independent verifier for consequential PASS state.

## Publication boundary

The agent uses the already-certified `ct.adapter.dynamic-feed.v1` publication path. The three ChatGPT Sites routes remain HOLD until each site proves that it consumes the governed feed and passes write, read-after-write, rollback, reapply, and public readback. Direct Sites mutation is not inferred from provider project custody.

A product can enter the publication queue only after all required dimensions are `pass` or `not_applicable`, the exact content hash is unchanged, four sovereign yes votes are present, Agent D is affirmative, no negative vote exists, the destination is certified, and any D3 boundary has explicit human approval.

## Required trust sequence

```text
exact product build
→ rights and license clearance
→ credit pricing and tax authority
→ private fulfillment certification
→ credit checkout/webhook certification
→ license acceptance and entitlement certification
→ accessibility certification
→ DNS/TLS and destination certification
→ independent governed acceptance
→ feed publication
→ read-after-write
→ rollback proof retained
```

The sequence follows the same institutional pattern used by Virality Music and KJV Visualized: inspectable catalog state, explicit rights classes, closed checkout until verified, license before entitlement, and protected delivery only after authorization.

## Private boundary

Protected scoring weights, coordination algorithms, retry/drift thresholds, private evidence, storage paths, provider identifiers, credentials, and recovery material are held in THIVEBASE/Vault. GitHub and Mintlify receive only the public-safe contract, identifiers, lifecycle state, and digests.
