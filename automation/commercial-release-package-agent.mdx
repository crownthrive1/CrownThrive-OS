# Commercial Release Package Agent

The canonical **CrownThrive Commercial Release Package Agent** extends the existing THIVEBASE `ct.agent-suite.commercial-release-factory.v1` and converts packaged CrownThrive products into exact-digest release candidates without fabricating rights, professional conclusions, independent review, provider delivery or sovereign acceptance.

```yaml
agent_id: ct.agent.commercial-release-packager
parent_agent_id: ct.governance.agent.commercial-sites-relay
autonomy_ceiling: A2
decision_ceiling: D2
vote_eligible: false
quorum_eligible: false
self_approval: false
production_activation: false
provider_write_default: false
```

## Current scope

The first controlled cohort is the 30 packaged `1.0.0-candidate.4` toolkits for CrownThrive Launch, CrownThrive Ready and CrownThrive Procure. The products remain credit-only. The agent may prepare a policy-band credit-price candidate, but it cannot authorize that price, tax treatment or checkout.

Each Launch or Procure product has **10 canonical release dimensions**. CrownThrive Ready adds one **qualified-professional-review** dimension, for **11 required dimensions**. Seven historical labels are preserved only as aliases and are not double-counted as independent gates.

The canonical dimensions are:

1. package integrity;
2. rights provenance, including licensing/assent boundary;
3. pricing and tax;
4. private fulfillment;
5. credit checkout and webhook controls;
6. entitlement and license separation;
7. refund, dispute and rollback;
8. accessibility and device/assistive-technology evidence;
9. DNS, TLS and canonical-route readback;
10. governed acceptance and ChatGPT Sites publication; and
11. Ready-only qualified-professional review.

Historical aliases retained for continuity are `rights_licensing`, `fulfillment`, `checkout_webhook`, `entitlement`, `accessibility`, `dns_tls`, and `destination_readiness` where applicable. Aliases never create extra approval seats or allow a release to satisfy a gate twice.

For every SKU, the package binds immutable product/version and asset-digest evidence; rights/license requirements; comparable-backed pricing and tax evidence; private delivery and rollback; credit redemption and replay controls; entitlement/remedy state; accessibility/device evidence; DNS/TLS/route proof; Vault-only credential custody; and exact-digest governed acceptance.

## Reference-site inheritance

The workflow inherits the proven operating patterns used by Virality Music and KJV Visualized / The Sermon Toolkit:

- product records and proof remain distinguishable from checkout activation;
- payment evidence is separate from license and entitlement;
- source, count, rights, editorial and technical evidence remain independently typed;
- account, store, support, accessibility, terms and correction paths are explicit;
- delivery and rollback are proven on the actual route rather than inferred from a build;
- public claims are date-bound and traceable.

This is pattern inheritance, not authority inheritance. Launch, Ready and Procure must produce their own exact evidence.

## Current controlled-test evidence

The current synthetic Crown Credits lane proves purchase planning, exact replay/idempotency, refund reversal and dispute reversal for all 30 products without customer-balance mutation, money movement, checkout activation or live entitlement. That evidence advances only the applicable technical gates. It does not satisfy operative license acceptance or private delivery.

Current public destination evidence is fail-closed:

- all three ChatGPT Sites provider roots return HTTP `401 Sign in required` to anonymous readback;
- `launch.crownthrive.com`, `ready.crownthrive.com` and `procure.crownthrive.com` do not currently resolve in DNS from the governed runtime;
- historical desktop interaction and CSS breakpoint/overflow checks exist, but exact device-width, screen-reader and representative-user testing remain open.

## Automatic publication boundary

Automatic publication is permitted only after every applicable canonical gate is accepted on the exact package digest, the required A/B/C/D/S quorum is satisfied with Agent D included, no current block exists, the destination consumer is certified, and rollback/read-after-write proof exists.

The agent never:

- creates or records a human review, qualified-professional conclusion or sovereign vote;
- treats green CI as institutional acceptance;
- creates cash checkout, Stripe Product/Price objects or money movement for these credit-only products;
- returns a raw credential or Vault locator;
- writes directly to `main`, merges itself or bypasses a HOLD;
- mutates DNS, TLS, provider state or customer entitlements without a separately accepted execution receipt.

## Replication model

The parent relay already federates seventeen scoped non-voting workers beneath the canonical packager and may install the same bounded contracts into future workers. Replication copies contracts, tests and fail-closed limits; it does not copy sovereign authority, credentials or reviewer identity. Every clone receives a stable ID, private fingerprint commitment, heartbeat TTL, tool allowlist, exact-head binding and separate independent verifier.
