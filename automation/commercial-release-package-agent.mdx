# Commercial Release Package Agent

The **CrownThrive Commercial Release Package Agent v2** converts each exact product build into a machine-addressed release package. It is the implementation originator, not an approver. It cannot vote, satisfy quorum, grant rights, authorize a price, determine tax, move money, activate checkout, expose credentials, certify accessibility, mutate DNS, or publish directly to a provider.

## Current cohort

The current source registry is `commercial_sites_candidate_4`, with the prior `commercial-gap-sites-2026-08-21-v1` identifier preserved as a compatibility alias. The first exact cohort contains 30 packaged candidate products across CrownThrive Launch, CrownThrive Ready, and CrownThrive Procure.

Each package binds:

- product SKU, version, asset SHA-256, package SHA-256, platform, and ChatGPT Sites surface;
- candidate Crown Credits band and tax-profile candidate;
- exact rights, fulfillment, credit checkout/webhook, entitlement, remedy, accessibility, DNS/TLS, publication, and governance gates;
- exact-version readback and rollback requirements; and
- one quarantined governed-release record with no manufactured vote.

## Credit-only commerce contract

First-party product checkout is **Crown Credits only**. Stripe is not a per-product checkout rail. Any future Stripe use remains a separately governed Crown Credit funding rail. A payment or credit debit is evidence; it cannot independently create a license, entitlement, payout authority, or fulfillment instruction.

## Nonsovereign worker federation

The parent agent delegates bounded evidence work to reusable A1/A2 and D1/D2 workers for:

- source normalization and exact asset identity;
- rights provenance and license lineage;
- Crown Credits pricing comparables and tax evidence;
- private fulfillment, protected delivery, readback, and rollback;
- credit redemption, webhook replay, idempotency, and negative controls;
- license acceptance, entitlement, and fulfillment authorization;
- refund, dispute, reversal, and rollback evidence;
- mobile, keyboard, device, and assistive-technology review;
- DNS, TLS, canonical route, and application readback;
- governed feed publication and post-publication readback;
- evidence hash chaining, drift reconciliation, provider capability checks, credential-alias continuity, and agent replication; and
- exact-version governance packet routing.

Replication creates reusable capability workers, not new sovereign voters. Every worker remains nonvoting, cannot inherit authority, cannot approve its own work, and cannot perform D3 actions.

## Canonical gate contract

Every Launch and Procure product requires ten current gates. Ready requires the same ten plus `qualified_professional_review`. Seven earlier dimension names are retained as historical aliases but are no longer counted as acceptance gates.

A product can enter the publication queue only after every current required dimension is `pass` or evidenced `not_applicable`, the package hash is unchanged, the accepted sovereign vote policy is satisfied with mandatory Agent D and no negative vote, the destination consumer is certified, and any D3 boundary has explicit human approval.

## Publication boundary

The three ChatGPT Sites projects use the existing `ct.adapter.dynamic-feed.v1` path and `ct.site.autopublish.v1` policy. Their routes remain HOLD until each site proves governed-feed consumption, read-after-write, rollback, reapply, and public readback. Direct Sites provider writes are prohibited by this factory.

## Private boundary

Protected scoring weights, coordination algorithms, retry and drift thresholds, recovery logic, private evidence, storage paths, provider identifiers, credential values, and private policy bodies remain in THIVEBASE and Vault. GitHub and Mintlify receive only public-safe contracts, stable identifiers, lifecycle state, sanitized reason codes, and digests.
