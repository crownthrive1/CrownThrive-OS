# Machine Trigger Asset Fabric

CrownThrive machine-led triggers are institutional assets, not informal automation rules. The Trigger Asset Fabric gives each trigger a stable identity, authority ceiling, plugin binding, custody profile, factory intake state, deterministic derivative plan and fail-closed execution boundary.

## Current candidate package

The first fabric contains **32 trigger bundles** across Phase 2.99 hard exit, Phase 3 bootstrap, perpetual commerce and continuity. Each bundle deterministically materializes one candidate algorithm contract, one governed skill, one machine prompt and one automation script: **128 derivative candidate assets**.

These candidates do **not** increase the current 100,800 authoritative generation-asset count. They enter the Proprietary Capability Factory as `candidate_hold` and remain outside a completed generation until the governed lifecycle, independent verification, custody/readback and generation-orchestration gates pass.

## Trigger groups

| Group | Function |
| --- | --- |
| Phase 2.99 | Evaluate blockers, absolute no-go, exact source/Git/THIVEBASE/docs freezes, authority, recovery and the gate decision |
| Phase 3 bootstrap | Create the GO-only bootstrap candidate and bind DAIL, THIVEBASE, Git release, Mintlify changelog, rollback and aggregate readback |
| Commerce | Discover/reopen candidates, build packages, run release gates, require ThriveEvergreen ECAC, publish only when authorized, monitor, reconcile and remedy |
| Continuity | Vault intake/integrity, DAIL append/verification and governed supersession |

## Factory binding

The fabric binds to `ct.fleet.chlom-proprietary-asset-factory.100k-plus`, ThriveInstitutionalize v1.1.1, `ct.agent-suite.commercial-release-factory.v1`, `ct.contract.phase-gate.p299-hard-exit.v1`, `ct.platform.thriveevergreen`, CHLOM, DAIL, THIVEBASE and CHLOM Vault.

Continuation never creates authority. A scheduled run can discover, materialize, validate, hash, queue and hold candidate assets. It cannot create a sovereign vote, exercise D3, grant rights, activate Phase 3, enable commerce, publish automatically, move money/Crown Credits or widen provider credentials.

## Plugin suite

Five D2-ceiling, non-voting plugin contracts are part of the fabric:

1. `ct.plugin.machine-trigger-router`
2. `ct.plugin.p299-phase-gate`
3. `ct.plugin.phase3-bootstrap`
4. `ct.plugin.commerce-factory`
5. `ct.plugin.vault-dail-continuity`

Plugins route governed events and contract calls. They never inherit sovereign authority from the system they invoke.

## Vault binding

Every trigger asset is assigned a public-safe Vault profile. Public Git stores only the profile class and required behavior. Raw secrets, private Vault locators and recovery material are prohibited.

The live binding remains `PENDING_RUNTIME_BINDING` because the THIVEBASE SQL/control channel is currently timing out. The fabric does not fabricate those receipts. When the governed control path is writable, every binding must be exact asset/SHA bound, opaque-reference only, read back and recoverable.

## Commerce non-bypass

Every commerce trigger binds to ThriveEvergreen. No economic activation may occur without a valid, non-superseded ECAC and the applicable independent acceptance. Provider payment, delivery, API or fulfillment success remains evidence only and cannot directly manufacture invoice, payout, earning, entitlement, settlement or public performance truth.

## Automation

`.github/workflows/machine-trigger-asset-fabric.yml` runs on relevant PR/push changes, hourly reconciliation and explicit dispatch. It uses read-only repository permissions, materializes all 32 bundles, proves 128 derivative candidates, builds five plugin records and 32 Vault binding candidates, and runs negative authority tests.

Negative controls reject D3 expansion, default provider writes, ECAC bypass and public Vault locator disclosure. The workflow must retain an authoritative-generation count delta of zero until the Proprietary Capability Factory actually admits the candidates through its governed lifecycle.
