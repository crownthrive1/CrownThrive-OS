# CSS and CHLOM CaaS Agent Mesh

**State:** controlled test  
**Schedule:** `ct.schedule.css-services-stack.hourly`  
**Database runtime:** `chlom_runtime.run_css_hourly_subroute`  
**Cron:** minute `:41` hourly  
**External task-slot increase:** zero

## Agents

### CSS Service Stack Orchestrator

`ct.css.agent-orchestrator`

Maintains service inventory, dependency topology, route gaps, collision-safe work selection, evidence handoffs, and lifecycle continuity.

### CSS Canonical Contract Steward

`ct.css.agent-contract-steward`

Versions public contracts, schemas, event contracts, public/private projections, contract digests, and drift evidence.

### CHLOM CaaS Control Controller

`ct.css.agent-compliance-controller`

Maintains the control catalog, service-control bindings, evidence freshness, readiness scans, assurance scores, exceptions, and remediation sequencing. It may not make automatic professional compliance claims.

### CSS Provider Adapter and Failover Steward

`ct.css.agent-provider-adapter`

Reconciles provider identities, credentials, quotas, exact contracts, read canaries, mutation-canary plans, exit/export requirements, failover, and provider portability. It never inherits provider-write authority.

### CSS Platform Adoption and Migration Steward

`ct.css.agent-adoption-steward`

Maintains the ecosystem adoption matrix, identifies duplicated local infrastructure, plans parallel canaries and bounded cutovers, and preserves predecessor history through supersession.

### CSS and CaaS Productization Steward

`ct.css.agent-productizer`

Packages services, controls, plugins, assets, licenses, support boundaries, and non-live CaaS offers. It cannot authorize operative legal terms, exact prices, checkout, entitlements, or seller payouts.

### CSS Independent Verification and TEVV Agent

`ct.css.agent-independent-verifier`

Independently verifies service contracts, provider bindings, routes, controls, evidence, platform adoption, assets, and product packages. It may return work to HOLD and cannot certify its own originating work.

## Authority boundary

All CSS agents are A2/D2 maximum, non-voting, self-healing, and no-self-approval. They add no sovereign voter and inherit no direct-main merge, provider-write, payment, checkout, entitlement, or D3 authority.

## Required handoff pattern

`owner work -> evidence receipt -> different verifier -> resolve | return | block`

Every handoff records the exact subject/version, evidence references, blocker or unlock condition, and immutable receipt.

## Work-in-progress rule

The mesh prioritizes the smallest dependency-unlocking tranche. It does not attempt to migrate every platform and service simultaneously. Identity, authentication, authorization, routing, documentation, and licensing evidence normally precede billing, commerce, rewards, CRM, and other dependent lanes.

## Self-healing boundary

The mesh may repair stale metadata, reconcile provider-binding evidence, re-run deterministic scans, refresh expiring evidence, and propose versioned supersession. It may not silently mutate a third-party provider, destroy history, broaden authority, publish protected implementation, or convert unresolved evidence into PASS.
