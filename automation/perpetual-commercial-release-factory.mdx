# Perpetual Commercial Release Factory

The CrownThrive Commercial Release Factory is an evergreen candidate-processing service. It has no permanent terminal product count and no authority to manufacture release eligibility.

## Perpetual operating loop

```text
catalog/source/platform change
  -> discover or reconcile candidate
  -> resolve canonical asset/product/version identity
  -> build or supersede release package
  -> run all applicable release dimensions
  -> ThriveEvergreen ECAC | HOLD | DENY
  -> independent specialist/governance acceptance where required
  -> bounded publication only when authorized
  -> readback and monitoring
  -> reconciliation / correction / rollback / compensation
  -> changed successor version re-enters the complete gate set
```

The factory may continually prepare and test candidate packages. It may not continually publish, charge, issue entitlements, move Crown Credits, move money, grant rights, create economic authority, or treat a prior release as authorization for a successor.

## Required invariants

- no fixed terminal product or generation count;
- no prior-version PASS inheritance;
- every material rights, pricing, tax, fulfillment, checkout, webhook, entitlement, accessibility, DNS/TLS, provider, advertising, security or policy change reopens the affected gate;
- canonical CrownThrive product/SKU identity survives provider replacement;
- ThriveEvergreen `ECAC | HOLD | DENY` is mandatory before economic activation;
- provider success is evidence only and cannot directly create institutional entitlement, invoice, earning, payout or settlement;
- producer/originator self-approval is prohibited;
- automatic publication is default-off;
- pause, quarantine, rollback, compensation, supersession and decommission remain available;
- perpetual operation never expands D-level authority or voting rights.

## Automation contract

The factory may run on catalog change, source change, relevant repository events and a bounded recurring reconciliation cadence. A scheduled run performs discovery, package build, validation, drift detection and queue updates only within its accepted authority.

A run with no new or changed candidate produces `NO_CHANGE`. A candidate that lacks evidence produces `HOLD`. A candidate that violates a hard rule produces `DENY`. Only exact-version packages with the required rights, economics, fulfillment, technical and governance evidence may become ECAC-eligible.

## Relationship to Phase 3

Perpetual candidate processing can exist during Phase 2.99 controlled test. Production economic activation remains blocked until the Phase 3 gate and the applicable product-level gates pass. The factory therefore helps populate Phase 3 work without itself triggering Phase 3.
