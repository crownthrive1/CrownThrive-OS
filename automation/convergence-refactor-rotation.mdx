# Convergence Rotation & Whole-Estate Refactoring

## Status

This is a Phase 2.99 controlled-test extension of the existing Collision Governance packet. It does not create a new sovereign voter, another master orchestrator, a provider-write path, or Phase 3 authority.

It exists to solve a specific institutional risk: **CrownThrive can generate good governed work faster than canonical `main`, documentation, review, recovery evidence, and current ownership can absorb it.** The answer is not deletion. The answer is rotation, refactoring, canonicalization, and preserved lineage.

## Convergence Rotor

Stable candidate identity: `ct.subagent.convergence.rotor`.

The **Convergence Rotor** reuses the existing Priority and Throttle Coordinator and Founder Orchestrator candidate. It measures open-PR pressure, stale-main pressure, and material collision pressure, then selects an attention mode:

| Mode | Closure | Current build | Research |
| --- | ---: | ---: | ---: |
| `EXPANSION` | 35% | 45% | 20% |
| `BALANCED` | 50% | 35% | 15% |
| `CONVERGENCE` | 70% | 20% | 10% |
| `INCIDENT` | 80% | 15% | 5% |

Controlled-test `CONVERGENCE` triggers when any of these is true:

- 20 or more open PRs;
- eight or more stale main-based PRs;
- eight or more material `CT-COLL-2+` collisions.

`INCIDENT` requires an explicit critical-security or founder-priority signal. Descriptive prose alone cannot trigger it.

The rotor changes **attention allocation**, not truth or history. Research may continue while final promotion is throttled.

## Refactor Steward

Stable candidate identity: `ct.subagent.refactor.steward`.

The **Refactor Steward** turns sprawl into one current ownership graph without erasing the path that produced it.

Allowed dispositions:

- `preserve_active`;
- `preserve_and_rebase`;
- `preserve_and_stack_on_current_owner`;
- `preserve_and_extract_unique_delta`;
- `preserve_as_superseded_history_with_successor_link`;
- `hold_for_adjudication`;
- `continue_research_without_promotion`.

It **never silently deletes** branches, files, pages, PR history, Canon, Doctrine, evidence, rejected experiments, prior current states, or institutional decisions. It cannot force-push, automatically close PRs, weaken validators, or turn UNKNOWN into PASS.

Supersession requires a predecessor reference plus a successor or explicit reason. Material current-page changes require version/changelog continuity.

## Whole-estate refactor order

Unless a higher-priority security or reserved-human event preempts it, refactoring proceeds in this order:

1. canonical `main` and merge perimeter;
2. Phase 2.99 hard exit and full-documentation hard gate;
3. current-truth documentation and source registry;
4. runtime/API/MCP/provider state;
5. agent/framework/federation state;
6. product/platform verticals;
7. future R&D and experiments.

The rule is **prefer updating the current owner over creating a parallel owner**. For stale packets, prefer extracting the unique useful delta over promoting the stale packet wholesale.

## Existing-agent integration

This extension reuses rather than duplicates:

- Collision Preflight Sentinel;
- Collision Adjudicator;
- Post-Merge Reconciler;
- Priority and Throttle Coordinator;
- Special Quorum Session Router;
- Founder Orchestrator candidate.

The Convergence Rotor tells those roles where attention should go. The Refactor Steward tells them how to preserve and reconcile lineage while moving work there.

## Workflow integration

The existing **Collision Governance** workflow is reused. No additional schedule family is created.

- `:40` — queue/collision scan plus whole-estate convergence/refactor plan;
- `main` push — immediate post-merge reconciliation plus refreshed refactor plan;
- `:50` — post-merge/staleness sweep plus refreshed refactor plan.

The workflow remains `contents: read` and `pull-requests: read`. It emits a plan and does not mutate branches, PRs, provider state, votes, or phase.

## Preservation rule

CrownThrive knowledge is append/supersession oriented. Refactoring may redirect attention and change which artifact is current, but it does not make prior knowledge disappear.

**No silent removal. No silent overwrite. No history-by-convenience.**

A prior artifact may become historical, superseded, merged into a successor, or non-current. Its existence and reason remain reconstructable.

## Phase boundary

This control reduces convergence risk. It closes no Phase 2.99 hard gate by itself and cannot authorize Phase 3.
