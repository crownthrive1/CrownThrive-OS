# Institutional Agent Relay v2

This page is the candidate successor to the historical five-agent relay. It becomes effective only when the CT-ADR-GOV-012 packet is independently accepted and merged. Until then, CT-ADR-GOV-011 remains canonical.

## Candidate hourly cycle

```text
:00  Agent A — Orchestrator & Integrator
  ↓
:15  Agent B — Evidence & Reconciliation Auditor
  ↓
:30  Agent C — Build & Documentation Executor
  ↓
:40  CIE Framework Agent — Cultural Imprint Engine
  ↓
:45  Agent D — Independent Gatekeeper & Handoff Steward
  ↓
:55  Agent S — Security & Resilience Sentinel
  ↓
next :00 → Agent A
```

The CIE position at `:40` lets the framework inspect the evidence/build packet after Agent C and before the independent Agent D gate. Agent A remains CIE's operational parent for task routing, but does not control the CIE vote.

Operational monitoring/specialist jobs may continue at their governed offsets. They do not add votes unless separately accepted as foundational framework agents.

## CIE handoff

Every material CIE-triggered packet adds:

```yaml
cie:
  required: true | false
  subject_id: <stable id>
  subject_type: <domain|page|website|document|campaign|product|media_asset|brand_asset|software_surface|digital_asset>
  score: 0-100 | null
  threshold: 85
  verdict: PASS | REVIEW | HOLD | FAIL | FAIL_HARD_BLOCK | HOLD_INSUFFICIENT_EVIDENCE | not_applicable
  dimension_scores:
    identity_fit: 0-20
    community_value: 0-20
    story_alignment: 0-20
    brand_safety: 0-20
    legacy_impact: 0-20
  hard_blocks: []
  findings: []
  corrections: []
  assigned_agents: []
  human_escalations: []
  evidence_refs: []
```

A CIE PASS does not create rights, legal approval, security certification, commercial authority or D3 permission.

## Cross-agent synchronization rule

All registered CrownThrive agents must call or route through CIE when their packet materially changes:

- a cultural/community public claim;
- canon, story or narrative continuity;
- identity, representation, aesthetics or language;
- source-community attribution;
- cross-imprint/cross-platform reuse;
- cultural commercialization;
- a public-facing asset whose cultural context is material;
- material brand repositioning.

Non-triggering technical changes may record `cie: not_applicable` with a reason.

CIE may assign a correction to an existing registered agent, but cannot grant that agent new authority. HIGH/CRITICAL or ambiguous cultural-governance findings route to Agent D and, where required, authorized human review.

## Retroactive scan lane

Existing assets are queued for retroactive CIE review without converting the queue into an artificial Phase-2.99 blocking count. The scan should prioritize current public P0/P1 surfaces, active monetized media/brand/product assets and material cross-imprint reuse. Historical/reserve/sunset assets remain preserved and need not be reactivated to be scored/dispositioned.

A retroactive result must include a score or an explicit insufficient-evidence HOLD, reasons, evidence references, corrections, owner/assigned agent and reopening trigger.

## Framework-agent growth rule

CIE is the first foundational framework agent. A later framework becomes a sovereign voter only after:

1. explicit founder authorization;
2. canonical framework doctrine and machine contract;
3. rigid code of ethics, boundaries and non-negotiables;
4. an operational parent without vote-control authority;
5. independent tests/evals;
6. CHLOM/service mapping;
7. rollback and correction model;
8. governed acceptance.

Each accepted framework agent increases the eligible voter denominator by one. The formula stays `ceil(N × 0.75)`, Agent D remains mandatory and D3 remains human-reserved.

## Historical continuity

The original [Institutional Hourly Agent Relay](/automation/institutional-hourly-agent-relay) remains predecessor evidence and must not be rewritten as though CIE always existed. CT-ADR-GOV-012 creates the successor state prospectively after acceptance.
