# Framework-agent relay candidate

This page describes a **non-voting framework handoff pattern**. It does not replace the accepted sovereign relay and does not make a framework, repository, subagent, MCP tool, model or transport identity a voter.

Current sovereign authority remains:

```yaml
eligible_voters: 5
voters:
  - ct.relay.agent-a
  - ct.relay.agent-b
  - ct.relay.agent-c
  - ct.relay.agent-d
  - ct.relay.agent-s
approval_ratio: 0.75
rounding: ceil
required_approvals: 4
agent_d_mandatory: true
deny_or_block_stops_merge: true
d3_human_reserved: true
```

## Non-voting framework handoff

A framework agent may run between implementation and final gatekeeping when its registered scope is triggered:

```text
Agent A — orchestrate / integrate
  ↓
Agent B — evidence / reconciliation
  ↓
Agent C — bounded build / documentation
  ↓
Triggered framework agent — non-voting assessment / HOLD / BLOCK / correction / escalation
  ↓
Agent D — mandatory independent gatekeeper
  ↓
Agent S — sovereign security/resilience vote and specialist evidence as applicable
```

The exact clock offset is operational scheduling, not authority. A framework assessment may create a stronger scoped HOLD/BLOCK or correction requirement, but it cannot increase permission, alter quorum, replace Agent D or create D3 authority.

## CIE handoff contract

When Cultural Imprint Engine review is triggered, the packet may record:

```yaml
cie:
  required: true | false
  subject_id: <stable-id>
  subject_type: <governed artifact type>
  score: 0-100 | null
  threshold: 85
  verdict: PASS | REVIEW | HOLD | FAIL | FAIL_HARD_BLOCK | HOLD_INSUFFICIENT_EVIDENCE | not_applicable
  dimension_scores:
    identity_fit: 0-20
    community_value: 0-20
    story_alignment: 0-20
    brand_safety: 0-20
    legacy_impact: 0-20
  hard_blocks: []
  findings: []
  corrections: []
  human_escalations: []
  evidence_refs: []
  sovereign_vote_created: false
```

CIE PASS never creates rights, legal approval, security certification, commercial authority, Phase transition or D3 permission.

## Cross-agent synchronization

Registered agents route through CIE when a material packet changes cultural/community public claims, canon/narrative, identity/representation, source-community attribution, cross-imprint reuse, cultural commercialization, a new public asset or material brand repositioning.

`repository_federation.sync_agents` may synchronize only governed **non-voting D0–D2 transport identities** to a linked-governed repository. It cannot create or activate a sovereign vote.

## Retroactive scan lane

Existing assets can enter retroactive CIE review without converting the scan queue or registry growth into automatic Phase-2.99 certification debt. Results preserve PASS/HOLD/BLOCK distinctions, evidence, owner/correction and reopening triggers.

## Separate constitutional admission

Issue #148 authorizes Framework Factory construction and permits future sovereign-vote candidacy, but **framework acceptance is not sovereign-vote acceptance**. Any later proposal to add CIE or another framework to the voter pool requires its own current-constitution packet, exact-head evidence, required specialists, Agent D, normal quorum and linked-governed child certification. The proposed voter cannot approve its own admission.

## Historical continuity

The accepted [Institutional Hourly Agent Relay](/automation/institutional-hourly-agent-relay) remains current sovereign lineage until a separate constitutional change is governed. This candidate page exists so future admission can be evaluated without pretending the change already happened.
