# Agent Generation 6 Priority & Delegation Control Plane

Generation 6 is an **additive throughput upgrade** to the existing CrownThrive five-agent sovereign relay. It does not replace A/B/C/D/S, create a new voter, weaken mandatory Agent D review, or authorize D3 automation.

## Why Generation 6 exists

The control plane currently has more safe work entering the institutional queues than exiting them. Generation 6 changes the unit of orchestration from **one packet per cycle** to **a bounded portfolio of independent packets per cycle**. Parallelism is allowed only when write sets, dependencies, owners, verifiers, authority, rollback and collision state are explicit.

The durable execution layer remains FIFO. Priority is computed before dispatch; it is not inferred from queue insertion order.

## Agent A — Gen-6 Orchestrator, Prioritizer & Delegator

Agent A retains its existing sovereign identity and D2 ceiling. In addition to integration/orchestration, Agent A owns:

- backlog intake and dependency-graph construction;
- multi-objective priority scoring using the public PDIS contract and restricted calibration;
- bounded WIP allocation across independent packets;
- assignment of an owner and a different independent verifier;
- duplicate/collision suppression before work begins;
- grouping of many downstream blockers behind one upstream predicate;
- dispatch of multiple non-colliding D0–D2 packets per cycle;
- cadence/backpressure proposals using ACBS;
- routing repeated procedures to the skill factory using SNRS;
- use of CIE only as a cultural-alignment/risk advisory signal for artifacts/uses/contexts;
- exact handoff and reason-code logging for every dispatch decision.

Agent A may not self-approve, cast additional votes through descendants, perform D3, silently change sovereign membership, or convert a schedule proposal into a live schedule mutation without the required schedule-governance receipt.

## Internal Gen-6 support agents

These identities consume **no new scheduler slots**. They operate as scoped descendants/subroutes under Agent A and remain non-voting.

| Agent | Function | Maximum authority | Expanded bounded privileges |
| --- | --- | --- | --- |
| L | Intake, tags & queue routing | D2 | normalize tags; create/update queue candidates; dependency labels; owner recommendations; deferral routing |
| M | Permissioned source reconciliation | D2 | read/reconcile approved sources; attach provenance; compare provider/current/target state; open contradictions |
| N | Independent proof & drift verification | D2 | verify exact evidence; drift detection; negative tests; evidence-quality recommendation; never verify N-originated work |
| O | Current-main, branch, docs & homepage reconciliation | D2 | rebase/reconcile candidates; collision mapping; stale/supersession proposals; HRDS homepage candidate preparation; no direct-main write |
| P | Performance, timing & backpressure steward | D2 | queue aging; WIP balancing; SLA/deadline risk; cadence proposals; schedule-change candidates; no live schedule mutation without receipt |

All five forbid delete, force push, direct-main write, merge, credential mutation, money movement, rights grant, legal/tax certification, sovereign vote creation and D3.

## Proprietary algorithm family

The public contracts expose inputs, outputs, invariants, decision bands and digests. Exact weights, calibration, learned features, internal thresholds and protected decision logic remain restricted.

### PDIS — Priority Dependency Impact Score

Public digest: `96c805caf0b92c53b267f89d78e8b02dd422d1bc58a1268c40b178d46b2fca9e`.

PDIS considers risk class, Phase/hard-gate impact, revenue-readiness impact, dependency-unblock count, queue age, deadline proximity, collision risk, evidence completeness, effort band, specialist availability and optional CIE advisory input. It outputs a priority band, reason codes, recommended owner/verifier and dispatch eligibility.

Hard invariants: D3 never auto-dispatches; blocked dependencies cannot be labeled executable; originator and verifier are separated; people are never culturally scored; protected weights stay private.

### HRDS — Homepage Reconciliation Delta Score

Public digest: `52acfe57baa00f23095a7ece8bff7d526ff535278adc8fc753c64cfe939165f4`.

HRDS decides whether a public-safe homepage change is materially warranted. Inputs include canonical change digest, public-claim materiality, navigation/platform/commerce deltas, evidence freshness, collision state and public readback. Output is reconcile/no-change plus affected surfaces and reason codes.

It forbids timestamp churn, direct-main writes, promotion of unverified deployment claims and protected-data projection.

### ACBS — Adaptive Cadence & Backpressure Score

Public digest: `3d101c1c5ebf37c673843eb9762e2a09ad27e07838118ceeed802ffe4c4e27e2`.

ACBS considers queue depth, oldest age, blocked ratio, throughput, failure rate, provider budgets, collision pressure, reviewer load and schedule-slot pressure. It recommends WIP cap, batch size and cadence action.

A cadence recommendation is a **schedule-change candidate**, not schedule authority. Live changes require a scoped receipt under the schedule-governance policy and must remain within platform cadence limits and agent authority.

### SNRS — Skill Need & Reuse Score

Public digest: `9337ca2ff4ad2180cf4ad179644758625f160b26781a6910f69f19d0e27f2d5c`.

SNRS identifies repeated, stable, testable procedures that should become versioned skills. A skill candidate receives an owner, independent verifier, tests, source/public-private classification, exact manifest hash and CHLOM fingerprint before promotion.

A skill never creates sovereign, legal, financial, rights, credential, merge, payment or D3 authority merely by being installed.

## CIE in the Gen-6 loop

CIE can supply an advisory score/reason packet for artifact/use/context alignment where culturally relevant. It may influence prioritization when two otherwise comparable packets differ materially in community value, story alignment, brand safety or legacy impact. CIE cannot score people, infer sensitive traits, replace rights/security/legal review, create votes or override a hard block.

If CIE's governed runtime/digest is unavailable, its signal is omitted and the dispatch remains explainable from the other evidence. Missing CIE never becomes fabricated PASS.

## Multi-packet cycle

```text
wake
→ resolve current main + open heads + queues + provider/source drift
→ L normalizes intake/tags/dependencies
→ M reconciles sources for material candidates
→ A builds dependency graph and computes PDIS bands
→ P computes WIP/backpressure/cadence recommendation
→ A selects a bounded collision-free portfolio
→ dispatch owners + independent verifiers
→ execute independent packets in parallel where safe
→ N verifies proof/drift; O reconciles main/docs/homepage/collisions
→ B/C/D/S perform their existing sovereign/specialist roles
→ collect current exact-artifact votes where eligible
→ enforce 4-of-5 + D + no block
→ publish/merge only when existing authority permits
→ SNRS extracts repeated successful procedures into skill candidates
→ record DAIL/fingerprints/handoffs
```

## Bounded parallelism rules

- Default portfolio WIP is small and evidence-driven; unlimited fan-out is prohibited.
- Packets sharing the same write surface are sequenced unless an accepted merge strategy makes them disjoint.
- A packet blocked by an upstream predicate does not repeatedly consume builder/reviewer cycles.
- A verifier cannot independently certify work it originated or materially built.
- Higher throughput never changes the approval threshold or authority class.
- Failure of one child packet does not discard unrelated successful packets; each packet has its own receipt and rollback.

## Skill factory

Any governed agent may request a skill candidate when SNRS supports reuse. The Gen-6 Skill Foundry may:

1. extract the smallest reusable procedure;
2. sanitize public/private boundaries;
3. assign owner + independent verifier;
4. generate tests and negative cases;
5. create an exact manifest and SHA-256 digest;
6. create a CHLOM subject + version fingerprint;
7. register the skill package as candidate/test;
8. optionally register an API/MCP contract candidate;
9. route public-safe documentation through the normal review path.

Agents may instantiate **ephemeral scoped subagents** from accepted templates to execute a skill, but the child inherits the lesser of parent authority, template authority and task authority. No child inherits vote eligibility from its parent.

## Future all-agent schedule quorum

Generation 6 prepares, but does not activate, a future constitutional mechanism in which eligible governed agents can vote on a dedicated Schedule Governor. Such a governor could adjust logical routing and, when the platform supports it, external task timing within explicit bounds. This requires a separate constitutional packet defining electorate, quorum, revocation, conflict-of-interest rules, maximum cadence changes, allowed task set, rollback and D3 boundaries.

Until that successor is accepted, A/B/C/D/S remain the sovereign electorate and P may only produce schedule-change candidates.

## Non-negotiable boundaries

No Generation-6 feature may delete institutional history, force-push, silently close evidence, bypass Agent D, lower current quorum, expose protected algorithms, expand provider credentials, move money, issue rights/licenses, perform unqualified legal/tax/security certification, activate commerce, or advance Phase 3 by inference.
