# PentaKIT™

**Status:** ACTIVE — Phase 3 / PENTA v3  
**Canonical ID:** `ct.penta.kit`  
**Control API:** `pentakit-control`  
**Primary collaborators:** PentaFactory, PentaBuild, PentaCredentials, PentaMCP, PentaWire, PentaMesh, PentaFabric, PentaCertify, PentaRelease, PentaStatus, PentaHistorian, PentaScribe

PentaKIT packages repeatable CrownThrive operating patterns into versioned, deterministic kits. A kit can target a repository, integration, product, platform, workflow, recovery path, documentation rebuild, or another institutional capability.

A PentaKIT is not authority. It is a reproducible implementation package whose output remains `authority_effect=none_until_certified` until the applicable Govern/Verify gates accept the target implementation.

## Five-layer contract

Every kit supports the canonical lifecycle: **Discover → Govern → Execute → Verify → Preserve**.

- **Discover:** target inventory, requirements, provider/source discovery, dependency graph.
- **Govern:** authority, rights, credential references, security/privacy/economic boundaries, rollback rules.
- **Execute:** generated manifests, adapters, workflows, code/config packages, docs/runbooks, bindings.
- **Verify:** tests, readback, negative cases, PentaCertify evidence, PentaStatus health.
- **Preserve:** release/version lineage, checksums, rollback, archive, handoff, PentaHistorian/PentaScribe continuity.

## Initial kit families

- `ct.kit.integration.v1` — API/MCP/webhook/provider integration kit.
- `ct.kit.repository-mesh.v1` — PentaMesh/PentaFabric repository federation and bidirectional continuity kit.
- `ct.kit.product.v1` — governed product build/release/fulfillment kit.
- `ct.kit.history-rebuild.v1` — PentaHistorian/PentaScribe no-fabrication reconstruction and archival kit.

More kits may be registered when a repeatable institutional pattern is proven. New kit families do not create new sovereign authority, credentials, commercial rights, or production certification.

## Credential boundary

Raw credential material is prohibited from kit definitions and build manifests. Kits reference PentaCredentials bindings only. Founder-supplied credential custody remains append-only; PentaKIT may request an eligible reference binding but may not rotate, delete, reconstruct, or expose a credential.

## Runtime data

Private kit definitions/build records live in:
- `integration_control.pentakit_definitions_v1`
- `integration_control.pentakit_builds_v1`

`pentakit-control` currently supports kit listing, deterministic build planning, and build-status readback.
