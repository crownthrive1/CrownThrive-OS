# Agent Lineage & Version Archive

This archive preserves **how CrownThrive's agent system evolved**, not just its latest state. Current role definitions live in the [Agent Registry](/automation/agent-registry) and [Agent Templates & Pallets](/automation/agent-templates-pallets-and-commercialization). Prior generations remain reconstructable rather than being rewritten out of existence.

## Archive doctrine

Agent history is append-only. A new prompt, scheduler, authority rule, tool binding, delegation rule or subagent does not erase the prior generation. Every material revision should record:

```yaml
agent_or_pack_id:
version:
effective_at:
status: current | superseded | archived | suspended | retired
predecessor_version:
change_reason:
schedule_or_trigger:
vote_eligibility:
authority_change:
tool_scope_change:
delegation_change:
independence_change:
research_promotion_change:
source_template_version:
validation_evidence:
rollback_or_restore_target:
related_changelog:
```

Historical prompts may remain in restricted operational records where appropriate. Public Mintlify records stable roles, material differences, versions and evidence references without leaking credentials or restricted implementation.

The machine-readable companion is `developers/manifests/agent-lineage-archive.v1.json`.

## Relay generation history

### Generation 0 — ad hoc conversational orchestration

**Historical.** Agent-like work existed as chat/session instructions without a complete repository-backed role registry, deterministic quorum or stable handoff contract. It remains valuable development lineage but is not institutional authority.

### Generation 1 — four-role hourly relay

**Historical/superseded.** A Orchestrator, B Evidence Auditor, C Builder and D Gatekeeper established staggered execution and separation of duties.

### Generation 2 — five-agent sovereign relay

**Current authority baseline.** Agent S joined A/B/C/D. A/B/C/D/S became the fixed five-voter pool under `CT-ADR-GOV-011`, with four affirmative votes plus mandatory D for eligible automatic D0–D2 promotion. D3 remains human/reserved regardless of consensus.

### Generation 3 — scheduled specialist ring

**Current specialist layer.** E API/MCP, F Source & Articleization, G Domain/Engine/Vendor and H Webhook/Delivery became scheduled non-voting specialists. They improve evidence and implementation capacity without changing the voter denominator.

### Generation 4 — embedded specialist and reconciliation expansion

**Current embedded layer.** Specialist identities were moved into existing schedules where an independent scheduler was unnecessary:

| Identity | Stable ID | Primary function |
| --- | --- | --- |
| I — Continuity & Recovery | `ct.subagent.continuity-recovery` | GATE-007 backup/restore/export/provider-exit/restricted-source continuity |
| J — Phase 3 Snapshot & Entry Packet | `ct.subagent.phase3-snapshot-packet` | GATE-008 exact source/schema/infrastructure/commit snapshot |
| K — Roadmap Transition | `ct.subagent.roadmap-transition` | downstream dependency/gate/test/risk propagation |
| L — Reconciliation Tag Sentinel | `ct.subagent.reconciliation-tag-sentinel` | work-routing and tag normalization |

All remain non-voting.

### Generation 5 — governed agent factory and R&D fabric

**Current delegation/research layer.** Generation 5 adds machine-governed parent/child delegation and a permanent non-voting R&D specialist fabric without changing Generation 2's sovereign voter baseline.

The delegation system records:

```text
parent
→ child
→ inherited authority ceiling
→ source/tool/data budget
→ parent/root/independence lineage
→ output class
→ promotion route
→ termination state
→ archive/reconstruction
```

Key controls:

- child agents never add sovereign votes;
- children of one governed root do not manufacture independent verification;
- persistent children require registered stable identity and lifecycle governance;
- ephemeral children require bounded scope, TTL, budget, authority ceiling and termination state;
- D is checks-only, not a builder host;
- N descendants cannot become an independent N verifier for N-originated material;
- operational probes do not spawn durable child fleets.

The six-role R&D fabric is:

- `ct.subagent.rnd.legal-regulatory`
- `ct.subagent.rnd.ip-rights-licensing`
- `ct.subagent.rnd.finance-tax-treasury`
- `ct.subagent.rnd.blockchain-cryptographic-protocol`
- `ct.subagent.rnd.accessibility-consumer-protection`
- `ct.subagent.rnd.regional-global-localization`

R&D defaults to `RESEARCH_CANDIDATE`. Research can expand faster than certification without creating a formal proof-coverage gap by count alone. Formal certification catches up only when a scope is promoted, touches a hard-exit predicate, changes an existing governed disposition, becomes canonical/production relevant or enters authoritative phase-entry evidence.

Machine contracts:

- `developers/manifests/agent-factory-delegation-policy.v1.json`
- `developers/manifests/agent-rnd-specialist-fabric.v1.json`

## Source-template lineage

### Template generation 1.0.0 — 2026-08-19

Initial reusable source set established agent roles, subagent roles, package manifests, capability pallets and third-party attribution. Defaults: no production writes, no phase advancement, no self-approval and no authorized price.

### Template generation 1.0.1 — 2026-08-19

Added `chlom-runtime-adapter-template.v1.yaml` as a separately governed research template for future decentralized, cryptographic or protocol-runtime adapters. It did not replace capability pallets and did not imply deployment.

### Template generation 1.1.0 — 2026-08-19

Generation 1.1.0 adds the explicit agent-factory delegation contract:

- parent and root agent identity;
- independence family;
- persistent versus ephemeral lifecycle;
- spawn mode and allowed child classes;
- maximum delegation depth;
- authority ceiling;
- required budget and TTL;
- child vote default `false`;
- production-write default `false`;
- termination state;
- promotion route;
- same-family non-independence;
- prohibition on R&D candidate → PASS without promotion.

It also adds the machine R&D promotion boundary and research-versus-certification tags. This is a material template generation rather than a silent prompt tweak.

## Version-preservation rules

1. Stable IDs survive prompt wording changes.
2. Scheduler/task IDs are runtime references, not institutional identities.
3. A schedule change receives a version/update record when it materially changes cadence or responsibility.
4. Prompt changes affecting authority, tools, data, phase gates, delegation, outputs or failure behavior are material.
5. Prior accepted versions remain reconstructable.
6. Retired agents remain queryable as historical lineage.
7. Commercial template versions and internal operational versions are related but separately versioned.
8. Capability-pallet and runtime-adapter versions remain independent.
9. Delegated children preserve parent/root/independence lineage.
10. Same-family descendants do not become independent reviewers through runtime multiplication.
11. Research candidates remain outside certification accounting until the governed promotion/material-touch boundary is crossed.

## Changelog routing

- **Major topology/authority/delegation changes:** Institutional Changelog Index plus a dedicated subject changelog.
- **Agent-specific material revisions:** this archive plus applicable agent/template page.
- **Mechanical D1 wording/metadata fixes:** subject changelog when reproducibility or machine behavior changes.
- **Runtime schedule optimization:** operational record/changelog when cadence changes materially, without creating a new institutional identity.
- **Runtime incidents:** operational watch/incident records unless they create a durable agent-contract change.

## Machine ingestion

Machine consumers should prefer current manifests/templates and registry records. This archive answers lineage questions such as:

- Which agent/template generation governed a decision?
- Was a child ephemeral or persistent?
- Which root and independence family produced an output?
- When did R&D become certification scope?
- Which behavior was superseded and why?
- What rollback target exists if a new generation regresses?

The archive is institutional evidence, not merely narrative history.
