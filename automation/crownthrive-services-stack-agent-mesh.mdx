# CrownThrive Services Stack Agent Mesh

**State:** controlled test / non-voting.  
**Authority:** A2 / D2 maximum.  
**Schedule:** internal PostgreSQL subroute at minute `:57`; no external task slot.

| Agent | Responsibility |
| --- | --- |
| `ct.css.agent-orchestrator` | inventory, priorities, dependency ordering, WIP control, collision prevention and handoffs |
| `ct.css.agent-contract-steward` | lane contracts, schemas, versions, public/private boundaries and drift reconciliation |
| `ct.css.agent-provider-router` | provider bindings, adapters, routing, failover, idempotency, rollback and readback plans |
| `ct.css.agent-control-mapper` | CHLOM CaaS control mapping, evidence requirements, unknowns and remediation sequencing |
| `ct.css.agent-sre-continuity` | SLOs, health, capacity, cost guardrails, backups, continuity and incident state |
| `ct.css.agent-productizer` | plugins, lane packages, licensing/pricing research, support boundaries and customer-package candidates |
| `ct.css.agent-independent-certifier` | independent contract, control, route, provider and package verification |

## Operating order

`inventory -> contract -> provider candidate -> control map -> evidence -> read canary -> verification -> write canary -> continuity -> shared-service activation`

The originating agent cannot certify its own output. The certifier cannot create sovereign acceptance or professional conclusions.

## Reuse before creation

CSS agents must reuse existing CrownThrive identity, CHLOM, Interoperability Fabric, Asset Fabric, ThriveEvergreen, CrownLytics, ThrivePush, CrownRewards, Mintlify, GitHub, Drive and provider adapters when current evidence supports them.

A new adapter is created only when:

- no current governed binding exists;
- exact contract differences require a distinct adapter;
- the new package has stable identity and version;
- negative, privacy, idempotency, rollback and readback requirements are defined;
- custody and supersession are preserved.

## WIP and scheduling

The mesh may evaluate the full fourteen-lane portfolio but should execute only the smallest dependency-unlocking tranche. Identity, authentication, authorization, routing and documentation usually unblock downstream lanes.

The internal `:57` scheduler records per-agent task, skill, work units, evidence, lifecycle and outcome. A registration is not proof of execution; scheduled receipts remain separately verified.

## Hard boundaries

- no D3 automation;
- no sovereign vote;
- no self-approval;
- no direct-main merge;
- no raw secret/private-identity export;
- no provider-write inheritance;
- no automatic payment, license, entitlement or public-compliance claim;
- no silent deletion;
- provider limits, billing and contracts remain authoritative.
