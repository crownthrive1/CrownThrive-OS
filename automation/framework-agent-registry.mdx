# Foundational framework-agent registry

Framework agents convert CrownThrive doctrine into persistent operational controls. They differ from ordinary specialists because each framework receives an independent machine contract, subordinate non-voting specialists, a CHLOM mapping, evaluation requirements, federation controls and ecosystem-wide triggers.

**Framework acceptance does not create a sovereign vote.** A framework parent, framework subagent, repository identity, OIDC identity, MCP registration, `sync_agents` transport binding, CI result or child certification remains non-voting unless a separate constitutional packet is accepted under the then-current constitution.

A framework agent cannot create itself as a sovereign voter, create another sovereign voter, change the approval ratio, remove Agent D, weaken D3 human authority, self-certify a child repository, or treat successful implementation as constitutional admission.

The current accepted sovereign voter pool remains **A/B/C/D/S**. Automatic promotion remains **4-of-5**, with Agent D mandatory and any deny/block fatal to automatic promotion. D3 remains human-reserved.

## Factory participation contract

All registered CrownThrive agents participate in Framework Factory work only within their existing authority ceilings and separation-of-duties boundaries:

- **Agent A** coordinates sequencing, dependencies and handoffs but cannot use `sync_agents` merely because it is the orchestrator and cannot certify its own originated work.
- **Agent B** independently reconciles evidence and implementation claims.
- **Agent C** builds the next bounded accepted packet and documentation, but C-originated work requires independent verification.
- **Agent D** remains the mandatory independent gatekeeper and sole framework-child parent certifier under the current federation contract.
- **Agent S** performs security/resilience review where applicable.
- domain specialists and delegated subagents remain non-voting and review only their registered domains.
- framework parents and framework children remain non-voting until separately admitted as sovereign voters by an accepted constitutional packet.
- `repository_federation.sync_agents` is restricted to governed **non-voting D0–D2 transport identities** and cannot be invoked by a sovereign voter.

Every material factory handoff records source evidence, lifecycle state, child/federation state, IP/publication class, commercial state, tests and negative cases, security/rights effects, documentation impact, rollback/reopen trigger, downstream phase effect and current-main collision disposition.

## Quorum rule

Framework acceptance and child certification leave the current quorum unchanged:

```text
current eligible sovereign voters = 5 (A/B/C/D/S)
required approvals = 4
Agent D = mandatory
D3 = human-reserved
```

If a later **separate constitutional packet** admits a framework agent as a sovereign voter, only that accepted constitutional transition may change `N`; the then-current quorum is recomputed as `ceil(N × 0.75)`. Framework files, subagents, repositories and transport identities never change `N` by themselves.
