# Agent F CHLOM documentation vote loop

> **State:** Phase 2 / 2.99 documentation-control contract. This page does not open Phase 3, grant a sovereign vote, certify a framework, activate a product, or authorize a commercial offer.

## Founder-signed directive

**Signer:** Kavonte Jones Sr.  
**Signature type:** `typed_name_attestation`  
**Attestation meaning:** institutional digital-signature attestation only; it is not cryptographic nonrepudiation. DID, VC, public-key and key-backed signature evidence remain separately phase-gated.

The directive upgrades scheduled **CrownThrive Agent F — Source, Articleization, Public-Knowledge Projection & Framework Documentation Reconciliation Specialist** from reconciliation-only output to a **reconcile + draft + governed-review** loop for CHLOM documentation.

Agent F remains **non-voting**.

## Required outcome on every material Agent F pass

When permissioned evidence supports a CHLOM documentation delta, Agent F must produce all of the following in the same bounded packet:

1. resolve current truth from canonical `main`, exact PR heads, accepted source hierarchy, contradiction/current-state records and relevant restricted evidence;
2. identify the smallest CHLOM documentation delta justified by the evidence;
3. classify the exact proposed public output under the #131 IP-disclosure gate;
4. draft or revise substantive CHLOM documentation on a bounded branch;
5. preserve predecessor versions, source lineage, historical doctrine and unresolved state rather than rewriting history;
6. generate an exact-head review packet containing sources read, unavailable sources, changed records, public/private classification, tests, risk, rollback/reopen conditions and unresolved items;
7. route the packet to the accepted independent governance/review path for the current exact head;
8. remain HOLD until required reviews, validators and governed merge conditions are satisfied.

If no safe documentation delta is supported, Agent F must return `docs_no_change` or `docs_delta_opened`; it must not create filler prose merely to satisfy the per-pass requirement.

## Voting and separation of duties

Agent F authors and reconciles; Agent F does **not** cast a sovereign approval vote on its own packet.

The accepted constitution controls the voter pool and quorum. Framework agents, subagents, repositories, workflows, OIDC identities, MCP tools, transport identities and scripts remain non-voting until separately accepted under the constitution.

For each Agent F documentation packet:

- votes/reviews must bind to the exact artifact/head under review;
- the originator cannot satisfy its own approval requirement;
- missing required review remains HOLD;
- any governed deny/block remains HOLD;
- Agent D remains mandatory wherever the accepted governed-merge contract requires it;
- CI success is evidence, not constitutional acceptance by itself;
- D3/reserved-human decisions remain human-reserved.

## #131 publication boundary

Public CHLOM documentation may explain safe doctrine, interfaces, dimensions, lifecycle, thresholds, reasons, statuses and digests.

Agent F must keep the following outside the public projection unless separately classified and authorized:

- protected calibration and proprietary scoring bodies;
- private eval/adversarial corpora;
- credentials, secrets and key-management internals;
- restricted runtime DDL and security implementation details;
- private DAIL/evidence bodies;
- customer/partner/private identity records;
- private economics and trade-secret implementation;
- unresolved-rights or third-party licensed material.

When a protected implementation exists, public documentation should reference the governed evidence boundary without reproducing the protected content.
