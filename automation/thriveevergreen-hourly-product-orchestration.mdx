# ThriveEvergreen Hourly Product Orchestration

The ThriveEvergreen hourly product-orchestration component is active at
semantic version `1.1.0` in
`ACTIVE_OBSERVER_WITH_FRESH_SLOT_CANARY_PENDING` state. It may advance at most
one bounded product candidate per UTC hour through evidence observation and
review routing without granting itself economic authority. The active state is
not full certification: a fresh unconsumed-hour persistence canary and other
listed HOLDs remain open.

<Warning>
  **Current effect boundary:** the schedule is active only for the governed
  observer. Economic write, product publication, price, checkout, Crown Credits
  movement, entitlement, provider mutation, revenue, settlement and payout
  remain `DENY`; the publication target is zero. A production observer is not
  a production commerce authority.
</Warning>

The one-per-hour value is a maximum candidate-attempt rate, not a promise that
one product will be published each hour. `HOLD` consumes the slot. Version 1.1
enforces a shared slot structurally, but full persistence certification waits
for the next legitimate unconsumed-hour canary; the already-consumed window was
not bypassed to manufacture a passing result.

## Active observer loop

```text
hourly trigger
  → claim one unique UTC window
  → select at most one existing governed candidate
  → capture the exact candidate/version projection
  → read available evidence and independent-review state
  → evaluate the current ThriveEvergreen boundary
  → record the work packet, blockers and sanitized outcome
  → append DAIL evidence
  → stop without economic effect
```

The observer is scheduled through the CrownThrive automation control plane.
Direct access to its internal runner is revoked; the service may call only the
governed wrapper. The public record omits the exact scheduler offset and
internal provider/task identifiers. Scheduler success proves only that the
observer ran; it does not prove that a candidate received `ECAC` or that a
provider write occurred.

## Candidate and gate behavior

The observer works only from existing governed candidate records and, where
applicable, their governed product/package records. It does not generate
approval facts to make a candidate eligible. For the selected candidate it
records available release, rights, accessibility, security, pricing, tax,
fulfillment, entitlement and independent-review state.

Outcomes remain distinct:

- `ECAC` requires the exact, current authority package and every applicable
  independent predicate;
- `HOLD` preserves the candidate and exact blockers for later review;
- `DENY` prevents an effect when a hard gate fails or current production-effect
  authority is absent.

A Founder objective or override may prioritize and direct the work. It cannot
replace independently required rights, legal/tax, accessibility, security,
license, entitlement, quorum or authenticated execution evidence.

## Economic and credit boundary

The observer cannot create or activate a CrownThrive SKU, a price, a credit
balance, a discount, an entitlement, a listing or a checkout. Crown Credits
remain a distinct governed ledger/program state and are not activated by an
hourly run. Payment, fulfillment, storefront or API success cannot be promoted
into economic authority.

The superseded v1 dormant publication path did not enforce the complete authority
boundary. It did not run and produced no publication, but its mere inactivity
was not a valid guard. Version 1.1 removes publication code from the observer.
Any future economic publication must be implemented only in a separately
certified component.

## Safety contract

The component contract requires:

- unique hourly-window and concurrency controls;
- a maximum of one candidate attempt and one possible publication ceiling per
  window, while current publication authority remains `DENY`;
- append-only run and work-packet evidence;
- no deletion of run history, candidate history or DAIL evidence;
- governed-wrapper-only service execution with a public-safe status projection;
- no raw secrets, tokens, private evidence or protected policy bodies in
  status, logs or documentation;
- a pause/rollback path that preserves history;
- exact reapplication and readback before a component activation claim;
- DAIL chain verification after material lifecycle changes.

The detailed hardening evidence is held by restricted reference. This public
page records only the sanitized result and does not reproduce receipt IDs,
provider task identifiers, internal schedules, candidate identities or private
gate evidence.

## Promotion gate

Full observer certification still requires the fresh unconsumed-hour
persistence canary, exact dispatcher rollback verification, applicable
service-principal authorization. The final DAIL event and subsequent chain
verification passed, but do not resolve those independent predicates. Economic
write/publication would still require
a separate governed change proving all applicable Phase 3 and ThriveEvergreen
requirements, authentic authority, exact release eligibility, rights,
accessibility, security, pricing/tax, license/entitlement/fulfillment readiness,
rollback and provider readback. Until both gates pass, active observer-only,
zero-publication behavior is the current ceiling.
