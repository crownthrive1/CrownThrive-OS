### Upgrade gate

Do not treat the visible update button as permission to update production. A v66.0.1 → v70.0.0 migration requires, at minimum:

1. current application/database/file backup and restore proof;
2. provider changelog and license/support review;
3. staging or equivalent reversible test environment;
4. database migration review;
5. custom CSS/JS, AdLuxe embed, theme/template and plugin compatibility checks;
6. API endpoint/auth regression tests;
7. custom-domain, redirect, link, QR and static-site smoke tests;
8. login/registration, notification and payment-surface regression tests;
9. rollback target and post-update readback.

Support expiration is an operational risk to manage, not permission to bypass those gates.

## Security and abuse priorities

- API keys remain secret, server-side, revocable and reference-only in documentation;
- no agent receives unrestricted user API keys;
- rotate/rebind credentials through governed secret custody before runtime certification when exposure is possible;
- per-account/tenant authorization must survive MCP wrapping;
- custom-domain ownership verification is required;
- link/QR creation requires abuse, phishing and malware controls;
- open registration requires email/identity quality, rate-limit, bot/abuse and anomaly controls;
- static-file hosting requires malware/content protections;
- custom HTML/JS and external embeds require content-security and abuse review;
- analytics/export must respect privacy and tenant isolation;
- team membership changes require strong authorization;
- payment endpoints require stricter side-effect controls;
- suspicious registration patterns must not inflate audience, customer or growth claims.
