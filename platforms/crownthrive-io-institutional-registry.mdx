## Institutional IO/MCP expansion boundary

The merged CrownThrive institutional architecture expands `CrownThrive IO` beyond its current public product role into a target interoperability corridor for platform adapters, webhooks, tool registration, event normalization, authorization propagation, metering and agent-facing MCP tools.

That expansion is an architectural target. Current verified public product capability must remain distinct from target institutional IO/MCP services.

### Current verified product

```text
links / bio pages / QR / static hosting / analytics / domains / teams / API
```

### Target institutional layer

```text
CrownThrive ID
    ↓
IO / MCP gateway
    ↓
CHLOM + approvals
    ↓
platform adapters / vendor tools
    ↓
DAIL events + CrownLytics signals
```

The target layer must not inherit end-user API keys as a universal credential system.

## Current conclusion

CrownThrive IO is verified as a live public platform with a documented Bearer-key REST API and broad digital-presence feature set. It is therefore further along technically than the prior `unverified` API seed implied. The correct Phase 2.98 state is `public-host-verified + docs-verified`, while endpoint execution, account authorization, production health, deployment engine and backend ownership remain to be verified.

The next sub-run should extract concrete API paths and schemas from the official docs, verify authorized account/API behavior, identify the deployment/vendor spine, reconcile platform-specific privacy/terms, and then map only proven capabilities into CrownThrive IO MCP adapters.
