  - only then an explicitly authorized mutation

`credential_access_blocked` is not `credential_invalid`. It means the current audit environment cannot securely inject the restricted key. The correct response is to preserve the write gate and continue non-secret reconciliation, not reconstruct or expose credential material.

CrownThrive IO remains a specialized routing, link, QR, analytics, project and digital-presence system. It is **not** CrownThrive ID, CHLOM rights authority, or the canonical institutional source of truth. API records may reference those systems only through governed stable IDs and explicit authority boundaries.

## Security priorities

- API keys remain restricted, revocable and runtime-only;
- secrets never enter GitHub, Mintlify, source examples, generated artifacts, screenshots, email, CI output or logs;
- runtime access failure is recorded as `credential_access_blocked`, never repaired by reconstructing a key from conversation text or screenshots;
- no agent receives unrestricted user API keys;
- per-account/tenant authorization must survive MCP wrapping;
- custom-domain ownership verification is required;
- link/QR creation requires abuse controls;
- static-file hosting requires malware/content protections;
- analytics/export must respect privacy and tenant isolation;
- team membership changes require strong authorization;
- payment endpoints require stricter side-effect controls;
- bounded read verification precedes writes, and every authorized mutation requires read-after-write evidence.
