## Material contradictions requiring canonical control

### CT-CF-001 — platform-count conflict

Observed public values include:

- `80+ platforms` on the current home page;
- `80 platforms and brands` in About narrative;
- `over 60 integrated platforms` in About FAQ;
- `more than 60 core and auxiliary platforms` in About FAQ.

Classification: `definition-and-currency conflict`.

Required resolution:

1. define `platform`, `brand`, `framework`, `engine`, `imprint`, `property`, `auxiliary platform`, `domain` and `retired/dormant asset` separately;
2. generate the public number from the canonical platform/brand registry rather than hand-maintained copy;
3. publish an as-of date with any numerical scale claim;
4. prohibit agents from converting `60+`, `80`, or `80+` into a canonical count without registry evidence.

### CT-CF-002 — institutional phase namespace collision

Observed public phase language includes:

- ecosystem `Phase 0` on About;
- CHLOM `Phase 1` on the home page;
- full SSO in a referenced `Phase 2` roadmap;
- institutional documentation/recovery phases `1–2.99` in CrownThrive Support.

Classification: `namespace collision`, not automatically a factual contradiction.

Required resolution: every phase statement must carry a namespace, for example:

- `ecosystem-rollout:0`
- `chlom-product:1`
- `identity-program:2`
- `institutional-recovery:2.98`

Unqualified `Phase X` language should be treated as unsafe for machine reuse.

### CT-CF-003 — shared-account versus incomplete-SSO language

Some CrownThrive copy describes one connected ecosystem and shared account behavior, while the current About FAQ explicitly says full SSO is not yet achieved and that multiple login methods remain in use.

Classification: `target-state/current-state conflation risk`.

Canonical rule: `One Seat, Multiple Industries` is a target operating doctrine. It must not be translated into `one production identity provider already authenticates every platform` without technical verification.
