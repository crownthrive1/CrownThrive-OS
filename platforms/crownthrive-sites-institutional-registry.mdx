## Purpose and corridor

CrownThrive Sites™ is the productized implementation lane between self-service digital products and bespoke platform development. It packages reusable site systems, bounded implementation, Site Care, and governed ecosystem upgrade paths for businesses that need a credible operating website without commissioning a custom platform from zero.

It serves the commerce, beauty-wellness-phygital, faith-ministry, media-culture, education-community, advertising-distribution, and professional-services corridors through distinct product configurations. It does not replace the bespoke-development pathway.

## Integration boundary

The service is connected to the CrownThrive operating system through governed records and release reconciliation:

- **Mintlify / CrownThrive Support:** public-safe institutional documentation, API/MCP boundary records, agent responsibilities, release history, and corrections.
- **GitHub:** reviewed change-control transport, CI evidence, and public documentation history. GitHub is not sovereign approval authority.
- **CHLOM:** rights, provenance, license, and release-gate requirements apply before any product, asset, template, or commercial fulfillment moves from candidate to active.
- **CrownThrive IO, CrownLytics, CrownPulse, ThrivePush, AdLuxe, CrownRewards, ThriveSeat, ThriveTickets, GSO, and CrownThriveU:** planned or conditional ecosystem upgrade paths. No individual customer connection is represented as active until configured and certified.

## Agent operating contract

The existing institutional relay governs this platform:

1. Documentation Sentinel detects route, metadata, deployment, claim, and documentation drift.
2. Website and Release work follows the [Website Patch Workflow](/workflows/website-patch).
3. Documentation Steward reconciles platform, API, workflow, and release records.
4. Evidence Auditor verifies current-state language and non-inflation.
5. Agent D and Agent S independently gate material automation, security, and release decisions.

No agent may activate commerce, payment, customer-data processing, identity, write-capable API tools, or a production MCP server solely because a route, plan, or documentation page exists.

## Deferred and blocked work

- Customer accounts, submissions, CRM routing, payment collection, protected delivery, and recurring billing are not activated by this registry.
- The `ct.mcp.crownthrive-sites` contract is specified for discovery and governance only; it is not a deployed MCP server or authorization boundary.
- Production release of individual kits remains gated by applicable rights, accessibility, pricing, fulfillment, policy, and evidence records.

## Change and rollback

Every material change uses a versioned, reviewed change set with a release record, verification evidence, and a recoverable rollback target. The public deployment may be republished only after the changed source is validated and the documentation impact is either completed or formally tracked under the governing workflow.
