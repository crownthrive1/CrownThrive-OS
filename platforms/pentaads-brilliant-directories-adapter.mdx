## Purpose

The Brilliant Directories adapter translates governed PentaAds manifests into bounded placements on BD sites. It is designed for dynamic pages and avoids embedding credentials or provider mutation authority in browser code.

## Runtime behavior

The adapter provides:

- strict manifest validation;
- deterministic placement markers;
- route allow/deny controls;
- viewport restrictions;
- consent policy hooks;
- lazy placement with `IntersectionObserver`;
- dynamic fragment reconciliation with `MutationObserver`;
- History API and route-transition reconciliation;
- banner rendering through provider-issued AdLuxe zone IDs;
- VAST player handoff;
- allowlisted direct-link components;
- PII-free lifecycle events;
- fail-open error handling.

The adapter does not transmit member names, email addresses, member IDs, listing IDs, search text or account details.

## Default route boundary

Advertising is denied by default on:

- admin and administrator routes;
- login and logout routes;
- member account and dashboard routes;
- billing, checkout and cart routes;
- API and AJAX routes;
- WordPress administrative routes when the adapter is reused outside BD.

## Provider formats

### Banner

The adapter creates the provider's `ins-zone` element and loads the AdLuxe rendering script from the allowlisted provider host. It does not synthesize a tag or infer a zone ID.

### VAST

The adapter emits `crownthrive:pentaads:vast-ready` with the exact provider VAST URL. The host player remains responsible for the player integration, fallback, controls and playback policy.

### Direct link

Direct links require an exact provider-read-back `aso1.net` URL and an explicit sponsored component. Automatic redirects or click hijacking are prohibited.

## Installation authority rule

A documented BD endpoint is not sufficient production authority. Live installation requires one of:

1. a verified global custom-code or template route;
2. a verified widget plus widget-placement write chain;
3. an authenticated manual admin installation with source/readback evidence;
4. another independently verified source connector.

Until one exists, the correct state is `HOLD_BD_TEMPLATE_WRITE_AUTHORITY`.

## Canary contract

A bounded canary must:

1. inventory existing PentaAds/AdLuxe placements;
2. choose one non-duplicative, non-intrusive surface;
3. capture source preimage and rollback payload;
4. install the exact-SHA runtime and manifest;
5. refresh BD cache only through a certified route;
6. read source and public output independently;
7. verify marker, zone, route exclusions and page health;
8. certify or roll back.
