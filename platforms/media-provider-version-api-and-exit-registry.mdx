# Media Provider Version, API and Exit Registry

## Purpose

CrownThrive media systems use or contemplate multiple specialized providers. This registry separates:

1. **current official vendor capability**;
2. **CrownThrive account/plan evidence**;
3. **CrownThrive deployment/version evidence**;
4. **API eligibility and credential state**;
5. **export/backup/vendor-exit state**.

A vendor offering a feature does not prove CrownThrive’s current account can use it, and an older management source naming a vendor does not prove that vendor is still the installed production engine.

**Pass:** Phase 2.98 Pass B9 — Media Provider Verification

The public API requires a station ID but the exact Backroad FM/ Virality station ID was not recovered in this pass, so no station-level API test is claimed.

`provider export capability` ≠ `complete CrownThrive backup exists`.

### CrownThrive account evidence

Gmail confirms a current Riverside account and an August 12, 2026 **14-day Pro trial**. Recent Riverside product/marketing/account messages are present.

The Melanated Studios V1.0 plan treats three independent Riverside Studios as an initial planning assumption—one per flagship show—but this pass does **not** verify that those three show-specific studios have been created.


### Current official API

Riverside’s current Business API documentation says:

- current API version: **v3**;
- API v1/v2 are deprecated with a stated Feb. 24, 2026 sunset date in the current introduction;
- Business API availability is limited to select **Business accounts**;
- authentication uses Bearer API keys;
- API use cases include traversing workspaces/studios/projects/recordings/tracks/files, obtaining recording media/exported edits, deleting content and registering webinar audience members.

Current documented base family:

```text
/api/v3/
```

Because CrownThrive’s evidenced account is Pro trial rather than verified select Business, **do not assume Business API access**.

### Documentation-version inconsistency watch

A current Riverside endpoint page for `List All Exports` still displays `/api/v1/exports` while the current introduction says v1/v2 are deprecated and recommends v3.

Institutional treatment: `provider_docs_version_inconsistency / verify_before_implementation`.

No adapter should be generated from one isolated endpoint page until the current v3 endpoint contract is reconciled.

### Export and exit

Riverside is replaceable production infrastructure. CrownThrive must retain independently:

- show/studio IDs and mapping;
- original recordings and local masters;
- transcript/caption masters;
- guest/release/evidence records;
- edit/export manifests;
- RSS/feed ownership;
- episode metadata;
- audience/subscriber lists where lawfully controlled;
- provider terms/plan/effective dates;
- deletion/export evidence.

### Upgrade control

Iqonic’s current update instructions explicitly distinguish existing deployments from new installs and warn existing users to apply the supplied updated-files package rather than replacing the entire code ZIP unless the changelog says otherwise.

CrownThrive must therefore treat Streamit upgrades as **migration-tested application releases**, not blind vendor ZIP replacement.

Required before update:

- full code/database/media backup;
- current version/license evidence;
- local customization diff;
- dependency/runtime inventory;
- staging restore test;
- migration/seed impact review;
- Short Drama/add-on compatibility;
- checkout/subscription/device/OTP regression tests;
- rollback plan.

## Viloud — channel/distribution provider candidate/lineage

### Current official API

Viloud’s current public docs expose a **Delivery API** intended for channel distribution and integrations with web/native apps and third-party TV platforms including Roku/Amazon/Apple TV.

Verified base:

```text
https://deliver.viloud.tv/channel/{channel_id}
```

Verified delivery operations include:

- channel attributes;
- channel schedule;
- EPG in XMLTV format;
- Roku-compatible `roku_json` response format.

Viloud’s overview still states that a **management API is forthcoming**, with dashboard-only management operations not yet exposed by that documented API.

### CrownThrive deployment state

Historical/management sources associate Viloud with programmed/linear channels for Melanated TV and related properties. This pass has not verified:

- current CrownThrive Viloud account;
- active channel IDs;
- current channel inventory;
- API authentication/account scope;
- EPG/feed mappings;
- Roku/Amazon/Apple integrations;
- billing/license state.

Do not claim API-driven channel management from the current Delivery API.

### Versioning

Viloud documents date-based API versioning and automatic backward-compatible changes. CrownThrive adapters should therefore tolerate additive fields and retain contract tests rather than validating against an unnecessarily rigid response schema.
