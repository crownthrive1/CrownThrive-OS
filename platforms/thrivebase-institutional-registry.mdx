### Disk behavior

For paid Supabase plans, database disks may auto-scale as utilization approaches the provider threshold. Provider documentation currently describes a resize at 90% allocated disk usage, normally increasing the disk by 50%, subject to provider modification limits. CrownThrive does not interpret auto-scaling capability as authorization for unrestricted cost growth.

Because Spend Cap is enabled, covered over-quota usage can be restricted rather than silently converted into unlimited provider overage. Compute and certain explicitly provisioned add-ons remain outside Spend Cap treatment and must be monitored separately.

## CrownThrive-local request-budget semantics

ThriveBase uses the canonical CrownThrive-local request-budget contract:

- `-1` = **unlimited CrownThrive-local monthly request ceiling**;
- `0` = **exactly zero requests permitted**;
- positive integer `N` = **exactly `N` requests permitted per month**;
- `null` = **unresolved / unknown and fail-closed**.

The current ThriveBase local request-budget value is `-1`.

<Warning>
  `-1` does **not** mean Supabase is unlimited, free, unmetered, or exempt from provider quotas. CrownThrive-local request ceilings and provider-native quotas are separate controls; the strictest applicable provider, security, governance, billing, or authority boundary still applies.
</Warning>
