## Release rule

> No title may be activated because a catalog line, description, cover, Stripe Product, or claimed historical filename exists.

`ACTIVE` requires a complete governed manuscript, rights/canon approval, production masters, accessibility/visual evidence, protected upload, exact commerce mapping, entitlement/license/delivery evidence and refund/revocation/redelivery tests.

## Fourteen publishing release gates

| Gate | Required evidence | Owner | Public posture before pass |
| --- | --- | --- | --- |
| 1. Recovery Search | archives, prior workspaces, source files, hashes, version history | Publishing | Not available |

| 3. Manuscript | complete substantive manuscript; no placeholder chapters | Editorial | In production |
| 4. Editorial | developmental, line/copy, proofread | Editorial | In production |
| 5. Rights & Canon | ownership, contributors, artwork, canon, maturity | Rights/Canon | Rights review |
| 6. Visual Production | cover, interior, illustrations, metadata, accessible text | Design | In production |
| 7. EPUB/PDF | EPUB 3.3, screen PDF, TOC, links, fonts, metadata | Production | Technical QA |
| 8. Accessibility | reading order, headings, alt text, contrast, app/device checks | Accessibility | Accessibility review |
| 9. Preview & Listing | public sample, cover, thumbnails, exact product copy | Publishing | Coming soon only |
| 10. Protected Upload | object key, bytes, checksum, version, manifest | Production | Not purchasable |
| 11. Stripe Mapping | one Product/Price per SKU/version; tax/metadata | Commerce | Not purchasable |
| 12. Checkout & Entitlement | checkout, webhook, order, entitlement, license | Commerce | Not purchasable |
| 13. Delivery & Refund | signed download, redelivery, refund/revocation, isolation | Commerce/Support | Not purchasable |
| 14. Active | all evidence \+ release record; production smoke test | SUPER\_ADMIN | Active |

A failed gate returns the title to the stated repair/recovery step; it does not skip forward.

## Recovery versus rebuild

Use `recover` when a plausible authoritative master/version is expected to exist. Use `rebuild` only after the recovery search is documented and a current governing source/canon record exists.

A rebuild must not masquerade as the recovered historical edition. It receives:

- a new edition/version;
- source references;
- reason for rebuild;
- human/AI contribution provenance;
- canon/rights approvals;
- new checksums;
- migration/supersession relation;
- current release tests.
