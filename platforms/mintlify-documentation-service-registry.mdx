# Mintlify Documentation Service Registry

## Identity

- **Service ID:** `ct.service.documentation.mintlify`
- **Institutional platform:** `ct.platform.crownthrive-support`
- **Role:** documentation rendering, search, navigation, review and governed public-safe institutional projection
- **Source repository:** `crownthrive1/CrownThrive-Support`
- **Deploy branch:** `main`
- **Current plan:** Hobby
- **Canonical target hostname:** `docs.crownthrive.io`
- **Current custom-domain state:** configured in Mintlify; DNS/TLS validation pending

Mintlify is a CrownThrive service dependency, not the owner of CrownThrive institutional knowledge. Git/source, registries, version history and approved evidence must remain recoverable independently.

## Current source and workflow state

At the time of this Phase 2.98 checkpoint:

- CrownThrive-Support is the only repository exposed to Mintlify workflows through the current organization connection;
- product/site source repositories are therefore `not_connected_to_mintlify_workflows`, not presumed nonexistent;
- current link-rot and spellcheck source checks are configured as warnings;
- an existing scheduled internal-audit workflow exists but is disabled;
- the GitHub documentation-governance action independently validates navigated pages, MDX/text files, internal links, whitespace and merge-conflict markers on documentation PRs.

## Required automation posture

As source repositories become available, each should be registered with:

- repository and branch;
- platform/service IDs;
- environment;
- documentation impact mapping;
- code owners and approval class;
- API/schema/event sources;
- changelog policy;
- secrets boundary;
- source-code agent permissions;
- rollback path.

Source-code docs agents should run on changed PRs or webhooks rather than frequent full-repository polling.

## Publication boundary

Mintlify may publish approved public-safe or authenticated projections. It must not receive unrestricted production secrets, raw customer/payment payloads, privileged communications, confidential rights evidence or protected trade-secret implementation merely because the rendering service can store text.

## Recovery standard

CrownThrive must retain:

- Git repository and release history;
- machine-readable navigation/article manifest;
- off-provider content export;
- source register and checksums;
- redirect/canonical map;
- custom-domain/DNS record;
- workflow definitions;
- rebuild instructions;
- last known good deployment reference.

The institution must be able to rebuild documentation if Mintlify becomes unavailable.

## Service-product status

Mintlify is registered as a **third-party documentation infrastructure service/product** in the CrownThrive operating spine. It is not a CrownThrive-owned SaaS product and should not be marketed as such.
