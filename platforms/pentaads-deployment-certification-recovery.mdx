## Evidence doctrine

PentaAds uses independently readable state transitions. A successful provider request or visible ad element is not, by itself, a production certification.

A deployable placement must prove:

1. canonical source identity;
2. target source/write authority;
3. source preimage;
4. exact manifest and runtime bytes;
5. provider-issued inventory and code;
6. bounded authority and route eligibility;
7. source post-write readback;
8. public post-publish readback;
9. rollback payload and rollback verification;
10. no secret export.

## Dual-lane public readback

The server-origin certification crawler received a real Locticians bot challenge and HTTP `403`. That response remains recorded as a challenged lane.

An independent browser crawl reached the full public site and verified:

- home and directory content;
- matchmaking/directory navigation;
- listing or profile content;
- footer and cross-platform links;
- TV/video surface;
- AdLuxe references.

The public result is therefore `PASS_EXTERNAL_BROWSER`, not a synthetic rewrite of the server-origin result.

## Append-only records

ThriveBase maintains additive evidence tables for:

- BD adapter definitions;
- surface contracts;
- certifications;
- convergence releases;
- recovery records;
- recent-change/PentaDocs reconciliation.

Certifications, recovery records and change-ledger rows are append-only. Delete and mutation guards prevent historical evidence from being rewritten. Superseded records remain available with forward lineage.

## Recovery record requirements

Every live write must record:

- provider site ID;
- target type and target reference;
- canonical release reference;
- source preimage SHA-256;
- installed-source SHA-256;
- runtime SHA-256;
- manifest SHA-256;
- public readback SHA-256;
- rollback payload reference;
- actor and authority ceiling;
- installation and rollback timestamps;
- independent verification result.

## Deterministic survival

`PENTA_SURVIVAL_CONTRACT` v1 declares:

- persistent identity and state;
- deterministic functions;
- queues and leases;
- idempotent recovery;
- evidence hashing;
- authority enforcement;
- health checks;
- replaceable model behavior;
- restart from ThriveBase, provider readback, canonical GitHub source and institutional mirrors.

## Health and drift checks

The maintenance plane must check:

- provider credential-lane health;
- site/zone inventory drift;
- provider-code drift;
- scheduler health;
- site-source binding health;
- public placement markers;
- pricing/economics normalization;
- Drive/PentaDocs mirror convergence;
- stale or superseded release pins.

## Prohibited certification shortcuts

Do not certify based only on:

- an HTTP 200 from a write endpoint;
- a declared API scope;
- a model-generated zone tag;
- a visible iframe without provider identity;
- a provider dashboard screenshot;
- a GitHub Actions job that never obtained a runner;
- a public page that was not read after deployment;
- a source hash with no target/source-authority proof.
