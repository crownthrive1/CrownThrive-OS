# CrownThrive App Factory

CrownThrive App Factory is the governed application-manufacturing and lifecycle-management layer of CrownThrive OS. It converts approved websites and digital properties into managed mobile applications, coordinates Android builds, preserves version and artifact lineage, and exposes only approved published applications to ThriveApps.

The factory is based on the acquired Appy 1.1.2 Laravel application, but Appy is an implementation substrate rather than the governing architecture. CrownThrive owns the deployment topology, authority boundaries, cultural configuration, economic rails, evidence model, automation contract, and commercial operating model layered around it.

## Product promise

The commercial promise is:

> Turn a governed website into an application, build it, operate it, monetize it, and keep it connected to the CrownThrive ecosystem.

A generated application may connect to:

- ThrivePush for notifications;
- CrownLytics for analytics;
- CrownPulse for operating intelligence;
- CrownRewards for loyalty and engagement;
- AdLuxe Network through PentaAds for advertising inventory;
- Crown Credits for metered builds, campaigns, storage, modules, and AI usage;
- CHLOM for rights, licensing, permissions, and entitlements;
- CIE for brand, audience, culture, canon, and imprint controls;
- Thrive AI Studio for governed generation and assistance;
- CrownThrive IO and MCP APIs for system integration;
- Penta for autonomous monitoring, repair, release, and evidence preservation.

## Internal ecosystem role

CrownThrive-owned properties are the first canary and portfolio lane. Suitable properties can become independently identified application projections without creating a separate copy of the App Factory platform.

Examples include:

- Locticians;
- Melanated Voices;

- Gretna Junction;
- CrownThriveU;
- ThriveBeacons;
- Rooted Noir;
- Go Flipbooks;
- FindCliques;
- The Mane Experience;
- Crown Affiliates.

Each application projection receives its own package ID, UUID or DID, signing identity, website origin, CIE profile, CHLOM authority record, version history, artifact lineage, release channel, entitlement state, health state, and rollback record.

## One factory, many governed projections

The factory is multi-tenant. A customer or CrownThrive property does not receive a separate cPanel account merely because it receives an application. Customer and application tenancy are managed inside the App Factory database.

A separate infrastructure account is created only when a real failure-domain or legal isolation boundary requires it.

## Non-negotiable boundaries

- GitHub is canonical source after exact source reconciliation.
- cPanel MySQL owns live transactional application state.
- ThriveBase owns CrownThrive institutional state and evidence.
- ThriveBase does not directly mutate vendor application tables.
- Vercel is a stateless edge and relay plane, not the Laravel transactional runtime.
- Android SDKs and compilation do not run on shared cPanel.
- GitHub Actions workers are ephemeral and receive only bounded build scope.
- Secrets, signing keys, payment credentials, service-role credentials, and keystores never enter source control or public documentation.
- ThriveApps receives only published catalog projections.
- Provider success is execution evidence, not production certification.
- Publication requires a completed build, independently verified SHA-256 digest, institutional receipt, and authorized promotion.
