# Source, Release, and Evidence Custody

CrownThrive App Factory separates canonical source, generated assets, deployment packages, and institutional evidence. These objects are related but are not interchangeable.

## Custody classes

| Class | Purpose | Canonical authority |
| --- | --- | --- |
| Runtime source | Human-maintained application, edge, builder, migration, test, and deployment code | Private GitHub after verified import |
| Generated assets | Vite output, Composer production dependencies, compiled Android artifacts | Reproducible build and release pipeline |
| Release candidate | Complete deployment candidate prepared for controlled activation | Governed Drive custody plus hash manifest |
| Transactional state | Live Laravel application and build data | cPanel MySQL |
| Institutional evidence | Source, provider, build, publication, health, and rollback receipts | ThriveBase and PentaOS |
| Long-form operational documentation | Architecture, runbooks, status, and public-safe evidence | PentaDocs |
| Secrets and signing material | Credentials, private keys, keystores, tokens | Vault and provider environment only |

## Import verification contract

The import must:

1. use the governed runtime-source archive;
2. verify archive SHA-256 before extraction;
3. verify all file paths and hashes;
4. reject `.env`, credentials, private keys, keystores, `vendor/`, and `node_modules/`;
5. verify the expected runtime-source tree;
6. run CI on the exact provider commit;
7. preserve the final GitHub commit and tree in PentaOS and ThriveBase;
8. retain the complete release candidate in Drive as separate custody evidence.

## Generated frontend assets

`public/build/` is intentionally not canonical source. The release pipeline must run:

```bash
npm ci
npm run build
```

The release must verify `public/build/manifest.json`, preserve generated asset hashes, and include the generated output in the exact cPanel release unit.

## Composer and PHP dependencies

`vendor/` is not committed. The cPanel release pipeline installs production dependencies from the exact `composer.lock` and records the dependency installation result.

## Android artifacts

APK and AAB artifacts are not committed as canonical source. Every build receipt includes:

- source commit;
- application and build ID;
- package ID;
- build type;
- signing identity reference;
- artifact filename and storage reference;
- byte length;
- SHA-256;
- worker and workflow identity;
- timestamps and result state.

## Evidence immutability

A provider result may be corrected by a later receipt, but prior receipts are not silently rewritten. Corrections reference the superseded evidence and explain the factual change.

## Certification boundary

Source custody is a prerequisite, not production certification. The factory remains uncertified until the exact source is deployed, read back, tested through a real controlled canary, projected into ThriveBase, and proven recoverable.
