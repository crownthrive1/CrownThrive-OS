# ThrivePush Institutional Registry

## Identity

- **Stable platform ID:** `ct.platform.thrivepush`
- **Canonical name:** ThrivePush
- **Owner/operator:** CrownThrive, LLC
- **Primary role:** consent-based re-engagement, release reminders, abandoned-interest recovery and permissioned communications across approved ecosystem lanes.
- **Current evidence state:** portfolio role is documented; exact provider/engine, connected channels, sender infrastructure, API and live campaign state remain subject to verification.

ThrivePush is a communications/orchestration layer. It must not become an independent source of truth for identity, consent, product state, rights, rewards or analytics.

## Canonical responsibilities

- resolve an approved audience from authorized source systems;
- honor channel-specific consent and suppression state;
- render approved templates from current product/content data;
- send through verified providers/channels;
- receive delivery/bounce/click/unsubscribe events;
- hand normalized evidence to CrownLytics;
- use CrownPulse signals only when the audience purpose and consent allow it;
- trigger CrownRewards or affiliate outcomes only through explicit current rules.

## Consent and suppression rules

A person appearing in a customer, member, directory, event, rewards or affiliate record does not automatically create permission to message through every channel.

Every send must resolve:

- purpose;
- source of the contact point;
- consent/notice state;
- channel;
- organization/platform context;
- suppression status;
- age/maturity and sensitive-data restrictions where applicable;
- frequency/cadence rules;
- current template/version;
- unsubscribe/opt-out path.

Private spiritual journals, health data, confidential support records, child/minor profiles, restricted rights evidence and unrelated sensitive attributes cannot be repurposed into ordinary marketing audiences.

## Message classes

Keep at least these classes separate:

- transactional/order/access;
- security/account;
- support/service;
- subscription/member;
- product/content release;
- abandoned-interest/re-engagement;
- affiliate/ambassador program;
- event/ticket;
- marketing/promotional;
- required policy/legal notice.

A transactional purpose cannot be used as a blanket marketing-consent substitute.

## Agent model

| Agent | Autonomous work | Boundary |
| --- | --- | --- |
| Consent Sentinel | compare audience/contact/suppression state and block inconsistent sends | cannot manufacture consent |
| Campaign QA Agent | validate links, template version, offer state and required disclosures | cannot approve sensitive/high-risk targeting alone |
| Delivery Watcher | monitor bounces, complaints, provider health and pacing; open incidents | cannot silently switch sender/provider or expand audience |
| Documentation Agent | update message/channel/support articles and provider state | cannot expose contact data or credentials |

## Self-healing

Permitted low-risk recovery includes retrying idempotent provider status pulls, rebuilding derived audience previews, quarantining an invalid template, pausing a campaign under preapproved complaint/bounce thresholds and opening a documentation/incident delta.

Do not automatically resume after a consent, privacy, credential, deliverability or legal-policy incident until the required review passes.
