Recovered CrownThrive/CHLOM institutional sources place `Ops Oasis + Collab Portal` in the execution layer and associate them with tasks, approvals, signatures and partner operations. ## Do not conflate with My CrownOasis

Current CrownThrive public portfolio/home copy also uses the name `My CrownOasis` in a different product context. No authoritative evidence in this pass establishes that `My CrownOasis` is an alias for `OpsOasis`.

Canonical rule: treat them as separate records until lineage evidence proves rename, merge or shared implementation.

## Agentic operating role

OpsOasis is a candidate execution surface for the CrownThrive automation control plane:

```text
institutional objective
→ governed run packet
→ work graph / dependencies
→ human + agent assignment
→ tool execution
→ evidence/tests
→ approval gates
→ deployment/publication
→ monitoring
→ completion/rollback
```

Automation must not treat a task status as proof that the underlying action actually occurred. Completion requires evidence appropriate to the action class.

## Private/public boundary

OpsOasis should default to internal/restricted rather than public. Public progress belongs in ThriveMaps/changelog/status projections after classification and approval.

Sensitive work may include credentials references, legal matters, private IP, unreleased products, partner data and security incidents. Those require resource-level authorization and separate secret/evidence storage.
