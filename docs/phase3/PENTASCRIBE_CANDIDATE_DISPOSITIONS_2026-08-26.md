## Maturity precision

Semantic admission is not maturity inflation.

- PentaGreen and PentaOFAC are recorded with production maturity because current institutional records identify verified/current runtime behavior within their exact bounded scopes.
- PentaPR, PentaMerge and PentaCloser are recorded as implemented because source-controlled schedules, write-capable workflows and executable runtime code exist; this semantic registry does not independently certify every scheduled execution as production-successful.
- PentaMap is an alias only and receives no separate maturity.
- Rejected names receive no system identity or execution rights.

## Enforcement

The source registry at `penta/scribe/sources.registry.json` now:

- federates `data/penta/systems.extensions.execution-commerce-compliance.json`;
- blocks PentaAnalytics, PentaLegal and PentaFramework from becoming new candidates;
- preserves the existing PentaCapital, PentaImpact and PentaOps rejection decisions.

The canonical PentaOS component registry maps `PentaMap` to PentaMaps. Regression tests ensure all nine names remain in their governed dispositions.

## Continuity rule

A future change may supersede one of these dispositions only through an explicit current-state governance change with source/evidence lineage. Merely re-observing a name in documentation, source code, a workflow, a provider, an AI output, or historical material does not reopen or promote it automatically.
