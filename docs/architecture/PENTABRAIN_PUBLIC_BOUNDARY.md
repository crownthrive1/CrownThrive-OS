# PentaBrain — Public Architecture Boundary

PentaBrain is CrownThrive's native cognitive control-plane identity for coordinating governed execution around CrownThrive-native model runtimes.

## Identity boundary

- **PentaBrain** governs the cognitive/execution envelope.
- **PentaChat Native** is the CrownThrive-native language-model inference identity.
- The two identities are related but are not aliases and do not replace one another.
- External model providers may be used elsewhere in the CrownThrive ecosystem as separately governed services; they are not represented as PentaBrain's native cognition or as PentaChat Native weights.

## PentaBrain family

The public-safe family vocabulary includes:

- PentaAuthority — authority and admission boundaries.
- PentaContext — bounded authorized context assembly.
- PentaMemory — governed persistent memory.
- PentaRecall — governed recall and evidence retrieval.
- PentaRoute — hot/warm/cold routing and degraded-mode selection.
- PentaState — persistent execution state and resumability.
- PentaCIE — bounded Cultural Imprint Engine context.
- PentaCore — native execution-kernel binding.
- PentaCells — bounded deterministic functions/tools.
- PentaVerify — evidence and contradiction verification.
- PentaMesh — authenticated inter-Penta routing and receipts.
- PentaSurvival — model-off, restart, recovery, degradation and replacement continuity.

## Public/private rule

This page is intentionally non-enabling. Proprietary architecture details, native-model implementation, weights, checkpoint lineage, exact runtime internals, confidential evidence and sensitive operational bindings remain in CrownThrive's governed private systems of record.

A public reference to PentaBrain does not imply production certification of every family member, public model availability, unrestricted API access, provider authority, legal/financial authority, or disclosure of CrownThrive proprietary implementation.

## Production invariant

A Penta is not production-capable merely because it is registered, can call a model, or can initiate a workflow. Persistent identity, persistent state, deterministic functions, queues, leases, recovery, evidence, authority enforcement, health behavior, model degradation, model replacement, and restart behavior remain separately declared, exercised and evidence-bound before production maturity.
