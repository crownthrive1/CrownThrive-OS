# Contact Support and Escalate an Issue

Use ThriveSupport when self-service documentation does not resolve the problem or when an issue requires account, transaction, platform, privacy, security, creator/partner, or operator review.

## Contact route

Use the support experience available at **crownthrivesupport.com** when available for the affected workflow. CrownThrive’s general contact address is **contact@crownthrive.com**.

## Build a useful support request

Include:

1. The CrownThrive property, product, or URL.
2. Your account email/username when relevant.
3. What you expected to happen.
4. What actually happened.
5. Exact error text.
6. Approximate date/time and time zone.
7. Order, transaction, ticket, campaign, or other reference ID.
8. Redacted evidence such as screenshots when useful.
9. The outcome you need.

Never include passwords, one-time codes, recovery codes, private keys, API secrets, full card details, or bank credentials.

## How issues are prioritized

**Critical:** active security/data exposure, suspected payment fraud, or a severe service-wide incident requiring immediate containment.

**High:** a major business capability is blocked, multiple users are materially affected, or a time-sensitive production workflow cannot proceed.

**Normal:** a single-user workflow, account issue, transaction question, how-to request, or reproducible feature defect without broad impact.

**Low:** cosmetic defects, content corrections, general feedback, or feature suggestions without current operational impact.

These classifications guide routing; they are not promises of a specific response time.

## When to escalate an existing issue

Escalate when the impact materially increases, new security or financial risk appears, the original issue was routed incorrectly, or you have new evidence that changes the diagnosis. Include the original ticket/reference so the history stays connected.

Avoid opening duplicate tickets for the same unchanged problem. Duplicates fragment evidence and can slow diagnosis.

## Escalation packet

For a complex issue, send a short chronology: when it started, what changed, actions already tried, current impact, exact references, and desired resolution. For a technical incident, also include device/browser/app version when known.
