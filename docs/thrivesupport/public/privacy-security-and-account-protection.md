# Privacy, Security, and Account Protection

Protecting your CrownThrive access starts with protecting the identity, email account, and authentication methods connected to it.

## Protect your account

- Use a unique password for each account system.
- Enable multi-factor authentication wherever the affected CrownThrive property provides it.
- Keep recovery email and phone information current.
- Do not reuse API keys, private tokens, or passwords across unrelated services.
- Verify the domain before entering credentials.
- Treat unexpected password-reset, payment, or verification messages as suspicious until verified through the official property.

## If you suspect account compromise

1. Change the affected password from a trusted device.
2. Secure the email account used for password recovery.
3. End unfamiliar sessions where session management is available.
4. Revoke or rotate exposed API keys/tokens through the owning system where available.
5. Review recent profile, billing, payout, integration, and security changes.
6. Record relevant timestamps, IP/session information shown to you, and redacted screenshots.
7. Contact ThriveSupport and identify the affected property.

## If a secret was exposed

Do not paste the secret into a support ticket. Rotate or revoke it through the owning service. Tell support **which credential type was exposed**, which property it belongs to, and when exposure occurred, but not the reusable secret value itself.

## Privacy or data requests

Requests involving access, correction, deletion, or other privacy rights may require identity verification before account-linked information can be disclosed or changed. Use the official CrownThrive support or privacy workflow for the property involved.

## What support should never request in a normal ticket

Do not provide passwords, one-time codes, recovery codes, private keys, full card numbers, CVVs, bank credentials, or secret API tokens. If anyone claiming to represent CrownThrive asks for these through an ordinary message, stop and verify the request independently.
