# PentaBooks Recovery and Failure Containment

PentaBooks quarantines the exact failing SKU, edition, package, provider object, or evidence event. It does not halt or roll back unrelated accepted work unless a shared dependency is proven unsafe.

Recovery reuses the original immutable subject and hash when bytes are unchanged, or creates a new explicit generation when bytes change. Idempotency prevents duplicate acceptance. Dead-letter and stale-readback records remain visible until repaired or terminalized with evidence.

A recovery run cannot upgrade a state merely because the retry executed. It must read the repaired predicate back from the authoritative source.
