# PentaBooks Release State Model

PentaBooks uses predicate-specific states so production progress cannot be mistaken for commerce or release.

| State | Meaning |
|---|---|
| `DISCOVERED` | A candidate artifact or source was located. |
| `CLASSIFIED` | Rotation, SKU, edition, rights, sensitivity, and owner were resolved. |
| `HASHED` | Exact bytes and SHA-256 were recorded. |
| `PACKAGE_COMPLETE` | The independent SKU package contract passed. |
| `DUAL_CUSTODY_VERIFIED` | Producer/Library and Drive copies passed download and equality readback. |
| `REGISTRY_CONVERGED` | Required registries agree on the exact subject and state. |
| `PENTAGREEN_CANDIDATE` | A complete candidate was handed to commerce control; it is not yet activated. |
| `PROVIDER_ACTIVATED` | Exact provider product, price, reader, entitlement, or license objects were created and read back. |
| `PUBLIC_RELEASE_VERIFIED` | Public route, checkout, delivery, recovery, analytics, and transaction predicates passed where applicable. |
| `RECOVERY_REQUIRED` | A required file, binding, readback, or predicate is absent or stale. |
| `QUARANTINED` | The exact subject is isolated because rights, integrity, identity, safety, or provider evidence is unsafe or contradictory. |

No state inherits an unproven later state. A workflow success badge, registry row, Drive ID, candidate price, or public-facing draft cannot substitute for the exact predicate evidence.
