# CrownThrive OS Support & Repository Routing 💬

**Phase 3 edition — effective 2026-08-26**

This repository is CrownThrive's authoritative public-safe **Operating System source and support-routing surface**. Use the route below that matches what you need so private or restricted information does not end up in a public issue.

> **Source-of-truth rule:** CrownThrive OS governs current institutional state. CHLOM, CIE, and other component repositories govern their exact component scopes. PentaDocs, websites, storefronts, media surfaces, and other public properties are downstream projections and may be reconciled later without overriding OS state. Mintlify is the current third-party rendering/hosting provider for PentaDocs.

## Current institutional information

For current Phase 3 state, use:

- `README.md` — CrownThrive OS orientation and source-of-truth hierarchy;
- `docs/phase3/CURRENT_STATE.md` — canonical Phase 3 operating picture;
- `docs/versioning/VERSION_REGISTRY.json` — current OS and component version lineage;
- `docs/archive/README.md` — archive and supersession policy;
- applicable CHLOM/CIE/component records for exact subsystem state.

A website, PentaDocs page rendered through Mintlify, public dashboard, storefront, provider page, or historical document can identify a projection or evidence item, but it does not redefine the OS merely because it remains publicly visible.

## Public documentation questions and corrections

A public GitHub issue is appropriate for:

- broken or incorrect public-safe OS documentation;
- missing or broken public-safe links;
- terminology, naming, navigation, accessibility, or formatting problems;
- a public-safe correction supported by a source you are authorized to share;
- historical/current-state or archive/supersession labeling errors;
- reproducible defects in repository tooling that do not expose restricted information.

Use the repository issue templates where available. Do not include restricted records, private account data, customer information, protected evidence, private contracts, or security-sensitive details.

## Private security, privacy, or credential issues

Do **not** open a public issue for vulnerabilities, exploit paths, exposed access material, private customer/personnel records, protected rights evidence, private contracts, incident evidence, or other restricted matters.

Follow `SECURITY.md` and contact **contact@crownthrive.com** with the subject:

`Private Security Report — <affected platform or repository>`

Send only the minimum information needed to route the report. Request a controlled transfer method for protected evidence.

## Account, order, payment, or entitlement support

Do not publish order numbers, payment details, customer information, protected delivery links, entitlements, disputes, refund evidence, or account identifiers in a GitHub issue.

Contact **contact@crownthrive.com** and identify the relevant CrownThrive platform or product using the minimum non-sensitive reference information necessary.

A provider receipt, checkout success, transaction event, webhook, or provider message is evidence from that provider and does not by itself establish a CrownThrive license, rights grant, entitlement, settlement, revenue-recognition state, or other institutional authority. Those states must reconcile through the applicable OS, CHLOM, ThriveEvergreen, and evidence records.
