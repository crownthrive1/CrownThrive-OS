# CrownThrive Services Stack™

The CrownThrive Services Stack™ (CSS) remains a useful **shared-services compatibility substrate**. It is no longer treated as a competing top-level governance framework or autonomous agent estate.

In Phase 3, CSS provides stable service identities and provider-independent contract boundaries beneath the current Penta operating environment. **PentaFabric™** owns orchestration/federation, **PentaCredentials™** owns credential binding, **PentaBuild™** owns adapter/software construction, **PentaCertify™** owns exact-scope certification, **PentaNurture™** owns maintenance/drift, and **PentaStatus™** owns current-state projection. CHLOM remains the governance/policy/evidence layer.

## Service / contract / provider separation

CSS preserves three distinct layers:

1. **Stable service identity** — what institutional capability is being requested.
2. **Versioned service contract** — the inputs, outputs, failure behavior, data class, authority requirements, evidence, and rollback semantics.
3. **Replaceable provider binding** — the specific vendor/native implementation selected for the contract.

Provider availability is not authority. A credential is not certification. A successful read does not grant unrelated writes. A provider write is eligible only when PentaCredentials reports a valid bound credential, PentaCertify has certified the exact operation, and current CHLOM/Penta authority permits that operation.

## Current runtime boundary

The August 23, 2026 CSS controlled-test records remain dated evidence. They included 14 service identities, 32 provider bindings, a version-1 Edge function, an hourly `:39` schedule, and a 10-healthy/4-degraded health snapshot.

Those values are **not current-runtime claims**. Before using any historical CSS provider binding, scheduler, health result, or Edge deployment, PentaNurture/PentaStatus must read back the current runtime and PentaCertify must determine whether the exact path remains eligible.

### Legacy Edge source disposition

The old controlled-test Edge source is preserved in branch history but is **not promotable as current production source**. It contains pre-Penta authorization assumptions, including hard-coded privileged identity allowlisting and a direct service-role token identity shortcut. Current execution must instead use governed identity/credential references and current authority envelopes.

## Economic and rights boundaries

The service names `billing`, `commerce`, `rewards`, and `licensing` do not themselves authorize economic or rights effects.

- PentaCost may enforce budgets and cost limits but does not move money.
- PentaPay may record approval/receipt state but does not create payment authority.
- PentaGreen/PentaCredits may operate only within their existing economic authority.
- CHLOM/PentaLegal govern licensing/rights conditions; CSS cannot grant rights.
