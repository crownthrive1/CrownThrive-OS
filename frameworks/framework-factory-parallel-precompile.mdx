# Framework Factory Parallel Precompile

**Contract:** `ct.contract.framework-factory.parallel-precompile.v1`  
**State:** controlled-test candidate  
**Authority ceiling:** D2  
**New scheduler slots:** 0  
**Promotion order changed:** no

CrownThrive may compile later Framework Factory work before earlier frameworks become eligible for activation. The optimization is deliberately narrow:

> **Parallelize preparation. Preserve sequential authority.**

The factory may run source discovery, reconciliation, public-safe skill compilation, schemas, APIs/MCP candidates, test/eval generation, documentation, gap analysis, dependency mapping, rollback design, and commercial-candidate packaging for downstream frameworks while Cultural Imprint Engine and other predecessor gates remain open.

It may **not** use that preparation to claim a downstream framework is accepted, canonical, operational, voting, customer-entitled, economically effective, publicly certified, or Phase-advancing.

## Why this changes the bottleneck

The prior failure mode was allowing a sequential promotion gate to serialize work that does not need promotion authority. Source recovery, contract drafting, skill compilation, negative tests, documentation, dependency maps, and evidence requests can be built safely ahead of the gate. Only promotion/activation remains serialized.

This keeps the high-consequence safeguards while removing avoidable idle time.

## Allowed precompile outputs

- `precompile_ready` — candidate preparation is internally complete enough for independent verification and the next governed handoff.
- `precompile_hold` — preparation is useful but evidence, predecessor state, or specialist review is incomplete.
- `precompile_denied` — the candidate crosses a prohibited authority, rights, privacy, security, economic, identity, or lifecycle boundary.

`precompile_ready` is **not** an activation verdict.

## Unchanged promotion firewall

The precompile optimization does not remove or weaken:

- exact-head/source and digest lineage;
- independent verification;
- mandatory Agent D where the Framework Factory promotion contract requires it;
- applicable Security/Privacy, IP/Rights/Licensing, Finance/Tax/Treasury, Accessibility/Consumer, SRE/Operations, regional/localization, or other specialist gates;
- rollback/readback evidence;
- valid quorum and no-block/no-deny requirements;
- founder/human-reserved D3 authority;
- Phase 2.99 hard-exit requirements;
- provider, payment, rights, entitlement, credential, or production-activation boundaries.

## Scheduling

No new top-level automation slot is created. Candidate precompile work is routed through the existing Framework Factory review/dispatch fabric and existing bounded agent capacity. Deduplication uses stable framework/package IDs, exact source/head lineage, and output digest.

## CIE boundary

CIE remains the first governed framework and its protected implementation remains restricted. Preparing CIE's public-safe skill, tests, schemas, evidence requests, and downstream handoff contract does not invoke its protected runtime and does not satisfy its remaining independent-review or parent-certification gates.

## Institutional effect

This policy is an efficiency change, not a governance downgrade. It converts the Framework Factory from **serial work + serial promotion** into **parallel preparation + serial promotion**.
