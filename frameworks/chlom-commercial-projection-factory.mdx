# CHLOM Commercial Projection Factory

## Institutional relationship

`crownthrive1/CrownThrive-Support` is the private canonical parent for CrownThrive-controlled CHLOM product policy, institutional state, protected implementation knowledge and release authority.

`crownthrive/chlom-protocol` is the public, monetized commercial projection of CHLOM. It is intentionally public-safe. It exists for product discovery, technical evaluation, integration documentation, public registries, commercial licensing surfaces, public developer contracts and verification artifacts.

The child repository is not permitted to manufacture parent authority or expose protected parent material.

## Factory flow

`canonical parent → public-safe source package → projection validator → deterministic build → independent verification → child candidate branch → child pull request`

The factory follows the existing Framework Factory Execution Builder doctrine: a builder materializes candidate artifacts, but a build receipt is not certification and the builder cannot certify its own output.

## CrownThrive OS paint

The commercial projection is a CrownThrive OS surface. Every generated projection carries:

- product ID and repository role;
- exact upstream parent commit SHA;
- projection schema version;
- CrownThrive ownership and commercial-license boundary;
- canonical CHLOM terminology;
- public/private security boundary.

## Canonical terminology

DAIL means **Decentralized Autonomous Information Ledger**.

DLA means **Dynamic Licensing Asset**.

Historical uses of DAL and historical uses of DLA as “Decentralized Licensing Authority” remain recoverable lineage, but are not current canonical product meanings. Current licensing authority responsibilities are expressed as **Licensing Stewardship / Issuer Authority**.

## Commercial posture

The child is designated a monetized commercial repository. That designation creates a commercial product surface; it does not by itself assert that checkout, a token, a mainnet, public APIs, a payment rail or a specific price is live.

Commercial capability classes are:

- Public / Community
- Developer / Integration
- Business / Commercial
- Enterprise / Institutional
- Ecosystem / Partner

Prices, entitlements and activation claims are resolved from separately governed commercial state rather than invented in repository documentation.

## Security boundary

The projection is allowlist-only. It must fail closed on credential-shaped material and may not export raw secrets, private contracts, customer records, protected-person data, private unit economics, confidential source evidence, unreleased implementation assets or Fingerprint implementation details.

The factory does not delete unmanaged child paths. This allows the public repository to retain validated registries, schemas, tests and research artifacts while the parent owns the commercial/public-policy overlay.
