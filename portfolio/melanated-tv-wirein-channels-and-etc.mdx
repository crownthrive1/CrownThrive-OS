## Powered-by mapping

Viloud is recorded as the current provider for live ingest, playback, iframe embedding, and configured destination distribution. Melanated TV remains the CrownThrive-owned network/brand layer; MVP and the named SYND/OD destinations are distribution surfaces. Provider identity must never replace network ownership or program identity in the institutional registry.

## Secret handling

The RTMP stream key is a restricted runtime credential. It must **never** appear in Git, public documentation, logs, screenshots, client-side JavaScript, analytics payloads, issue bodies, or public configuration. ThriveBase stores only the logical secret reference `VILOUD_BLESS_THE_MIC_STREAM_KEY`; the raw credential belongs in the authorized runtime secret/vault layer.

The RTMP ingest endpoint itself is not sufficient to publish without the secret and may be documented internally where useful.

## Intake contract for every channel supplied next

Every future channel/live-stream record supplied under this workflow should be normalized into the same fields: canonical asset ID, network/brand owner, program title, provider, ingest protocol and endpoint, **secret reference only**, public playback URL, embed URL, destination set, asset roles, storage/plan snapshot, current status, provenance, and evidence timestamp.

Duplicate source text must reconcile into one canonical asset record rather than generating duplicate institutional assets. New destinations extend the destination set; changed provider values create an auditable update event.

## Governance boundary

This record institutionalizes configuration and ownership topology. It does not claim that every downstream destination is currently broadcasting unless runtime evidence confirms it. “Configured destination,” “registered asset,” “verified playback,” and “verified live carriage” are separate evidence states.
