# Asset Resurrection & Disposition Registry

This register operationalizes the [Revival Doctrine](/doctrine/revival-doctrine). It is a public-safe projection; restricted source bodies, credentials, private infrastructure and trade-secret implementation remain outside public documentation.

## Requirements-archaeology source lane

The recovered Help Center provides concise functional descriptions for assets such as CrownConsult, CrownInsights, Crown Affiliates/Ambassadors, SocialAIly, StonkCliques and Thrive AI Studio. Those descriptions establish historical requirements and object identity. They do not prove current implementation, users, payments, provider accounts or legal sufficiency.

## Activation governance

A record may move to `ACTIVATE`, `REVIVE`, `MIGRATE` or `LICENSE` only when its applicable current acceptance packet covers:

- source and rights lineage;
- current owner/authority;
- current use case and non-duplication rationale;
- security/privacy/data boundaries;
- applicable legal/regulatory/consumer-protection review;
- economics and settlement where money is involved;
- current technical architecture and recovery;
- accessibility/localization when applicable;
- exact specialist and independent governance/quorum;
- rollback/sunset path.

## Phase 3 relationship

This register is a **pre-Phase-3 documentation hard-gate artifact**. It does not authorize all revival candidates to be built in Phase 3. Phase 3 begins with the accepted institutional core, identity/authority, and one bounded adapter pilot; each asset activates in the phase appropriate to its risk and dependency graph.
