# Platform State and Phase Register

CrownThrive manages more assets than it actively builds at one time. This register separates **portfolio presence** from **active implementation state**.

## Required fields per platform

- stable platform ID;
- canonical and alias names;
- portfolio priority;
- current lifecycle state;
- current institutional-build phase;
- public URL(s);
- repository/deployment;
- authentication state;
- commerce state;
- entitlement/fulfillment state;
- admin/ops state;
- support state;
- data/integration state;
- last verified date;
- blocker list;
- next milestone.

Capability fields remain independent. A platform may be publicly reachable while source, API, commerce, entitlement, admin, support or recovery states remain blocked or unverified.

## Rule for the larger portfolio

Any asset not recently verified must remain `unverified-current-state` even if it appears in the 80\+ public portfolio. Portfolio membership does not prove production readiness.

## Phase 3 requirement

The registry should become machine-readable and periodically verified through domain checks, repository/deployment evidence, smoke tests, billing/entitlement tests where applicable, and owner review.
