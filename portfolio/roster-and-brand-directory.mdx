# Roster and Brand Directory

The **Roster \+ Brand Directory** is the authoritative institutional inventory of what CrownThrive calls, owns, controls, operates, incubates, licenses, archives, or publicly routes.

## Why it exists

CrownThrive's history contains overlapping product names, vendors, archived platforms, current properties, imprints, framework names, legacy descriptions and new successor systems. Search engines and old pages should not determine the current organization chart.

## Record classes

The directory should distinguish:

- legal entities;
- operating platforms;
- customer-facing brands;
- imprints and media channels;
- internal engines/services;
- governance frameworks;
- programs and initiatives;
- product families;
- domains/deployments;
- archived/sunset assets;
- historical aliases.

## Required fields

Each record should include stable ID, canonical name, aliases, class, parent/steward, corridor, status, priority, current description, canonical URL, owner/operator, rights relationship, predecessor/successor, source authority, public visibility and last review.

### Phase 2.99 founder expansion

The directory is now explicitly **state-independent**. Every known CrownThrive identity remains indexed whether it is active, developing, reserve, legacy, predecessor, successor, sunset, archived, research, never-adopted source lineage, or future build.

Each record must now also resolve:

```yaml
public_domains: []
public_domain_roles: []
internal_docs: []
portfolio_relationships: []
press_room:
public_powered_by_lineage: []
current_public_copy_state:
public_copy_drift_state:
page_version:
correction_history: []
```

Public-safe domains should be exposed when known so humans, agents, search and routing systems can use them. Private admin URLs, infrastructure hostnames, credentials, secret callbacks, customer data and trade-secret routes remain excluded.

See [Public Brand & Platform Portfolio](/portfolio/public-brand-platform-portfolio) and the [CrownThrive Press Room](/press/index).

## Public routing

If a public asset is archived or renamed, its directory record should identify the current destination and preserve the old name as an alias. This allows support, AI, search, redirects and partner communications to resolve old references consistently.

## Phase 3 implication

The Roster becomes a core registry consumed by CrownThrive IO/MCP, Support, websites, analytics, CHLOM, the Orchestrator and future Holdings dashboards.

Phase 3 entry now also requires material portfolio documentation to be reconciled: known identities cannot be missing simply because they are inactive, and public-safe domain/press/internal-link relationships cannot remain materially stale.
