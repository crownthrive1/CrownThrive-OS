# CHLOM Wallet Policy Assurance Threat Model

This threat extension governs the controlled-test policy-assurance layer that evaluates Wallet intents into `ECAC | HOLD | DENY`. It does not authorize production activation or replace independent review.

## Protected properties

The layer must preserve these invariants:

1. deterministic policy output for the same normalized intent and rulepack;
2. A2/D2 maximum controlled-test authority;
3. no self-approval by the Wallet Agent;
4. no executable authority inherited from pending role aliases;
5. no AI model output becoming final policy authority;
6. no provider success becoming a rights grant, settlement authority, or fulfillment instruction;
7. no production, custody, token, money, rights, broadcast, pricing, checkout, merge, or phase side effect;
8. no secret-shaped material entering public rulepacks, decision receipts, manifests, or advisory records;
9. source-controlled skill-to-pallet closure for all governed Wallet skills and component pallets;
10. append-only/versioned runtime evidence rather than silent mutation of prior evidence.

## Threats and controls

| Threat | Failure mode | Control |
| --- | --- | --- |
| AI authority escalation | A model recommends `ECAC` over deterministic `HOLD`/`DENY` | AI Counsel Firewall preserves deterministic disposition and records the attempted upgrade only |
| Stale identity | An old heartbeat or source snapshot is treated as current | stale heartbeat/source adds risk and blocks `ECAC` |
| Self-review | Originator acts as independent reviewer | originator/reviewer equality blocks `ECAC` |
| Alias privilege creation | `ct.agent.api-mcp` or `ct.agent.webhook-delivery` is treated as an executable stable identity | pending alias dependency blocks `ECAC`; crosswalk grants no capability |
| Authority-ceiling bypass | A3/D3 work is routed through the Wallet Agent | ceiling excess is a hard `DENY` |
| Semantic collapse | Money evidence is treated as Rights, Rewards, Impact, or Proof authority | Value-Class Lattice preserves explicit classes and Mixed-state review |
| Production leakage | controlled-test code is used to activate provider/commerce/chain state | hard boundary action and requested-effect checks return `DENY` |
| Rulepack tampering | weights, environments, or boundaries are changed without trace | canonical source digest + compiled digest + source-controlled manifest |
| Receipt ambiguity | different inputs produce an apparently identical untraceable result | decision receipt binds intent digest, rulepack digest, action, value class, reasons, and disposition |
| Secret leakage | credentials or key material enter metadata, policy, AI rationale, or manifest | canonical utility secret-shape scanning plus CI grep boundary |
| Mapping drift | skill exists without pallet coverage or pallet exists without governed skill linkage | closure test requires all 23 current skills and all 12 current pallets |
| Adversarial combinations | several individually minor defects combine into unsafe `ECAC` | deterministic 50,000-case chaos suite and invariant assertions |
| Evidence replay mutation | an existing policy receipt is silently changed | THIVEBASE policy evidence remains append-only/versioned; new v2 IDs supersede rather than overwrite v1 |

## AI advisory classification

AI advisory content is **non-authoritative evidence**. It may summarize, classify, detect contradiction, recommend a stricter disposition, or identify missing evidence. It cannot:

- lower the deterministic risk score;
- remove deterministic reasons;
- upgrade `DENY` to `HOLD` or `ECAC`;
- upgrade `HOLD` to `ECAC`;
- create a capability grant;
- create a reviewer heartbeat or receipt;
- authorize provider mutation, rights, settlement, chain execution, public pricing, checkout, merge, or phase advancement.

## Test boundary

The controlled-test suite includes deterministic positive, HOLD, DENY, self-review, pending-alias, and AI-upgrade negatives, plus 50,000 deterministic chaos cases. Passing these tests proves the policy contract behaves as encoded; it does not prove production suitability, legal sufficiency, economic correctness, or independent release approval.

## Reopen conditions

Reopen this threat model when any of the following changes:

- Wallet autonomy or decision ceiling;
- stable agent IDs or pending alias disposition;
- WalletKit pallet catalog or skill suite;
- effective commerce authority or ThriveEvergreen rulepack;
- Rights/Finance/Security/Recovery review requirements;
- public or private AI model role;
- provider-write, custody, money, rights, chain, pricing, checkout, merge, or phase permissions;
- rulepack algorithm, risk weights, or receipt schema;
- THIVEBASE append-only/RLS posture.
