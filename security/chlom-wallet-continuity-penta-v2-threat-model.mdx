# CHLOM Wallet Continuity Penta v2 — Threat Model

## Scope

This model covers the source-canonical Phase-3 compatibility layer for Wallet continuity. It does not certify a public API, MCP server, provider adapter, or destructive recovery path.

## Primary risks and controls

### Stale runtime truth
Risk: historical Phase-E counts, bindings, or health are treated as current.
Control: dated readback is explicitly non-evergreen; current runtime decisions require PentaStatus refresh.

### Authority inheritance
Risk: historical Gen6 agent ownership is treated as current authority.
Control: ownership is rebound to PentaNurture/PentaCredentials/PentaCertify/PentaFactory/PentaBuild/PentaTriage; standalone agent authority, voting, and self-approval remain false.

### Unbound MCP/API activation
Risk: compatibility tool names are interpreted as deployed endpoints.
Control: all eight MCP tools remain disabled and the API deployment state remains HOLD until current server binding and exact-operation certification exist.

### Unsafe SQL replay
Risk: old Phase-E migrations overwrite or conflict with newer shared continuity layers.
Control: source replay is false and old Phase-E SQL replay is explicitly prohibited by the current evidence/contract.

### Oracle mutation
Risk: an oracle becomes a write-capable authority path.
Control: deterministic evaluation denies non-read-only oracle observations.

### Destructive recovery
Risk: a recovery plan is executed automatically.
Control: recovery output is plan-only; provider write and automatic destructive action remain false.

### Advisory-model escalation
Risk: risk scoring becomes decision authority.
Control: ML score remains advisory-only with `final_authority=false`.

### Secret exposure
Risk: continuity execution returns or embeds credential material.
Control: credential material return is false; binding is delegated to PentaCredentials references and PentaCertify evidence.

## Promotion rule

No runtime promotion is permitted from source presence alone. Production enablement requires current provider readback, credential readiness, exact-operation certification, rollback evidence where applicable, and CHLOM-governed authority. Failure or ambiguity resolves to HOLD or DENY, never manufactured authority.
