# Documentation Gap & Article Rebuild Register

This register is the working institutional map for what CrownThrive documentation still lacks and how the recovered **795-title Help Center estate** is converted into substantive, current, versioned knowledge.

It is governed by the [Documentation Reconciliation & Continuity Framework](/standards/documentation-reconciliation-continuity-framework) and the [Articleization Contract](/support/articleization-manifest-and-autopublication-contract).

## What counts as a gap

A documentation gap is not limited to a missing page. It includes:

- stale or superseded current-state language;
- a claim without adequate source/evidence qualification;
- a page missing canonical platform/framework identity;
- missing legal, privacy, rights, support, commerce or API state;
- a missing alias/successor/historical relationship;
- no internal links to the records needed for continuity;
- a recovered Help Center title without terminal disposition;
- a current capability without a changelog/version trail;
- a Phase 3 machine object not represented in documentation;
- a future phase dependency not propagated;
- a private/public boundary not documented;
- an unresolved source or owner decision that has not been made machine-visible.

## Terminal disposition contract

Every one of the 795 recovered titles must resolve to exactly one of:

1. `canonical_article`
2. `merged_successor`
3. `permanent_redirect`
4. `restricted_record`
5. `superseded_history`
6. `unresolved_source`

A title-only stub is not closure.

## Rebuild sequence

```text
legacy title / source fragment
        ↓
source recovery and authority classification
        ↓
stable identity / platform / framework mapping
        ↓
current-vs-historical-vs-target reconciliation
        ↓
substantive article or explicit non-article disposition
        ↓
continuity links
        ↓
claims / legal / rights / API / security validation
        ↓
versioned publication
        ↓
changelog + machine-seed delta
        ↓
future sprint freshness monitoring
```

## Current gap families

The current documentation program must continuously inventory at least these families:

| Gap family | Typical evidence source | Required result |
| --- | --- | --- |
| Platform identity/state | platform registry, source files, provider/admin evidence | current canonical identity + evidence-qualified state |
| Provider/API | provider docs, account evidence, adapters | verified/unverified boundary + endpoint/auth/webhook/export status |
| Legal/policy | Legal Depot, public legal surfaces, acceptance evidence | effective policy/addendum/disclaimer state |
| Rights/licensing | CHLOM, rights records, source masters | chain-of-title/license/entitlement state without overclaim |
| Commerce | ThriveEvergreen, Stripe/provider evidence, catalog | SKU/offer/price/order/fulfillment/settlement boundaries |
| Support/runbook | support sources, incidents, workflows | user/operator recovery path |
| Security/private boundary | Vault/RBAC/security evidence | public-safe projection + restricted-reference rule |
| History/lineage | legacy Help Center, source variants, ADRs | alias/predecessor/successor/supersession graph |
| Internal continuity links | Mintlify route graph | meaningful, valid cross-page edges |
| Phase 3 seed | registries/schemas/adapters | exact object/contract delta or explicit blocker |
| Phase 11–20 horizon | founder direction + later authoritative sources | impact notes now; definitions only after authority |

## Prioritization

### P0 documentation

Pages that govern or unblock:

- Phase 2.99 hard exit;
- Phase 3 readiness;
- source authority and contradiction resolution;
- CHLOM/DAIL/identity/rights/rules/economics;
- security/private data/Vault boundaries;
- platform/API/adapter registries;
- commerce/economic authority;
- operational runbooks and rollback;
- documentation automation itself.

### P1 documentation

Current revenue, customer, distribution, media, education, beauty/wellness, creator, affiliate, event and support surfaces that need substantive public/operator coverage.

### P2/P3 documentation

Reserve, historical, research, dormant and long-horizon assets. These still require explicit dispositions so they cannot vanish from institutional memory.

## Internal-link continuity minimum

Substantive articles should ordinarily link to at least two relevant internal records. High-value articles should usually connect to four or more classes:

- canonical identity;
- source/evidence authority;
- governing standard;
- operational workflow/runbook;
- phase gate;
- lineage/successor;
- related platform/corridor.

## Sprint execution model

Every sprint uses two passes:

- **Pass A:** identify and repair stale state.
- **Pass B:** plug evidence-backed gaps and add continuity links.

The Sprint receipt records all three page outcomes:

```text
docs_updated
docs_no_change
docs_delta_opened
```

A page that needs no correction may still need gap closure or continuity links.

## Success condition

The program is complete only when CrownThrive can answer, from governed records rather than conversational memory:

- what documentation exists;
- what is missing;
- why each page/article exists;
- which source governs it;
- what state it describes;
- what it supersedes;
- what it links to;
- what machine object or phase gate depends on it;
- and how to rebuild the knowledge system if Mintlify or another provider disappears.
