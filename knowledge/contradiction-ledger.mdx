## Founder metric rule

For a metric with the **same definition** across older and newer snapshots, where the Founder confirms the larger value is current, the larger Founder-confirmed value becomes provisional canonical current state until automated telemetry replaces it. This does **not** permit converting one metric type into another.

Example: 75,000\+ Locticians members may be retained as a prior dated snapshot while 125,000\+ is current. A verified-record count cannot be silently treated as a member count unless the schema says they are the same population.

## Phase 3 machine rule

Every conflict must carry a status. Services may use `resolved` values. `implementation-gated`, `evidence-required`, `legal-review`, and `unresolved` values must block consequential automation that depends on the unresolved fact.

No conflict is resolved by deleting its source history.
