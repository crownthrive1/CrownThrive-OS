## Lifecycle/disposition vocabulary crosswalk

Portfolio records must distinguish **priority**, **lifecycle**, **implementation state** and **disposition**.

| Dimension | Canonical examples | What it answers |
| --- | --- | --- |
| priority | `P0`, `P1`, `P2`, `P3`, `unassigned` | How execution capacity is sequenced. |
| lifecycle | `concept`, `validate`, `build`, `pilot`, `beta`, `active`, `growth`, `license`, `reserve`, `merge`, `sunset`, `archive` | Where an asset sits in its product/operating lifecycle. |
| implementation | `uninspected`, `recovered`, `specified`, `prototype`, `test`, `controlled_pilot`, `production`, `maintained`, `degraded`, `superseded` | What implementation maturity is evidenced. |
| disposition | `current_canonical`, `current_alias`, `lineage_predecessor`, `reserve`, `sunset`, `research_target`, `needs_owner_validation` | How the identity should be treated institutionally. |

A P0 priority does not prove production. An `active` public lifecycle label does not prove every capability. A sunset disposition does not erase domain/IP/contract history.
