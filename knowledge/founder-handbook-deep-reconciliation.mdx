## Deep-pass source findings — August 19, 2026

The extended source review confirms several high-value institutional patterns that must be carried into current knowledge without promoting historical implementation claims:

### Knowledge is an operating control

The Handbook does not treat documentation as optional reference material. It describes the Help Center as the written brain/memory of the ecosystem, requires founders to keep their lane documentation updated, and treats documentation as protection against single-point-of-failure, misinformation and reputational drift. That doctrine is now strengthened by the no-silent-destruction rule, Git version history, THIVEBASE source/evidence records and governed chat/notebook capture.

### The roster is living history

The Handbook's ecosystem roster is explicitly a living reference. Launches, retirements, restructures, licenses and successor relationships therefore belong in the institutional knowledge graph rather than being removed when a brand stops operating. This is now implemented through the public brand/platform portfolio, alias/successor records and the [Asset Resurrection & Disposition Registry](/portfolio/asset-resurrection-disposition-registry).

### CHLOM historical research is requirements and R&D IP

The recovered **Building and Understanding the CHLOM Metaprotocol** source contains detailed Substrate governance, dual-token, treasury, off-chain AI/oracle and ZK design. Preserve that depth as technical R&D and requirements archaeology. It is not current production proof.

Later technical build authority establishes a more progressive first implementation around identity, assets/evidence, DLA/licensing, entitlements, settlement, disputes, audit and governed API/event surfaces. The institution therefore preserves the blockchain-first source without letting it override the current cloud/API/evidence/rights/governance-first implementation path.

### The old Help Center is requirements archaeology

Recovered Help Center structure gives concise functional requirements for CrownConsult, CrownInsights, Crown Affiliates, Crown Ambassadors, SocialAIly, StonkCliques, Thrive AI Studio and many other properties. These records are useful even where the old application no longer exists. Their modern role is to answer **what job was this asset supposed to perform?** before the Revival Doctrine decides whether the current answer is REVIVE, MERGE, RESERVE, RESEARCH, SUPERSEDE or another governed disposition.

### NeuralCraft has a current narrow commercialization role

Current Holdings material provides a stronger current relationship than older generic AI/Web3 descriptions: Thrive AI Studio builds/configures governed tools and agents; **NeuralCraft is the AI workforce marketplace/deployment lane**. Initial agent categories include support triage, documentation, catalog QA, media intake, affiliate onboarding, SEO/content operations, product publishing, rights metadata, incident response and operating reports. This current role does not automatically certify a live marketplace or deployment.

### Testimony Aisle Sessions is a substantive revival candidate

A current V4 production bible exists for **The Testimony Aisle Sessions** and describes a production-ready listening-room system spanning Gospel Soul, Virality Music and The Sermon Toolkit with testimony ethics, music development, rooms, release architecture and revenue design. Treat the source as high-value production IP and a controlled revival candidate, while commerce, licensing, venue, sponsor and distribution activation remain independently governed.

### Resurrection is selective

The current Holdings direction and the Revival Doctrine reject the idea that every recovered brand should be relaunched. Reusable functionality can be merged into a current successor while the old brand remains preserved. This is how CrownThrive retains its IP estate without recreating historical sprawl.
