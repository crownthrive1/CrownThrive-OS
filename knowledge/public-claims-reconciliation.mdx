# Public Claims Reconciliation

The pre–Phase 3 audit found public CrownThrive pages from different implementation eras using different platform counts, phase labels, capability descriptions, and integration claims. This is expected in a fast-moving ecosystem, but it must now be governed.

## Examples requiring reconciliation

- Some current CrownThrive pages display **80\+ platforms**, while older/about/service FAQ content says **60\+**.
- Older public FAQ content still describes the ecosystem as **Phase 0** and future Phase 1 onboarding, while the current institutional build is separately using Phase 1, 2, 2.5 and 3 labels for the CrownThrive Operating System / CHLOM reconstruction.
- Some older public copy describes a shared account system or specific platform as more integrated than current source evidence supports; newer copy correctly treats **One Seat, Multiple Industries** as a goal still being built.
- Historical platform descriptions may still say a product is active even when the current CrownThrive homepage marks it archived or its implementation has changed.
- Current live properties such as Virality Music and KJV Visualized have rapidly changing catalog counts that should be sourced from their own production/proof records rather than repeated manually across unrelated pages.

## Claim record

Material public claims should include:

- stable claim ID;
- statement and claim class;
- asset/platform;
- source;
- measurement period;
- methodology;
- evidence location;
- current/superseded/disputed status;
- approver;
- last verified date;
- approved public wording.

## Claim classes

- identity / ownership;
- product capability;
- availability / production status;
- customer or member counts;
- performance metrics;
- revenue/financial claims;
- geographic reach;
- rights/legal/compliance status;
- phase/roadmap status;
- partner/client relationship;
- impact claim;
- technical/security claim.

## Supersession rule

Do not delete the older statement from institutional history. Mark it superseded, record why, and route public surfaces to the current approved version.

## Phase 3 implication

Websites and agents should retrieve approved claim records rather than copying numbers or statuses from prose. CrownLytics and production systems should be the evidence source for dynamic metrics wherever feasible.
