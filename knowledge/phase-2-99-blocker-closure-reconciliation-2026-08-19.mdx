## Locticians / Brilliant Directories permission reconciliation

The existing Locticians API key is server-side in Supabase Vault. Authenticated `GET /api/v2/token/verify` returned HTTP 200 while `GET /api/v2/site_info/get` returned HTTP 403.

Official Brilliant Directories API documentation classifies `site_info` under **Advanced API Endpoints → Website Configuration** and states that Advanced endpoints require the Advanced API permission on the API key. The Site Info endpoint itself is read-only and takes no parameters beyond authentication.

The reconciled root cause is therefore a key permission issue, not a missing API, invalid credential or unknown endpoint.

Required provider-admin step:

1. Open the existing Locticians API key in Brilliant Directories Developer Hub.
2. Enable the Advanced API permission that covers **Site Info**.
3. Do not enable Sensitive endpoints merely to make the test pass.
4. Preserve CrownThrive provider writes as closed.
5. Rerun `GET /api/v2/site_info/get` through the server-side read-only adapter.
6. Mark the gate passed only on HTTP 200 application/json and bounded response validation.
