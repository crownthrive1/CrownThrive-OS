# Phase 2.99 Workstream 3A — Engine/Domain Identity Edge Register

## Purpose

This register is the deterministic **stable identity → S103 source → S100 portfolio → S100 engine/service → S100 domain** relationship layer for Workstream 3A. Tranche 1 established the pattern across CrownApps and the media federation. Tranche 2 expanded it across current operating-spine, support, beauty/wellness, analytics, messaging and growth/distribution identities. **Tranche 3** now resolves the ThriveTools SEO and ThriveTools OPT child identities from direct API/application evidence without allowing either child engine or API to become an inherited root-ThriveTools capability.

The edges are **dated source relationships only**. They do not certify provider accounts, current license entitlement, installed versions, repositories, deployments, APIs, exports, registrar custody, DNS, TLS, HTTP health, public availability, rights, legal authority, commerce activation or revenue state.

## Scope and non-goals

This tranche is limited to already accepted stable identities and exact source-row relationships supported by S100/S103 and current institutional registries. It does not create new platform identities, resolve the remaining S103 unresolved identities, adjudicate ThriveTools child-capability identity, promote the abstract ThriveSupport family into an implementation, infer SuitePro/Brilliant Directories from provider notes into the 85-engine count, or certify any live provider/domain state.

## Evidence baseline and assumptions

Source-row presence is historical evidence; current operational truth requires an independent certification chain.

## Edge rules

- stable IDs come from accepted identity work; this register does not invent new identities;
- S100/S103 row IDs remain immutable dated source records;
- one engine may serve multiple platform identities and one platform may have multiple engines/domains;
- shared engine assignment never collapses the platform identities it serves;
- a family/umbrella identity does not automatically inherit implementation-provider edges from one projection;
- a parent platform does not automatically inherit child-capability rows where parent/child identity remains unresolved;
- an S100 source `Active`, `Live`, `Rebuild`, `Current`, support date, license label or domain status does not prove current CrownThrive deployment or entitlement;
- absence of an S100 engine/domain row means only that the dated S100 tables do not contain an exact row for that identity;
- provider references in source notes, such as SuitePro or Brilliant Directories, are not forced into the 85-engine count;
- The historical `MVP (Roku)` edge remains preserved as pre-adjudication evidence. Founder adjudication now treats it as historical Roku/distribution lineage merged into Melanated TV; any **current** engine/domain/provider edge still requires independent evidence and is not inferred from that identity decision.
