# Legacy, Alias and Successor Register

Phase 2.7 formalizes naming lineage so old and new CrownThrive terminology can coexist without confusing agents, operators, customers, or future successors.

## Required relationship types

- alias-of
- historical-name-of
- misspelling-of
- predecessor-of
- successor-of
- merged-into
- split-into
- imprint-of
- subsystem-of
- public-brand-of
- internal-name-for
- deprecated-name

## Priority reconciliation queue

The source corpus contains name/meaning drift that should be recorded explicitly, including:

- DLA: historical **Decentralized Licensing Authority** vs current **Dynamic Licensing Asset**
- DAL / DAIL terminology drift
- CrownThrive Studios vs ThriveStudio vs AdLuxe Studio
- CrownThrive Music vs Virality Music
- CrownInsights vs CrownLytics vs CrownPulse
- CrownApps vs ThriveApps
- ThriveSeat vs ThriveSeats
- Kinetic vs Kenetic spellings
- ThriveCafe vs Melanin Magic Cafe
- MM Suites vs Melanin Magic Suites
- Suite Pro / SuitePros / location / franchise / regional-license terminology

## Canonical rule

A current canonical term must have:

- an effective date or version;
- source authority;
- stable ID;
- prior aliases;
- successor/predecessor relationships;
- whether old URLs or public materials require redirect/correction;
- whether the legacy term remains valid in historical documents.

## Agent behavior

When an agent encounters a legacy term, it should resolve the stable ID first and then use the current canonical display name unless the task is historical, legal, forensic, or source-preserving.
