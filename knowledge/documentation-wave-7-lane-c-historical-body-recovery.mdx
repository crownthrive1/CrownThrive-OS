## Wave 7 Lane C — Historical Body Recovery

Lane C addresses the separate problem that candidate mapping is complete while historical body reconstruction remains incomplete. Its job is source recovery, not current-state promotion.

## Recovery sources

Valid sources may include surviving Help Center exports, repository history, archived CrownThrive documentation, Drive or mail records when independently available to an authorized process, preserved source fragments, prior governed snapshots, and other provenance-bearing institutional records.

A remembered idea, modern successor page, or similarly titled article is not sufficient evidence for reconstructing a missing historical body.

## Required recovery receipt

```yaml
inventory_id:
legacy_title:
source_locations: []
source_hashes: []
recovered_body_state: NOT_FOUND
reconstruction_method: NONE
verbatim_or_normalized: null
lineage_links: []
current_state_claims_added: false
parent_review_required: true
```

When a body is recovered, normalization may fix encoding, broken formatting, or obvious transport artifacts, but substantive changes must be separately versioned. Historical language must remain distinguishable from current CrownThrive doctrine.

## Not-found is a valid result

Lane C does not fabricate content to improve completion metrics. A documented `NOT_FOUND` or `PARTIAL_SOURCE` state is a stronger institutional result than an inferred article presented as recovered history.

Recovered material should connect to the [Source Register](/knowledge/source-register), [Restricted Source Register](/knowledge/restricted-source-register), [Legacy Alias & Successor Register](/knowledge/legacy-alias-successor-register), and [Documentation Gap & Article Rebuild Register](/knowledge/documentation-gap-article-rebuild-register).

## Exit behavior

Recovered history may strengthen Lane A, Lane B, or Lane D, but it does not itself activate a current platform, API, license, right, payment flow, credential, or production capability.
