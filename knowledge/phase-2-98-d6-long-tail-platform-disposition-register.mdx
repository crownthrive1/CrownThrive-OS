# Phase 2.98 D6 Long-Tail Platform Disposition Register

## Purpose

Phase 2.7 requires every recovered platform/framework record to receive an explicit current, merge, successor, dormant, research, reserve, sunset or owner-validation disposition. D6 closes the highest-confidence long-tail records without inventing state for names whose current role remains unsupported.

<Warning>
  Domain ownership, a purchased engine, an old Help Center title or a historical portfolio card does not establish current production. This register records the strongest currently supported disposition and preserves unresolved records as unresolved.
</Warning>

## Disposition vocabulary

- `current_canonical` — current operating identity supported by adopted/current evidence;
- `current_alias` — same stable asset as another current name;
- `lineage_predecessor` — predecessor/history retained under a current successor;
- `reserve` — brand/domain/IP preserved without current operating burden;
- `sunset` — implementation retired; history/redirects/evidence preserved;
- `research_target` — future/research architecture, not operating capability;
- `needs_owner_validation` — name/source recovered but current role cannot yet be safely resolved.

## Engine lineage preserved

Holdings registry evidence must remain separate from current deployment state:

```text
TrendyGroup → FindCliques / ChainCliques / NFTCliques / StonkCliques / ThriveCafe → sunset implementation, brands preserved
WebAI → My Crown Oasis → retired foundation / brand reserve
Appy → ThriveApps/CrownApps → future-build candidate
PixelPages → ThriveFoundry → retired/reserve
Zaialumni + Donation Add-on → ThriveAlumni → build/revamp lineage; support expired in dated registry
```

An expired vendor-support period does not erase CrownThrive's brand/source records, and an active domain does not prove the application is active.

## Phase 2.99 inheritance

Seed one stable asset record per canonical identity with:

- aliases and predecessors;
- disposition/effective date;
- domain/engine/source references;
- current implementation state;
- successor/merge relationship;
- public redirect policy;
- data/archive/export state;
- rights/IP custody;
- reactivation authority;
- article/changelog mappings;
- correction history.

`needs_owner_validation` rows must remain machine-readable unresolved records rather than being omitted from Phase 3 seeds.

## D6 completion rule

D6 is complete for a row when the strongest defensible disposition is recorded, not when every recovered name is forced into an active platform.
