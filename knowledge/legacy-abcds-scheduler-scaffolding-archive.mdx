## Supersession

The former Agent A / B / C / D / S staggered ChatGPT scheduling topology and related per-agent clocks are retired scheduling scaffolding. Historical identities, receipts, handoffs, source references, hashes and prior decisions remain append-only evidence, but they are not executable runtime dependencies.

The canonical successor is `ct.scheduler-topology.production.v1`. Primary execution belongs to ThriveBase, CrownThrive OS, Software Factory, Framework Factory, pg\_cron, governed queues and provider-native workflows. Connector-dependent work that cannot execute inside that fabric may use only the single governed external connector relay `ct.schedule.external-evidence-relay.hourly.v1`.

## Historical model

For historical interpretation only, the retired model used role labels Agent A, Agent B, Agent C, Agent D and Agent S, staggered hourly clocks, handoff packets, a five-role voting/quorum construct, and a dedicated gatekeeper/security sequence. Those constructs must not be treated as current scheduler topology or required current authority.

## Preservation policy

- Preserve historical records, hashes, receipts, prior task IDs and source lineage.
- Remove legacy A/B/C/D/S scheduler logic, clock requirements and current-runtime dependencies from active code and current documentation.
- Never silently rewrite historical evidence to make it appear that the current Penta/production fabric existed earlier.
- Never reactivate a legacy clock to satisfy a missing internal executor.
- Historical references must point here or otherwise be explicitly labeled `historical`, `superseded`, `retired`, or `RETIRED_SCHEDULING_SCAFFOLDING`.
- The scheduler clock never manufactures authority.

## Current replacement

Current scheduling and execution use the production topology and Penta/OS execution fabric. Existing internal executors are preferred. The external relay is a connector failure domain only and must not become another one-agent-one-clock scheduler.
