## Canonical disposition

The former **Agent A / Agent B / Agent C / Agent D / Agent S one-agent-one-clock scheduling model is permanently retired as scheduling scaffolding**. It is preserved only to explain lineage and prior operating assumptions.

<Warning>
  Do not reactivate, reconstruct, clone, schedule, or treat any A/B/C/D/S clock as a current CrownThrive executor. Historical role names do not manufacture present authority.
</Warning>

The canonical successor is:

```yaml
topology_id: ct.scheduler-topology.production.v1
primary_execution:
  - ThriveBase
  - CrownThrive OS
  - Software Factory
  - Framework Factory
  - pg_cron
  - queues
  - provider_native_workflows
connector_failure_domain:
  schedule_id: ct.schedule.external-evidence-relay.hourly.v1
clock_authority: none
```

The external relay is not a general-purpose scheduler. It services only due connector-dependent subroutes that the production software fabric cannot perform internally.

## What was retired

| Historical role | Former scheduling interpretation | Current treatment |
| --- | --- | --- |
| Agent A | Portfolio/preflight or coordinating clock | Historical-only; no external clock |
| Agent B | Specialist/production scheduling lane | Historical-only; internal executors preferred |
| Agent C | Continuity/compliance scheduling lane | Historical-only; governed subroutes only |
| Agent D | Review/certification scheduling clock | Historical scheduler retired; legitimate certification capabilities may remain when independently governed |
| Agent S | Supervisory or synthesis scheduling clock | Historical-only; no supervisory recurring task |

The retirement applies to **per-agent ChatGPT clocks, external task bindings, duplicate cron paths, and code that assumes those clocks are required**. It does not erase legitimate capability names, evidence, metrics, prior migration records, certification roles, or append-only receipts merely because they contain a lettered agent identifier.

## Records intentionally preserved

CrownThrive preserves the following as immutable or append-only history:

- applied scheduler topology and retirement migrations;
- historical scheduler rows with `historical_reference_only=true`;
- generation and preflight evidence tables that remain useful as non-executable records;
- DAIL, scheduler topology, maintenance, certification, and recovery receipts;
- predecessor and successor references;
- hashes, timestamps, prior task identifiers, commit IDs, Drive IDs, and bounded provider evidence;
- legitimate non-scheduler certification and supervisory capabilities where current governance separately recognizes them.

Preservation does not mean activation.

## Records prohibited from active execution

The following must remain absent or retired:

- enabled external tasks whose only purpose is an A/B/C/D/S recurring clock;
- `pg_cron` jobs that duplicate those external clocks;
- active automation bindings that depend on the historical role model;
- workflows using an A/B/C/D/S label as scheduling authority;
- code that treats an external scheduler tick as approval, quorum, entitlement, rights, money-movement, or provider-write authority;
- documentation that instructs operators to recreate the old clock topology.

## Reactivation prohibition

A future team may study this archive but may not revive it by renaming the clocks. Any new recurring external task requires a current governed source, proof that no compatible internal executor exists, explicit authority boundaries, dedupe, rollback, evidence handling, and current human approval where reserved. The historical A/B/C/D/S record supplies none of those things.

## Recovery and audit use

Use this page to:

1. distinguish historical references from live scheduling code;
2. identify and retire accidental duplicate clocks;
3. explain why lettered-agent receipts remain in historical tables;
4. verify that the canonical external relay is the only connector failure-domain relay; and
5. preserve institutional lineage without allowing history to become execution authority.
