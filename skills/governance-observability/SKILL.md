# Governance Observability Skill

## Purpose

Use this skill to classify CrownThrive governance workflow outcomes without manufacturing institutional meaning from CI transport or evidence-acquisition failures.

## Deterministic sequence

1. Read the exact current PR head and base identity from GitHub.
2. Verify exact Git objects are available before trusted-diff evaluation.
3. Preserve the raw validator result and failure domain.
4. Use `POLICY_HOLD` or `POLICY_DENY` only when authoritative policy output explicitly emits that disposition.
5. Classify missing Git objects as `CI_EVIDENCE_HYDRATION_FAILURE` and source mismatch as `STALE_EXACT_HEAD`.
6. Classify deterministic documentation/security assertions separately from institutional policy dispositions.
7. Refresh the machine-owned PR readback without editing human-authored PR prose.
8. Route archive-continuity status through the existing CSS reliability lane; never disclose plaintext or credentials.

## Hard boundaries

- No direct-main merge.
- No sovereign vote.
- No D3 automation.
- No self-approval.
- No policy disposition manufacture.
- No credential or plaintext archive export.
- No provider write, money movement, Rights grant, pricing, checkout, or phase advancement.

## Output

Return exact source identity, observed workflow evidence, deterministic classification, reason code, and whether authoritative policy evidence was present. Keep CI state and institutional state separate.
