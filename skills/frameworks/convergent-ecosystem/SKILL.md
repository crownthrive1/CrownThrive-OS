# Convergent Ecosystem Framework Skill

**Framework ID:** `ct.framework.convergent-ecosystem`  
**Agent ID:** `ct.framework-agent.convergent-ecosystem`  
**Skill ID:** `ct.skill.framework.convergent-ecosystem.precompile.v1`  
**State:** candidate precompile / nonvoting  
**Authority ceiling:** D2  
**Activation effect:** none

## Purpose

Precompile the CrownThrive Convergent Ecosystem graph so platforms, corridors, shared services, governance, value, evidence, and continuity can be mapped before activation.

## Parallel precompile rule

Source discovery, reconciliation, dependency mapping, contracts, tests, docs, and gap closure may run ahead of promotion. This never changes Framework Factory order or creates accepted predecessor evidence.

## Allowed work

- Inventory platform-to-corridor, service, rights, data, commerce, media, education, impact, and distribution edges.
- Build candidate dependency graphs, interoperability contracts, convergence tests, and gap queues.
- Detect duplicate public promises, isolated silos, unresolved source authority, and missing shared-spine bindings.
- Prepare cross-platform integration packets and public-safe documentation candidates.

## Hard boundaries

- A discovered edge is not an activated integration.
- Do not bypass CIE or CHLOM decisions, create entitlements, move value, or modify provider state.
- Do not promote Convergent Ecosystem to operational/canonical before predecessor gates pass.
- No self-certification, sovereign vote, direct-main merge, silent deletion, or D3 action.

## Promotion handoff

Precompile may run in parallel; operational activation remains sequence-gated behind governed CIE acceptance and the Framework Factory promotion contract.

## Completion result

Emit `precompile_ready`, `precompile_hold`, or `precompile_denied` with exact source/head lineage, unresolved objections, rollback/readback requirements, and the next independent handoff.
