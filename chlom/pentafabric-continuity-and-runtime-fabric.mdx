# Pentafabric Continuity & Runtime Fabric

CrownThrive Pentafabric™ is more than a static five-layer map. It is operated as a governed, continuously running program with three institutional commitments:

1. a **seven-generation continuity charter** that defines how mission, provenance, rights and stewardship survive succession;
2. an **autonomous lifecycle and maintenance model** that lets bounded agents build, verify, maintain, recover and retire capabilities without manufacturing authority;
3. a **continuous runtime fabric** that fans out bounded agent lanes on a recurring schedule and emits DAIL evidence for every cycle.

This page summarizes the current governed state. The layer architecture itself is described on [CrownThrive Pentafabric](/chlom/pentafabric), and the build-to-commercialization loop on [Continuous Build & Commercialization](/chlom/continuous-build-commercialization).

## Seven-generation continuity charter

The charter establishes a long-horizon planning rule for CrownThrive, CHLOM, CrownThrive OS, the Cultural Imprint Engine, Pentafabric and associated institutional assets. The horizon is a **planning and stewardship commitment, not an irrevocable transfer of legal ownership**. Each generation inherits an evidence-backed institutional state, operating constraints, rights records, maintenance obligations, and only the authority actually granted to it at the time.

The planning model:

1. Generation 1 — Founder and originating architecture.
2. Generation 2 — Continuity and institutionalization.
3. Generation 3 — Expansion and professional stewardship.
4. Generation 4 — Distributed leadership and ecosystem maturity.
5. Generation 5 — Long-horizon resilience and succession.
6. Generation 6 — Intergenerational modernization and preservation.
7. Generation 7 — Re-adjudication of mission, rights, and stewardship under then-current law and evidence.

Key charter rules:

- **Founder intent is evidence, not authority.** It is preserved as historical and governance evidence and does not allow an automated system to manufacture legal authority or bypass applicable law.
- **Generational lock.** Consequential changes must preserve or explicitly adjudicate canonical source lineage, IP provenance, rights and licensing state, DAIL evidence lineage, CHLOM contracts, Pentafabric layer ownership, recovery capability, security boundaries, economic authority, human succession evidence, and public/private classification. The lock is a preservation mechanism, not a permanent freeze.
- **No autonomous succession.** Agents may maintain succession records, detect gaps, prepare candidate packets and request review. Agents may not appoint themselves, transfer ownership, rewrite founder lineage, appoint a successor, dissolve CrownThrive, or create a new legal entity without separately authorized human and legal processes.
- **Continuity tests.** At each institutional release gate, the system tests whether a qualified successor could reconstruct the architecture, understand the rights state, locate protected evidence through authorized paths, restore required services, operate the public-safe documentation, and identify unresolved obligations. A system that only its current builders understand is not generationally maintainable.

The canonical charter is `standards/crownthrive-generational-continuity-charter.v1.md` in the parent repository.

## Autonomous lifecycle and maintenance model

The Pentafabric autonomous lifecycle defines how the five layers continuously build, verify, publish, monetize, maintain, recover and retire capabilities without collapsing governance boundaries.

### Hybrid autonomy, fail-closed

The operating model is hybrid rather than fully autonomous:

- **Autonomous:** observation, reconciliation, documentation preparation, research, testing, candidate generation, non-consequential maintenance, and bounded recovery.
- **Human-gated:** legal authority, ownership transfers, founder-reserved decisions, production economic activation, destructive operations, privileged credentials, public claims of certification, and other reserved actions.

Agents must **fail closed** when required evidence is absent. No step in the continuous loop may silently manufacture the authority required by a later step. Economic and legal authority gates are stated as fail-closed boundaries; they are not activated by the runtime.

### Lifecycle states

Every material artifact carries a lifecycle state:

```text
PROPOSED → CANDIDATE → VERIFIED → AUTHORIZED → RELEASED → OBSERVED → MAINTENANCE → DEPRECATED → RETIRED
```

A failure routes an artifact through a repair path:

```text
HOLD → QUARANTINE → REPAIR → VERIFY → RELEASE
```

Retirement must preserve historical evidence and replacement lineage. Deletion is not the default continuity action.

### Maintenance controller boundaries

The maintenance controller observes dependency drift, documentation drift, schema drift, API/MCP contract drift, security findings, stale providers, failing checks, unreachable projections, vault-binding gaps, economic-state divergence, and broken recovery routes.

| It may | It may not |
| --- | --- |
| Open repair candidates | Create legal authority |
| Regenerate derived documentation | Change ownership |
| Run tests and rebuild projections | Disclose secrets |
| Quarantine broken candidates | Activate unapproved commerce |
| Request verification | Bypass required verification or self-certify |
| Prepare rollback packets | Self-merge protected changes |
| Mark stale artifacts for review | Destroy canonical evidence |

### Runtime truth rule

A repository file, workflow definition, API specification, MCP manifest, agent manifest, generated document, provider response, or successful build is not by itself proof of live production. Runtime promotion requires current machine readback and applicable verification evidence.

## Continuous runtime fabric

The runtime fabric runs the governed portion of the Pentafabric lifecycle continuously. A scheduled workflow executes twice per hour and also runs on relevant contract, manifest, framework and schema changes. Each cycle has three stages:

1. **Contract discovery.** A bounded controller collects registered contract and candidate manifests, hashes each one, and sets the cycle state. If any contract fails to parse, the cycle state is `HOLD` and agent lanes do not run. Otherwise the state is `READY`.
2. **Agent lanes.** Eight bounded agent lanes fan out in parallel, each executing only its contracted scope and emitting its own evidence packet:
   - `rnd`
   - `documentation`
   - `rights_identity`
   - `compliance_oracle`
   - `commercial`
   - `mesh_reliability`
   - `continuity`
   - `maintenance`
3. **Assurance.** A reconciliation step assembles the DAIL evidence packet for the cycle, publishes a run summary, and uploads the reconciliation evidence with a longer retention window than the per-lane artifacts.

The controller executes only the safe, observable portion of the lifecycle. It does not manufacture legal or economic authority, mutate protected repositories, transfer ownership, disclose secrets, or self-certify production state.

### DAIL runtime evidence contract

Every cycle emits an event conforming to the `dail.chlom.runtime-event.v1` schema. Required fields are the schema identifier, event type, run ID, UTC timestamp, cycle state (`READY`, `HOLD`, `RECONCILED`, or `FAILED`), and a SHA-256 event hash computed over the canonicalized packet. An illustrative event:

```json
{
  "schema": "dail.chlom.runtime-event.v1",
  "event_type": "RUNTIME_FABRIC_CYCLE",
  "run_id": "17429981234",
  "timestamp_utc": "2026-08-25T14:07:00Z",
  "state": "READY",
  "agents": ["rnd", "documentation", "rights_identity", "compliance_oracle", "commercial", "mesh_reliability", "continuity", "maintenance"],
  "authority": {
    "mode": "hybrid_bounded",
    "economic_activation": "THRIVEEVERGREEN_ECAC_ONLY",
    "legal_ownership": "HUMAN_GATED",
    "destructive_operations": "HUMAN_GATED",
    "secrets": "VAULT_ONLY",
    "self_certification": "PROHIBITED"
  },
  "event_hash": "…64-hex-digit SHA-256…"
}
```

The `authority` block records the fail-closed envelope for every cycle: economic activation resolves only through ThriveEvergreen / ECAC, legal ownership and destructive operations remain human-gated, secrets remain vault-only, and self-certification is prohibited.

The canonical schema is `schemas/dail/chlom-runtime-event.v1.json` and the orchestration definition is `.github/workflows/chlom-runtime-fabric.yml` in the parent repository. This page summarizes the contract; the machine schema remains the source of truth.

## When to use this page

- To understand which decisions agents can make autonomously and which are human-gated.
- To verify that a runtime cycle produced DAIL evidence and what its state means.
- To evaluate succession, retirement, or shutdown plans against the generational lock.
- To confirm that Layer 5 economic activation and legal-authority boundaries remain fail-closed rather than activated.
