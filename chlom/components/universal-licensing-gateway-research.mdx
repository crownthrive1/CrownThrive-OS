## Conservative functional meaning

A Universal Licensing Gateway is the boundary through which heterogeneous CrownThrive or external systems can submit licensing requests and receive normalized CHLOM rights/license results without directly coupling to one provider, marketplace or historical blockchain runtime.

```text
EXTERNAL / CROWNTHRIVE SYSTEM
           |
           v
  UNIVERSAL LICENSING GATEWAY
           |
   normalize request / identity / asset aliases
           |
           v
RIGHTS GRAPH -> DLA -> POLICY -> AUTHORITY
           |
           +--> PASS candidate / governed activation
           +--> HOLD
           +--> DENY
           |
           v
 canonical receipt / DAIL evidence / adapter response
```

This mapping is a **current engineering reconstruction**, not recovered historical body text.

## Candidate responsibilities

The gateway can safely be specified to:

- normalize external asset, party and provider aliases to stable CHLOM IDs;
- identify the requested right/use, territory, term, channel and other scope dimensions;
- resolve the applicable source-right and DLA context;
- route through eligibility, Compliance Packs and authority checks;
- expose provider-neutral license status and required remediation;
- create idempotent request/decision receipts;
- emit DAIL evidence for consequential decisions;
- hand valid offers/transactions to LEX or another authorized commercial surface;
- reject unsupported provider-specific shortcuts that bypass CHLOM rights truth.

## Relationship to DLA

The gateway cannot create rights. DLA activation remains governed by source-rights closure, issuer authority, licensee eligibility, policy, approvals and versioned evidence. The gateway merely provides a normalized orchestration entry point.

## Relationship to LEX

LEX is the license exchange/marketplace family. The gateway may feed LEX listing, transaction or verification flows, but it is not synonymous with the marketplace. Direct/private licensing can also use the gateway without creating a public listing.

## Relationship to CrownThrive IO / APIs / MCP

A current implementation can project the gateway through REST, GraphQL, MCP, internal service calls or partner adapters. Those transport surfaces remain replaceable. The canonical request/rights/decision objects are CHLOM institutional records.

## Security and authority

- authenticate caller/client;
- enforce tenant/object scope;
- map provider aliases without trusting them as rights truth;
- prevent cross-tenant license discovery;
- apply idempotency to side-effect requests;
- never expose restricted contracts/evidence through generic gateway responses;
- route consequential writes through ALG-002 authority checks;
- fail closed when required rights/evidence are unresolved.

## State model

```text
RECEIVED
 -> NORMALIZED
 -> RIGHTS_RESOLUTION
 -> POLICY_ELIGIBILITY
 -> AUTHORITY_GATE
 -> READY_FOR_ACTION | HOLD | DENY
 -> EXECUTION_REQUESTED
 -> EXECUTED / RECONCILED / FAILED
```

Not every request traverses execution; read/verification requests can terminate after a safe result.

## Evidence and observability

Each request should retain stable request ID, caller/client identity, normalized aliases, policy/DLA versions, evidence references, result, latency and any downstream action receipt. Operational metrics must not replace DAIL/canonical decision evidence.

## Failure states

Unknown asset alias, disputed rights, unsupported scope, stale credentials, policy conflict, missing approval, adapter failure, provider outage, rate limit, duplicate request and restricted-data projection violation.

## Tests

Test same licensing request through two providers producing the same canonical normalization; overscope request; alias collision; external provider claiming rights absent from CHLOM; renewal; transfer; stale evidence; duplicate request; cross-tenant request; and provider replacement.
