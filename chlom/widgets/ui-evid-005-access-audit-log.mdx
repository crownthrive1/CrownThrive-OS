# UI-EVID-005 — Access / Audit Log

## Component identity

```yaml
surface_id: UI-EVID-005
component: Access / Audit Log
classification: role_scoped_component_contract
owner_capabilities: Audit; Evidence; Security; DAIL
```

## Purpose

This component shows who or what accessed a protected resource or performed an auditable administrative action, when, through which role/service context, and with what recorded outcome. It supports accountability without becoming a secret-exposure surface.

## Data contract

Audit event ID, actor/service stable ID, action class, object/evidence ref, timestamp, tenant, purpose/scope where recorded, outcome, source client/integration class and DAIL/audit receipt. Raw credentials, tokens and sensitive payload bodies are excluded.

## States

`SUCCESS`, `DENIED`, `FAILED`, `REDACTED`, `SYSTEM_ACTION`, `REVIEW_REQUIRED`.

## Security semantics

Audit viewers require explicit scope. Being able to view an object's content does not automatically grant access to all security metadata or other users' audit history.

## Interactions

Filter by actor/action/time/object, inspect safe event details, export where policy permits and open associated case/incident. Exports themselves should generate an audit event for sensitive scopes.

## Accessibility/tests

Provide accessible table semantics, timestamps, sortable columns and textual outcomes. Test denied access, service-account activity, export logging, cross-tenant isolation, redaction and large-result pagination.

## Versioning

Audit event schemas and retention rules are versioned; history remains append-only under the adopted retention policy.
