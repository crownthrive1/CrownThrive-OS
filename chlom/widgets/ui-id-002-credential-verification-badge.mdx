# UI-ID-002 — Credential / Verification Badge

## Component identity

```yaml
surface_id: UI-ID-002
component: Credential / Verification Badge
classification: public_safe_component_contract
owner_capabilities: Identity; Attestations
```

## Purpose

This badge communicates whether a specific credential or verification requirement is currently usable for the viewing context. It is intentionally narrower than the Identity Card and can be embedded beside licenses, applicants, reviewers, transactions or compliance tasks.

## Data contract

Credential type, public-safe label, state, issuer/source class, issued/verified time where permitted, expiry/reverify time, revocation indicator, proof/attestation reference and policy-context note. Raw credential content remains outside the component unless a separately authorized evidence view is opened.

## States

`VERIFIED_CURRENT`, `VERIFIED_STALE`, `PENDING`, `REVOKED`, `EXPIRED`, `FAILED`, `HOLD_REVIEW`, `NOT_REQUIRED`, `REDACTED`.

## Truth semantics

The badge must reflect ALG-012/ALG-013/FORM-025 style currentness and revocation checks. A cryptographically valid credential is not shown as current if its issuer authority, revocation or policy context fails.

## Interactions

Role-scoped expansion can show public-safe issuer details, verification receipt, expiry, policy requirement and evidence lineage. Never reveal private witnesses, identity documents or secret proof material in a tooltip.

## Accessibility

Text status is mandatory; icons are supplementary. Expiry warnings need machine-readable dates and accessible descriptions.

## Tests

Test active, stale, revoked, expired, replaced credential, source unavailable, restricted evidence, dark/mobile layout and badge rendering in dense tables.

## Versioning

Credential-state vocabulary and disclosure rules are versioned centrally so every portal renders the same meaning.
