# UI-ID-004 — Consent State

## Component identity

```yaml
surface_id: UI-ID-004
component: Consent State
classification: public_safe_component_contract
owner_capabilities: Identity; Privacy; Evidence
```

## Purpose

Consent State renders whether a defined subject has granted a specific, current and evidenced consent for a particular purpose. It prevents the UI from reducing consent to a generic permanent yes/no flag.

## Data contract

Consent purpose, subject, recipient/controller class, granted scope, granted-at time, expiry/review time, revocation state, source agreement/evidence reference, policy version and any required reauthorization state. Sensitive agreement bodies remain in protected custody.

## States

`GRANTED_CURRENT`, `GRANTED_EXPIRING`, `REVOKED`, `EXPIRED`, `NOT_GRANTED`, `NOT_APPLICABLE`, `HOLD_EVIDENCE`, `REDACTED`.

## Semantics

Consent for one purpose cannot be projected as consent for another. Consent does not substitute for another lawful/contractual authority requirement, and revocation effects follow the governing policy/agreement rather than generic UI assumptions.

## Actions

Authorized flows can view consent evidence, request consent, renew/reauthorize or record revocation. The widget itself does not alter consent without a governed write workflow and DAIL receipt.

## Privacy

Only expose the minimum purpose/scope needed for the viewer. Do not render hidden personal-data categories or evidence text to users lacking clearance.

## Tests

Test current, expired, revoked, scope mismatch, new policy requiring re-consent, multiple consent purposes, missing evidence and cross-tenant subject resolution.

## Versioning

Purpose taxonomy, evidence schema and state semantics are versioned; prior consent records remain auditable.
