# UI-POLICY-006 — Exception / Override Record

## Component identity

```yaml
surface_id: UI-POLICY-006
component: Exception / Override Record
classification: public_safe_component_contract
owner_capabilities: Governance; Authority; Cases; DAIL
```

## Purpose

This component displays an authorized exception, emergency restriction, override or other non-routine intervention as a bounded institutional event rather than an invisible administrator action.

## Data contract

Override/exception ID, target object/action, public-safe action type, invoking authority class, reason code, evidence refs, effective time, expiry/TTL, scope, required review/ratification, rollback/reversal state and DAIL lineage.

## States

`ACTIVE`, `PENDING_REVIEW`, `RATIFIED`, `EXPIRED`, `REVERSED`, `SUPERSEDED`, `DENIED`, `HOLD_AUTHORITY`, `REDACTED`.

## Semantics

An override does not erase the underlying rule; it records an authorized exceptional state under a defined scope and duration. It cannot be used by an agent to manufacture or expand its own authority.

## Protected boundary

Exploit-sensitive kill-switch mechanics, private emergency credentials and trade-secret override algorithms are not rendered. Public-safe records can show that an override occurred, its authorized scope and status.

## Actions

Inspect reason/evidence lineage, view review deadline, ratify/reject/reverse through authorized workflows and open associated case. All writes require the authority gateway.

## Tests

Test active TTL, expired override, wrong-scope use, missing authority, subsequent ratification, reversal, competing override and restricted evidence.

## Versioning

Override types and review rules are versioned; historical events remain append-only.
