# UI-CASE-003 — Hold / Suspension State

## Component identity

```yaml
surface_id: UI-CASE-003
component: Hold / Suspension State
classification: role_scoped_component_contract
owner_capabilities: Cases; Policy; Authority; DAIL
```

## Purpose

This component shows when an object, action, license, entitlement or workflow is temporarily prevented from progressing and why. It distinguishes a remediable HOLD from a final DENY and a scoped suspension from blanket revocation.

## Data contract

Hold/suspension ID, target, state, reason code, initiating policy/authority class, evidence refs, affected actions/scope, start time, expiry/next review, remediation requirements and resolution/reversal lineage.

## States

`HOLD_EVIDENCE`, `HOLD_REVIEW`, `HOLD_APPROVAL`, `SUSPENDED`, `PARTIAL_SUSPENSION`, `EXPIRING`, `RESOLVED`, `SUPERSEDED`, `REDACTED`.

## Semantics

A hold should say what cannot happen and what may still proceed. The UI must not imply wrongdoing solely from a hold, and a timed hold must not silently become permanent.

## Actions

Open reason/evidence, view remediation tasks, request review, inspect authority, or navigate to resolution workflow. Clearing the display requires an authorized resolution event, not a local toggle.

## Tests

Test scoped versus global suspension, expired TTL, missing evidence hold, resolved hold, new hold after resolution, action unaffected by scope and restricted rationale.

## Versioning

Reason/state taxonomies and review rules are versioned with the governing policy.
