# UI-INT-004 — Provider / Dependency Status

## Component identity

```yaml
surface_id: UI-INT-004
component: Provider / Dependency Status
classification: role_scoped_component_contract
owner_capabilities: Observability; Integrations; Continuity
```

## Purpose

This component shows whether a provider or internal dependency required by a CHLOM workflow is currently usable and within its operational contract. It helps distinguish infrastructure failure from policy, rights or authority decisions.

## Data contract

Dependency ID/class, capability supplied, health state, last observed time, freshness, quota/spend-cap state where permitted, rate-limit state, fallback/degraded-mode availability, affected workflows and evidence/monitor refs.

## States

`HEALTHY`, `DEGRADED`, `OUTAGE`, `STALE_OBSERVATION`, `QUOTA_EXHAUSTED`, `SPEND_CAP_BLOCK`, `RATE_LIMITED`, `FALLBACK_ACTIVE`, `DISABLED`, `UNKNOWN`.

## Semantics

Provider availability is operational evidence, not rights or authority. If a mandatory verification dependency is unavailable, policy may HOLD rather than reuse stale success.

## Privacy and tests

Do not expose secrets, restricted plan/billing data or sensitive infrastructure identifiers outside authorized roles. Test outage, stale monitor, quota exhaustion, fallback, restoration, wrong-account mapping and metadata redaction.

## Versioning

Dependency contracts and health semantics are versioned; providers remain replaceable execution systems.
