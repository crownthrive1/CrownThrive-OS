# UI-CASE-002 — Evidence Checklist

## Component identity

```yaml
surface_id: UI-CASE-002
component: Evidence Checklist
classification: role_scoped_component_contract
owner_capabilities: Cases; Evidence; Audit
```

## Purpose

The Evidence Checklist enumerates what evidence a case or audit requires and whether each item has been located, verified, refreshed, reviewed or deemed not applicable by valid authority.

## Data contract

Checklist item ID, evidence requirement, source class, required currentness, collection state, evidence refs, applicability/N-A decision, reviewer state, deficiency reason and due date.

## States

`REQUIRED_MISSING`, `REQUESTED`, `RECEIVED_UNVERIFIED`, `VERIFIED_CURRENT`, `STALE_REFRESH`, `CONFLICT`, `NOT_APPLICABLE_AUTHORIZED`, `REDACTED`.

## Semantics

A file attachment is not automatically verified evidence. `N/A` must have an authorized reason. Missing mandatory evidence keeps the dependent decision on HOLD.

## Interactions

Attach a stable evidence reference, request evidence, verify/reject, refresh, mark N/A through governed review, inspect source status and navigate to deficiencies.

## Privacy/accessibility

Do not expose evidence bodies in list cells. Use clear state text and keyboard-accessible checklist controls.

## Tests

Test mandatory missing item, stale item, conflicting sources, N/A without authority, protected evidence, duplicate attachment and case closure with incomplete checklist.

## Versioning

Checklist templates bind to case/control policy versions; a later template change does not rewrite historical case requirements.
