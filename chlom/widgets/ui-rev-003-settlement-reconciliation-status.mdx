# UI-REV-003 — Settlement / Reconciliation Status

## Component identity

```yaml
surface_id: UI-REV-003
component: Settlement / Reconciliation Status
classification: role_scoped_component_contract
owner_capabilities: Economics; Providers; DAIL
```

## Purpose

This component communicates whether an expected CHLOM economic obligation matches the external execution evidence. It makes mismatches, partial settlement, reversals and duplicates visible rather than normalizing them away.

## Data contract

Expected obligation ID, provider/event aliases, expected amount/currency/destination, normalized provider amount/status, variance, semantic-match state, event time, reconciliation outcome, reason code and DAIL/correction refs.

## States

`MATCH`, `PENDING`, `PARTIAL`, `DUPLICATE`, `ROUNDING_REVIEW`, `HOLD_MISMATCH`, `REVERSAL_REQUIRED`, `REFUNDED`, `ERROR`.

## Semantics

A same-amount provider event to the wrong destination is not a match. Provider success does not rewrite the expected obligation. Corrections/reversals are new governed records.

## Interactions

Open expected calculation, inspect normalized provider event, reconcile/assign review where authorized, open refund/reversal path and trace duplicate/idempotency evidence.

## Tests

Exact match, wrong amount, wrong currency, wrong recipient, duplicate, partial, refund, pending-to-settled, provider fee variance and out-of-order events.

## Versioning

Provider normalization and reconciliation rules are versioned and displayed with the outcome.
