# UI-POLICY-001 — Policy Result Badge

## Component identity

```yaml
surface_id: UI-POLICY-001
component: Policy Result Badge
classification: public_safe_component_contract
owner_capabilities: Policy Engine; ACE; DAIL
```

## Purpose

This component renders a policy/control disposition consistently across CHLOM: `PASS`, `HOLD`, or `DENY`, plus the minimum context needed to understand whether the result is current and actionable.

## Data contract

Disposition, reason code/summary, policy pack ID/version, evaluated-at time, validity/freshness window, hard-block indicator, evidence completeness and optional next-action/remediation route.

## Semantics

`PASS` means the evaluated policy/control passed for the stated context; it does not equal execution authority. `HOLD` means unresolved/stale/missing evidence or approval prevents a conclusion/execution. `DENY` means an authoritative rule affirmatively blocks the action.

## States

`PASS`, `HOLD`, `DENY`, `NOT_EVALUATED`, `STALE`, `ERROR`, `REDACTED`.

## UX rules

Never display `HOLD` as warning-only while enabling an action that requires PASS. Status must include text and reason; color is supplemental. Hard blocks should be visually distinct from ordinary denials where useful.

## Interactions

Open reason/explanation, policy version, evidence lineage, remediation task or authority decision. Restricted policy internals remain redacted.

## Tests

Test every disposition, stale prior PASS, missing reason, hard-block deny, nested table display, role-based redaction and accessibility.

## Versioning

State vocabulary and reason-code schema follow CHLOM policy-engine versions.
