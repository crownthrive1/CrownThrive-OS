# UI-CASE-005 — Remedy / Action Panel

## Component identity

```yaml
surface_id: UI-CASE-005
component: Remedy / Action Panel
classification: role_scoped_component_contract
owner_capabilities: Cases; Authority; DLA; Economics; DAIL
```

## Purpose

The Remedy / Action Panel presents the specific action authorized by a case/review outcome—such as correction, reinstatement, suspension, refund/compensation, license amendment, access change or other governed remedy—and tracks execution separately from decision.

## Data contract

Remedy/action ID, source decision, target, public-safe action type, scope, responsible executor, authority/approval refs, not-before/expiry, compensation/economic refs if applicable, execution state, provider aliases and reconciliation/DAIL receipts.

## States

`PROPOSED`, `AUTHORIZED`, `TIMELOCKED`, `EXECUTION_PENDING`, `EXECUTED`, `PARTIALLY_EXECUTED`, `HOLD_RECONCILIATION`, `REVERSED`, `EXPIRED`, `DENIED`.

## Semantics

Decision, authority, execution and reconciliation are separate. A case finding does not automatically execute a remedy; an execution provider success does not prove the remedy was institutionally authorized.

## Actions

Authorized users can inspect authority, execute when gate conditions pass, record external execution evidence, reconcile, reverse/compensate through a governed workflow and open DAIL history.

## Safety/privacy

Never expose emergency credentials, payment secrets or private settlement instructions. High-consequence actions require exact-snapshot approval and idempotency.

## Tests

Test authorized/not-authorized, timelock, changed decision, duplicate execution, provider failure, partial remedy, reversal, expired action and cross-tenant target mismatch.

## Versioning

Remedy types and execution contracts are versioned; past decisions remain linked to the action version actually executed.
