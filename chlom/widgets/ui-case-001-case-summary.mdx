# UI-CASE-001 — Case Summary

## Component identity

```yaml
surface_id: UI-CASE-001
component: Case Summary
classification: role_scoped_component_contract
owner_capabilities: Cases; Audit; Governance; DAIL
```

## Purpose

The Case Summary is the compact canonical view of a dispute, compliance review, incident, appeal or other governed case. It communicates procedure and current state without exposing all evidence or implying a conclusion before an authorized decision.

## Data contract

Case ID/type, subject/object refs, public-safe party identities, issue summary, procedural state, assigned reviewers, governing policy/version, opened/due dates, evidence completeness, safeguards/holds, next action and DAIL lineage.

## States

`OPEN`, `TRIAGE`, `EVIDENCE_COLLECTION`, `UNDER_REVIEW`, `AWAITING_PARTY`, `AWAITING_AUTHORITY`, `DECIDED`, `APPEAL`, `CLOSED`, `REOPENED`, `REDACTED`.

## Semantics

Procedural state is not guilt, liability or noncompliance. Conclusions and remedies appear only through authorized decision records.

## Actions

Open evidence checklist, reviewer assignment, timeline, decision/remedy or appeal. Mutations require role/authority checks and append-only events.

## Tests

Test multi-party case, missing evidence, reassignment, appeal/reopen, restricted identities, deadline changes and cross-tenant isolation.

## Versioning

Case types and state schemas are versioned; historical cases preserve original policy context.
