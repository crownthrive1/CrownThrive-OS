# UI-REV-001 — Split Tree

## Component identity

```yaml
surface_id: UI-REV-001
component: Split Tree
classification: public_safe_component_contract
owner_capabilities: Economics; Rights; DAIL
protected_companion: VAULT-IP-003; VAULT-IP-004
```

## Purpose

The Split Tree displays who participates in a governed revenue/allocation schedule and how hierarchical relationships such as creator, licensor, platform, affiliate, ambassador or approved override roles connect. It visualizes the **authorized schedule**, not secret calculation code.

## Data contract

Schedule ID/version, recipient stable IDs, public-safe role labels, share values where disclosure is allowed, parent/child relationship, effective window, reserve/hold nodes, status and source agreement/policy refs.

## States

`ACTIVE_SCHEDULE`, `FUTURE`, `EXPIRED`, `SUPERSEDED`, `HOLD_CONFLICT`, `REDACTED_SHARE`, `ERROR`.

## Semantics

A displayed split does not imply funds were paid. Allocation calculation, payout execution and settlement reconciliation are separate. Tree edges cannot create shares unsupported by the governing agreement/schedule.

## Protected boundary

Restricted override compression, exact internal path-calculation mechanics and calibration logic remain in the private vault. Public views may show authorized output relationships and safe percentages when publication is permitted.

## Interactions

Select recipient/node, inspect schedule/evidence, compare versions and open allocation/settlement statements. Editing requires a separate governed economic-schedule workflow.

## Accessibility/tests

Provide list/table equivalent. Test deep hierarchy, redacted share, schedule supersession, zero share, reserve node, cycle rejection and responsive layout.

## Versioning

Schedule and component versions are distinct; the viewer preserves historical schedules.
