# UI-INT-002 — Webhook Delivery Health

## Component identity

```yaml
surface_id: UI-INT-002
component: Webhook Delivery Health
classification: role_scoped_component_contract
owner_capabilities: Integrations; Delivery; Audit
```

## Purpose

This component shows whether an outbound or inbound webhook integration is healthy and whether events are being authenticated, delivered, retried and idempotently processed.

## Data contract

Webhook ID, direction, endpoint host/alias (redacted where required), subscribed event classes, auth/signature method class, status, last delivery, success/failure counts, retry/dead-letter state, latency summary, idempotency/duplicate metrics and adapter version.

## States

`HEALTHY`, `DEGRADED`, `RETRYING`, `DEAD_LETTER`, `AUTH_FAILURE`, `DISABLED`, `RATE_LIMITED`, `UNKNOWN`, `ERROR`.

## Security

Never display signing secrets, tokens or full sensitive payloads. Diagnostic payload samples require separate protected access and redaction.

## Semantics

A successfully delivered provider/webhook event is transport evidence; business effects remain governed by normalization, idempotency, reconciliation and authority rules.

## Interactions

Inspect delivery attempts, retry or replay where permitted, rotate endpoint/auth config through an approved workflow, view adapter logs and open associated incident/case.

## Tests

Test successful delivery, retry, duplicate, invalid signature, timeout, endpoint 5xx, dead-letter, disabled endpoint, event-schema version mismatch and no secret leakage.

## Versioning

Webhook event schemas and adapters are versioned independently; health views identify both.
