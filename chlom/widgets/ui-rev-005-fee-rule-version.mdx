# UI-REV-005 — Fee Rule Version

## Component identity

```yaml
surface_id: UI-REV-005
component: Fee Rule Version
classification: public_safe_component_contract
owner_capabilities: Economics; Policy; DAIL
```

## Purpose

The Fee Rule Version component identifies exactly which approved fee/economic schedule governed an event. It prevents current pricing pages or provider fees from being retroactively assumed to apply to historical transactions.

## Data contract

Rule/schedule ID and version, fee class, calculation basis, public-safe rate/fixed amount where disclosure is permitted, effective-from/until, source agreement/policy, superseding version and applied transaction/calculation refs.

## States

`CURRENT`, `FUTURE`, `EXPIRED`, `SUPERSEDED`, `HOLD_CONFLICT`, `REDACTED_TERMS`, `NOT_APPLICABLE`.

## Semantics

A provider's native fee is not automatically a CHLOM fee rule. The governing agreement/policy determines whether provider fees are absorbed, passed through or excluded from the economic basis.

## Interactions

Open safe schedule details, compare versions, inspect source authority and view transactions calculated under this version.

## Tests

Test transaction at version boundary, backdated correction, provider fee versus institutional rule, redacted commercial terms, supersession and missing schedule.

## Versioning

The component exists specifically to make versioning explicit; historical applied rules remain immutable references.
