# UI-REV-004 — Refund / Clawback State

## Component identity

```yaml
surface_id: UI-REV-004
component: Refund / Clawback State
classification: role_scoped_component_contract
owner_capabilities: Economics; Cases; Authority; DAIL
```

## Purpose

This component shows the lifecycle of a refund, reversal, recoupment or authorized clawback without treating every negative economic adjustment as the same legal/accounting event.

## Data contract

Adjustment ID/type, source transaction/obligation, amount/currency, basis/reason, authority/decision ref, responsible party, provider aliases, requested/approved/executed times, deadline, state, compensation/offset method and reconciliation/DAIL refs.

## States

`REQUESTED`, `UNDER_REVIEW`, `APPROVED`, `DENIED`, `EXECUTION_PENDING`, `EXECUTED`, `PARTIAL`, `HOLD_MISMATCH`, `REVERSED`, `SUPERSEDED`.

## Semantics

A refund can be customer-facing payment reversal; a clawback can be contractual/governance recoupment; a correction can be accounting-only. The UI must identify the actual class and its authority.

## Actions

Inspect source event and authority, execute through approved provider flow, reconcile evidence, appeal/review where applicable and view resulting adjusted statements.

## Tests

Test refund, partial refund, contractual clawback, wrong amount, expired authority, provider failure, duplicate reversal and adjustment crossing accounting periods.

## Versioning

Adjustment types and economic treatment follow versioned policy/agreement definitions.
