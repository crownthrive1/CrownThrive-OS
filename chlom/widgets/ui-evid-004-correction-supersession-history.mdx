# UI-EVID-004 — Correction / Supersession History

## Component identity

```yaml
surface_id: UI-EVID-004
component: Correction / Supersession History
classification: public_safe_component_contract
owner_capabilities: DAIL; Evidence; Governance
```

## Purpose

This component shows how an earlier record was corrected, superseded, revoked, reversed or adjudicated while preserving the original event. It is the UI implementation of CHLOM's append-only correction rule.

## Data contract

Original event/object version, correction/supersession events, correction class, authority/source class, effective time, reason code, evidence refs, current effective version and unresolved branch/conflict indicators.

## States

`UNCHANGED`, `CORRECTED`, `SUPERSEDED`, `REVOKED`, `REINSTATED`, `CONFLICT`, `HOLD_ADJUDICATION`, `REDACTED`.

## UX semantics

The current effective value can be highlighted, but the history remains inspectable to authorized users. A correction should never look like the original record never existed.

## Interactions

Compare versions, trace source/evidence, inspect adjudication, open current effective object and copy stable record references.

## Privacy

Restricted correction rationale/evidence may be summarized or redacted while the existence and effective state remain visible according to policy.

## Tests

Test one correction, multiple supersessions, conflicting branches, founder adjudication, reinstatement, backdated effect and protected correction evidence.

## Versioning

The renderer follows the DAIL correction/reducer schema version and must support historic chains.
