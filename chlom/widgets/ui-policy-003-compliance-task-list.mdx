# UI-POLICY-003 — Compliance Task List

## Component identity

```yaml
surface_id: UI-POLICY-003
component: Compliance Task List
classification: public_safe_component_contract
owner_capabilities: Policy; Cases; Audit; DAIL
```

## Purpose

The Compliance Task List converts unresolved controls and findings into explicit work instead of leaving a generic `HOLD` with no remediation path. It is reusable in DLA activation, audits, cases, provider onboarding and policy migration.

## Data contract

Task ID, parent decision/case/control, public-safe task summary, responsible role/assignee, required evidence/action, priority/severity, created/due times, dependency tasks, state, completion evidence and reviewer/approval requirement.

## States

`OPEN`, `BLOCKED`, `IN_PROGRESS`, `AWAITING_EVIDENCE`, `AWAITING_REVIEW`, `COMPLETE_PENDING_RECHECK`, `CLOSED`, `CANCELLED`, `OVERDUE`.

## Semantics

Completing a task does not automatically convert the parent decision to PASS. The relevant control/policy must be re-evaluated against the new evidence.

## Actions

Open task, submit evidence reference, assign/reassign within authority, request review, mark work ready for recheck and inspect closure receipt. Evidence uploads use protected custody rather than embedding confidential data in task text.

## Accessibility

Support keyboard list/table navigation, clear state labels, due-date formatting and filters that retain accessible names.

## Tests

Test dependency chains, overdue states, task completion without evidence, cancelled control, reassignment, restricted evidence and parent re-evaluation after completion.

## Versioning

Task workflow and state semantics are versioned; historical completed tasks remain attached to their original decision/audit.
