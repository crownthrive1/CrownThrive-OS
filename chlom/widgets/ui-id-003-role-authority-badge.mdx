# UI-ID-003 — Role / Authority Badge

## Component identity

```yaml
surface_id: UI-ID-003
component: Role / Authority Badge
classification: public_safe_component_contract
owner_capabilities: Identity; Governance; Authority
```

## Purpose

This component shows a human-readable role plus the current status of any relevant delegated or reserved authority. It exists to prevent interfaces from treating a role title such as `reviewer`, `admin`, `issuer`, or `founder` as proof that the holder may execute every action.

## Data contract

Public-safe role label, authority state, scope summary, tenant/object scope, effective window, delegation/issuer class, required cosigner indicator and revoked/expired status. Sensitive delegation documents remain referenced, not embedded.

## States

`ROLE_ONLY`, `AUTHORIZED_IN_SCOPE`, `AUTHORIZED_WITH_COSIGN`, `OUT_OF_SCOPE`, `EXPIRED`, `REVOKED`, `HOLD_VERIFICATION`, `REDACTED`.

## Semantics

The badge is a projection of authority resolution, not an authorization engine. Consequential actions still pass ALG-002 using the exact action and current snapshot.

## UX rule

Never display a green 'authorized' badge solely because the user has an administrative UI role. The label must identify whether authority is action-specific or merely descriptive.

## Accessibility

Use explicit text such as `Authorized for this scope` or `Role only — no execution authority`; do not rely on shield color.

## Tests

Test active delegation, wrong tenant, wrong object, expired, revoked, cosigner required, role-only admin and current action outside delegation scope.

## Versioning

Authority-state terminology is shared across CHLOM surfaces and must change through governed schema/version updates.
