# UI-POLICY-002 — Risk / Rule Explanation Panel

## Component identity

```yaml
surface_id: UI-POLICY-002
component: Risk / Rule Explanation Panel
classification: public_safe_component_contract
owner_capabilities: Risk; ACE; Policy Engine
```

## Purpose

This panel explains **why** a risk or policy result occurred using public-safe reason codes, evidence categories, model/rule versions and uncertainty. It does not expose trade-secret weights, private features or raw sensitive data.

## Data contract

Assessment ID, model/rule version, normalized score if disclosure is permitted, uncertainty state, triggered rule/reason codes, evidence categories, threshold policy version, hard-rule indicator, evaluation time and review requirement.

## States

`EXPLAINED`, `PARTIAL_EXPLANATION`, `REDACTED`, `MODEL_UNAVAILABLE`, `HOLD_REVIEW`, `ERROR`.

## Explanation semantics

Separate deterministic rule hits from probabilistic model contributions. Never imply that an explanation equals legal reasoning or execution authority. A high score is evidence, not a verdict.

## Protected boundary

Proprietary feature engineering, calibration, exact weights, training data, private Fingerprint signals and adversarial thresholds remain in restricted model documentation/vaults.

## Accessibility

Use plain-language summaries plus machine-readable reason codes. Charts require text equivalents; uncertainty must not be conveyed solely through color.

## Tests

Test hard-rule-only decision, model-only assessment, redacted features, high uncertainty, stale model version, missing evidence and accessibility with screen readers.

## Versioning

Explanation schema must track model/rule versions so reason codes are not reinterpreted retroactively.
