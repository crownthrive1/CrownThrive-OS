## Historical purpose

The Pause/Guardianship Pallet was designed as a circuit breaker. Authorized guardians could temporarily stop sensitive CHLOM operations when continuing execution would be unsafe, disputed, noncompliant or otherwise unacceptable.

```text
NORMAL OPERATION
      |
trigger / evidence
      |
      v
PAUSE REQUEST / EMERGENCY SIGNAL
      |
GUARDIAN AUTHORITY CHECK
      |
      +--> invalid -> DENY
      |
      v
SCOPE + DURATION
      |
      v
PAUSED / HELD
      |
REVIEW / REMEDIATION
      |
RESTORE | MODIFY | REVOKE / CLOSE
```

## Pause is bounded

A pause should identify:

- exact scope;
- reason/evidence;
- authority;
- start time;
- review/expiry condition;
- affected operations;
- restoration criteria;
- downstream compensation/reconciliation needs.

A universal indefinite pause with no scope/review path is not the intended safe pattern.

## Guardian model

A guardian is a bounded emergency role, not a universal system administrator.

```text
GUARDIAN ROLE
   |
allowed emergency scopes
   |
maximum action class
   |
required evidence / post-review
```

Current CHLOM should treat guardian assignments as explicit P-01/P-02 authority records.

## Historical emergency use cases

- compromised issuer/provider;
- suspicious transaction/license activity;
- oracle/feed failure;
- governance exploit;
- contract/runtime vulnerability;
- disputed rights/license;
- treasury/economic anomaly;
- security incident;
- critical policy mismatch.

## HOLD mapping

Current CHLOM generalizes many pause conditions into the explicit `HOLD` state.

```text
PAUSE = operational suspension mechanism
HOLD  = governance/decision state saying do not proceed yet
```

They may coexist. A HOLD may trigger a pause; a pause may remain while a case/review resolves.

## Scope hierarchy

```text
institution-wide
  > pallet/service
    > tenant/platform
      > asset/object
        > operation
```

A guardian authorized for a narrow scope cannot silently pause broader scopes.

## Restoration

Restoration requires affirmative evidence that the pause condition is resolved or that an authorized decision permits safe resumption.

```text
PAUSED
  |
remediation/readback
  |
review
  |
criteria satisfied?
 no -> remain paused
 yes
  |
RESTORE exact scope
  |
DAIL
```

## Override relationship

A pause lift/override cannot erase the reason the pause existed.

```text
original condition
   +
original pause
   +
override/restoration authority
   +
new state
```

all remain linked in DAIL.

## Incident response relationship

Security incidents can invoke emergency pause while incident procedures continue under P-10/security governance. Public pages should not expose exploit-sensitive pause mechanisms.

## Economic/rights compensation

Pausing an action may create obligations to:

- refund;
- reschedule;
- restore entitlement;
- halt payout;
- re-run verification;
- preserve evidence;
- notify affected parties.

The pause pallet does not itself decide every remedy; it routes/blocks safely.

## Security threats

- unauthorized guardian;
- stolen guardian credentials;
- overbroad pause scope;
- guardian censorship/abuse;
- failure to expire/review;
- stale pause caches;
- bypass through another provider;
- premature restoration;
- hidden pause with no audit trail.

## Public / restricted split

Public-safe:

- pause/guardian lifecycle;
- bounded authority principles;
- HOLD mapping;
- remedy/evidence semantics.

Restricted:

- guardian identities where sensitive;
- exact emergency routes;
- exploit triggers;
- provider kill-switch details;
- security topology;
- incident evidence.
