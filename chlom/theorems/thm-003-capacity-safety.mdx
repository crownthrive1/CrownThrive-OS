## Recovered statement

The Gold Paper states the capacity-safety guarantee as:

```text
guards + nonce => used <= cap
```

under the modeled license-state transition system.

## Meaning

If every usage transition verifies the required guard conditions, advances a replay-protected nonce, and rejects any transition that would exceed the licensed capacity, valid system state cannot progress to `used > cap`.

## Assumptions

Atomic state transitions, authoritative license/cap state, correct nonce semantics, no unauthorized direct state mutation, integer/overflow safety, correct replay protection and a stable interpretation of the usage unit.

## Public boundary

The theorem statement and invariant are public-safe. The exact proof, contract implementation and mechanized state model remain restricted.

## Current mapping

Modern CHLOM can apply the same invariant to usage quotas, seats, entitlements, API allowances, licensed copies or other finite rights. Current cloud services must implement transactional/serialized updates or equivalent concurrency controls before claiming the property.

## Verification targets

Test exact-cap use, attempted over-cap use, concurrent updates, duplicate nonce, skipped nonce, rollback/retry, cap decrease after prior use, unlimited-cap representation and integer boundary cases.

## Production claim boundary

Only implementation-specific proof/property tests tied to deployed code can establish current capacity safety.
