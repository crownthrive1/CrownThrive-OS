## Recovered guarantee

Under the historical Splitter model, processing the same valid economic event set in different orders or valid batch partitions does not change the modeled recipient totals, assuming the same schedule, basis and residual rules.

## Assumptions

Stable schedule version, deterministic arithmetic and residue handling, no duplicated or dropped events, event identity, and no intentional policy behavior dependent on batch boundaries.

## Current mapping

Cloud-first payout/allocation services should preserve the same property through idempotent semantic event identity, deterministic calculation records and reconciliation. Retries, pagination, worker concurrency or batch size must not change who is owed what.

## Protected boundary

The exact source proof and protected splitter mechanics remain vaulted.

## Verification targets

Replay identical event sets under randomized order and partitioning; compare per-recipient totals and residue; test retries, partial failures, refunds, schedule boundaries and concurrency.
