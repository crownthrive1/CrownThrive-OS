## Purpose

Historical CHLOM described licenses as NFTs/SBT-like tokenized assets carrying machine-readable metadata. This engine captures that design while separating the **license semantics** from any specific blockchain/token wrapper.

```text
RIGHTS / AGREEMENT
      |
      v
LICENSE / DLA RECORD
      |
      v
METADATA ENGINE
      |
      +--> canonical metadata
      +--> integrity digest
      +--> public verification
      +--> optional token/NFT wrapper
```

## Historical token wrapper

The historical wrapper could represent:

- unique license identity;
- issuer/holder;
- scope;
- duration;
- transferability;
- metadata URI/digest;
- current status;
- relationship to LEX.

The wrapper never creates source rights by itself.

## Current DLA mapping

Current CHLOM keeps the license object provider-neutral:

```yaml
dla_id: stable ID
asset_ref: required
rights_ref: required
issuer_ref: required
holder_ref: required
scope: structured
agreement_ref: required/optional by license type
version: string
status: candidate|active|held|suspended|revoked|expired|superseded

```

A future token wrapper can point to this object without replacing its institutional meaning.

## Token-wrapper separation

```text
DLA semantics
   |
   +--> database/API object
   +--> signed credential/attestation
   +--> NFT/SBT wrapper (future adapter)
   +--> other provider representation
```

The same DLA can migrate representations without changing the canonical identity.

## URI independence

Metadata can reference object storage, IPFS/Arweave research, CDN or API representations. Canonical metadata ID/version is independent of a mutable provider URL.

## Integrity

```text
metadata_digest = H(canonical_serialization(metadata_version))
```

Digest algorithm/serialization rules must be versioned. Hash integrity does not prove the license is legally valid.

## Historical NFT/SBT distinction

- NFT-like license: potentially transferable according to rules;
- SBT-like credential/license: non-transferable or identity-bound.

Current CHLOM represents transferability explicitly rather than relying on token class alone.

## LEX integration

```text
DLA current + transferable/sublicensable scope
      |
      v
LEX listing candidate
```

Marketplace metadata is a projection of DLA/right state, not an independent source.

## Revocation

Revocation changes current DLA/license state. A historical token may remain visible on-chain while its current institutional status is revoked.

```text
token exists != license active
```

This distinction is essential for any future chain adapter.

## Transfer

A token transfer is not sufficient unless the institutional rights/license transfer rules pass.

```text
token transfer observed
      |
      v
local rights / DLA / policy reconciliation
      |
      v
current holder/entitlement state
```

## Failure cases

### NFT exists but source rights were invalidated

DLA becomes HOLD/revoked according to rights process; token existence does not override rights.

### Metadata URI breaks

Canonical metadata remains recoverable via registry/source custody; update projection/locator without changing DLA identity.

### Token transferred outside CHLOM policy

Treat chain event as evidence and HOLD/reconcile local holder status.

### Private agreement fields leaked into public metadata

Contain/correct public projection and review data-minimization controls.

## Security/privacy

- avoid PII in immutable public metadata;
- protect restricted agreement/evidence;
- validate metadata schemas/content;
- prevent malicious URI/content injection;
- reconcile chain/provider state;
- no secret keys in metadata.
