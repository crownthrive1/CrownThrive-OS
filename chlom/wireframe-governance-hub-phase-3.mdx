## Purpose

The Governance Hub is the consolidated interface for **proposals, decisions, reviews, approvals, councils, timelocks, overrides, enactment and governance evidence**. It preserves historical DAO/council design without representing current CHLOM as a live tokenized DAO unless separate deployment evidence exists.

## Overview

Summary blocks can show:

- proposals requiring actor action;
- active voting/review windows;
- approved-but-not-enacted decisions;
- active timelocks;
- pending overrides;
- founder adjudications/corrections;
- policy/config changes awaiting certification;
- governance conflicts/HOLDs;
- recent enacted changes with readback state.

## Proposal payload

The interface shows the exact object/diff proposed:

```text
policy version update
parameter/config change
registry membership
runtime/service release
budget/treasury action
override/exception
governance rule change
other controlled action
```

Approvals bind to a payload digest/version so the enacted change cannot silently differ.

## Tally / approval view

For a weighted process:

```text
Eligible weight: W_e
Participating weight: W_p
Quorum: W_p / W_e
Yes / No / Abstain according to process
Approval rule: exact version
```

If eligibility changes mid-process, the page states which snapshot/version governs the tally.

## Non-voting approvals

Many current CrownThrive changes use approvals rather than public voting.

```text
Reviewer A      approved
Reviewer B      pending
Founder/reserved authority   required / not required
Security review              PASS / HOLD
Documentation gate           pending
```

## Founder adjudications

```text

```

A founder ruling is not rewritten as a DAO vote.

## Conflict state

If two authority paths conflict or source authority is unresolved:

```text
GOVERNANCE HOLD
Conflict: policy authority / proposal scope
Affected enactment: blocked
Required review: ...
```

Do not pick the newest proposal as automatic winner.

## Discussion/review

Comments/review are evidence and deliberative records; they are not votes unless the process says so. Private deliberation can remain restricted.

## Loading/stale

Governance actions disable when:

- process/eligible set unavailable;
- target payload version changed;
- actor authority expired;
- policy/constitutional source unresolved;
- exact enactment artifact cannot be resolved.

## Errors

- actor ineligible;
- duplicate/replayed approval;
- proposal payload digest changed;
- quorum rule invalid;
- timelock clock/state mismatch;
- enactment failed;
- provider state differs from approved result;
- documentation/security gate failed.

## Accessibility

- tally charts include numeric/table equivalents;
- decision status not color-only;
- proposal diff accessible in linear text;
- countdown/timelock status announced without excessive live updates;
- approval confirmation describes exact payload;
- historical/current banners accessible.

## Restricted companion

Can hold private deliberations, security-sensitive governance payloads, signer/multisig topology, emergency procedures, protected thresholds, unreleased proposals and exploit-related changes.

## Invariants

```text
proposal != decision
approval != enactment
vote != unlimited authority
quorum reached != constitutional validity
founder adjudication != DAO vote
multiple agents != independent human quorum
clock expired != automatic enactment
provider execution != confirmed governance state
historical DAO design != current live DAO
reconstructed layout != recovered original visual
```
