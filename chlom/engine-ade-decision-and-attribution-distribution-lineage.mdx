## Purpose

ADE is a collision-bearing CHLOM acronym with two distinct architectural lives. Historical Genesis-era material uses ADE for the **Autonomous Decision Engine**: a system that acted on AI/compliance/governance signals. Later material uses ADE for the **Attribution & Distribution Engine**: determine who receives credit/economic allocation from qualifying events and route that evidence into royalty/distribution workflows.

Both are valuable IP. Neither may silently replace the other.

```text
                 ADE LINEAGE
            +---------+---------+
            |                   |
            v                   v
AUTONOMOUS DECISION       ATTRIBUTION & DISTRIBUTION
    historical                 later/current mapping
            |                   |
       ACE / policy          P-05 evidence
       authority gate        + P-11 schedules
            |                   |
      bounded action          allocation / settlement
```

## Part I — Historical Autonomous Decision Engine

### Historical purpose

The Autonomous Decision Engine was designed to take verified signals and execute or recommend protocol actions with less manual intervention.

```text
AIE / ORACLE / EVENT
       |
       v
ACE / POLICY RESULT
       |
       v
ADE AUTONOMOUS DECISION
       |
       +--> execute allowed action
       +--> schedule action
       +--> route governance
       +--> HOLD / escalate
```

### Constitutional modernization

Current CHLOM narrows autonomy through explicit authority/delegation ceilings.

```text
AUTOMATION MAY OPTIMIZE WITHIN AUTHORITY
AUTOMATION MAY NOT MANUFACTURE AUTHORITY
```

A historical design that describes autonomous enforcement is therefore mapped into a current bounded workflow/agent execution model.

### Decision record

```yaml
automated_action_id: stable ID
trigger_ref: event/evidence
policy_decision_ref: required
authority_ref: required
delegation_ref: required when actor is agent
action_type: controlled
side_effect_class: read|write|rights|economic|security|external
status: candidate|authorized|held|executed|failed|compensated
```

### Autonomy ceiling

The engine can act only if:

- the requested capability is delegated;
- the action class is within authority ceiling;
- all mandatory policy gates PASS;
- evidence freshness is adequate;
- no human-reserved decision is required;
- rollback/compensation is defined for side effects.

## Part II — Attribution & Distribution Engine

### Purpose

The later ADE determines **which participant, source, license, campaign or rights holder should receive attribution from a qualifying event, then passes a versioned attribution result to economic allocation/settlement**.

```text
QUALIFYING EVENT
      |
      v
CORRELATION / PROVENANCE
      |
      v
ATTRIBUTION MODEL VERSION
      |
      v
ATTRIBUTION RESULT
      |
      v
P-11 ECONOMIC SCHEDULE
      |
      v
OBLIGATIONS / DISTRIBUTION / SETTLEMENT
```

### Attribution is not payout

```text
attribution
   !=
royalty schedule
   !=
commission obligation
   !=
provider payout
   !=
settlement
```

The stages remain separate so corrections can be applied without fabricating economics.

## Attribution evidence

Possible inputs:

- campaign/referral identifiers;
- rights/license relationships;
- creator/contributor provenance;
- orders/payments after reconciliation;
- event timestamps;
- session/correlation IDs;
- content/media identifiers;
- provider receipts;
- corrected duplicate/fraud filters.

Provider IDs remain aliases.

## Deterministic attribution example

A simple rules model could be:

```text
if exact contractual source ID exists:
    attribute to that source
else if valid campaign touchpoint exists within adopted window:
    evaluate model
else:
    HOLD / unattributed
```

This is an illustrative algorithm family, not the production model for every program.

## Weighted attribution

Where an approved model uses weights:

```text
credit_i = normalized(weight_i)
```

Economic amounts are calculated later from the governed economic basis/schedule. Model weights can be protected IP.

## Distribution model

ADE can generate a distribution candidate/plan but P-11 owns economic obligation/settlement semantics.

```text
ADE attribution result
      |
P-11 rights/agreement/schedule
      |
allocation plan
      |
authorization
      |
provider execution
      |
reconciliation
```

## Rights boundary

ADE cannot attribute royalty ownership broader than P-03 rights evidence supports.

```text
attribution candidate
      subset of
verified eligible rightsholders / participants
```

If rights are disputed, dependent economic distribution can HOLD.

## Versioning

Attribution must retain the model version effective for the event/reconciliation.

A later model update should not silently recalculate settled historical outcomes unless an adopted correction policy explicitly does so.

## Correction

```text
original attribution A1
       |
new evidence / duplicate / error
       |
corrected attribution A2
       |
P-11 reversal / obligation correction if required
```

A1 remains in lineage.

## Failure modes

### Historical ADE meaning ambiguous

Use source/version namespace. Do not infer which ADE was intended from acronym alone.

### Model attributes conversion to wrong campaign

Preserve original result, correct with evidence, propagate economic correction only under adopted schedule/remedy.

### Autonomous ADE receives AI recommendation outside delegated scope

DENY execution; recommendation remains evidence.

### Provider payout succeeds before attribution correction arrives

P-11 handles reversal/clawback/compensation; ADE does not delete the original attribution/payout record.

### Rights holder disputed

HOLD rights-dependent distribution.
