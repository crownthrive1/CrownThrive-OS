## Reconstruction envelope

Every substantive article should identify where applicable:

1. historical/source meaning;
2. current institutional meaning;
3. source-support quality;
4. implementation status;
5. stable objects and schemas;
6. lifecycle/state machine;
7. authority boundaries;
8. evidence/trust boundaries;
9. failure/HOLD conditions;
10. current service mapping;
11. founder-adjudication status;
12. correction/supersession behavior.

## Identity and credential invariant

```text
IDENTITY   = who the actor is
CREDENTIAL = what an authorized issuer has attested
ROLE       = institutional function
DELEGATION = bounded authority granted
APPROVAL   = permission for a specific consequential action
EXECUTION  = actual side effect
```

These layers must not collapse into one token, badge or provider record.

## ZK proof invariant

```text
proof valid
   != credential current
   != policy still effective
   != action authorized
   != legal conclusion
```

ZKX/proof verification is evidence for a statement, not universal authority.

## External evidence invariant

```text
AUTHORITY      = source entitled to make claim?
RELIABILITY    = source historically accurate?
FRESHNESS      = observation current enough?
CORROBORATION  = independent sources agree?
```

Unresolved critical source conflict resolves HOLD.

## Economic invariant

```text
CALCULATION
   != OBLIGATION
   != AUTHORIZATION
   != PROVIDER EXECUTION
   != INSTITUTIONAL SETTLEMENT
```

Every layer can be audited and corrected independently.

## Temporal invariant

A previously approved future action must be revalidated when dynamic prerequisites may have changed.

```text
approved at T0
     |
     v
scheduled / timelocked
     |
     v
revalidate at T1
     |
 PASS / HOLD / DENY
```

## Interoperability invariant

```text
MESSAGE != CLAIM != PROOF != LOCAL INSTITUTIONAL DECISION
```

Remote chain/provider state enters CHLOM as attributable evidence and is interpreted through local rights/policy/authority rules.

## Observability invariant

```text
INDEX = read model
DAIL / canonical service = authority
```

If an index is stale or corrupt it must be rebuildable from canonical records.

## Failure-state standard

Every comprehensive Wave 2B article includes explicit failure/HOLD behavior. Common reasons include:

- unresolved source authority;
- stale evidence;
- contradictory current state;
- missing rights or permissions;
- exceeded delegation;
- provider mismatch;
- invalid proof/version;
- incomplete rollback/compensation path;
- policy conflict;
- missing independent verification;
- privacy/authorization ambiguity.
