## Historical purpose

The RBAC/Permissions Pallet was designed as a runtime authorization primitive: sensitive protocol calls would not rely solely on possession of an account/key but would require an appropriate role/capability at the relevant module boundary.

```text
CALLER
  |
  v
IDENTITY / ACCOUNT
  |
  v
ROLE MEMBERSHIP
  |
  v
CAPABILITY SCOPE
  |
  v
PALLET / EXTRINSIC BOUNDARY
  |
ALLOW | REJECT
```

## Capability principle

A role name should resolve to explicit capabilities.

```text
"admin"
   !=
unbounded protocol authority
```

A safe capability model asks:

```text
who
may perform what operation
on which object/module
under which scope
for what time period
```

## Delegation improvement

Current CHLOM extends basic RBAC with explicit delegation and authority ceilings.

```text
ROLE
  |
DELEGATION
  |
AUTHORITY CEILING
  |
OBJECT / TENANT SCOPE
  |
TIME WINDOW
```

This avoids treating inherited role membership as unlimited authority.

## Agent boundary

Agents are separate institutional subjects. An agent inherits only explicitly delegated capabilities.

```text
principal capability set = C_p
agent delegated set = C_a

required invariant:
C_a subseteq C_p
```

An agent cannot grant itself capabilities outside the principal/delegator's valid scope.

## Fail-closed behavior

```text
role missing -> DENY
capability unknown -> DENY/HOLD
scope unresolved -> HOLD
assignment expired -> DENY
conflicting authority -> HOLD
```
