## Purpose

The Risk Scoring Engine produces **bounded, versioned risk estimates** from defined evidence for a specific purpose. It does not label a person/entity as generally risky and does not issue legal/compliance sanctions by itself.

```text
EVIDENCE / OBSERVATIONS
       |
       v
FEATURE / NORMALIZATION VERSION
       |
       v
RISK MODEL VERSION
       |
       v
SCORE + BAND + UNCERTAINTY
       |
       v
AIE / ACE / REVIEWER
       |
POLICY CONSEQUENCE
```

## Risk is purpose-specific

Examples of separate risk models:

- transaction anomaly risk;
- provider integration risk;
- rights/evidence uncertainty;
- account/identity compromise risk;
- settlement/reconciliation risk;
- model/system health risk;
- partner/provider operational risk.

A score from one model must not be reused for an unrelated purpose without an adopted mapping.

## Historical weighted example

Recovered CHLOM material includes weighted-risk examples. A generic public-safe model is:

```text
risk = α*x1 + β*x2 + γ*x3 + ...
```

Weights/features are model/version specific. Historical formulas are lineage, not production calibration.

## Normalization

If multiple features use different scales, the model must define normalization explicitly. Example conceptual normalization:

```text
z = (x - μ) / σ
```

or robust/min-max alternatives. This page does not declare a production method.

## Score range

If a model uses `[0,1]` or `[0,100]`, the scale definition is versioned. Consumers may not assume `100` always means worst risk across models.

## Bands

A band mapping can be:

```text
score -> LOW / MEDIUM / HIGH / CRITICAL
```

but thresholds belong to the exact model/policy and can be restricted.

## Uncertainty

```text
score = 0.73
uncertainty = high
```

can appropriately route HOLD/review rather than treating `0.73` as precise truth.

## Freshness

```text
usable(score, t) = score.status == current AND t <= valid_until
```

where applicable. If no valid-until is explicit, domain policy controls reuse.

## ACE relationship

ACE consumes risk as one input:

```text
risk score HIGH
      |
policy says human review required
      |
HOLD + reviewer
```

A risk engine never hard-codes the business remedy unless that rule is formally part of the governed policy layer.

## AIE relationship

AIE can create anomaly/risk features and orchestrate multiple models; this engine owns risk-model execution/calibration contracts.

## Evidence quality

The engine can record evidence quality/provenance rather than silently treating all sources equally.

```text
provider-reported
internal observed
corroborated
independently verified
unknown/stale
```

No universal quality weights are declared here.

## Calibration

Calibration asks whether predicted risk corresponds to observed outcomes. When valid ground truth exists, metrics can include calibration error/Brier score or bucketed reliability. These are evaluation tools, not authority.

## Threshold governance

Threshold changes are versioned configuration/policy changes. They do not silently alter historical scores or decisions.

## Human review feedback

```text
score / decision
   |
human review / verified outcome
   |
evaluation record
   |
model improvement candidate
```

Feedback does not automatically retrain/promote the model.

## Drift

Monitor:

- feature distribution drift;
- calibration drift;
- outcome/base-rate drift;
- provider/schema drift;
- performance degradation.

Material drift can HOLD the model/version.

## Failure modes

### Missing required feature

Return incomplete/HOLD-compatible output, not a fabricated zero-risk value.

### Model service unavailable

If mandatory, ACE holds; no fail-open bypass.

### Ground-truth labels unreliable

Qualify evaluation results and avoid false precision.

### Model update materially changes scoring

Version and compare against regression/evaluation corpus before activation.

### Provider schema changes

Hold affected model until normalization validated.
