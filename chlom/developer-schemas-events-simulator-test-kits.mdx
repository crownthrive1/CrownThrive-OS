# Developer Schemas, Events, Simulator and Test Kits

The Grand Prospectus dedicates its developer appendices to **technical schemas for policies, licenses, payouts and events**, ASCII system maps, simulators, SDKs, CI/CD references, test kits and runbooks. These materials are design inputs for the modern CHLOM developer surface.

This article converts that source intent into a provider-independent developer contract without claiming that every illustrated endpoint or schema is deployed today.

## Developer principle

CHLOM integrations should bind to **stable institutional contracts**, not vendor-specific database tables or one-off provider payloads.

```text
INSTITUTIONAL SCHEMA
       |
       +--> REST adapter
       +--> MCP tool
       +--> SDK object
       +--> event/webhook
       +--> provider adapter
       +--> future chain adapter
```

The contract should survive a provider migration.

## License schema lineage

The Grand Prospectus gives a human-readable license schema containing issuer/holder fingerprints, asset identity, rights, regions, validity, usage limits, royalty percentage, transferability, status, parent license and metadata hash.

Current CHLOM preserves the semantics while separating mutable economics and identity aliases into referenced objects.

```json
{
  "dla_id": "ct.dla.example",
  "asset_ref": "ct.asset.example",
  "issuer_authority_ref": "ct.auth.issuer",
  "holder_ref": "ct.org.licensee",
  "parent_dla_ref": null,
  "rights": {
    "media": ["streaming"],
    "territories": ["US"],
    "exclusive": false,
    "transferable": false,
    "sublicensable": false,
    "modification_allowed": false
  },
  "effective_from": "2026-08-23T00:00:00Z",
  "expires_at": null,
  "economic_schedule_ref": "ct.econ.schedule.v1",
  "status": "active",
  "source_evidence_refs": ["ct.evidence.1"],
  "version": "1.0.0"
}
```

This is an illustrative contract, not a statement that this exact JSON is production-canonical today.

## Policy schema lineage

The Grand Prospectus also illustrates a Compliance Policy object with policy ID, name, description, rules, jurisdiction, issuer and version.

Current mapping should preserve explicit applicability and effect.

```json
{
  "policy_id": "ct.policy.kyc-basic",
  "version": "2.1.0",
  "issuer_authority_ref": "ct.policy-authority.compliance",
  "jurisdictions": ["US"],
  "applies_to": ["regulated_transaction"],
  "rules": [
    {
      "rule_id": "tx-threshold-credential",
      "when": {"amount_usd_gt": 10000},
      "require": {"credential_class": "KYC_LEVEL_1"}
    }
  ],
  "default_disposition": "HOLD"
}
```

## Idempotency

Every side-effecting developer interface should define idempotency.

```text
client request
   |
   +--> idempotency key
            |
            v
       already processed?
        /           \
      yes            no
      |              |
 return prior      execute once
 result             + persist key
```

A retry must not create duplicate licenses, payouts or entitlements.

## Error model

A common error envelope should distinguish:

```json
{
  "error": {
    "code": "EVIDENCE_STALE",
    "disposition": "HOLD",
    "message": "Required evidence is outside its freshness window.",
    "retryable": true,
    "required_actions": ["refresh_evidence"],
    "correlation_id": "ct.flow.123"
  }
}
```

## PASS / HOLD / DENY developer semantics

```text
PASS
  request may proceed within returned authority

HOLD
  do not proceed; missing/uncertain dependency may be resolvable

DENY
  request is not authorized under current rules/evidence
```

Clients must not convert HOLD into PASS by retrying against a different provider.

## Simulator

The Grand Prospectus proposes a CHLOM Simulator where developers can run license, violation and dispute scenarios without real stakes.

Modern simulator topology:

```text
SCENARIO FIXTURE
      |
      v
+-------------------+
| Simulator Runtime |
+-------------------+
  |    |    |    |
  v    v    v    v
 ID  POLICY DLA  DAIL
  \    |    /     /
   +---+---+-----+
       |
       v
 deterministic trace
       |
       v
 expected vs actual
```

## Scenario file

```yaml
scenario_id: license-transfer-001
initial_state:
  rights: fixtures/rights.json
  dlas: fixtures/dlas.json
  credentials: fixtures/credentials.json
events:
  - type: lex.transfer_requested
    actor: buyer-A
expect:
  disposition: HOLD
  reason_codes:
    - REQUIRED_CREDENTIAL_MISSING
  emitted_events:
    - lex.transfer_held
```

## Simulator rules

The simulator should:

- never use production credentials;
- never move production money;
- use isolated tenants/namespaces;
- produce deterministic event traces where possible;
- support seeded randomness when testing probabilistic models;
- record model/policy versions;
- support time travel for expiry/timelock cases;
- support failure injection;
- export replayable evidence.

## SDK design

SDKs should expose institutional types rather than provider wrappers.

Illustrative TypeScript:

```ts
const decision = await chlom.licenses.checkTransfer({
  dlaId,
  recipientId,
  context
});

if (decision.disposition !== "PASS") {
  throw new ChlomDecisionError(decision);
}
```

The SDK must preserve HOLD/DENY semantics.

## MCP/tool design

MCP tools should declare:

- tool identity;
- side-effect class;
- required authority;
- input schema;
- output schema;
- evidence behavior;
- idempotency behavior;
- sandbox availability;
- rollback/compensation behavior.

A tool description is not authorization to execute it.

## Versioning

```text
schema version
API version
policy version
model version
event version
SDK version
```

These should be separately identifiable. Bumping one does not silently bump the others.

## Compatibility

Preferred change types:

- additive optional fields: backward compatible;
- new enum value: requires tolerant readers;
- required-field change: breaking;
- semantic meaning change: breaking even if JSON shape is unchanged.

Semantic drift is more dangerous than syntax drift.

## Webhooks

A webhook event should include:

- event ID;
- event type/version;
- timestamp;
- tenant/org;
- subject reference;
- signature;
- replay protection;
- delivery attempt;
- correlation ID.

Consumers must treat delivery as transport evidence, not institutional state unless they verify the event.

## API quotas/request budgets

Request-budget semantics must be machine explicit and not overloaded. API-level provider quotas remain separate from any CrownThrive-local policy ceiling.

Clients should receive deterministic budget/limit metadata where exposed, and fail closed when the local policy state is unresolved.

## Conformance testing

An implementation claiming CHLOM contract compatibility should pass a defined suite, for example:

```text
CT-CONFORMANCE-IDENTITY
CT-CONFORMANCE-POLICY
CT-CONFORMANCE-DLA
CT-CONFORMANCE-DAIL
CT-CONFORMANCE-LEX
CT-CONFORMANCE-ECONOMICS
CT-CONFORMANCE-CASES
```

Passing a conformance suite proves compatibility with that suite/version, not universal legal compliance.

## Failure injection

The simulator/test kits should test:

- database outage;
- oracle timeout;
- model outage;
- stale evidence;
- webhook duplicate;
- provider partial failure;
- delayed settlement;
- key rotation;
- clock skew;
- unavailable reviewer;
- schema mismatch;
- corrupted evidence digest.

## Golden traces

A **golden trace** is a canonical expected event sequence for a scenario.

```text
request
-> policy.check
-> DLA.transfer_check
-> HOLD
-> case/review requested
-> evidence refreshed
-> policy.check
-> PASS
-> transfer completed
-> DAIL reconciled
```

Golden traces help detect semantic drift across implementations.

## Public examples must be synthetic

Developer examples should use synthetic identities, assets, prices and evidence. Production names, customer data, credentials, secrets or restricted economic terms do not belong in public test fixtures.

## Core invariants

```text
schema shape != semantic authority
API success != institutional PASS
webhook delivery != settlement
retry != permission to duplicate
sandbox != production
test fixture != real evidence
SDK convenience != authority bypass
version bump cannot silently change rights meaning
```

## Current implementation boundary

Canonical JSON schemas, REST/MCP contracts, SDKs, fixture packs and simulators are compatible with the current cloud-first architecture. Protocol-native JSON-RPC, Solidity or Substrate-specific tooling should remain adapters where justified rather than defining the institutional contract.
