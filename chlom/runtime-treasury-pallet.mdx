## Source basis

The recovered Help Center defines the Treasury Pallet as **fee intake, proposals, disbursements and on-chain accounting for transparent budget management**. Historical papers then extend that baseline into Smart Treasury, reserve rules, automated routing and later investment/yield research.

The Treasury Pallet should therefore remain separate from:

- Treasury Routing Pallet — how approved value is allocated/routed;
- Fee Router Pallet — fee-specific splitting;
- Smart Treasury Engine — higher-level policy/orchestration;
- historical Smart DeFi/Capital/Yield — experimental optimization layers.

## Non-purpose

The pallet does not:

- authorize spending merely because funds exist;
- allow AI to move money without adopted authority;
- create investment products;
- make historical token treasury policy current;
- substitute a provider wallet/bank balance for canonical treasury accounting;
- override tax, rights, legal or contract constraints.

An inflow must have:

- source/transaction evidence;
- amount/currency;

- applicable restrictions;
- reconciliation status;
- DAIL receipt.

Provider success is evidence, not final classification.

## Authorization checks

Before disbursement:

1. treasury/object current;
2. authority valid;
3. budget/category available;
4. obligation/right basis valid;
5. currency/unit correct;
6. reserve/minimum controls satisfied;
7. recipient identity resolved;
8. provider destination current;
9. sanctions/risk/professional checks if applicable;
10. timelocks/approvals satisfied;
11. idempotency key unused.

## Accounting equation

A simplified internal consistency relationship is:

```text
book_balance
= prior_book_balance
+ reconciled_inflows
- reconciled_outflows
+ corrections
```

`available_to_authorize` may be lower because reserves and commitments are excluded.

## Reserve model

```text
available = max(0, book_balance - reserved - committed - other_locked)
```

Exact reserve formulas are policy/version controlled and may be restricted.

## Treasury proposals and governance

Historical DAO-era designs used treasury proposals/votes. Current CHLOM can bind a spend request to any authorized governance/approval mechanism without requiring token voting.

## Smart Treasury relationship

```text
Treasury Pallet = canonical treasury state + base controls
Treasury Routing = allocation/routing instructions
Smart Treasury Engine = policy/orchestration/recommendations
provider/bank/wallet = execution adapter
```

AI may recommend; it does not manufacture authority.

## Failure modes

- insufficient available balance -\> HOLD/DENY;
- provider balance mismatch -\> reconcile/HOLD;
- unauthorized recipient -\> DENY;
- budget expired -\> HOLD;
- duplicate payment instruction -\> idempotent refusal/reuse;
- provider success but wrong amount -\> correction/recovery;
- stale FX -\> HOLD or refresh;
- reserve breach -\> DENY/HOLD;
- current legal/professional requirement unresolved -\> HOLD.

## Threat model

- unauthorized spend;
- provider destination substitution;
- balance spoofing;
- double disbursement;
- rounding/currency errors;
- hidden reserve release;
- AI automation overreach;
- stale authority;
- unrecorded manual provider movement;
- provider evidence incorrectly treated as institutional settlement.

## Tests

1. approved spend within available budget -\> execute/reconcile;
2. duplicate idempotency key -\> no second payment;
3. provider outage -\> hold/retry;
4. provider reports amount mismatch -\> unreconciled state;
5. reserve constraint violated -\> reject/hold;
6. recipient alias changes -\> stable party identity remains;
7. AI suggestion without approval -\> cannot execute;
8. historic token treasury proposal -\> not current authority;
9. correction -\> separate correction event;
10. settlement requires provider readback \+ institutional reconciliation.

## Current mapping

Modern CHLOM maps Treasury Pallet semantics to an institutional treasury ledger/control service inside P-11, connected to ThriveEvergreen economic authority, payments/providers, budgets, reconciliation, audit and DAIL.

## Restricted companion

Contains private balances, bank/wallet/provider aliases, budgets, reserve targets, approval matrices, transaction evidence, treasury strategies, tax-sensitive records and protected economic parameters.

## Invariants

```text
balance != spend authority
provider balance != canonical book balance
approval != provider execution
provider success != settlement
AI recommendation != money movement authority
reserve policy change != silent retroactive release
historical token treasury != current treasury rail
```
