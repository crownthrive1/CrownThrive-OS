## Historical purpose

BAMP was the historical CHLOM runtime concept for **mirroring selected attestations or claims between systems** without copying every private evidence object or trusting an external chain/provider blindly.

```text
SOURCE CHAIN / SYSTEM
        |
 attestation / claim
        |
 proof + finality
        |
        v
      BAMP
        |
 validate source / replay / schema / issuer
        |
        v
LOCAL MIRROR RECORD
        |
        +--> policy
        +--> DLA / LEX
        +--> audit / explorer
```

## Mirror is not source authority

```text
mirrored attestation
       !=
local factual truth automatically
       !=
local authority to act
```

BAMP preserves origin and proof. Local CHLOM policy still decides how the imported assertion may be used.

## Selective projection

BAMP's strongest reusable design is **minimal proof portability**.

```text
PRIVATE SOURCE EVIDENCE
         |
     attestation
         |
   minimal claim / digest
         |
         v
      MIRROR
         |
PUBLIC / CROSS-SYSTEM VERIFICATION
```

The mirror should carry only the fields required for the cross-system purpose.

## Schema/version gate

A mirror is meaningful only if the local verifier understands the source attestation schema/version.

```text
source schema known and allowed?
   no -> HOLD
   yes
     |
issuer authorized for claim type?
   no -> DENY/HOLD
   yes
     |
proof/finality/replay checks pass?
   no -> DENY/HOLD
   yes
     |
LOCAL MIRROR VERIFIED
```

## Revocation propagation

If the source attestation is revoked or superseded, BAMP must propagate that change rather than leaving a permanently valid local copy.

```text
SOURCE ATTESTATION A
   |
revoked / superseded
   |
BAMP update
   |
LOCAL MIRROR -> revoked / superseded
```

## Finality and rollback

Source systems can have different finality models. A mirrored claim may remain `candidate` until its source reaches the required finality/confirmation threshold.

If a source later reverses, the local mirror records a correction/revocation chain rather than deleting the imported history.

## Failure cases

### Source attestation valid but issuer not locally trusted for this claim

Keep the mirror as evidence if useful but do not treat it as a locally accepted compliance assertion.

### Source system unavailable

Do not infer current validity if the use case requires live revocation/currentness; apply the configured freshness/HOLD behavior.

### Mirror provider duplicates message

Idempotency prevents duplicate local state or downstream side effects.

### Public mirror leaks private subject fields

Contain/remove projection, preserve incident evidence, correct the public schema and re-certify.
