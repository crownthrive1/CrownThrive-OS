# Wireframe: Embedded License, Status & Entitlement Widgets

## Wireframe identity

```yaml
wireframe_id: WIRE-EMBED-001
source_family: recovered platform-embedded license/status/entitlement widget family
classification: source_grounded_functional_reconstruction
version: 1.0.0
```

## Purpose

This article defines CHLOM's embeddable proof/status surfaces that let a CrownThrive platform or authorized external tenant display a limited, verifiable view of a license, permission, credential, rights state or entitlement without exposing the underlying restricted evidence or giving the host application authority to modify CHLOM state.

## Widget types

### DLA Status Widget

Displays DLA stable public reference/version, lifecycle state, permitted public scope summary, effective term and last verification/currentness. It never exposes private agreement terms merely because the license is active.

### Rights / Scope Widget

Displays approved public-safe rights summary such as permitted medium/channel, territory, term, transfer/sublicense indication and public restrictions. Unknown values render as unknown/HOLD, not global/unlimited.

### Verification / Attestation Widget

Displays approved credential/attestation state, issuer/source class, currentness and verification receipt where permitted. It does not expose private witness or identity documents.

### Entitlement Widget

Displays whether the current subject has an effective entitlement to a defined product/service/content/action, its valid period/cap state and fulfillment/reconciliation status. Provider delivery state remains separate.

## Host integration contract

The host passes a stable widget/object reference and authenticated viewer/context where required. CHLOM returns a role/audience-scoped projection. The embed cannot submit an arbitrary subject/object and receive restricted records outside the caller's scope.

## Public projection

The widget response contains only fields approved for the embed audience. A public website can show a simple `Verified / Active / Expires` state while an authenticated operator surface may receive more detail under policy.

## Tamper resistance

Where a widget is used as a verification surface, signed/attested response metadata or a canonical verification URL/reference can help distinguish current CHLOM state from copied screenshots or stale static markup. Verification UX must still state the observed time/currentness.

## State handling

`ACTIVE`, `HOLD`, `SUSPENDED`, `REVOKED`, `EXPIRED`, `UNKNOWN`, `REDACTED`, `DEPENDENCY_ERROR`. A widget must not keep displaying a stale `ACTIVE` state when mandatory revalidation fails.

## Host actions

Embeds are read/projection-first. Consequential actions such as activate, revoke, transfer, pay, approve or change scope route the user to an authenticated governed workflow rather than being implemented as an unaudited widget callback.

## Privacy/security

- no secrets/tokens in embed markup;
- short-lived audience-scoped access where authentication is needed;
- tenant/object authorization on every read;
- CORS/origin policy as appropriate;
- no protected evidence in client-side payloads;
- no private Fingerprint or model internals;
- cache TTL compatible with revocation/freshness requirements.

## Accessibility

All status widgets expose explicit text and accessible labels; scope/expiry is understandable without hover/color. External embeds support responsive layout and text fallback.

## Tests

Test public versus authenticated projection, revoked DLA after cached ACTIVE, wrong tenant/object, expired entitlement, stale credential, copied/stale embed response, provider outage, unauthorized host origin and screen-reader state.

## Versioning

Widget API/schema and visual component versions are distinct from the DLA/evidence/entitlement objects they render. Host integrations can pin supported widget versions with deprecation/migration policy.
