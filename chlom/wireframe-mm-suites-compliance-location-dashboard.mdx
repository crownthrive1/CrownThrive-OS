# Wireframe: MM Suites Compliance Scorecard & Location Dashboard

## Purpose

This wireframe defines the MM Suites / Suite Pro location-level operating dashboard described across recovered MM Suites and CHLOM materials. It is the local operational projection of CHLOM's six functions, not a generic beauty-suite CRM screen.

## Header and location identity

Display canonical location/suite ID, brand/location name, operator/owner, current operating state, jurisdiction, provider aliases, last evidence refresh, current certification/assurance state and any active HOLD/suspension.

## Operator and credential panel

Show assigned professionals/operators, credential types, currentness/expiry, required training, role/authority state and missing evidence. A green booking provider status cannot override expired or missing mandatory credentials.

## Compliance scorecard

The scorecard lists applicable Compliance Packs/controls individually:

```text
Control
Current result: PASS | HOLD | DENY
Evidence freshness
Owner / remediation task
Last evaluation
Next review
```

A headline percentage may be secondary analytics only; it can never hide a DENY or mandatory HOLD.

## Booking/service readiness

A service is shown as bookable/operable only when relevant location, operator, service-right/policy and provider dependencies satisfy their required states. The page distinguishes institutional readiness from external marketplace/calendar availability.

## Evidence and audit

Compose Evidence Checklist, Evidence Reference Panel, DAIL Timeline, Access/Audit Log and current audit package. Restricted documents remain behind role-scoped custody references.

## Incident and remedy panel

Show open incidents/cases, facility or operator holds, deadlines, assigned reviewers, authorized remedies and appeal/review state. Case existence is procedural and not itself an adverse conclusion.

## Local economic panel

Show local approved economic schedules, bookings/transactions as reconciled events, commissions/royalties, refunds, settlement mismatches and provider evidence. ThriveEvergreen/economic authority remains separate from payment-provider execution.

## Training and ecosystem participation

Show CrownThriveU training/certificates and any approved CrownRewards, CrownFluence, affiliate, ambassador or AdLuxe program participation. Each program has its own eligibility and agreement state.

## Layout

```text
LOCATION HEADER
[readiness] [credential alerts] [active holds]

COMPLIANCE SCORECARD        BOOKING/SERVICE READINESS
EVIDENCE & AUDIT            INCIDENTS / REMEDIATION
LOCAL ECONOMICS             TRAINING / PROGRAMS
PROVIDER HEALTH             DAIL / CHANGE HISTORY
```

## Accessibility

Scorecard state uses labels and reason text, not color alone. Credential expiry and incident deadlines have accessible dates. Charts have table equivalents.

## Tests

Test expired operator credential, location HOLD, provider outage, all-controls PASS, one hard DENY among many PASS, missing evidence, multi-operator location, revenue mismatch and restricted document access.

## Versioning

Location, operator, control, economic and provider states remain independently versioned. The wireframe composes them without creating a new source of truth.
