# CHLOM Historical Runtime Pallet Contract

## Canonical record

```yaml
artifact_id: ct.chlom.historical-runtime-pallet.contract.v1
namespace: historical_runtime_pallet
source_lineage:
  - recovered CHLOM Help Center pallet/module inventory
  - CHLOM Technical Blueprint
  - Building and Understanding the CHLOM Metaprotocol
  - CHLOM Genesis Volume
current_status: reconstructed_source_grounded
public_projection: public_safe
production_claim: prohibited_without_runtime_evidence
```

## Purpose

Historical CHLOM sources use **pallet** in the Substrate sense: a runtime module with state, extrinsics/calls, events, permissions and protocol-level behavior. These modules contain valuable architecture and IP even though the current CHLOM implementation plan is cloud-first and does not presume a dedicated Substrate chain is deployed.

Every recovered runtime pallet therefore receives its own article under one rule:

```text
PRESERVE ORIGINAL MODULE
        |
        v
EXTRACT STATE / CALLS / EVENTS / INVARIANTS
        |
        v
CLASSIFY HISTORICAL ASSUMPTIONS
        |
        v
MAP TO CURRENT SERVICE / REGISTRY / WORKFLOW
        |
        v
RETAIN FUTURE RUNTIME ADAPTER
```

## Namespace separation

```text
historical_runtime_pallet
          !=
current_capability_pallet P-01 ... P-12
```

The same word `pallet` cannot be used without namespace in machine records.

## Historical pallet article requirements

Each runtime pallet article should include:

- exact recovered title/name;
- source-era purpose;
- historical state model;
- historical calls/extrinsics where supported;
- event model;
- actors/permissions;
- invariants;
- security/failure cases;
- relationships to other runtime modules;
- current cloud/service mapping;
- preserved future decentralized adapter;
- public/restricted split;
- maturity/implementation evidence;
- version/supersession behavior.

## Runtime-to-current mapping

```text
HISTORICAL PALLET
      |
      +--> current service
      +--> current database/registry
      +--> current policy engine
      +--> current workflow
      +--> current DAIL events
      +--> future chain/runtime adapter
```

A historical pallet can map to multiple modern services. A modern service can implement the institutional semantics without reproducing the original chain design.

## Historical state

Historical pallet state can be reconstructed from source fields such as:

```text
storage maps
status enums
role sets
configuration parameters
proof/attestation references
license IDs
policy IDs
proposal IDs
settlement records
```

If exact storage names are not recovered, the article must say so rather than inventing Rust storage declarations.

## Historical calls

Calls/extrinsics are recorded only when supported by source. Otherwise the article uses a capability-level operation name and marks it as reconstructed.

```yaml
operation:
  name: issue_license
  provenance: recovered_source_pattern|reconstructed_from_requirements
```

## Event discipline

Historical on-chain events are mapped to modern canonical events without claiming the exact event name existed in source if it did not.

```text
historical event intent
        |
        v
current ct.* event contract
```

## Permission discipline

Historical source assumptions such as root origin, council, validator, issuer or governance token are preserved as source-era authority models. Current authority is resolved through current CHLOM roles, delegated authority and P-02 policy.

```text
historical Root / Council
       !=
current founder / institutional authority automatically
```

The mapping must be explicit.

## Token/chain discipline

A historical pallet may mention:

- CHLOM Coin;
- CHM;
- staking/slashing;
- NPoS validators;
- on-chain escrow;
- smart contracts;
- cross-chain bridges.

These are historical architecture unless current runtime evidence separately proves activation.

## DAIL mapping

Current DAIL replaces the need to describe every evidence function as a blockchain write.

```text
historical immutable event
          |
          v
current DAIL event/evidence/correction lineage
          |
          +--> optional external cryptographic anchor later
```

DAIL is the **Decentralized Autonomous Information Ledger** in current CHLOM.

## Current service maturity

Every runtime pallet article carries two maturity tracks:

```yaml
historical_source_recovery: title_only|partial_body|substantive_body|complete_source
current_semantic_implementation: not_mapped|mapped|specified|prototype|test|staged|production|maintained
future_runtime_adapter: research|candidate|deferred|not_planned
```

This prevents `source recovered` from becoming `code deployed`.

## Security boundary

Public runtime articles may include:

- purpose;
- state machine;
- public-safe operations;
- public-safe schemas/events;
- threat categories;
- future/current mapping.

Restricted companions may include:

- exploit-sensitive logic;
- threshold values;
- protected algorithms;
- unreleased contract code;
- private audit findings;
- infrastructure topology;
- secrets references.

Raw credentials/private keys are never stored in public or ordinary restricted documentation.

## Versioning

Historical source meaning does not change when current mapping changes.

```text
Historical Pallet Source Record v1
            |
            +--> Current Mapping 2026-v1
            +--> Current Mapping future-v2
```

## Core invariants

```text
pallet title != pallet code recovered
pallet design != deployed chain
historical Root != current authority
historical token role != live token
historical event != DAIL event name automatically
current service mapping != source rewrite
future adapter != roadmap commitment
Substrate pallet != P-01..P-12 capability pallet
```

## Completion rule

The runtime-pallet recovery program is complete only when every recovered pallet/module title has an individual article and one of these states:

```text
source_grounded
partial_source_reconstruction
source_not_located_but_title_preserved
founder_adjudication_pending
superseded_current_mapping
```

No pallet remains only as a bullet in an atlas.
