## Historical purpose

The Metadata Registry Pallet provided a protocol-level source for structured metadata associated with CHLOM assets, licenses and marketplace objects.

```text
ASSET / LICENSE
    |
metadata schema
    |
metadata record / digest / URI
    |
HISTORICAL METADATA REGISTRY
    |
    +--> DLA
    +--> LEX
    +--> indexers / explorers
```

## Metadata is descriptive, not sovereign rights

```text
metadata says owner = X
       !=
verified ownership automatically
```

P-03 rights evidence remains authoritative for rights/licensing semantics.

## Schema versioning

Metadata meaning depends on schema version.

```text
schema v1
  |
breaking field/meaning change
  |
schema v2
```

Historical records retain the schema that governed their creation.

## Immutable reference versus mutable projection

Historical blockchain designs could point to immutable hashes/IPFS/Arweave content while allowing the registry to update the active reference.

Current CHLOM preserves the same separation:

```text
source/master evidence
      |
versioned metadata record
      |
current public projection
```

A public projection can change without deleting prior metadata versions.

## DLA relationship

DLA metadata can include:

- license type;
- asset reference;
- issuer/holder public refs;
- scope;
- validity;
- transferability/sublicensing;
- agreement/policy refs;
- status.

Metadata mirrors current license semantics but does not independently grant them.

## LEX relationship

LEX listings consume approved public-safe metadata. Listing presentation must not reveal restricted license terms or evidence.

## P-04 media relationship

Media metadata includes master/edition identity, creators, format, release state and rights references. Provider metadata remains an alias/projection.

## URI/provider independence

```text
canonical metadata ID
      |
      +--> object store URI
      +--> IPFS CID historical/future
      +--> provider URL
      +--> public API projection
```

Changing storage/provider should not change the canonical record ID.

## Integrity

Metadata can carry content digests to detect substitution.

```text
stored_digest == digest(retrieved_content)?
  yes -> integrity check passes
  no  -> HOLD / corruption investigation
```

The algorithm/digest format is implementation/version specific.

## Security threats

- metadata substitution;
- schema confusion;
- poisoned external URI;
- private-data leakage;
- malicious HTML/content;
- rights misrepresentation;
- provider URL takeover;
- digest/encoding mismatch.

## Public / restricted split

Public-safe:

- approved descriptive metadata;
- schema definitions;
- public digests/IDs;
- public status.

Restricted:

- private contract/evidence metadata;
- source-file locations;
- security-sensitive URIs;
- unpublished asset metadata;
- internal labels/notes.

## Invariants

```text
metadata != rights
metadata != agreement
provider metadata != canonical metadata
URI != canonical identity
schema change != silent semantic change
public metadata != all metadata
historical registry design != deployed runtime
```

The Metadata Registry Pallet is preserved as historical runtime architecture and maps to current versioned metadata/schema registries supporting P-03 rights/licensing and P-04 media/IP.
