## Purpose

RSE models royalty obligations that accrue over **events or time** and converts them into claimable/payable obligations according to exact rights/agreement/schedule versions.

```text
QUALIFYING RIGHTS-BASED EVENT
          |
          v
ROYALTY SCHEDULE VERSION
          |
          v
RSE ACCRUAL
          |
          +--> beneficiary balances/obligations
          +--> HOLD/dispute state
          |
          v
BATCH / DISTRIBUTION AUTHORIZATION
          |
          v
PROVIDER EXECUTION
          |
          v
P-11 RECONCILIATION / SETTLEMENT
```

## Rights prerequisite

```text
royalty event requires valid rights/agreement basis
```

RSE cannot manufacture a beneficiary/right because a usage/payment event exists.

## Event-driven accrual

```text
accrual_total = Σ royalty(event_i, schedule_i)
```

Each event retains its qualifying evidence and schedule version.

## Time-driven accrual

A generic model:

```text
accrued(t) = ∫ rate(τ) dτ over authorized interval
```

The actual rate function/units are schedule-specific and not set here.

## Claimable versus payable

```text
accrued
  -> eligible/claimable
  -> authorized payable
  -> provider executed
  -> reconciled/settled
```

These are distinct states.

## Micro-accrual batching

Current payment providers may not support efficient real-time micro-transfers. RSE can ledger small accruals and batch settlement under an approved threshold/schedule.

```text
streaming accounting != continuous provider payment
```

Batch/minimum thresholds are restricted/current economic configuration.

## Beneficiary changes

If rights/agreements change:

```text
old events -> old effective beneficiary/schedule version
new events -> new version
```

Do not retroactively redirect settled royalties unless a governed correction/remedy requires it.

## Dispute/HOLD

Rights, attribution or payment disputes can pause distribution while accrual treatment follows agreement/policy.

```text
stream ACTIVE
  |
dispute opens
  |
HOLD distribution / possibly accrual depending rule
  |
decision
  |
resume / correct / terminate
```

## Failure modes

### Duplicate usage event

Idempotency prevents duplicate accrual.

### Rights revoked after accrual but before payout

Agreement/policy governs HOLD/correction; do not automatically pay or erase.

### Provider minimum exceeds claimable amount

Remain accrued/claimable or batch per schedule; do not call settled.

### Currency/provider mismatch

HOLD distribution until reconciled.

### Historical rate discovered in old paper

Record historical lineage only, not current schedule.
