## Purpose

The Licenses Overview gives an authorized actor a current, filterable portfolio of license/DLA records without reducing a complex rights state to a single `active` checkbox.

```text
ROLE / SCOPE
   |
   v
AUTHORIZED LICENSE SET
   |
   +--> active
   +--> pending
   +--> HOLD
   +--> expiring
   +--> suspended/revoked
   +--> disputed
```

## Role scoping

The overview can show different sets:

- licenses held by actor;
- licenses issued/stewarded by actor;
- organization portfolio;
- reviewer queue;
- case-related licenses;
- public verification subset.

Every view states its scope.

## Summary counts

Counts require exact definitions:

```text
Active = current status ACTIVE and visible to role at as_of
Expiring = active and expiration falls in selected presentation window
HOLD = current state blocks requested/defined action
```

Do not double-count a record across summary cards unless UI explicitly explains overlapping categories.

## Table columns

Recommended core columns:

```text
DLA ID
```

Sensitive identity/economic fields are role/classification gated.

## Status semantics

```text
DRAFT

PENDING_REVIEW
ACTIVE

SUSPENDED

```

The exact status enum is implementation-version controlled; historical source labels remain mapped rather than silently discarded.

## Row status

A row can show multiple orthogonal states:

```text
DLA: ACTIVE
Evidence: STALE
Transfer eligibility: HOLD
Provider projection: MISMATCH
```

Do not force all dimensions into one misleading color badge.

## Bulk actions

Bulk actions are restricted because rights actions are high impact. Allowed examples can include export/assign-review rather than mass revocation by default.

Any material bulk action requires:

- exact selected set;
- authorization;
- policy preflight;
- confirmation;
- idempotent execution;
- per-object results;
- DAIL receipts.

## Saved views

A saved view stores filters/layout, not a frozen rights state. Reopening re-queries current canonical data.

## Expiration management

Selecting `Expiring` can show:

```text
DLA
expires at
renewal permitted?
required evidence
current holder/issuer state
renewal candidate status
```

The list cannot assume renewal is permitted.

## HOLD queue

HOLD rows expose safe reason class and next step:

```text
DLA-123 | HOLD | rights evidence conflict | Review case C-55
```

Protected fraud/security reasons can use generalized reason classes.

## Stale/readback indicator

Each table fetch has an `as_of` and service/readback state. If a dependent provider/index is stale, the UI marks the affected field/row rather than pretending all values are current.

## Search

Search results can match DLA ID, asset/public title, permitted participant identifier, agreement/public tag and provider alias when authorized.

Search index results are revalidated on detail/material action.

## Export

Exports are classified. Public-safe export differs from internal rights/evidence export.

```text
public export -> safe metadata
internal export -> role-authorized fields
restricted export -> explicit elevated permission / audit
```

## Empty states

- no licenses in scope;
- no matches for filters;
- data unavailable/syncing;
- role lacks visibility.

These are distinct states.

## Error states

- rights service unavailable;
- filter/schema mismatch;
- evidence currentness unavailable;
- provider/index mismatch;
- tenant context unavailable;
- permission change during session.

## Data dependencies

- P-01 actor/organization scope;
- P-03 DLA/right graph;
- P-02 policy/HOLD state;
- case service;
- Evidence Vault/DAIL;
- search/indexer;
- provider projections.

## Events

Material list-level operations can reference:

```text
ct.dla.review.assigned.v1
ct.dla.export.generated.v1
```

Ordinary views/search are UX analytics only if intentionally collected.

## Accessibility

- table headers/sort announced;
- filters labeled;
- status text plus icons;
- horizontal overflow manageable;
- mobile card view retains DLA ID/status/scope/action;
- row menus keyboard accessible.

## Restricted companion

Can include private rights/economic columns, reviewer queues, protected conflict indicators, provider reconciliation details and administrator-only bulk operations.

