# Wireframe: Treasury, Revenue & Royalty Console

## Wireframe identity

```yaml
wireframe_id: WIRE-ECON-001
source_family: recovered treasury/revenue/royalty statement and routing interfaces
classification: source_grounded_functional_reconstruction
version: 1.0.0
```

## Purpose

This console composes CHLOM's economic control surfaces into one operator/reviewer view while keeping schedule definition, calculation, provider execution and final settlement as separate states.

## Economic-event header

Display stable economic event/obligation ID, source transaction/license/campaign, gross or defined basis, currency/unit, current schedule version, expected total, settlement status and any HOLD/reversal.

## Schedule and split panel

Show Economic Schedule identity/version, gross/net basis, authorized deductions, Split Tree, recipient shares, floors/caps/reserves, rounding policy and effective window. Private commercial terms are role-scoped/redacted.

## Calculation panel

Expose governed calculation result, formula/model version, normalized inputs, evidence refs, unit/precision, rounding/residue, review state and DAIL receipt. A provider balance is not substituted for the calculation.

## Obligation / statement panel

Show per-recipient royalty/commission/treasury obligations, calculated amount, hold/reserve amount, due/effective state and statement status. Calculated earnings remain distinct from paid/settled amounts.

## Provider execution panel

Display provider/payment/payout aliases, normalized event status, provider amount/currency, execution time, fees observed and authentication/currentness state. Provider events remain external execution evidence.

## Reconciliation panel

Compose expected versus provider result, variance, duplicate/replay state, rounding review, partial settlement, refund/reversal and HOLD\_MISMATCH. Mismatch investigations preserve both expected and observed values.

## Treasury panel

Show approved treasury categories/weights, reserve target/current balance, contribution/overflow calculation and actual movement/reconciliation where authorized. Historical Smart Treasury/token research is not presented as live token economics unless separately activated.

## Correction and reversal

Refunds, chargebacks, clawbacks, schedule corrections and source-event reversals create explicit adjustment/correction chains rather than editing the historical statement to match the provider.

## Layout

```text
ECONOMIC EVENT HEADER
SCHEDULE / SPLIT TREE      GOVERNED CALCULATION
RECIPIENT STATEMENTS       PROVIDER EXECUTION
RECONCILIATION             TREASURY / RESERVES
REFUNDS / REVERSALS        DAIL / CORRECTIONS
```

## Authority boundary

The console cannot edit rates, move funds or approve deductions solely because the operator can view them. Schedule adoption and execution pass their own authority/approval workflows.

## Tests

Test full match, partial settlement, wrong recipient, provider fee disagreement, rounding residue, refund, schedule boundary, reserve target, private terms redaction, duplicate provider event and cross-tenant economic data.

## Versioning

Schedule, calculation, provider-adapter and reconciliation versions are separately preserved so a historical statement can be reproduced.
