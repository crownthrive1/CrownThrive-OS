## Research purpose

The bridge research asks how a CHLOM rights/license/compliance claim created or observed in one ledger/system can be carried to another environment without allowing the transport layer to create new rights or bypass local policy.

```text
SOURCE SYSTEM / CHAIN
      |
      v
source event / claim / proof
      |
      v
bridge verification + replay protection
      |
      v
normalized CHLOM remote claim
      |
      v
LOCAL rights / policy / authority evaluation
      |
      +--> ACCEPTED CANDIDATE
      +--> HOLD
      +--> DENY
      |
      v
local DAIL / entitlement / adapter action if authorized
```

## Core invariants

```text
remote finality != local authority
remote asset representation != local source rights
bridge message != DLA
remote payment != local settlement truth
```

## Source claim types

A bridge might carry carefully defined claims such as:

- asset identity/provenance reference;
- DLA/license state reference;
- credential/attestation result;
- settlement/economic receipt;
- governance/proposal result;
- proof/anchor receipt;
- revocation/suspension update;
- other typed interoperable claims.

Each claim type needs an explicit schema and local interpretation policy.

## Source-system registry

The destination must know which source systems/adapters are recognized, what their finality/evidence model means, accepted message/proof versions, current security status and which claim domains they can support.

Being an approved source for one claim type does not make the system authoritative for all rights, identity or economic facts.

## Remote finality

Historical blockchain-oriented research can use light-client/finality proofs or another source-consensus receipt. Current provider/API systems can use signed receipts, authenticated APIs or other evidence. The adapter must state exactly what was verified.

## Replay protection

Each source message/semantic event must be processed at most once for a destination scope. Cross-chain replay, re-submission after adapter restart or duplicate relaying cannot multiply entitlements, license transfers or economic effects.

## Rights conservation

A bridged license/asset claim cannot expand beyond the source rights proved and the destination's accepted interpretation. A wrapped/mirrored representation is an alias/projection; it does not manufacture rights absent from the source chain of title.

## DLA mapping

If a remote claim supports a local DLA action, CHLOM still resolves:

- canonical asset/source rights;
- issuer authority;
- requested scope;
- licensee eligibility;
- current policy/evidence;
- required approvals;
- local lifecycle.

Remote proof can satisfy evidence inputs but cannot skip DLA activation rules.

## Revocation propagation

A bridge architecture must support source-side revocation, suspension, correction or reorg/finality reversal according to the source model. The destination appends a new remote-claim observation and re-evaluates local state rather than deleting the original message.

## Economic settlement

If cross-system messages describe payment/settlement, provider/chain receipts remain evidence. CHLOM reconciles the expected local obligation before marking institutional settlement or entitlement state.

## Failure and emergency handling

Bridge operation needs bounded controls for:

- source finality uncertainty;
- replay or sequence gap;
- invalid/unknown source;
- proof verification failure;
- adapter compromise;
- source reorg/reversal;
- rate/volume anomaly;
- contradictory source claims;
- destination policy mismatch;
- emergency pause/guardian action;
- safe resumption and reconciliation.

Exact protected kill-switch thresholds/implementation remain restricted where applicable.

## Privacy

Cross-system messaging should minimize personal/confidential data. Prefer stable opaque references, commitments, attestations or ZK/public-safe proof receipts over copying raw credentials/contracts across networks.

## Observability

Track source/destination IDs, adapter version, message status, finality/receipt state, replay protection, local disposition, latency, failures and DAIL references. Explorer views are projections and can redact private payloads.

## Threat model

Replay, forged source, compromised bridge key/adapter, chain reorg/finality assumptions, alias collision, double representation, wrapped asset treated as source-right truth, stale revocation, bridge-induced privilege escalation, cross-tenant leak and economic double settlement.

## Tests

Test valid remote claim, unregistered source, replay, source reversal, remote DLA revoked after local observation, cross-tenant alias collision, duplicate economic event, proof failure, bridge outage, emergency pause/resume and provider/chain replacement.
