## Purpose

P-10 is CHLOM's capability container for **institutional memory and operational continuity**. It records what CrownThrive/CHLOM knows, what work was authorized, what changed, where evidence lives, which version is current, what remains unresolved, how work is handed off, and how public documentation is derived from protected source material.

This pallet is the connective operational memory between policy, source files, workflows, Git/Mintlify documentation, provider state, Vault-bound evidence, support and recovery.

```text
SOURCE / DECISION / WORK
          |
          v
CAPTURE + CLASSIFY
          |
          v
CANONICAL RECORD / EVIDENCE
          |
          +--> restricted master / Vault binding
          +--> machine registry
          +--> operational workflow
          +--> public-safe documentation
          |
          v
READBACK / TEST / CERTIFY
          |
          v
DAIL + VERSION + HANDOFF
```

## Source-component interpretation

### Collab Portal

Collab Portal contributes partner/project workspaces, NDAs/briefs/files/milestones/approvals and granular collaboration access. A collaborator's portal access is not global institutional authority.

### ThriveSupport

ThriveSupport is the institutional written-memory/support surface: rules, governance posture, corridors, runbooks, procedures, incident/security posture, versioned frameworks and public documentation.

### ThriveTools

ThriveTools contributes utility/tooling surfaces and operational aids. A tool output is evidence/input, not automatically canonical institutional state.

### Ops Oasis

Ops Oasis represents operational coordination/work management where used. Provider/workspace task state must be reconciled to institutional evidence rather than treated as the sole source of truth.

### ThriveRelay

ThriveRelay contributes relay/integration/automation workflow capability. Messages/automations must remain idempotent, purpose-scoped and evidenced.

### SuiteDash portal

SuiteDash and similar client/partner portals can act as provider adapters for projects, CRM/portal interactions, files, tasks and collaboration; provider IDs remain aliases.

## Capture

Capture means preserving the originating evidence before normalization destroys context.

Examples:

- uploaded source file;
- founder decision;
- provider readback;
- email/thread relevant to a decision;
- code/PR/workflow result;
- screenshot/provider evidence;
- generated paper or model;
- meeting/partner artifact;
- incident evidence.

## Classification

Every captured object receives an information class before broad propagation.

```text
PUBLIC
INTERNAL
RESTRICTED
VAULT-BOUND / SECRET-REFERENCE
LEGAL/PROFESSIONAL REVIEW REQUIRED
HISTORICAL / SUPERSEDED
```

Classification controls projection. It does not change source ownership.

A canonized record can preserve multiple contradictory sources until adjudicated.

## Protection

Protection routes material according to sensitivity.

```text
SECRET VALUE
   -> approved secret store

RESTRICTED DOCUMENT / MASTER
   -> governed private repository / Drive custody

PUBLIC-SAFE PROJECTION
   -> public GitHub / Mintlify

EVIDENCE LINEAGE
   -> DAIL / registry references
```

P-10 explicitly prevents public documentation from becoming a secret store.

## Certification

Certification records that a defined artifact/process passed specified controls at an exact version/head. It does not create broader authority than the certification scope.

## Handoff

Handoff packages context so another authorized actor/agent can continue without reconstructing intent.

A handoff should include:

- objective;
- current exact state/version;
- completed work;
- open gaps;
- authority constraints;
- source/evidence locations;
- validation status;
- next dependency;
- rollback/recovery information.

## Source hierarchy

P-10 preserves a controlled source hierarchy rather than allowing the newest-looking timestamp to overwrite higher-quality evidence.

```text
verified current institutional state / founder adjudication
                 |
verified runtime/provider readback within scope
                 |
adopted policy / current technical build pack
                 |
source-era paper / prospectus / master document
                 |
reconstructed title / partial source
                 |
unverified inference
```

Exact precedence depends on the question; the hierarchy never justifies fabricating a missing source.

## Current private/public continuity rule

```text
SUPABASE VAULT
   secret values / protected runtime config

GOOGLE DRIVE / PRIVATE REPOSITORY
   governed human-readable restricted masters and recovery artifacts

PUBLIC GITHUB + MINTLIFY
   public-safe architecture / schema / status / docs
```

P-10 should never publish a secret simply because a public article needs to reference the existence of a credential or integration.

## File/body integrity

## Operating procedures

### New institutional asset

1. capture source;
2. assign stable asset/record ID;
3. classify confidentiality;
4. preserve source custody/digest where available;
5. reconcile current/historical meaning;
6. register dependencies;
7. route restricted/private master;
8. publish public-safe projection if allowed;
9. wire workflows/code/agents;
10. validate/read back;
11. record certification/DAIL.

### Documentation correction

1. identify affected statement/source;
2. preserve prior version;
3. record correction authority/evidence;
4. update canonical interpretation;
5. update dependent pages/registries;
6. run link/body/security/reconciliation tests;
7. emit correction lineage.

### Provider migration

1. inventory canonical records/provider aliases;
2. export controlled data;
3. freeze high-risk writes if required;
4. migrate to certified adapter;
5. read back canonical objects;
6. reconcile differences;
7. preserve old provider evidence;
8. update documentation/registry.

### Recovery

Recovery is verified through readback/round-trip, not merely by existence of a backup artifact.

## Failure modes

### Public article contains restricted detail

**Response:** contain/remove public exposure, preserve incident evidence, restore public-safe version, review source/projection controls.

### Editor nav exists but body missing in Git

**Response:** fail documentation certification, restore body from source/session/verified predecessor, then rerun exact-head checks.

### Provider task says complete but change not live

**Response:** task state is not runtime readback; keep institutional state unresolved until verified.

### New source contradicts current page

**Response:** classify conflict, update source lineage/adjudication queue, do not silently normalize.

### Historical article mistaken for current production

**Response:** add/strengthen current-vs-historical boundary and maturity status.

### File exists only in chat

**Response:** capture into institutional custody/register; do not leave canonical IP solely in conversation history.
