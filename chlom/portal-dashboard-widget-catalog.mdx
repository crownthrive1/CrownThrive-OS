# CHLOM Portal, Dashboard and Widget Catalog

Legacy CHLOM, MM Suites, MVP and Help Center sources describe many dashboards, wireframes, scorecards and widgets. Phase 2.95 normalizes these into **role surfaces composed from reusable components**.

## Recovered named surface families

- DLA dashboard for issuers, holders and validators;
- Fingerprint Management Dashboard;
- historical DAL / Distributions Authority dashboard;
- CHLOM LEX marketplace UI/UX and license-exchange wireframes;
- compliance scorecards and location dashboards in MM Suites architecture;
- validator/oracle monitoring and simulation interfaces;
- governance/council proposal and voting views;
- evidence/audit/case review views;
- treasury/revenue/royalty statements and routing views;
- API/developer portal and test/sandbox surfaces;
- MVP widgets and TV/ecosystem widget operations;
- platform-embedded license/status/entitlement widgets.

## Role compositions

**Founder/Holdings** gets portfolio, risk, authority, capital, incident and system-health compositions.

**CHLOM Steward/Reviewer** gets rights, policy, evidence, approval, case and remedy compositions.

**Licensor/Rights Holder** gets asset, license, offer, royalty and dispute compositions.

**Licensee/Operator** gets permissions, conditions, evidence tasks, renewal, payment and support compositions.

**Developer** gets apps/clients/scopes, sandbox, API docs, events, logs, quotas and certification status.

**Suite Pro/MM Suites Operator** gets credentials, location/suite state, booking, compliance scorecard, local revenue, campaigns and training.

**Affiliate/Ambassador** gets approved offers, links, conversions, disclosure/training, commission and payout state.

**Publisher/Advertiser** gets property/inventory, creative rights, campaign status, delivery, billing and measurement.

## Registry fields

Each surface/widget receives `surface_id`, owner platform/pallet, roles, capabilities, required scopes, data classification, API dependencies, event subscriptions, version, implementation state, accessibility state and embed policy.

## Phase 3 engineering rule

Do not begin by coding hundreds of pages. Build a governed component library and compose surfaces by role. A single evidence timeline, rights card, approval panel or payout statement should be reusable across Virality Music, MM Suites, Locticians, AdLuxe, CrownThriveU and external CHLOM tenants when their policies allow it.
