## Historical purpose

The Oracle Pallet was the historical runtime boundary through which off-chain facts—sanctions data, identity status, market/risk data, regulatory feeds or AI outputs—could become consumable by CHLOM's deterministic on-chain modules.

```text

      +--> source A
      +--> source B
      +--> source C

      v

      |

      |
      v
ORACLE PALLET
      |
      +--> Policy
      +--> DLA / LEX
      +--> Risk
      +--> Treasury
```

## Oracle fact versus truth

An oracle submission is evidence from a source.

```text
source report
  !=
objective truth
  !=
authority to take arbitrary action
```

CHLOM therefore separates source identity, freshness, corroboration and policy consequences.

## Source registry

Oracle sources should carry:

- stable source identity;
- approved scope/data types;
- authentication/signature method;
- freshness expectation;
- reliability/assurance state;
- provider aliases;
- suspension/revocation state.

Source registration does not mean every observation is accepted.

## Freshness

```text
observation_age = now - observed_at
```

If the applicable policy requires `observation_age <= max_age`, stale data produces HOLD/requery rather than silent PASS.

The actual maximum age is data/policy specific.

## Quorum / aggregation

Historical Oracle Lattice concepts use multiple sources to reduce dependence on a single provider.

A generic median model for numeric observations is:

```text
aggregate = median(x_1, x_2, ..., x_n)
```

A generic weighted model is:

```text
aggregate = sum(w_i * x_i) / sum(w_i)
```

These are public-safe algorithm families, not adopted production weights.

## Quorum gate

```text
eligible sources >= required quorum?
   no -> HOLD
   |
  yes
   v
observations fresh?
   no -> HOLD
   |
  yes
   v
conflict within tolerated rule?
   no -> HOLD / review
   |
  yes
   v
aggregate / accepted observation
```

## Non-numeric evidence

For sanctions, credential or regulatory claims, aggregation can mean corroborated claims rather than arithmetic averaging.

```text
source A says X
source B says X
source C says not-X / unavailable
     |
policy-specific confidence / review
```

## Failure cases

### One source unavailable

Use applicable quorum/freshness policy; do not invent data.

### Two sources conflict materially

HOLD high-impact decisions or route review rather than selecting preferred data silently.

### Source changes historical record

Preserve original observation and new/corrected source evidence; propagate correction through DAIL where necessary.

### AI source produces unexpected risk spike

Treat as input to P-02/AIE/ACE review; do not automatically punish subject.

## Security threats

- source compromise;
- forged submissions;
- Sybil sources controlled by one actor;
- stale replay;
- data poisoning;
- front-running/manipulated market values;
- source collusion;
- hidden provider dependency;
- unit/scale mismatch.

## Public / restricted split
