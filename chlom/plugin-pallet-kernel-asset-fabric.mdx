# Plugin–Pallet–Kernel Asset Fabric

**State:** controlled-test candidate catalog.  
**Catalog:** 5,760 deterministically materialized candidate records.  
**Pallets:** 12.  
**Capability families:** 120.  
**Asset types:** 12.  
**Deployment profiles:** 4.  
**Dependency edges:** 8,640.

The Asset Fabric converts CrownThrive's existing institutional IP into deterministic, interoperable package candidates without confusing a package projection with a new independent source-IP claim.

## Formula

`12 pallets × 10 capability families × 12 asset types × 4 profiles = 5,760 candidates`

The asset types are plugin, pallet bundle, kernel, executable, script, skill, prompt, MCP tool pack, API adapter, event handler, schema contract, and test suite.

The deployment profiles are internal controlled, service runtime, edge/serverless, and customer package.

## Package dependency rules

- plugins depend on a pallet bundle, MCP tool pack, and test suite;
- pallet bundles depend on a kernel, schema contract, and test suite;
- executables depend on a kernel, script, and test suite;
- API adapters depend on a schema contract, event handler, and test suite;
- MCP packs and event handlers depend on schema contracts and tests;
- skills depend on prompts and tests.

Dependency references are stable asset IDs and are validated against the complete catalog.

## Validation state

A complete deterministic materialization verifies:

- 5,760 unique asset IDs;
- 12 pallets;
- 120 pallet-scoped capability families;
- 12 asset types;
- four deployment profiles;
- 8,640 dependency edges;
- owner/verifier separation;
- SHA-256 contract and package digests;
- no forbidden secret/private-field keys;
- no checkout, entitlement, provider write, D3, or sovereign-vote activation.

Independent scrutiny returns `PASS_WITH_CONTROLLED_TEST_HOLDS`. Every record remains a specified candidate until applicable rights, security, tests, custody, runtime, accessibility, fulfillment, and independent-verification gates pass.

## Public/private boundary

Public-safe records expose IDs, versions, classifications, lifecycle state, dependency IDs, owner/verifier identities, and cryptographic digests.

Protected kernels, scripts, prompts, credentials, private identities, implementation bodies, and commercial calibration remain restricted or Vault-bound.

## Promotion boundary

A generated record is not production code, a deployed plugin, a tested executable, a rights-cleared product, a live entitlement, a provider-write grant, or a new sovereign authority.

Promotion requires exact evidence and independent verification. The repository stores the compact source matrix, generators, contracts, and cryptographic receipts; expanded records are materialized on demand rather than committed as repository bloat.
