## Purpose

CSN combines computational assistance with accountable humans.

```text
CASE / QUESTION / SOURCE SET
            |
            v
   RETRIEVAL / SEARCH / AI
            |
  evidence-linked suggestions
            |
            v
      HUMAN SCRIBE REVIEW
            |
   verify / correct / reject
            |
            v
  ATTESTATION / REVIEW OUTPUT
            |
   verifier/quorum if required
            |
            v
       DOMAIN WORKFLOW + DAIL
```

## Core principle

```text
AI accelerates evidence work.
Human authority remains explicit.
```

The network is designed to prevent a common failure mode: AI-generated synthesis being mistaken for source evidence or institutional authority.

## Evidence-grounded output

A CSN output should separate:

```yaml
source_facts: source-linked observations
model_inferences: clearly labeled inference
human_assessment: Scribe-reviewed interpretation
unknowns: unresolved gaps
conflicts: conflicting sources
recommended_next_step: non-authoritative suggestion unless separately authorized
```

## Retrieval contract

The system should prefer explicit source references and quote/claim boundaries rather than model memory.

```text
request
 -> retrieve authorized corpus
 -> rank/reconcile sources
 -> extract with provenance
 -> model synthesis
 -> human verification
```

If the source does not support a claim, the output should say so.

## Human review

Human review is substantive, not a ceremonial checkbox. The assigned Scribe must be able to:

- inspect relevant source material;
- reject unsupported model output;
- identify uncertainty;
- correct entity/time/version errors;
- disclose conflicts;
- escalate when professional authority is needed.

## Authority boundaries

```text
model != Scribe
Scribe != verifier automatically
verifier != final governance/legal authority automatically
```

CSN can support high-impact workflows but cannot bypass their authority gates.

## Confidentiality

Restricted-source retrieval should use least privilege. Model/provider terms and data-handling capability must be appropriate to the information class.

Public outputs should never reveal:

- secrets/credentials;
- private fingerprints/biometric evidence;
- private case/customer data;
- trade-secret algorithms/thresholds;
- unpublished contracts/rights evidence;
- protected source payloads.

## Model hallucination handling

If an AI-generated statement lacks a source:

```text
UNSUPPORTED
  -> do not convert to fact
  -> search/retrieve again or mark unknown
```

Repeated unsupported output can trigger model/tool quality review.

## Conflicting sources

CSN should preserve conflict sets:

```text
Source A -> claim X
Source B -> claim not-X
       |
       v
CONFLICT OBJECT
       |
human/domain review
```

No model is allowed to hide a contradiction merely by producing a smooth narrative.

## Uncertainty

Uncertainty should be explicit and scoped. A generic confidence percentage can mislead unless its meaning is calibrated. Use structured states such as:

- source-confirmed;
- source-conflicted;
- inference;
- unresolved;
- professional review required.

## Versioning

Every material output should retain:

- model/tool version;
- retrieval corpus snapshot or source refs;
- prompt/workflow version where relevant and safe;
- Scribe/reviewer identity/role;
- time;
- correction lineage.

Protected prompts/workflows can be stored in restricted custody while the public article exposes only the operating contract.

## Failure modes

- no authorized source access -> HOLD;
- model unavailable -> human/manual route or HOLD according to SLA;
- unsupported claim -> reject/unknown;
- sensitive source sent to unauthorized provider -> security incident;
- human review unavailable -> do not auto-promote output;
- sources conflict -> conflict review;
- model version changed -> prior output remains tied to prior version;
- Scribe exceeds domain/authority -> reject/escalate.

## Threat model

- hallucination;
- prompt injection from source documents;
- data exfiltration;
- training/retention policy mismatch;
- malicious source poisoning;
- model bias;
- reviewer automation bias;
- hidden source omission;
- authority laundering through AI prose;
- stale corpus/version.

## Test vectors

1. answer fully supported by authorized sources -> human can approve within scope;
2. unsupported factual claim -> rejected;
3. conflicting sources -> conflict surfaced;
4. prompt injection in source -> treated as untrusted content, not instruction;
5. restricted source + unauthorized model provider -> blocked;
6. model says PASS but policy/evidence does not -> no action authority;
7. model unavailable -> workflow degrades safely;
8. corrected source -> output re-evaluated/new version;
9. Scribe outside domain -> cannot attest;
10. public projection -> restricted source detail removed while provenance remains safe.

## Metrics

Useful metrics include:

- source-link coverage;
- unsupported-claim rate;
- correction rate;
- human rejection rate;
- conflict-detection rate;
- latency;
- model/provider availability;
- reviewer agreement by task class.

Metrics do not become a universal Scribe trust score automatically.

## Current mapping

Modern CHLOM can implement CSN through approved AI models/search/retrieval tools, source registries, Scribe assignments, review workflows, model governance and DAIL. The architecture is provider-neutral.
