# ROLE-SURF-005 — Developer / Integration Surface

## Institutional identity

```yaml
surface_id: ROLE-SURF-005
role_family: Developer / Integration
classification: governed_role_composition

```

## Purpose

This surface is the canonical developer/operator entry point for building against CHLOM APIs, MCP tools, event streams, schemas, SDK/test kits and provider-neutral adapters. It exposes executable contracts while keeping runtime secrets and protected algorithm internals out of documentation.

## Application and client registry

Compose API Client Status, scopes, environment, tenant ownership, auth method, rotation state and usage/quota. Client credentials never appear after creation except through the approved secret-management mechanism.

## Contract browser

Expose versioned API, event, policy, DLA, evidence, calculation and entitlement schemas. Each contract links to source authority, compatibility/migration notes, implementation state and test fixtures. A schema in docs is not proof the endpoint is deployed.

## MCP and agent interfaces

List registered tools/resources, input/output schemas, side-effect class, authority requirements, idempotency expectations, evidence/DAIL behavior, error taxonomy and environment. Write tools must declare exact confirmation/approval boundaries and cannot manufacture authority from client access.

## Sandbox and simulator

Provide synthetic tenants, example rights graphs, DLA candidates, policy packs, webhook events, payment/reversal fixtures and adverse test cases. Sandbox state must be unmistakably non-production and must never contain copied production secrets or personal evidence.

## Events and webhooks

Compose Webhook Delivery Health, event schema/version, subscriptions, retries, signature/auth method, dead-letter state and semantic idempotency guidance. Provider event delivery is treated as evidence requiring normalization/reconciliation.

## Adapter/dependency health

Use Platform Adapter Health, Provider/Dependency Status and Rate-Limit/Usage Meter so developers can distinguish contract bugs from provider outages, quota limits and schema drift.

## Certification status

A client/integration can show `UNREGISTERED`, `SANDBOX`, `CONFORMANCE_PASS`, `SECURITY_REVIEW`, `HOLD`, `CERTIFIABLE`, or `PRODUCTION_APPROVED` only under the applicable certification workflow. `CONFORMANCE_PASS` is not production authority.

## Protected IP boundary

Developer docs describe interfaces, invariants and safe examples. Proprietary model weights, Fingerprint internals, secret keys, restricted splitter/override algorithms, exploit-sensitive controls and confidential provider credentials remain vaulted.

## Tests

Test wrong scope, expired credential, sandbox/production separation, schema version mismatch, webhook duplicate/replay, adapter outage, rate-limit semantics, cross-tenant client and certification status movement.

## Versioning

Every API/MCP/event/schema surface is versioned. Breaking changes require migration, compatibility, deprecation and continuity handling rather than silent replacement.
