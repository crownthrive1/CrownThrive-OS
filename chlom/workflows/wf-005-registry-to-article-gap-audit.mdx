# WF-005 — Registry-to-Article Gap Audit Workflow

## Workflow identity

```yaml
workflow_id: WF-005
name: Registry-to-Article Gap Audit
classification: canonical_reconstruction_quality_workflow
version: 1.0.0
```

## Purpose

WF-005 enforces the rule that a material CHLOM object cannot be considered institutionalized merely because its name appears in a master catalog or registry. It continuously scans the recovered corpus for **registry-only, paper-only, chat-only, diagram-only and combined-article objects** that still require dedicated articles.

## Audit populations

The audit enumerates at minimum:

- pallet and pallet-container entries;
- runtime modules and engines;
- services and adapters;
- algorithms and pseudocode patterns;
- formulas, models, equations and theorem statements;
- schemas, APIs, MCP tools and event contracts;
- wireframes, portals, dashboards and reusable UI widgets;
- role surfaces;
- workflows, agents and governance controls;
- paper titles, appendices, templates and test vectors;
- proprietary/private vault assets that require public-safe companion records.

## Gap states

```yaml
TITLE_ONLY:
REGISTRY_ONLY:
MASTER_ARTICLE_ONLY:
SOURCE_BODY_ONLY:
CHAT_ONLY:
PRIVATE_ONLY_NO_PUBLIC_COMPANION:
ARTICLE_PARTIAL:
ARTICLE_COMPLETE:
IMPLEMENTATION_MAPPED:
PRODUCTION_VERIFIED:
```

These states are separate; `ARTICLE_COMPLETE` does not imply implementation or production verification.

## Stage 1 — Enumerate named objects

Extract stable names/IDs from registries, source papers, navigation, diagrams, appendices, developer guides and project conversations. Deduplicate aliases only when lineage proves they represent the same object.

## Stage 2 — Crosswalk article existence

For each object, resolve whether a dedicated article exists. A section heading inside a 700-line registry is not a dedicated article. A combined article representing several distinct objects is flagged for decomposition when each object has independent behavior, lineage or engineering value.

## Stage 3 — Score institutionalization priority

Priority increases for:

```text
proprietary/trade-secret lineage
core protocol dependency
pallet/module/engine
formal algorithm or formula
runtime/build dependency
wireframe/component needed for implementation
rights/economic/security consequence
high cross-ecosystem reuse
historical IP significance
```

But low relevance or historical status never authorizes deletion; it only affects sequencing.

## Stage 4 — Create article queue

Generate deterministic article IDs/titles and route each gap through WF-001. Protected gaps also invoke WF-002.

## Stage 5 — Verify decomposition completeness

Use FORM-028 and object-specific requirements to check concepts, inputs/outputs, dependencies, states, invariants, security/privacy, tests and implementation mapping. An article with only a paragraph and no substantive contract remains partial.

## Stage 6 — Re-run after every recovery wave

New source discovery can reveal new objects inside an old paper. WF-005 is therefore recurring: every recovery wave can increase the article denominator. The historical 795-title Help Center count remains a separate recovery baseline and does not cap the institutional corpus.

## No-hallucination rule

An extracted name can create a `TITLE_ONLY` or `SOURCE_NOT_LOCATED` article/reservation. It cannot justify inventing an architecture body the source does not support.

## Tests

Seed known registry-only objects, alias collisions, combined articles, private-only assets, title-only papers, duplicate provider aliases and an old article with a newly recovered appendix; verify each enters the correct gap state.

## Versioning

Object taxonomies and article-completeness requirements are versioned. Historical audit snapshots remain reproducible.
