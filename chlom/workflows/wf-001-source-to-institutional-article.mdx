# WF-001 — Source-to-Institutional-Article Workflow

## Workflow identity

```yaml
workflow_id: WF-001
name: Source-to-Institutional-Article
classification: canonical_reconstruction_workflow
version: 1.0.0
```

## Purpose

WF-001 is the default CHLOM institutionalization path for any substantive object recovered from project conversations, papers, files, source repositories or previous documentation: pallets, pallet containers, modules, engines, formulas, algorithms, theorem statements, schemas, wireframes, portal surfaces, workflows, agents, registries, policies and implementation contracts.

The workflow exists to enforce the founder directive that material CHLOM IP must not remain buried inside a master article, chat or attachment.

## Entry criteria

An item enters WF-001 when there is source evidence that it was developed, specified, named, diagrammed, calculated, governed or materially discussed as a distinct CHLOM object. Historical or deprecated status does **not** disqualify it from institutionalization.

```text
if developed_or_recovered_as_distinct_object:
    institutionalize
```

## Stage 1 — Source capture

Capture source title/identifier, exact source location, date/version if known, supporting excerpts/sections, duplicate/variant sources and confidentiality markers. Do not infer a missing body from a recovered title.

## Stage 2 — Object classification

Assign object family and stable ID namespace where appropriate:

```text
PALLET / CONTAINER / MODULE / ENGINE / SERVICE
ALGORITHM / FORMULA / THEOREM / MODEL
SCHEMA / API / MCP / EVENT
WIRE / UI COMPONENT / ROLE SURFACE
WORKFLOW / AGENT / GOVERNANCE CONTROL
PAPER / APPENDIX / TEMPLATE / TEST VECTOR
```

## Stage 3 — Historical/current separation

Record historical source meaning, current canonical meaning, implementation status and any founder adjudication. Current `DAIL` means **Decentralized Autonomous Information Ledger**. Current `DLA` means **Dynamic Licensing Asset**. Historical meanings remain lineage, not erased text.

## Stage 4 — Public/private classification

Before writing the public article, classify each claim, formula, diagram, pseudocode block and implementation detail as public-safe, internal, restricted, trade secret, credential/secret or legally sensitive. Protected material routes through WF-002.

## Stage 5 — Full article construction

Every article should explain its own title completely: identity, purpose, source lineage, role in architecture, inputs/outputs, states, dependencies, invariants, authority boundary, failure states, data/evidence expectations, public/private boundary, tests, implementation mapping and version lineage where applicable.

A registry entry does not substitute for the article.

## Stage 6 — Dependency wiring

Link the object into relevant CHLOM relationships: pallet/container, engine/service, Six Functions, DAIL, DLA, LEX, Compliance Packs, rights/economic/control planes, UI surfaces, tests and implementation maps. The object must be discoverable from both its family and its dependency graph.

## Stage 7 — Version and correction

If an article already exists, new source evidence creates a versioned update, addendum or superseding interpretation. Do not erase the prior source/interpretation. Use WF-003 for material corrections/adjudications.

## Stage 8 — Verification and publish

Check no unsupported production claim was introduced, protected content is absent from public output, canonical terms are correct, article body is substantive and navigation/links resolve. Publish to the governed documentation branch and record the commit/head.

## Fail-closed rules

```text
missing_source_body -> title/source-not-located record, not invention
historical_design -> not production unless evidenced
protected_detail -> vault, not public paste
unknown_authority -> HOLD
registry_only -> incomplete if material object needs article
```

## Tests

Audit a random sample back to exact source; detect duplicate articles; detect registry-only material assets; detect historical/current conflation; scan for secret/protected detail; verify links/navigation; and confirm current terminology.

## Versioning

This workflow is itself institutional IP. Any change to mandatory stages is versioned and applied prospectively with an explicit reconstruction-policy change record.
