# Wireframe: Historical DAL / Distributions Authority Dashboard

## Wireframe identity

```yaml
wireframe_id: WIRE-DAL-HIST-001
```

## Why this article exists

Recovered CHLOM materials include a named historical **DAL / Distributions Authority dashboard** family. That interface must be preserved as IP lineage without collapsing it into the current DAIL architecture or silently renaming the historical source.

## Historical role

The historical DAL dashboard centered on distribution/attribution authority and downstream economic routing concepts associated with legacy ADE/DAL/treasury architecture. Depending on source version, DAL terminology also appears in other legacy meanings; this page is explicitly the **Distributions Authority dashboard** lineage record.

## Historical functional zones

A source-grounded functional reconstruction includes:

- governed distribution/recipient relationships;
- attributed economic events;
- distribution/split schedule inspection;
- authority or validator/reviewer status;
- queued/processed distribution actions;
- exception/dispute state;
- treasury/provider execution status;
- historical ledger/audit events.

The source corpus does not justify claiming a single final production visual layout where exact screens were not recovered.

## Current mapping

Current CHLOM decomposes these responsibilities into:

```text
DAIL event/evidence lineage
+ versioned Economic Schedule
+ ALG-009 allocation
+ ALG-010 settlement reconciliation
+ Split Tree / Royalty Statement UI
+ authority/approval controls
+ ThriveEvergreen economic activation governance
```

The historical DAL dashboard is therefore not a current standalone authority service unless a future founder/governance decision explicitly reactivates that architecture.

## Public/private boundary

Historical trade-secret splitter/override and economic calibration material remains protected under the private Gold Paper/vault bindings. This wireframe records functions and current mapping only.

## State model

Historical state labels are source-dependent; current reconstruction normalizes safe equivalents such as `PENDING`, `AUTHORIZED`, `HELD`, `EXECUTED`, `RECONCILED`, `REVERSED` solely for modern mapping, not as a claim about the original exact UI text.

## Acceptance tests
