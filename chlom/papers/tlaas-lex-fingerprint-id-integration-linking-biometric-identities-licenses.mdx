## Critical terminology boundary

The recovered historical title explicitly says **“Biometric Identities.”** That phrase is preserved because it is part of the recovered IP lineage. Current CHLOM does not infer that Fingerprint ID means raw fingerprints, face templates or other biometric data must be stored publicly or on-chain.

```text
Fingerprint ID != raw biometric
historical biometric wording != current biometric-storage mandate
```

## Source-grounded purpose

Related CHLOM sources describe decentralized identity, Fingerprint ID, DIDs, credentials/SBT research and ZK proofs as mechanisms for tying a real actor/entity to licenses and compliance state while preserving privacy.

The licensing problem is:

```text
Is this actor the correct authorized holder/subject?
Does this actor meet the credential predicates?
Can the system prove that without exposing unnecessary private data?
```

## Identity stack

A current-safe stack separates:

```text
PERSON / ORGANIZATION / SERVICE
        |
INSTITUTIONAL IDENTITY
        |
optional DID / credential adapters
        |
CHLOM Fingerprint ID
        |
role / authority / consent relationships
        |
DLA holder / issuer references
```

No single identifier automatically grants authority.

## Fingerprint ID role

Fingerprint ID can provide a stable cryptographic/institutional anchor for:

- identity continuity;
- issuer/holder references;
- credential relationships;
- consent records;
- license history;
- evidence/case history;
- provider-account aliases;
- DAIL event subjects.

## Identity versus authority

```text
identity verified
  != issuer authority
  != license eligibility automatically
  != transfer authority
```

Issuer authority must resolve independently from source rights/delegation.

## Privacy-by-design

Sensitive identity source material belongs in restricted storage governed by purpose, retention and access controls.

Public/marketplace surfaces should prefer:

- stable pseudonymous/institutional references;
- verified status;
- proof result;
- credential class/status;
- expiration/currentness;
- safe evidence digest.

## Revocation/currentness

Identity credentials can expire or be revoked independently from the DLA. A license profile may require revalidation when a credential changes.

```text
credential revoked
 -> identify dependent active DLAs
 -> evaluate policy
 -> HOLD/suspend/review only where adopted rules require it
```

No automatic global punishment is inferred.

## Recovery and key rotation

Identity continuity should survive provider account/key changes through governed recovery.

```text
institutional identity stable
 -> credential/key/provider bindings rotate/version
```

A lost wallet must not necessarily destroy the legal/institutional identity or license history.

## Anti-Sybil boundary

Historical sources discuss duplicate-identity/Sybil detection. Exact algorithms, thresholds, device signals and biometric matching methods are protected unless explicitly released.

Public doctrine can state the goal without exposing evasion-sensitive logic.

## Consent

Where biometric or sensitive identity processing is used, the system should record the applicable consent/legal-basis profile and purpose limitation rather than assuming possession of data authorizes every future use.

## Failure modes

- provider verifies a person but issuer authority missing -> no issuance authority;
- raw biometric exposed in public metadata -> security/privacy incident;
- credential stale -> HOLD where required;
- wallet changed -> recover/rebind rather than silently mint new identity;
- duplicate identity suspected -> review/HOLD under policy, not automatic guilt;
- identity proof PASS but transfer forbidden by DLA -> transfer DENY.
