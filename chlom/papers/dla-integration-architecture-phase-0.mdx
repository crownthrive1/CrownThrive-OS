## Integration objective

Historical DLA was never isolated. Related source bodies place it in the center of identity, compliance, oracle, exchange, treasury and governance flows. This article preserves that integration intent while decomposing it into current bounded services.

## Historical integration map

## Identity integration

Historical sources connect licenses to:

- DID identity;
- credential/SBT evidence;
- Fingerprint identifiers;
- issuer and holder identities;
- revocation/expiry of credentials.

Current identity surfaces are separate from licensing authority and are evaluated as evidence, not as automatic permission.

## Compliance integration

Historical DLA used AI/compliance checks before or during issuance/use. Current decomposition routes policy through versioned Rules Registry and Approval Service semantics.

```text
license action
   |
rules resolve
   |
evidence/risk inputs
   |
PASS | HOLD | DENY
```

## Oracle integration

External data can support eligibility, sanctions, regulatory, identity or other checks, but:

```text
oracle evidence != institutional authority
```

Current oracle inputs need provenance, freshness, quorum/confidence where applicable and an explicit policy consumer.

## LEX integration

Historical DLA issued/managed the license; LEX provided controlled transfer/exchange. Current flow:

```text
Dynamic Licensing Asset
        |
listing eligibility
        |
       LEX
        |
pre-trade rights + participant checks
        |
agreement / settlement
        |
entitlement + DLA lifecycle update
        |
       DAIL
```

## Treasury/economic integration

Historical sources describe license fees, royalties, taxes and treasury routing. Current CHLOM treats economic schedules as governed records that cannot override rights state.

```text
payment success != license activation
settlement success != source-rights proof
```

Economic routing reconciles after institutional licensing/entitlement rules pass.

## Governance integration

Historical DAO/council concepts supplied parameter updates, exceptions and emergency actions. Current-safe integration requires:

- bounded authority;
- explicit approval scope;
- no self-escalation;
- timelocks/quorum where adopted;
- audit evidence;
- reversible hold/rollback where feasible.

## Audit integration

All material licensing transitions need durable evidence. Current event destination:

```text
DAIL = Decentralized Autonomous Information Ledger
```

Historical DAL meanings remain separate source-era concepts.

## Interface contract classes

```yaml
interfaces:
  identity_read: read-only proof/credential resolution
  authority_read: source-backed issuer scope
  license_write: governed state transitions
  policy_read: versioned rule resolution
  approval_write: disposition + evidence
  oracle_read: external evidence with freshness
  lex_write: listing/trade lifecycle
  entitlement_write: downstream access/right activation
  dail_append: immutable/superseding event record
```

## Integration failure rules

Fail or HOLD when:

- identity cannot be resolved;
- source rights conflict;
- issuer authority is stale/revoked;
- required oracle evidence is stale;
- policy version is unknown;
- a downstream provider contradicts institutional state;
- LEX attempts transfer beyond DLA scope;
- economic routing is inconsistent with the governed schedule.
