## Purpose

Before changing licensing/compliance rules, validators, or cross-chain behavior, CHLOM needs a way to test how the system responds across interacting layers rather than validating one function in isolation.

## Simulation layers

```text
L1 IDENTITY / CREDENTIALS
L2 RIGHTS / ISSUER AUTHORITY
L3 DLA LIFECYCLE
L4 POLICY / APPROVAL
L5 ORACLE / EXTERNAL EVIDENCE
L6 VALIDATOR / QUORUM
L7 LEX / ENTITLEMENT / ECONOMIC HANDOFF
L8 DAIL / CORRECTION / REMEDY
```

These labels are current reconstruction organization, not authenticated lost numbering.

## Scenario families

Simulate at least:

- valid license issuance;
- missing issuer authority;
- conflicting source-rights evidence;
- credential expiry/revocation;
- stale oracle data;
- validator disagreement;
- transfer outside scope;
- sublicensing beyond parent rights;
- policy change during an in-flight request;
- AI false-positive/false-negative cases;
- bridge replay or source-chain reorg;
- entitlement/payment success while DLA activation fails;
- correction of a previously wrong decision.

## Invariant testing

Every simulation should assert institutional invariants, including:

```text
DLA_RIGHTS <= ISSUER_AUTHORITY <= SOURCE_RIGHTS
SUBLICENSE_RIGHTS <= PARENT_RIGHTS
UNKNOWN_MANDATORY_INPUT -> not PASS
AI_SIGNAL -> no self-created authority
PROVIDER_SUCCESS -> no automatic institutional truth
CORRECTION -> preserves history
```

## Validator simulation

Validator tests can vary availability, eligibility, signer compromise, conflicting observations and quorum composition. A numerical majority of invalid/stale validators must not satisfy an eligibility-aware quorum.

## Oracle simulation

Inject delayed, stale, conflicting, malformed and unavailable external evidence to verify fail-closed/HOLD behavior.

## Policy simulation

Compare candidate rules against a frozen scenario corpus before activation. Record changed dispositions and affected rights/actors so governance can see consequences before approving a new policy version.

## AI/model simulation

Use synthetic or properly governed datasets to measure precision/recall, false-positive cost, false-negative cost, calibration, bias/fairness dimensions where applicable, drift sensitivity and explanation stability. Exact private metrics/datasets remain restricted.

## Cross-layer fault injection

```text
one layer fails
   |
verify dependent layers do not silently infer success
```

Examples: bridge unavailable, validator quorum degrades, DAIL write fails, entitlement provider succeeds while institutional approval is held.
