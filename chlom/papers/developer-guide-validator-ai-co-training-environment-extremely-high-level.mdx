## Source-grounded lineage

Recovered CHLOM sources describe AI/ML models learning from historical and emerging network data, federated-learning concepts for privacy, oracle/validator participation and governance oversight of model changes. The exact lost co-training implementation is not recovered.

## Core separation

```text
TRAINING DATA
    !=
MODEL
    !=
MODEL EVALUATION
    !=
POLICY
    !=
AUTHORITY
```

Validator participation in training or evaluation does not make validators legislators, licensors or owners of the underlying data.

## Training-data governance

Training inputs require documented provenance, permitted use, retention/privacy treatment, quality controls and dataset/version identity. Public documentation never exposes private personal records, sensitive credentials or protected internal datasets.

## Federated/distributed learning lineage

Historical sources contemplate federated learning so models can learn across distributed data sources without centralizing all raw data. Current reconstruction treats this as research architecture unless exact implementation evidence exists.

## Validator roles in co-training

A validator/assurance node could, depending on an adopted implementation:

- attest dataset or observation provenance;
- verify signed training/evaluation artifacts;
- participate in distributed aggregation;
- challenge inconsistent results;
- contribute sanitized/synthetic observations within authority;
- verify model/version hash used for evaluation.

It must not disclose protected data or use data outside authorized purpose.

## Evaluation before adoption

Candidate models should be evaluated against frozen scenarios, known historical incidents, adversarial cases, calibration/uncertainty behavior and domain-specific fairness/bias risks where applicable.

## Feedback loop

Operational outcomes can become future training/evaluation evidence only under explicit data-use rules. A wrong model decision should be labeled/corrected rather than silently becoming reinforcement data.

```text
bad decision -> adjudicated correction -> curated learning signal
```

## Poisoning and manipulation controls

Co-training architecture must assume malicious, biased or low-quality contributions. Potential controls include source authorization, provenance signatures, outlier detection, aggregation robustness, contribution quarantine and reproducible evaluation before adoption.

Exact protected anti-poisoning algorithms/thresholds remain restricted.

## Model governance

No model becomes authoritative simply because validators trained or agreed on it. Deployment requires a separate approved model/policy profile.

## Rollback

Every promoted model needs an identifiable prior known-good version and a rollback/disable path. If a model contaminates material decisions, affected decisions are enumerated and re-evaluated.
