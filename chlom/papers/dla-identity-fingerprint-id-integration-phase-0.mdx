## Source-grounded identity role

Recovered CHLOM sources consistently connect licensing to identity. The historical DLA needed to answer not only “is this license valid?” but also “is the actor presenting it the correct, eligible subject or authorized holder?”

## Identity functions supporting licensing

### Subject binding

A license should resolve to the intended person, organization, role or service identity.

### Credential proof

Eligibility may depend on verifiable credentials without exposing unnecessary private data.

### Issuer binding

The issuer/steward identity must be distinct from the license holder and supported by authority evidence.

### Revocation awareness

A credential can expire or be revoked independently of the license; policies must define how that affects license state.

### Recovery/key rotation

Identity keys can rotate without silently transferring the underlying institutional identity or rights.

## Fingerprint ID purpose

Historical materials use Fingerprint ID as a cryptographic/unified identity anchor connecting identity, licenses, audit and economic routing. Current CHLOM preserves Fingerprint ID as its own system identity and does not publish raw sensitive telemetry or biometric material.

```text
Fingerprint ID = governed identity anchor
Fingerprint ID != public biometric database
Fingerprint ID != automatic legal identity conclusion
```

## Credential and SBT lineage

Historical sources describe SBT/non-transferable-token patterns for credentials. Current interpretation treats that as one possible representation. What matters institutionally is a verifiable credential/attestation with clear issuer, subject, status and evidence.

## ZK relationship

Historical CHLOM uses zero-knowledge proof concepts to prove predicates such as eligibility or credential possession without exposing underlying sensitive data.

```text
private credential data
      |
 predicate/proof generation
      |
 proof + public inputs
      |
 verifier
      |
 PASS / FAIL for defined predicate
```

A valid proof establishes only the proved predicate, not every legal or licensing condition.

## Privacy rules

Public documentation must never expose:

- raw biometric templates;
- private KYC documents;
- government ID numbers;
- private device fingerprints;
- unreleased anti-Sybil derivation features;
- secret salts/keys;
- private fraud thresholds;
- protected recovery factors.
