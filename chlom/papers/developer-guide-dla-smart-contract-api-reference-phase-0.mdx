## Idempotency

Retries must not create duplicate licenses or duplicate state transitions.

```text
same idempotency key + same canonical request
=> same institutional result or safe replay response
```

## Optimistic version control

State-changing operations should reject stale writes when the target version has changed since the client read it.

```text
expected_version == current_version
```

unless an explicit migration/merge contract says otherwise.

## Authorization

Historical `onlyOwner`-style implementation patterns are insufficient as institutional authority by themselves.

```text
key/control authentication
AND action-specific issuer/governance authority
AND source-rights ceiling
```

must be resolved for privileged licensing changes.

## Verify/read semantics

A license verification response should distinguish object existence from usability:

```text
exists?
active?
current term?
requested use in scope?
holder eligible?
required policies/evidence current?
```
