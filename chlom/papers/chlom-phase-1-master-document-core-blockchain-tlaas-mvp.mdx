## MVP success criteria — reconstructed

A safe reconstruction of functional proof criteria is:

```text
create candidate
 -> enforce identity/authority prerequisites
 -> PASS/HOLD/DENY deterministically
 -> activate one valid license

 -> revoke/expire it correctly

```

A demo that only mints a token would not prove licensing correctness.

## Test plan

### Happy path

```text
valid rights -> valid authority -> valid applicant -> policy PASS -> active DLA -> verification PASS
```

### Negative paths

- no rights -> HOLD/DENY;
- no issuer authority -> DENY;
- stale credential -> HOLD;
- duplicate issuance -> idempotent;
- revoked DLA -> verification fails for active-use predicate;
- provider token exists without DLA -> not valid institutional license;
- policy unavailable -> HOLD, not fail-open;
- unauthorized lifecycle change -> DENY.
