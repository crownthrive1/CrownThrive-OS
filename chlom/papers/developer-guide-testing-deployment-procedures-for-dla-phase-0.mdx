## Unit-test targets

At minimum test:

- candidate creation;
- rights/authority ceiling enforcement;
- active/held/revoked/expired state transitions;
- identity/credential predicates;
- transferability and sublicensing;
- renewal/amendment versioning;
- policy PASS/HOLD/DENY behavior;
- idempotent retry handling;
- DAIL event emission/reference.

## Negative tests

Critical tests must prove prohibited paths fail:

```text
issue without authority -> fail
issue beyond source rights -> fail
transfer non-transferable DLA -> fail
use revoked/expired DLA -> fail
stale version mutation -> fail
unknown mandatory evidence -> HOLD/fail
unauthorized override -> fail
```

## Integration tests

Exercise end-to-end flows across identity, rights, issuer authority, DLA, Rules Registry, Approval Service, evidence/oracle inputs, LEX/entitlement and DAIL.

## State-machine tests

Generate or enumerate allowed transitions and prove invalid edges are rejected.

```text
ACTIVE -> REVOKED         allowed if authorized/profile permits
REVOKED -> ACTIVE         not silently allowed
EXPIRED -> ACTIVE         requires renewal/new authority path
DENIED -> ACTIVE          requires new/superseding approved candidate
```

## Property/invariant tests

Preserve core invariants:

```text
DLA_RIGHTS <= ISSUER_AUTHORITY <= SOURCE_RIGHTS
SUBLICENSE_RIGHTS <= PARENT_RIGHTS
SETTLED_VALUE allocations conserve governed basis
CORRECTION preserves prior evidence/history
```

## Adversarial tests

Include attempts at:

- replay/duplicate issuance;
- stale evidence reuse;
- authority escalation;
- conflicting oracle/evidence inputs;
- key/role mismatch;
- LEX transfer bypass;
- provider success bypassing institutional state;
- malformed ZK/credential proof where relevant;
- event omission or correction-chain break.

## Environment progression

Historical sources discuss local testnets and staged network rollout. Current-safe release sequence is evidence-based:

```text
local/dev
 -> automated test suite
 -> isolated integration environment
 -> controlled test / sandbox
 -> staging candidate
 -> governed production promotion only after current gates PASS
```

No historical phase label authorizes production today.

## Post-deployment verification

Read back deployed version/configuration, run smoke tests, verify event/evidence write paths, confirm rollback readiness and compare actual state to the approved packet.

## Failure rule

```text
deployment succeeded technically
      !=
production certified institutionally
```

A provider green check cannot replace governance/security/reconciliation gates.
