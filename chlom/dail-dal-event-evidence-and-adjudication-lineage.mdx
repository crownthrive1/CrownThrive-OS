# DAIL and DAL — Event, Evidence, Attestation and Adjudication Lineage

Current CHLOM reserves **DAIL = Decentralized Autonomous Information Ledger** for governed event, evidence, audit and correction lineage. Historical CHLOM sources reused **DAL** for several different systems. Wave 2 preserves those older meanings without allowing them to overwrite current DAIL semantics.

## What DAIL is now

DAIL is the durable institutional memory layer for **what happened, to what, by whom, under which authority, against which evidence, and how later corrections relate to the earlier record**.

It is not merely an application log and it is not automatically a blockchain. The core contract is semantic and evidentiary; storage and anchoring providers remain replaceable.

## Event envelope

A consequential DAIL event should be able to identify:

- stable `event_id` and event type;
- actor, service or agent identity;
- organization/tenant context;
- subject/object stable IDs;
- prior and new state where applicable;
- source/evidence references and cryptographic digests;
- policy/rule/authority version;
- decision, approval or override references;
- observed time, recorded time and effective period;
- causation, correlation and idempotency references;
- confidentiality/evidence class;
- correction, reversal or supersession relationships;
- downstream propagation/read-model state.

## Event versus current state

DAIL does not require every consumer to replay the whole ledger every time. Current-state services can project an accepted state from the event chain.

```text
EVENT 001: license approved
      |
EVENT 002: license activated
      |
EVENT 003: suspension evidence received
      |
EVENT 004: license suspended
      |
EVENT 005: appeal successful
      |
EVENT 006: license restored
      |
      v
CURRENT PROJECTION: ACTIVE / RESTORED
```

The current projection changes. The historical chain does not disappear.

## Append-only correction principle

```text
original event
     |
     v
new evidence / contradiction
     |
     v
correction or remedy event
     |
     v
new effective state
```

A correction changes effective institutional meaning without silently deleting the earlier event. This same rule governs reconstructed Help Center articles and founder adjudications.

## Historical DAL — Decentralized Attestation Ledger

The Genesis Volume uses **DAL = Decentralized Attestation Ledger** as a proof/evidence memory layer. It stores or anchors attestations, proof references, identity/license evidence and other cryptographic or oracle-supported claims.

Modern mapping:

```text
Attestation Service
      +
Evidence Service
      +
DAIL Event Lineage
      +
optional cryptographic anchoring
```

Historical batching/Merkle-root concepts remain valid architectural research for efficiency, but are not required for the current cloud-first ledger.

## Historical DAL — Decentralized Adjudication Layer

The Grand Prospectus uses **DAL = Decentralized Adjudication Layer** for disputes, mediation, arbitration, verdicts, enforcement, appeals and restoration.

Modern mapping:

```text
Case / Remedy Service
       |
       v
Appeal / Resolution Workflow
       |
       v
DAIL event + evidence trail
```

Adjudication therefore **uses DAIL**. It is not the current expansion of DAIL.

## Historical distribution-related DAL

Later recovered Help Center/module material also associates DAL with distribution/distributions authority or layer concepts. Those records remain historical lineage and must be resolved by exact source/effective period rather than string matching.

Distribution economics now map to attribution, allocation, obligation and settlement services, with ThriveEvergreen governing current economic activation where applicable.

## Evidence is not sovereign truth

```text
provider says SUCCESS
        |
        v
DAIL records provider observation
        |
        v
CHLOM reconciles rights / policy / authority
        |
   +----+-----+
   |          |
 PASS/HOLD   DENY
```

A provider/API/oracle response is evidence. It may still require rights, financial, policy or entitlement reconciliation before it changes institutional state.

## Failure and hold conditions

DAIL consumers should fail closed or HOLD when:

- the event references unknown stable IDs;
- required evidence is missing or stale;
- a correction chain is broken;
- an event signature/digest does not verify where required;
- a policy or authority version cannot be resolved;
- two mutually exclusive current-state projections exist;
- restricted evidence is requested by an unauthorized actor;
- provider evidence conflicts with institutional state and has not been reconciled.

## Founder adjudication

A later founder ruling may refine historical DAL names or the current DAIL implementation/anchor strategy. Current **DAIL = Decentralized Autonomous Information Ledger** remains the default unless prospectively changed through a governed adjudication.
