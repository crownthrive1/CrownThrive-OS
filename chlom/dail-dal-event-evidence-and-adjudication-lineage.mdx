# DAIL and DAL — Event, Evidence, Attestation and Adjudication Lineage

Current CHLOM reserves **DAIL = Decentralized Autonomous Information Ledger** for governed event, evidence, audit and correction lineage. Historical CHLOM sources reused **DAL** for several different systems. Wave 2 preserves those older meanings without allowing them to overwrite current DAIL semantics.

## Current DAIL

DAIL is the durable information/event ledger concept used to preserve **what happened, why, under which authority, against which evidence, and how later corrections relate to the earlier record**.

DAIL may record or reference events such as asset registration, source/evidence ingestion, rights review, policy decisions, DLA creation/activation, payment confirmation, entitlement issuance, correction, hold, suspension, revocation, appeal, restoration, provider reconciliation and continuity events.

## DAIL event envelope

A governed event should be able to carry:

- stable event ID and event type;
- actor/service/agent identity;
- organization/tenant context;
- subject/object stable IDs;
- prior/new state where applicable;
- source/evidence references and digests;
- policy/rule/authority version;
- decision/approval references;
- timestamp and effective period;
- causation/correlation/idempotency references;
- confidentiality/evidence class;
- correction/supersession relationships;
- downstream propagation state.

DAIL is not permission to expose restricted evidence publicly. It may store a digest/reference while the evidence body remains in protected custody.

## Append-only correction principle

```text
original event
→ contradiction/new evidence
→ correction/remedy event
→ effective current state
```

A correction changes current institutional meaning without silently deleting the earlier event. This is the same continuity rule used for Help Center reconstruction and founder adjudication.

## Historical DAL — Decentralized Attestation Ledger

The Genesis Volume uses **DAL = Decentralized Attestation Ledger** as a proof/evidence memory layer. It stores or anchors attestations, proof references, identity/license evidence and other cryptographic or oracle-supported claims.

Modern mapping: Attestation Service + Evidence Service + DAIL event lineage + optional cryptographic anchoring.

## Historical DAL — Decentralized Adjudication Layer

The Grand Prospectus uses **DAL = Decentralized Adjudication Layer** for disputes, mediation, arbitration, verdicts, enforcement, appeals and restoration.

Modern mapping: Case/Remedies Service + Appeals/Resolution workflow + DAIL records. Adjudication is therefore a domain that **uses DAIL**; it is not the current expansion of DAIL.

## Historical distribution-related DAL

Later recovered Help Center/module material also associates DAL with distribution/distributions authority or layer concepts. Those records remain historical lineage and should be resolved by exact source/effective period rather than string matching.

Distribution economics now map to attribution/allocation/settlement services and ThriveEvergreen where applicable.

## DAIL is not automatically blockchain

The current DAIL contract is an event/audit architecture. A future decentralized implementation may replicate or cryptographically anchor selected event commitments, but business meaning stays provider-independent.

```text
institutional event
→ DAIL canonical record
→ optional digest/Merkle commitment
→ optional external/private/public anchor
```

A chain receipt can prove that a commitment existed; it does not independently prove that the underlying legal/rights/economic claim was correct.

## Evidence versus truth

Provider/API/oracle evidence enters DAIL as attributable observation, not as unquestioned sovereign truth. A provider success response may still require policy, rights, financial or entitlement reconciliation before it changes effective institutional state.

## Privacy and retention

DAIL should support classification, access controls, evidence references, purpose limitation, retention/legal hold and off-provider continuity. Public projections must exclude credentials, private evidence bodies, personal data and protected implementation details.

## Relationship to DLA and LEX

```text
rights/policy decision
→ DLA lifecycle change
→ LEX/commerce event where eligible
→ entitlement/economic/remedy effects
→ DAIL event chain
```

DAIL records the institutional history across those services; it does not replace them.
