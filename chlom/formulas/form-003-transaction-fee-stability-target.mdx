# FORM-003 — Historical Transaction-Fee Stability Target

## Historical target concept

Recovered Genesis material explores maintaining an effective median transaction cost around an illustrative target such as:

```text
target_median_transaction_fee ≈ $0.10
```

The target is a historical design example, not current CrownThrive/CHLOM pricing.

## Derived adjustment abstraction

To make the concept mathematically explicit without pretending to reproduce source code, the reconstruction uses:

```text
fee_units_next = fee_units_current * clamp(P_market / P_target, lower, upper)
```

This is a **derived model**, not verbatim source logic.

`P_market / P_target` represents a relative adjustment signal and `clamp` limits abrupt changes. Production use would require exact definitions for both prices, update frequency, smoothing, oracle source, bounds and fallback behavior.

## Purpose

The concept attempts to keep effective user transaction cost reasonably predictable even if a native utility token's market value changes. This was relevant to historical blockchain-first CHLOM architecture.

## Missing dimensions

A real fee market must also consider network load, resource consumption/weights, validator economics, anti-spam cost, oracle freshness, currency volatility, manipulation resistance, minimum/maximum fees and user experience.

## Oracle dependency

Any fiat-relative fee adjustment would depend on external pricing evidence. FORM-003 therefore requires Oracle Lattice/aggregation controls and fail-closed behavior when reliable price evidence is unavailable. A stale price should not silently reset fees.

## Stability versus peg

The source concept is not a stablecoin peg. It is a fee-target mechanism. Documentation should not imply CHLOM Coin itself is or was intended to maintain a fixed fiat value from this formula alone.

## Current authority boundary

Current CHLOM is cloud-first and evidence-driven; historical token fee models are preserved as future/decentralized research. No production fee or token pricing rule is activated by this page.

## Test vectors for any future simulation

Test market price equal target, above target, below target, extreme change hitting upper/lower clamp, stale oracle, contradictory oracle sources, zero/invalid price, repeated adjustment stability and manipulation scenarios.

## Versioning

The source target and reconstructed abstraction remain separate provenance fields. Any future adopted fee controller gets a new formula/model ID with implementation evidence.
