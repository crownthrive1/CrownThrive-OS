# FORM-002 — Historical Staking APY Estimate

## Formula identity

```yaml
formula_id: FORM-002
classification: historical_source_formula
origin: CHLOM Genesis Volume
adopted: false
current_status: historical_research_only
```

## Expression

```text
nominal_staking_apy = annual_staking_rewards / total_staked
```

The source gives an illustrative scenario:

```text
reward_pool = 200,000,000 CHLOM
release_period = 4 years
annual_rewards ≈ 50,000,000 CHLOM
staked = 500,000,000 CHLOM

APY ≈ 50,000,000 / 500,000,000
    ≈ 0.10
    ≈ 10%
```

## Meaning

This is a simple nominal reward-rate estimate. It asks: if a known amount of rewards is distributed across a known staked supply for a year, what is the reward quantity relative to stake?

It does not include token-price movement, compounding frequency, validator commission, uptime, slashing, changing stake participation, inflation dilution, taxes, liquidity constraints or time-varying emissions.

## Units

Both numerator and denominator use the same token unit, leaving a dimensionless annual ratio expressed as a percentage.

## Historical lineage

The formula belongs to the Substrate/NPoS-era CHLOM design, where CHLOM Coin was contemplated as a network utility/staking asset. That architecture remains historically important but does not establish a live token, current validator network, current APY or investment product.

## Related historical slashing

Recovered source discusses illustrative slashing ranges around `1%–10%` depending on severity. Those examples are not a current slash schedule and should not be combined with FORM-002 as if they were adopted investment terms.

## Model limitations

If total stake changes during the year, a more realistic simulation would integrate rewards and stake through time rather than divide two static annual quantities. If rewards are emitted per block/epoch, compounding and participation changes would need explicit modeling.

## Authority and legal boundary

Publishing this formula is preservation of historical engineering/economic research. Any live staking, token issuance, rewards, yield representation or public offering would require separate technical activation, economic governance and applicable legal/regulatory review.

## Calculation record

A simulation should record reward-pool source, release period, annualization method, staked-supply date/window, compounding assumption, excluded factors and scenario classification.

## Tests

Test zero stake as invalid/division-by-zero, zero rewards, the source 10% example, changing-stake scenario flagged as static approximation and unit mismatch.

## Versioning

Keep the original static historical formula immutable. Any dynamic staking model receives a new formula/model identifier.
