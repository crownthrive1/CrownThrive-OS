# FORM-029 — Confidence–Authority Separation

## Formula identity

```yaml
formula_id: FORM-029
classification: categorical_formal_invariant
origin: CHLOM authority, AI and evidence governance
adopted_as_reconstruction_constitutional_rule: yes
```

## Core relation

CHLOM explicitly separates epistemic confidence from authority to act:

```text
P(correct | evidence) can be high
while
authority_to_act = false
```

A concise institutional expression is:

```text
high_confidence * no_authority = no_execution
```

The multiplication is conceptual, not a probabilistic arithmetic operator. It means authority is a hard gate rather than a score that can be compensated for by confidence.

## Why this matters

AI models, anomaly detectors, provider APIs, oracle aggregations, test results and cryptographic proofs can all produce strong evidence. None inherently grants CrownThrive/CHLOM authority to revoke a license, transfer money, publish confidential data, change policy, sign a contract or exercise founder powers.

## Two-axis decision model

A more precise conceptual model uses separate axes:

```text
Evidence/Confidence: low -> high
Authority: absent -> valid
```

Only the valid-authority region can proceed to execution, and even then policy/evidence may still HOLD or DENY.

## Anti-patterns prevented

- 'The model is 99% confident, so execute.'
- 'The provider succeeded, so CHLOM approved it.'
- 'The proof verifies, so the user is authorized.'
- 'The CI is green, so merge without required approval.'
- 'The agent can technically do it, so it is allowed.'

## Relation to ALG-002

ALG-002 operationalizes this invariant by resolving authority after provisional policy/evidence evaluation.

## Testing

Create matrices covering high/low confidence with valid/invalid authority and verify that no-confidence state can manufacture authority. Also test expired delegation, wrong tenant, wrong object scope and AI-generated self-approval.

## DAIL evidence

Consequential decisions should record both confidence/evidence state and authority resolution separately.

## Versioning

This is a stable constitutional invariant. Any exception would require explicit founder/governance adjudication and should be treated as a major architecture change.
