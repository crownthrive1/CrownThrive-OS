## Purpose

Oracle Hub is the service boundary between **external observations** and CHLOM's governed decisions. It registers sources, ingests signed/authenticated observations, normalizes them, enforces freshness/provenance rules, detects conflicts, performs allowed aggregation/corroboration and exposes evidence to ACE/domain services.

```text
EXTERNAL SOURCE A ----+
EXTERNAL SOURCE B ----+--> ORACLE HUB --> normalized observations
EXTERNAL SOURCE C ----+         |
                               freshness
                               provenance
                               conflict
                               quorum/corroboration
                                  |
                                  v
                         ACE / domain consumers
```

## Freshness

A generic freshness test:

```text
age = now - observed_at
usable = age <= max_age(policy, observation_type)
```

The actual max-age is policy/source specific and may be restricted.

## Corroboration

Different source types require different aggregation methods.

### Numeric

Possible public-safe algorithms:

```text
median(x_1..x_n)
weighted_mean = sum(w_i*x_i)/sum(w_i)
```

No production weights are set by this article.

### Categorical/claim evidence

Use source identity, independence, agreement/conflict and policy-specific confidence rather than meaningless arithmetic averaging.

## Source independence

Multiple feeds from one upstream origin are not automatically independent sources.

```text
3 API vendors all reselling Source X
   !=
3 independent corroborations
```

Source-lineage metadata should record common upstream dependencies where known.

## Conflict state

```text
source A -> X
source B -> not-X
source C -> unavailable
      |
      v
CONFLICT
      |
HOLD / additional source / human review according to policy
```

## Human Scribe relationship

Scribes can contribute structured human-attested observations when their role/authority and evidence scope are defined. Oracle Hub records them as source observations, not superior truth.

## AI relationship

AIE/model outputs can be source inputs to Oracle Hub or consume Oracle Hub evidence depending on architecture. Their model/version/provenance remain explicit.

## Sanctions-cache relationship

Oracle Hub ingests accepted source snapshots; Sanctions Cache provides fast time-bounded current datasets to policy evaluation.

## Failure modes

### All sources unavailable

Return unknown/HOLD where current external evidence is mandatory; never default to clear.

### Source clock invalid

Quarantine/HOLD observation until time semantics are resolved.

### Provider changes units/schema

Hold normalization/aggregate until adapter/schema migration is validated.

### Source later retracts observation

Record correction/supersession and propagate dependent review where material.

### One high-weight source compromised

Suspend source, recalculate affected aggregates, open incident/correction path.

## Security threats

- credential compromise;
- data poisoning;
- Sybil/common-upstream sources;
- stale replay;
- unit manipulation;
- source censorship;
- provider lock-in;
- hidden manual edits.

