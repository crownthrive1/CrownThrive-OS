## Historical purpose

The ZK Verifier Pallet was designed to verify zero-knowledge proofs inside CHLOM's historical runtime so participants could prove compliance/eligibility facts without exposing underlying sensitive data.

```text
PRIVATE WITNESS / CREDENTIAL
        |
        v
ZK PROVER
        |
        v
PROOF + PUBLIC INPUTS
        |
        v
ZK VERIFIER PALLET
        |
  circuit/key/current-state checks
        |
 VALID | INVALID
        |
        v
POLICY / LICENSE / ACTION GATE
```

## Proof validity is narrow

```text
proof cryptographically valid
       !=
credential current
       !=
issuer authorized
       !=
policy current
       !=
action authorized
```

Current CHLOM verifies all required layers.

## Proof receipt

A public-safe proof receipt can contain:

```text

time

public input digest
```

without exposing the private witness.

## Privacy threats

- public-input overexposure;
- correlation/linkability across proofs;
- side-channel leakage;
- verifier key substitution;
- circuit backdoor;
- compromised prover;
- stale credential/revocation state;
- proof replay outside intended scope.

## Scope/replay binding

Proofs should bind to context when required:

```text
subject/session
purpose
action/object
nonce/challenge
policy/circuit version
expiry
```

A proof valid for one purpose cannot automatically be reused for all purposes.

## Public / restricted split

Public-safe:

- proof architecture;
- public circuit IDs/verification interfaces where approved;
- proof receipts;
- privacy principles.

Restricted:

- protected circuit internals;
- private witnesses;
- proving keys where sensitive;
- security/audit findings;
- anti-correlation design;
- exploit-sensitive verifier configuration.
