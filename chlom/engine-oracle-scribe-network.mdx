## What OSN is not

OSN is not a generic crowdsourcing layer and does not make every submitted observation true. It does not:

- give Scribes universal institutional authority;
- make a provider feed sovereign truth;
- allow AI to self-certify high-impact facts;
- turn consensus into legal truth;
- require public blockchain deployment;
- expose restricted source evidence publicly.

## Scribe relationship

A Scribe is a human/domain evidence contributor or reviewer under an explicit assignment/authority profile. Scribes can:

- interpret source material;
- attest observed facts within scope;
- resolve ambiguity;
- document context;
- review machine/provider conflicts;
- escalate to professional/governance paths.

Scribe evidence should be attributable and challengeable.

## Corroboration

For facts requiring multiple sources:

```text
source A observation
source B observation
source C observation
        |
        v
corroboration rule
        |
 PASS / HOLD / CONFLICT
```

The rule can use count, weight, trust profile, median or domain-specific logic. The exact weighting is policy-controlled and may be restricted.

## Conflict handling

Conflicting sources must remain visible as a conflict set.

```yaml
conflict_id: stable ID
subject_ref: required
observation_refs: list
conflict_type: contradiction|freshness|identity|jurisdiction|measurement
status: open|review|resolved|superseded
resolution_ref: optional
```

The system should not silently choose the newest or most convenient feed.

## Freshness

Different source classes age differently. A price/FX observation may need short freshness; a corporate charter may remain valid longer. Freshness profiles are typed and source/policy specific.

## Reputation and assurance lineage

Historical designs contemplated staked or reputation-bearing oracle providers. Modern CHLOM can preserve accountability through:

- source history;
- reliability metrics;
- probation/suspension;
- independent corroboration;
- contractual assurance;
- reviewer quality/evaluation;
- cryptographic signing.

Financial staking/slashing remains historical/optional unless separately activated.

## AI relationship

AI outputs are observations/recommendations with model/version/evidence metadata.

```text
AI output -> evidence candidate
        != final institutional fact
```

High-impact use requires model governance and, where applicable, human review.

## Attestation relationship

An attestation can be issued after a source/reviewer with the required authority validates a claim.

```text
observation(s)
  -> review/verification
  -> attestation
  -> policy use
```

Attestation authority is separate from observation source identity.

## Oracle Hub relationship

The Oracle Hub is the normalization/routing/control service. OSN is the broader participant/source network.

```text
OSN = sources + Scribes + assurance relationships
Oracle Hub = ingestion/normalization/corroboration/control plane
```

## Failure modes

- source unknown -\> HOLD;
- signature/proof invalid -\> reject;
- stale observation -\> HOLD/refresh;
- sources conflict -\> preserve conflict and route review;
- Scribe outside scope -\> evidence not accepted as authoritative;
- source provider outage -\> use policy-defined stale/fallback behavior, never assume current;
- AI provider output lacks model/version -\> hold/reject for governed use.

## Threat model

- oracle manipulation;
- bribed/colluding Scribes;
- Sybil sources;
- stale data;
- provider account takeover;
- source spoofing;
- jurisdiction confusion;
- hidden weighting manipulation;
- restricted evidence leakage;
- model output promoted as fact without review.

## Test vectors

1. registered source \+ valid signed fresh observation -\> accepted as observation;
2. unknown source -\> HOLD;
3. two trusted sources disagree -\> conflict, not arbitrary PASS;
4. Scribe assigned outside domain -\> no authoritative attestation;
5. source expires/withdrawn -\> dependent currentness reevaluated;
6. AI observation \+ required human review missing -\> HOLD;
7. provider feed says payment succeeded -\> economic reconciliation still required;
8. source correction -\> new observation/attestation lineage;
9. restricted observation -\> public projection redacted;
10. source collusion simulation -\> assurance/quorum tests catch concentration when configured.

## Current mapping

OSN maps naturally to a provider-neutral external evidence network with Oracle Hub, Scribe/reviewer workflows, source registry, cryptographic signing, conflict handling, DAIL and domain policy.
