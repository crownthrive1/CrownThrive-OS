## Source basis

The CHLOM Grand Prospectus uses **DAL = Decentralized Adjudication Layer** for a dispute/mediation/arbitration system involving verdicts, enforcement, appeals and related governance. This conflicts with the Genesis-era `Decentralized Attestation Ledger` meaning and later distribution-related DAL lineage.

The conflict is preserved through separate atomic records rather than choosing one historical definition retroactively.

## Historical purpose

The source-era Adjudication Layer was intended to provide a programmable dispute-resolution and enforcement lane inside the CHLOM ecosystem.

## What this record does not claim

It does not establish that:

- CHLOM currently operates a binding arbitration forum;
- historical DAL had governmental judicial authority;
- an on-chain verdict is legally enforceable merely because code executed;
- AI can act as a final judge/arbitrator;
- a DAO vote can create remedies outside contracts/rights/law;
- a current production adjudication layer is deployed.

## Jurisdiction/authority boundary

A dispute-resolution mechanism can only bind parties/actions within valid authority.

```text
technical adjudication mechanism
   != legal jurisdiction automatically
```

Source agreements, governance charters, applicable law and professional/legal requirements remain external authority inputs.

## Mediation

Historical DAL can support a mediation phase before formal adjudication.

```text
dispute
 -> voluntary/authorized mediation
 -> settlement candidate
```

A settlement becomes binding only under the applicable agreement/authority, not because the protocol labels it settled.

## Arbitration

If a valid arbitration agreement/profile exists:

```text
case eligibility
 + arbitrator/panel authority
 + evidence
 + procedure
 -> arbitration decision
```

Current CHLOM should route real legal arbitration to properly authorized/legal processes rather than assume source-era smart arbitration is sufficient.

## Adjudicator identity and conflict

Historical decentralized governance may select reviewers/arbitrators from a pool, council, DAO or reputation/staking mechanism. Current-safe requirements include:

- identity;
- qualification where required;
- scope/authority;
- conflict disclosure;
- recusal;
- assignment evidence;
- decision ceiling.

```text
stake/reputation != professional authority
```

## Evidence

The adjudication layer consumes evidence; it should not own all raw evidence publicly.

```text
Evidence Vault/source custody
 -> case evidence refs
 -> adjudicator review
 -> decision/finding
```

## Remedy/enforcement boundary

A decision can create a remedy candidate. Execution still requires the appropriate rights/economic/provider authority.

```text
verdict
  != provider action
  != money movement
  != rights transfer automatically
```

## Appeals

Historical DAL supports appeals. Current CHLOM preserves the principle:

```text
Decision v1
   -> appeal
   -> new review/decision v2
```

The original decision remains in history and is explicitly affirmed/modified/reversed/superseded.

## Guardianship/pause relationship

Source-era governance can use emergency guardianship or pause controls while a dispute is unresolved. Current mapping uses bounded HOLD/suspension/guardian controls with explicit review and sunset.

## DAIL relationship

Current DAIL records case, evidence, decision, appeal and remedy events. It is not itself the adjudicator.

```text
current DAIL = evidence/history
current case/DREP/DAP = adjudication workflow
```

## Failure modes

- no valid adjudication authority/agreement;
- conflicted reviewer;
- evidence inaccessible or tampered;
- AI recommendation treated as verdict;
- DAO majority exceeds legal/contractual rights;
- remedy executed before appeal/timelock where required;
- provider dispute outcome mistaken for institutional verdict;
- original decision deleted after appeal;
- historical DAL confused with current DAIL.

## Threat model

- governance capture;
- bribery/collusion;
- fake evidence;
- reviewer conflict;
- Sybil jurors/validators;
- automated enforcement bugs;
- privacy leakage;
- denial of appeal;
- hidden emergency powers;
- legal-jurisdiction overclaim.

## Test vectors for modernization

1. valid contractual dispute -\> current case/DREP flow can proceed;
2. no adjudication authority -\> HOLD/external legal route;
3. reviewer conflict -\> recusal;
4. AI recommends adverse result -\> no final decision without required human/professional authority;
5. provider refund dispute -\> provider evidence only, institutional case remains separate;
6. appeal filed -\> original decision retained \+ new review;
7. remedy requires money movement -\> separate economic authority gate;
8. historical smart arbitration source -\> preserved as research, not current legal service;
9. historical DAL phrase in Grand Prospectus -\> resolves this article, not current DAIL;
10. source decision corrected -\> explicit supersession/correction lineage.
