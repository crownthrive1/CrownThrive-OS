## Purpose

LEX is the governed exchange layer for discovering, offering, negotiating and transacting **eligible licensing rights**.

```text
SOURCE RIGHTS
    |
LICENSING STEWARDSHIP
    |
DYNAMIC LICENSING ASSET / RIGHTS PACKAGE
    |
LISTING ELIGIBILITY
    |
    v
   LEX
  / | \
discovery qualification agreement
  \ | /
 payment/economic activation
       |
rights transfer / entitlement
       |
settlement / reporting / remedies
       |
      DAIL
```

## What LEX is not

LEX is not:

- a generic ecommerce marketplace;
- proof of ownership;
- a rights issuer;
- a payment processor;
- a token/NFT exchange requirement;
- a live public exchange merely because historical papers exist;
- permission to list every CrownThrive asset;
- authority to sell or sublicense rights a seller does not control;
- a replacement for agreements/contracts;
- a reason to collapse payment, license, entitlement and settlement into one state.

## Rights-before-listing invariant

```text
LISTED_RIGHTS <= DLA/LICENSABLE_RIGHTS <= SOURCE_RIGHTS
```

A listing cannot expand source rights or issuer authority.

## Listing eligibility

Before activation:

1. canonical asset/right exists;
2. licensor/issuer authority is current;
3. offered rights are within source/DLA scope;
4. exclusivity/capacity is available;
5. territory and term are valid;
6. applicable policy/Compliance Packs resolve;
7. agreement terms exist where required;
8. economic offer/schedule is authorized;
9. public/private classification is appropriate;
10. required approvals are complete.

Unresolved material rights state yields HOLD.

## Agreement/assent

A LEX transaction should reference a versioned agreement or rights instrument.

```text

```

A checkout click or payment does not prove assent to terms that were not properly presented and recorded.

## Transaction lifecycle

```text
ACTIVE LISTING
     |
PARTICIPANT QUALIFICATION
     |
AGREEMENT / ASSENT
     |
ECONOMIC AUTHORIZATION
     |
PAYMENT HOLD / AUTHORIZATION if required
     |
RIGHTS ISSUE / TRANSFER
     |
ENTITLEMENT / FULFILLMENT
     |
RECONCILIATION / SETTLEMENT
     |
COMPLETED
```

Failure at any stage preserves prior events and routes compensation/remedy rather than fabricating completion.

## Payment boundary

```text
provider payment success
   != license issued
   != rights transferred
   != entitlement active
   != settlement reconciled
```

Payment is evidence for one stage only.

## Rights issuance/transfer

LEX requests the governed rights action from Licensing Stewardship/DLA services. It does not manufacture a license itself.

```text
LEX transaction authorized
   -> issuer/rights action
   -> DLA/version/holder state changes
   -> DAIL event
```

## Entitlement

An entitlement grants access, download, service or use only after required DLA, agreement and economic conditions are satisfied.

```text
DLA/right valid
+ agreement
+ required economic state
 -> entitlement candidate
```

## Sublicensing

A sublicensing listing must satisfy conservation:

```text
child rights <= parent DLA rights
child term <= parent remaining term
child territory <= parent territory
child transfer/sublicense rights <= parent permissions
```

Rights Graph and ALG-004 enforce closure.

## Lease/rental

Historical LEX research includes rental/lease structures. Current implementation can model a time-bounded license and entitlement rather than a transfer of ownership.

## Auctions and bidding

Historical sources contemplate auctions/bids. These are optional modules, not baseline current functionality. If implemented they require:

- bid identity;
- bid validity;
- reserve/eligibility;
- anti-manipulation controls;
- timing/expiry;
- final offer conversion;
- payment/rights lifecycle.

## Fractional licensing

Historical fractionalization concepts are research. Fractional rights/economic products can create significant legal, securities, rights and accounting complexity and require separate professional/legal/economic review.

No current fractional product is created by this article.

## Token/NFT representations

## Idempotency

All material transaction stages use stable semantic identifiers so provider/webhook retries cannot create duplicate licenses, entitlements or obligations.

## Holds

LEX can HOLD for:

- rights conflict;
- issuer authority conflict;
- stale qualification;
- missing agreement;
- economic mismatch;
- provider failure;
- sanctions/risk evidence;
- DLA suspension/revocation;
- capacity/exclusivity conflict;
- dispute/case.

HOLD is an explicit remediable state, not silent failure.

## Disputes/remedies

A transaction can route to case/DREP/DAP workflows for misrepresented rights, duplicate exclusivity, payment/refund disputes, non-delivery, entitlement mismatch, unauthorized sublicense or provider execution conflict.

Original transaction events remain in lineage after correction or reversal.

## Accessibility/privacy/support

A public LEX requires accessible listing, checkout and agreement interfaces; clear license-rights summaries; privacy-safe identity verification; support/remedy paths; current terms/disclosures; data-handling controls and anti-fraud/security protections.

## Public-safe listing projection

Can expose:

- safe asset/title;
- licensor identity/brand where intended;
- DLA/license class;
- territory/term/use summary;
- public price/offer;
- availability/currentness;
- safe proof/attestation;
- current version.

Private rights agreements, evidence and protected economics remain restricted.

## Failure modes

- listing published without rights proof -> HOLD/governance defect;
- provider marketplace account not mapped to issuer authority -> deny/hold;
- payment succeeds but rights transfer fails -> compensate/reconcile;
- rights transfer succeeds but fulfillment fails -> remedy/recovery;
- search index stale -> canonical read wins;
- qualification expires -> re-evaluate;
- duplicate transaction -> idempotency/capacity control;
- parent DLA revoked -> child/listing reevaluation;
- provider marketplace disappears -> canonical LEX/DLA state survives.

## Threat model

- counterfeit rights listings;
- account takeover;
- double sale of exclusive rights;
- unauthorized sublicensing;
- payment replay;
- duplicate entitlement;
- hidden term changes;
- price/split manipulation;
- privacy leakage;
- provider lock-in;
- token/rights divergence;
- AI-generated rights metadata presented as proof.

## Test vectors

1. valid rights + active issuer + eligible participant -> transaction can progress;
2. no source rights -> listing cannot activate;
3. duplicate exclusive capacity -> conflict/HOLD;
4. stale qualification -> re-evaluate;
5. payment succeeds + transfer fails -> no entitlement; compensation path;
6. transfer completes + fulfillment fails -> case/remedy;
7. same webhook replayed -> one semantic effect;
8. token representation absent -> LEX can still operate;
9. historical fractional feature requested -> separate legal/economic gate;
10. listing withdrawn -> canonical state changes immediately and index catches up.
