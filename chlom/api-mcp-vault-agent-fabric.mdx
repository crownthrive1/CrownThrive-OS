# CHLOM API, MCP, Vault & Agent Fabric

CHLOM machine execution is deliberately decomposed into public contracts, protected state references, bounded agents, and independently verified factory outputs.

## Machine surfaces

The candidate machine surface registry includes public-safe patterns for:

- identity and provenance resolution;
- Fingerprint verification;
- DLA evaluation;
- policy/compliance evaluation;
- DAIL append candidates;
- evidence verification;
- remedy evaluation;
- commercial-package preparation;
- website-mesh observation.

These are **contracted candidates**, not a claim that a public production endpoint or MCP server is currently active.

## Default access posture

Machine access defaults to `DENY_UNLESS_EXPLICITLY_AUTHORIZED`.

Authorization can depend on:

- identity and credential;
- organization and role;
- environment;
- purpose and field of use;
- data classification;
- territorial or contractual scope;
- request/rate budgets;
- commercial entitlement;
- consent and revocation state.

Technical reachability is not permission.

## Vault boundary

Public repositories and ordinary agent outputs must not carry protected bodies such as:

- credentials and private keys;
- signing secrets;
- private contracts;
- protected evidence;
- private customer/protected-person data;
- private economic and pricing logic;
- private prompts or scoring;
- Fingerprint private derivation;
- confidential implementation and unreleased source.

When protected inputs are needed, agents and factories should receive opaque references or authorized bounded operations rather than raw-secret export.

The current machine-readable CHLOM vault contract is **pending verified runtime binding**. Documentation of the boundary does not fabricate a live vault receipt.

## Identity, DID and Fingerprint

Public machine records may expose stable IDs, DID or equivalent references, public Fingerprint verification references, versions, source references, content digests, and public-safe provenance.

A hash, DID, signature, Fingerprint or DAIL record is evidence in context. It does not automatically prove authorship, ownership, legal identity, exclusivity or enforceability without the controlling evidence and rights chain.

## Agent pack

The first specialized CHLOM candidate pack contains:

- **CHLOM R&D Researcher** — research recovery, comparison, testing and version candidates;
- **CHLOM Rights & Identity Steward** — stable IDs, DIDs, Fingerprints, provenance, ownership evidence and DLA references;
- **CHLOM Compliance Oracle** — advisory condition and evidence evaluation;
- **CHLOM Documentation & Projection Steward** — canon, public/private boundaries, articleization and parent/child projection;
- **CHLOM Commercial Packager** — licensable package and PentaGreen™ handoff preparation;
- **CHLOM Mesh Reliability Agent** — public discovery and interface-reachability observation.

The identities are registered as factory candidates. A manifest does not prove a persistent production worker is currently executing under that identity.

## Factory relationship

```text
source / evidence / current state
        ↓
R&D + identity + compliance agents
        ↓
agent-factory candidate intake
        ↓
Execution Builder / PentaFactory
        ↓
asset candidates
        ↓
independent verification
        ↓
public projection or internal promotion candidate
```

Builders may produce pallets, modules, components, frameworks, plugins, skills, schemas, APIs/MCP candidates, portals, dashboards, wireframes, tests and documentation. They may not certify their own work.

## Plugin and skill model

A public plugin or skill can expose a high-level contract and compatibility method while protected prompts, private scoring, restricted datasets, credentials and confidential implementation remain vault-bounded.

This allows CrownThrive to monetize implementation, integration, support and licensed execution without giving away the protected operating core merely because an interface is documented.

## Economic boundary

Agents and machine interfaces may prepare commercial candidates. PentaGreen™ remains the exclusive CrownThrive SKU issuer, and ECAC controls economic activation. No CHLOM agent or API/MCP candidate may independently activate price, checkout, entitlement, payment, payout or settlement.
