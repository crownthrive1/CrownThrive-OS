## Historical purpose

The DLA Pallet was the historical runtime implementation of CHLOM's **Decentralized Licensing Authority**: issuing, renewing, suspending and revoking machine-readable licenses while enforcing eligibility and license terms.

```text
APPLICANT / ASSET
      |
ELIGIBILITY + IDENTITY + POLICY
      |
      v
HISTORICAL DLA AUTHORITY
      |
      v
DLA PALLET
      |
LICENSE TOKEN / RECORD
      |
ACTIVE / RENEW / SUSPEND / REVOKE
```

## Terminology correction without erasure

Historical DLA must remain preserved as **Decentralized Licensing Authority** in source-era records.

Current CHLOM decomposes the overloaded term:

```text
Licensing Stewardship / Issuer Authority
                    +
Dynamic Licensing Asset (DLA)
```

This article is the historical runtime record. Current machine-readable DLA objects use the Dynamic Licensing Asset meaning.

## Historical license object

Historical sources describe licenses as NFTs/SBTs or on-chain records carrying terms, issuer, validity and transfer conditions.

A public-safe semantic reconstruction:

```yaml
license_id: stable ID
asset_or_right_ref: required
issuer_ref: authorized issuer
holder_ref: subject
scope: structured rights/permission
issued_at: timestamp
expires_at: nullable
transferability: prohibited|conditional|allowed
status: active|suspended|revoked|expired
metadata_ref: required
```

The exact historical Rust struct/storage fields are not fully recovered.

## Issuer authority

The historical DLA assumed approved/staked/governed issuers. Current mapping requires explicit issuer authority without assuming CHM staking.

```text
issuer identity
   |
issuer authority / registry
   |
policy scope
   |
license issuance capability
```

A provider account cannot self-declare issuer authority.

## Renewal

Renewal is a new authorized continuation/version, not merely changing an expiry timestamp with no history.

```text
license v1 expires
    |
renewal eligibility
    |
license v2 / renewed effective state
```

## Revocation

Historical revocation disabled future use while preserving chain history. Current DAIL/P-03 preserve the same non-erasure principle.

## Transferability

Historical DLA distinguished transferable licenses from personal/non-transferable credentials. Transfer conditions can depend on eligibility and LEX policy.

```text
transfer requested
    |
license transferable?
    |
recipient eligible?
    |
policy / compliance pass?
    |
transfer / deny
```

## Sublicensing

Historical CHLOM supports child/sub-license concepts. Current rights conservation is explicit:

```text
child_rights <= parent_rights <= source_rights
```

The historical DLA Pallet is therefore mapped to the current P-03 Rights Graph before DLA creation.

## Metadata relationship

License metadata can include:

- license type;
- scope;
- issuer;
- holder;
- validity;
- transfer/sublicense rules;
- evidence/proof references;
- agreement reference;
- policy version.

Metadata does not override underlying rights evidence.

## Identity relationship

Historical DID/SBT/Fingerprint systems supplied identity/eligibility evidence. Current P-01 identity and credential services replace the requirement for on-chain identity while preserving the semantics.

## Compliance relationship

Historical DLA issuance could call compliance/risk/oracle logic before license activation. Current P-02/Compliance Packs provide the gate.

## Security threats

- unauthorized issuer;
- license mint without source rights;
- metadata substitution;
- revocation bypass;
- stale eligibility;
- transfer of non-transferable license;
- child license exceeding parent scope;
- duplicate issuance;
- issuer key compromise.
