# Wireframe: Validator / Oracle Monitoring & Simulation Console

## Wireframe identity

```yaml
wireframe_id: WIRE-ORACLE-001
source_family: recovered validator/oracle monitoring and simulation interfaces
classification: source_grounded_functional_reconstruction
version: 1.0.0
```

## Purpose

This console institutionalizes CHLOM's recovered validator/oracle monitoring and simulation surface family. It supports external-evidence assurance, source quorum, freshness, contradiction analysis, attestations, model/policy simulation and historical validator-network research without claiming that a live public-chain validator set currently operates.

## Source/oracle registry panel

Display registered sources/oracles, claim domains, current applicability, independence groups, last observation, freshness, failure rate, revocation/suspension state and provider/endpoint aliases. Reliability metrics do not override source applicability or authority.

## Observation stream

Show recent normalized observations with source, subject/claim, time, currentness, evidence digest/reference, contradiction flag and resulting aggregation/hold state. Raw sensitive payloads remain protected.

## Quorum and contradiction panel

Compose source-count requirements, independent-source count, weighted/median aggregation method, current contradiction state and policy thresholds. Material disagreement is surfaced rather than averaged away.

## Validator/reviewer panel

Where human/domain or historical validator roles apply, show assignment, credential/eligibility, independence/conflict state, review/quorum, attestations and any bond/slash research status. Historical economic-security models remain future-gated and cannot be shown as live penalties without activation evidence.

## Simulation workspace

Permit sandbox simulation of:

- source outage/staleness;
- conflicting observations;
- different aggregation methods;
- threshold changes;
- validator/oracle collusion research;
- model/policy outcomes;
- replay/delayed evidence;
- bridge/remote claim inputs.

Simulation outputs are explicitly `SIMULATION` and cannot self-adopt policies, weights or authority.

## Incident and drift panel

Show source compromise, schema drift, dependency outage, model drift, repeated contradiction, replay/security incidents and required remediation/review tasks.

## Historical decentralized lineage

A dedicated historical mode may display BFT/validator research, staking/slashing assumptions and oracle-accountability theorem lineage. It must be visually and semantically separated from current cloud-first operational assurance.

```text
QUORUM / CONTRADICTIONS      VALIDATOR / REVIEWER STATE

```

## Data dependencies

Oracle/source registry, evidence service, attestation records, DAIL, policy engine, reviewer network, model registry, dependency monitoring and sandbox/simulator fixtures.

## Tests

Test insufficient independent sources, stale source, conflicting equal-quality sources, revoked source, correlated aliases, model drift, simulation isolation, historical-mode labeling and restricted evidence redaction.

## Versioning

Source/aggregation policies, models and visual console versions are separate. Historical research state remains source lineage unless separately implemented/certified.
