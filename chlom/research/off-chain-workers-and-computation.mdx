## Source boundary

The recovered CHLOM component atlas identifies **off-chain workers/computation** inside the oracle, Scribe and external-truth architecture. Historical CHLOM engineering sources are Substrate/blockchain-first and reference AI/oracle/external processing, but a standalone off-chain-worker specification with exact worker functions has not been located.

This article therefore preserves the recovered component family and maps it conservatively to current cloud jobs and evidence-driven services without inventing historical worker names or code.

## Research purpose

Off-chain computation exists because not every task belongs inside a deterministic consensus/runtime environment. External API calls, document/evidence retrieval, AI inference, large calculations, indexing, media processing, notifications and other expensive or nondeterministic work can execute outside the canonical state machine and return evidence/results for governed acceptance.

## Historical conceptual pattern

```text
CANONICAL / RUNTIME STATE
      |
      v
OFF-CHAIN JOB REQUEST
      |
      +--> external provider/API
      +--> oracle/source retrieval
      +--> AI/ML processing
      +--> large computation
      |
      v
SIGNED / ATTRIBUTED RESULT
      |
      v
VALIDATION / POLICY / AUTHORITY
      |
      v
CANONICAL EVENT OR HOLD
```

The off-chain result is evidence/candidate state; it cannot directly mutate protected canonical state without validation and authority.

## Determinism and provenance

Off-chain work can be nondeterministic. Consequential results should preserve model/tool/provider version, input snapshot, source evidence, time, output digest/reference and any uncertainty so the result can be reviewed and, where possible, reproduced.

## AI/ML jobs

AI inference is explicitly advisory/evidentiary unless an adopted policy grants bounded automated effect. Model identity/version, feature/evidence refs, uncertainty and explanation/reason codes must accompany consequential outputs.

## Oracle/source jobs

External data retrieval records source registry ID, source time, retrieval time, signature/auth state, freshness, normalized claim and evidence digest. Worker success does not make the source authoritative for every claim.

## Side-effect jobs

Jobs that can call external providers or change state require stronger controls:

- exact action/version binding;
- authority precheck;
- execution-time revalidation;
- semantic idempotency;
- bounded retry;
- rollback/compensation where applicable;
- provider readback;
- DAIL receipt.

A queue retry cannot multiply money, rights or entitlements.

## Scheduling

Scheduled workers follow temporal controls and currentness. A job authorized yesterday can HOLD at execution if rights, authority, evidence or policy changed before the scheduled time.

## Failure handling

Typed states can include:

```text
PENDING
RUNNING
SUCCEEDED_EVIDENCE
SUCCEEDED_ACTION
RETRYABLE_FAILURE
PERMANENT_FAILURE
HOLD_REVIEW
CANCELLED
EXPIRED
DEAD_LETTER
SUPERSEDED
```

A job failure must not be hidden by leaving a stale successful projection active when current verification is mandatory.

## Security boundaries

- least-privilege service identity;
- tenant isolation;
- secret references rather than plaintext secrets;
- egress/provider allowlisting where applicable;
- payload classification and protected result custody;
- timeout/resource caps;
- no arbitrary self-generated authority;
- signed/attributed worker identity;
- audit logs and correlation IDs;
- controlled code/model versions.

## Historical blockchain boundary

Historical Substrate off-chain-worker semantics and current cloud job infrastructure are related architectural patterns but are not identical. No current public-chain runtime or off-chain worker deployment is implied by this mapping.
