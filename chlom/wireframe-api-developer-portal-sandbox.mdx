# Wireframe: CHLOM API / Developer Portal & Sandbox

## Wireframe identity

```yaml
wireframe_id: WIRE-DEV-001
source_family: recovered API/developer portal and sandbox surfaces
classification: source_grounded_functional_reconstruction
version: 1.0.0
```

## Purpose

This portal is the technical implementation surface for developers integrating with CHLOM. It presents registered applications/clients, API and MCP contracts, scopes, sandbox fixtures, events, logs, provider adapters, quotas and certification state without placing runtime secrets or trade-secret algorithms into documentation.

## Application/client dashboard

Show client stable ID, owner/tenant, environment, auth method, granted scopes, current state, credential rotation status, last successful request, last error and usage/rate-limit summary. Secret material is never re-rendered after creation unless an approved secret system explicitly supports it.

## API/MCP contract explorer

Browse versioned operations/tools by domain: identity, rights, DLA, DAIL, policies, evidence, calculations/economics, cases, attestations, adapters and observability. Each contract exposes:

```text
method/tool name
input/output schema
read/write/side-effect class
authority/approval requirements
idempotency expectations
event/DAIL behavior
error taxonomy
version/deprecation state
```

## Schema library

Link SCHEMA-001 onward, event schemas, enum/state definitions, stable ID formats and compatibility notes. A documented schema does not claim its endpoint is deployed unless implementation state is separately evidenced.

## Sandbox

Provide synthetic tenants and fixtures for:

- identity/credential lifecycle;
- source-rights graphs;
- DLA activation and revocation;
- policy PASS/HOLD/DENY;
- webhook duplicates/reversals;
- economic calculation/reconciliation;
- audit/case flows;
- ZK/attestation safe fixtures;
- provider outage and rate-limit cases.

Sandbox data is unmistakably non-production and contains no copied secrets or personal evidence.

## Event/webhook console

Show subscriptions, schema versions, endpoint/auth class, recent deliveries, retry/dead-letter state, signature verification result, latency and semantic idempotency. Payload display is sanitized/redacted.

## Adapter and dependency panel

Display provider-neutral adapter version/compatibility, dependency health, schema drift and capability mapping. Provider-specific configuration remains a replaceable adapter layer.

## Logs and audit

Developers can inspect role-scoped request logs, correlation IDs, error classes and public-safe audit receipts. Sensitive payloads and other tenants' data remain protected.

## Certification panel

Show conformance suite, security review, required scopes, exact release/client version and state: `SANDBOX`, `CONFORMANCE_PASS`, `HOLD`, `CERTIFIABLE`, `PRODUCTION_APPROVED`. A green test alone does not grant production authority.

## Layout

```text
APPLICATIONS / CLIENTS
API + MCP EXPLORER          SCHEMA LIBRARY
SANDBOX / FIXTURES         EVENT / WEBHOOK CONSOLE
ADAPTER HEALTH              LOGS / AUDIT
USAGE / QUOTAS              CERTIFICATION
```

## Tests

Test secret redaction, wrong scope, schema-version mismatch, sandbox/production separation, webhook replay, provider outage, quota semantics, cross-tenant logs and certification for wrong client version.

## Versioning

API, MCP, schema, fixture and adapter versions are first-class; breaking changes use explicit migration/deprecation rather than silent replacement.
