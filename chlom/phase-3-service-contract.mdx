# Phase 3 Service Contract

Phase 3 should implement the institutional model rather than invent a parallel architecture.

## Recommended service sequence

1. **DAIL / event and audit service**
2. **Approval Service**
3. **Rights Registry**
4. **DLA service**
5. **Rules / Policy Registry**
6. **Roles and Authority Service**
7. **Revenue Allocation Registry**
8. **Remedies / Case Service**
9. **Orchestrator**
10. **CrownThrive IO / API / MCP surface**

## Orchestration model

```text
Founder objective
      ↓
CrownThrive OS knowledge + registry lookup
      ↓
Orchestrator
      ↓
CHLOM rights / rules / authority check
      ↓
Specialist agent
      ↓
Human approval when required
      ↓
Codex / MCP execution
      ↓
QA
      ↓
Production action
      ↓
DAIL event + evidence reference
```

## Phase 3 non-negotiables

- no blanket autonomous legal authority
- no rights grant without governed authority
- no silent evidence mutation
- no public-chain or token deployment merely because historical papers describe it
- no production secret in the public documentation repository
- every irreversible action must have a defined owner and approval gate
- every state change should be auditable
- every integration should use stable institutional IDs
- every correction should preserve lineage

## Phase 3 definition of success

Phase 3 succeeds when CrownThrive can register an asset, review its rights, define a rule set, create a governed license object, collect required approvals, record the economic obligations, emit audit events, and apply remedies consistently across connected platforms.

Decentralized settlement can come later. The governance meaning must work first.
