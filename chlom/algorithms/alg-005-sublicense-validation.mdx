# ALG-005 — Sublicense Validation

ALG-005 determines whether a proposed child license can lawfully and contractually descend from an existing parent DLA/license. Its purpose is to stop downstream licenses from inventing rights, surviving longer than their parent, reaching unauthorized territories, or bypassing required approvals.

## Preconditions

The parent license must be located by canonical ID/version and its effective rights must be computed using the rights graph. Provider labels, PDFs or marketplace listings are supporting evidence, not substitutes for the canonical parent state.

## Procedure

```text
function validate_sublicense(parent_dla, requested_child):
    if not parent_dla.active:
        return DENY

    if not parent_dla.sublicensing_allowed:
        return DENY

    if not subset(requested_child.rights, parent_dla.rights):
        return DENY

    if exceeds_term(requested_child, parent_dla):
        return DENY

    if exceeds_territory(requested_child, parent_dla):
        return DENY

    if missing_required_approval(requested_child):
        return HOLD

    return PASS
```

## Required comparisons

The validator should compare at minimum rights type, medium/channel, territory, effective dates, exclusivity, derivative-use scope, sublicensing depth, transferability, prohibited uses and any economic or approval conditions inherited from the parent.

Inheritance is restrictive. If a parent says nothing about a sensitive downstream permission, silence should not be interpreted as permission when the relevant policy requires an affirmative grant.

## Licensee evaluation

A child licensee may have requirements independent of the parent: identity, accreditation, jurisdiction, sanctions screening, platform eligibility, brand standards or other policy controls. A structurally valid child grant is not active until those conditions also pass.

## Failure semantics

Confirmed attempts to exceed parent rights are DENY. Missing approval, stale parent evidence, unresolved rights conflict or ambiguous parent language routes to HOLD where remediation or adjudication is possible.

## DAIL lineage

The validation receipt should reference the exact parent version and the effective-rights calculation. If the parent is later revoked or corrected, affected child licenses must be reevaluated according to the adopted lifecycle policy; historical validation receipts remain preserved.

## Security and abuse controls

The implementation must prevent license-chain laundering, where a broad child grant is created through successive transformations to hide that the original source never granted the right. Depth limits, parent-chain traversal and source-root verification are therefore part of the security model.

## Tests

Test exact subset, partial subset, prohibited sublicense, expired parent, revoked parent, term overrun, territory overrun, channel overrun, missing approval, stale parent, invalid child licensee and a multi-level chain where a grandchild tries to regain a right removed at the child level.

## Versioning

Any change to inheritance, silence/default semantics, or parent-child constraint handling requires a new algorithm version and migration analysis for existing license chains.
