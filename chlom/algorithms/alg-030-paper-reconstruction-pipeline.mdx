# ALG-030 — Paper Reconstruction Pipeline

ALG-030 formalizes how a recovered CHLOM paper, title, attachment, archived Help Center entry or technical source is converted into institutional knowledge without inventing missing content or erasing historical design.

## Core invariants

```text
title recovered != body recovered
historical design != production state
source ambiguity != permission to hallucinate
correction != erasure
```

## Procedure

```text
function reconstruct_paper(reference):
    source = locate_source(reference)

    if not source:
        register_title_only(reference)
        return SOURCE_NOT_LOCATED

    verify_integrity(source)
    extract_text_figures(source)
    map_terminology(source)
    classify_claims(source)
    extract_algorithms_math_ascii(source)
    separate_historical_current(source)
    write_source_grounded_article(source)
    mark_conflicts(source)
    register_founder_adjudication(source)
    return RECONSTRUCTED
```

## Source location

Search retained files, Drive, GitHub/docs, archived exports and other authorized repositories. Match by exact title, aliases, distinctive phrases, document IDs, dates and internal references. Do not merge two similarly named bodies without evidence they are versions of the same work.

## Integrity and provenance

Capture source location, file metadata where available, digest/hash when custody supports it, recovered title, version/date and any duplicate relationships. Duplicate files can be deduplicated as source copies without losing provenance.

## Extraction

Extract full text and meaningful figures/tables/diagrams. For PDFs or visual documents, inspect pages rather than relying only on truncated text. Preserve headings and internal organization before decomposition.

## Terminology mapping

Record historical terminology and current canonical interpretation separately. Examples include historical `DAL` meanings versus current `DAIL`, and historical Decentralized Licensing Authority versus current Dynamic Licensing Asset. Never silently rewrite a quotation or historical source body.

## Claim classification

Each substantive claim is tagged as source-derived historical design, source-derived current rule, illustrative example, derived reconstruction, unresolved conflict, founder-adjudicated rule, implementation evidence or production-verified state.

## Technical asset extraction

Extract and register formulas, algorithms/pseudocode, schemas, state machines, ASCII/visual diagrams, invariants, APIs, modules/pallets, workflows and proprietary/trade-secret markers. Restricted assets are routed to private custody; the public article records only safe lineage/interface information.

## Articleization

A recovered paper can remain as a source-guide article, but each material component should be decomposed into its own canonical article where it represents a distinct institutional object. Master registers are navigation and provenance, not substitutes for individual articles.

## Conflict and adjudication

Conflicts are explicit. Founder rulings append a current interpretation and propagate to dependencies while retaining the earlier record.

## Tests

Test full source, title-only source, duplicate source, conflicting versions, historical acronym conflict, confidential source, missing formula body, scanned/visual source, and source later found after title-only registration.

## Versioning

Reconstruction methodology is versioned. A later, richer recovery updates or adds articles and lineage rather than deleting the record of what was previously known.
