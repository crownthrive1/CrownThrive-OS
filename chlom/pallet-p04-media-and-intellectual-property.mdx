## Purpose

P-04 is CHLOM's capability container for **media and intellectual-property objects after they exist but before downstream licensing, distribution, commercialization or public claims can be treated as institutionally settled**.

It provides a shared model for masters, editions, publications, recordings, visual works, catalogs, derivative assets, contributor relationships, provenance, release state, media-specific rights metadata and evidence handoff to P-03 Rights & Licensing.

```text
CREATE / INGEST MEDIA
        |
        v
CANONICAL ASSET RECORD
        |
        v
PROVENANCE + CONTRIBUTORS
        |
        v
RIGHTS / RELEASE EVIDENCE
        |
        +--> P-03 Rights & Licensing
        |
        v
EDITION / MASTER / DERIVATIVE STATE
        |
        v
DISTRIBUTION / PUBLICATION / LICENSING
        |
        v
USAGE + PERFORMANCE + DAIL EVIDENCE
```

## Source-platform interpretation

### Virality Music

Virality Music contributes music/audio catalog, recording, release, publishing, performance, edition and associated media-lineage use cases. P-04 should not infer music rights merely because a track exists on a provider or platform.

### Melanated Voices / TV

Melanated Voices and related TV/media surfaces contribute editorial, audio, video, creator-submission, cultural-storytelling and broadcast/streaming use cases. Historical MVP acronym variants remain source lineage and must not be confused with `minimum viable product` in engineering contexts.

### CrownThrive Studios

CrownThrive Studios is the current studio/production identity for creative production workflows. Historical `ThriveStudio` references are retained where they occur in source-era material rather than rewritten without lineage.

### Go-Flipbooks

Go-Flipbooks contributes document-to-interactive-publication transformations, editioning, embeds and publication outputs. Conversion does not change underlying ownership or license scope.

### Locticians TV

Locticians TV contributes domain-specific video/tutorial/interview/cultural-media workflows and publication/distribution relationships.

## Master versus edition

A master and an edition are different objects.

```text
MASTER
  |
  +--> Edition A / format A
  +--> Edition B / format B
  +--> Broadcast cut
  +--> Printable edition
  +--> Promotional derivative
```

An edition inherits only the rights permitted by the source/master relationship.

## Provenance

Provenance captures who/what contributed and how the asset was produced.

It can include:

- creator/author/artist;
- producer/editor;
- studio;
- source prompts where institutionally retained;
- AI/tool/provider lineage;
- source recordings/files;
- transformation steps;
- publication/release records;
- import/acquisition source;
- correction/supersession lineage.

Provenance is not equivalent to copyright ownership.

## AI-generated and AI-assisted media

P-04 records provider/source provenance and applicable contractual evidence. It does not promise copyrightability or exclusive ownership merely because CrownThrive stores or publishes the output.

## Rights handoff to P-03

P-04 must not become a duplicate rights ledger.

```text
P-04 says:
"this master, edition and contributor/provenance evidence exists"

P-03 says:
"these verified rights/permissions currently apply"
```

Rights-sensitive publication requires a current P-03 resolution appropriate to the action.

## Release state

```text
DRAFT
  |
SOURCE / PROVENANCE REVIEW
  |
RIGHTS REVIEW
  |
CONTENT / QUALITY REVIEW
  |
RELEASE CANDIDATE
  |
  +--> HOLD
  +--> REJECT / WITHDRAW
  +--> RELEASED
          |
          +--> SUPERSEDED
          +--> WITHDRAWN
          +--> ARCHIVED
```

A provider upload is not automatically a CHLOM `RELEASED` state.

## Publication contract

Before a public edition is represented as released, P-04 can require:

- exact master/edition identity;
- public-safe title/metadata;
- rights release/permission;
- contributor status appropriate to publication;
- content review if applicable;
- delivery/provider readback;
- public URL or distribution evidence when claimed;
- DAIL release event.

## Derivative works

A derivative asset receives its own stable identity and lineage.

```text
SOURCE MASTER
      |
      +--> excerpt
      +--> translation
      +--> adaptation
      +--> remix
      +--> printable
      +--> promotional edit
```

The derivative cannot automatically inherit broader rights than the source.

## Catalog model

A catalog is a collection/projection over canonical assets, not a separate ownership claim.

```yaml
catalog_id: stable ID
name: string
membership_rule_or_list: reference
owner_or_steward_ref: institutional scope
public_projection: optional
version: integer
```

Catalog counts require defined membership rules and `as_of` time.

## Operating procedures

### New media ingest

1. assign canonical media ID;
2. preserve source/master evidence;
3. classify media type;
4. attach contributor/provenance claims;
5. bind provider aliases;
6. resolve P-03 rights state before restricted uses;
7. create edition(s);
8. run release gate;
9. publish through adapter;
10. read back and emit DAIL evidence.

### Edition correction

Corrections create a new edition/version or explicit correction record; the prior released edition remains in lineage.

### Takedown/withdrawal

1. identify exact edition/master;
2. determine authority/reason;
3. preserve evidence;
4. stop new distribution where applicable;
5. request provider removal/disable;
6. read back;
7. update institutional release state;
8. trigger dependent commerce/license reconciliation.

### Provider exit

Export controlled assets/metadata where rights allow, remap aliases, preserve release lineage and re-certify new delivery endpoints.

## Failure modes

### Provider upload with unresolved rights

**Result:** provider upload does not authorize public/commercial release; HOLD institutional release.

### Missing master

**Result:** do not claim a derivative/provider copy is the protected canonical master without evidence.

### Conflicting contributor claims

**Result:** preserve both claims, route to P-03/case workflow and hold affected exploitation where required.

### Broken public link

**Result:** public availability state is not current until delivery is restored/read back.

### Metadata drift

**Result:** reconcile provider metadata against canonical metadata; do not silently import provider changes as truth.

### AI provenance missing

**Result:** mark provenance incomplete rather than inventing generation details.

## Release gates

```text
[ ] canonical master identity resolved
[ ] source files/custody recorded
[ ] provenance state classified
[ ] contributor records attached
[ ] P-03 rights state resolved for intended use
[ ] edition identity/version assigned
[ ] content/release rules satisfied
[ ] provider execution/readback verified
[ ] public metadata projection reviewed
[ ] DAIL release evidence emitted

```

## Invariants

```text
media exists != rights cleared
provider upload != institutional release
contributor != rights owner by default
provenance != ownership
catalog membership != ownership
master != edition
edition != entitlement
AI output != guaranteed copyright
provider metadata != canonical metadata
withdrawal != historical erasure
```

## Current implementation effect

P-04 is a **Pilot** pallet in the July 2026 Technical Build Pack. Individual named media platforms have their own maturity and evidence states; P-04's pilot priority does not homogenize those states or prove complete cross-platform integration.
