## Historical purpose

The Fee Router Pallet was designed to make fee distribution deterministic after a CHLOM transaction or protocol action produced a fee.

```text
QUALIFYING FEE EVENT
      |
      v
FEE SCHEDULE / ROUTE VERSION
      |
      v
FEE ROUTER
      |
 +----+----+----+
 |         |    |
treasury  party other authorized destination
```

Historical token/burn destinations remain source-era concepts; current routing must use current economic authority.

## Fee existence comes before routing

```text
configured route
   !=
valid fee obligation
```

A fee must have an authorized current basis before routing occurs.

## Conservation

For a closed route plan:

```text
sum(routed amounts) + governed remainder = fee basis
```

The schedule defines rounding/remainder semantics.

## Failure cases

### Route percentages do not conserve basis

HOLD; do not silently create/destroy value.

### Destination account/provider unavailable

Hold obligation or route according to explicit fallback policy; do not redirect to an arbitrary account.

### Historical burn route found

Preserve historical record; do not activate without live token/economic authority.

### Duplicate event

Idempotency prevents duplicate fee obligations.

## Security threats

- destination substitution;
- unauthorized schedule update;
- rounding extraction;
- duplicate routing;
- hidden fallback destination;
- provider/account alias drift.

## Public / restricted split

Public-safe:

- route architecture;
- public fee semantics where approved;
- conservation principles.

Restricted:

- confidential fee rates;
- private destinations/account mappings;
- partner economics;
- anti-fraud controls.
