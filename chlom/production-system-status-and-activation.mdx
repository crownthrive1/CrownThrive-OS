## Production gateway

Base route:

```text
https://tzajnzshmtzjenqulehq.supabase.co/functions/v1/chlom-control-plane-v1
```

Routes:

```text
GET  /status
GET  /capabilities
GET  /health
POST /dispatch
```

Every request requires an authenticated Supabase bearer token. Mutation requests additionally require an `Idempotency-Key` header. The gateway forwards the caller identity to the database; it does not use a public service-role credential as the caller.

## Request contract

A read request uses the authenticated session:

```bash
curl \
  --request GET \
  --header "Authorization: Bearer $SUPABASE_ACCESS_TOKEN" \
  "https://tzajnzshmtzjenqulehq.supabase.co/functions/v1/chlom-control-plane-v1/status"
```

A mutation uses an exact action, payload, and stable idempotency key:

```bash
curl \
  --request POST \
  --header "Authorization: Bearer $SUPABASE_ACCESS_TOKEN" \
  --header "Content-Type: application/json" \
  --header "Idempotency-Key: ct-idem:asset-example:v1" \
  --data '{
    "action": "register_asset_binding",
    "payload": {
      "canonical_asset_id": "ct.asset.example",
      "asset_version_ref": "v1",

      "fingerprint_sha256": "<64-lowercase-hex-characters>",

  }' \
  "https://tzajnzshmtzjenqulehq.supabase.co/functions/v1/chlom-control-plane-v1/dispatch"
```

The same operator, action, and idempotency key with the same canonical payload returns the first persisted result. Reuse with a different payload is rejected.

## Production candidate

The following components are implemented or materially developed but are not certified here as an independently operating public Layer-1 network:

- FRAME/native runtime and pallet suite.
- Reproducible release-mode Wasm and canonical chain specification.
- Validator deployment automation.
- Runtime-upgrade and recovery procedures.
- ZK proof circuits and verifier infrastructure.
- Token and NFT provider adapters.

A repository or local test result does not promote these components to public-network production.

## Provider-gated

These predicates require evidence from systems outside the database:

- A real founder sign-in producing a valid Supabase session, followed by an external HTTPS status and mutation canary through this gateway.
- Independently administered validator nodes in distinct failure domains.
- Provider-observed node identities, block production, finality, restart survival, and snapshot recovery.
- Reproducible Wasm and chain-spec byte hashes from independent builders.
- Stripe or other provider transaction, transfer, payout, refund, and dispute receipts.
- Testnet and then bounded production mint receipts read through independent blockchain providers.
- Public-chain anchor transaction and finality receipts.

The authenticated database-context canary proves role, scope, mutation, DAIL, receipt, and replay behavior. It is not represented as a browser-generated founder-session canary.

## Legal and governance-gated

The following cannot be activated by software alone:

- Adjudication of legal ownership or title.
- CHLOM Coin or CHM issuance.
- Transferability or redemption rights.
- Public tokenomics.
- Validator economic incentives.
- Securities, money-transmission, tax, sanctions, AML, consumer-disclosure, or jurisdictional determinations.
- Binding third-party licenses without the required signed instrument and authority.
