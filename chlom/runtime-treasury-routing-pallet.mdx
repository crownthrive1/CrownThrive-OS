## Historical purpose

The Treasury Routing Pallet separated **where protocol-controlled value should go** from the Treasury Pallet's broader custody/governance role. It encoded authorized distribution paths among reserves, programs, incentives, fees and other destinations.

```text
TREASURY / QUALIFYING INFLOW
          |
          v
ROUTING POLICY VERSION
          |
          v
TREASURY ROUTING PALLET
          |
    +-----+-----+-----+
    |           |     |
 reserve     program  other authorized destination
```

## Routing is not authority

A route configuration does not create the right to move value.

```text
route exists
   !=
spend authorized
```

Current P-11 requires economic authority, schedule version and provider/accounting reconciliation.

## Routing versus Fee Router

```text
Fee Router
  routes a defined fee obligation

Treasury Routing Pallet
  routes treasury/inflow/budget value across governed treasury purposes
```

They can share allocation algorithms but are distinct historical modules.

## Conservation

For a closed route plan:

```text
sum(destination allocations) + remainder = governed routing basis
```

Rounding/remainder rules must be deterministic and versioned.

## Failure cases

### Destination invalid/revoked

HOLD route execution and reconcile authority rather than selecting a fallback silently.

### Route sum exceeds basis

DENY/HOLD; do not create unsupported obligations.

### Provider transfer partially succeeds

Reconcile each destination independently and compensate/hold according to P-11 policy.

### Historical incentive destination recovered

Preserve lineage; do not create current payout destination.

## Security threats

- destination substitution;
- unauthorized route update;
- circular routing;
- rounding extraction;
- duplicate execution;
- cross-currency ambiguity;
- hidden fallback account.

## Public / restricted split

Public-safe:

- route architecture;
- public program allocation semantics where approved;
- conservation/versioning principles.

Restricted:

- current routes/percentages;
- private accounts/destinations;
- budget/reserve targets;
- provider/banking mapping;
- protected anti-abuse controls.

