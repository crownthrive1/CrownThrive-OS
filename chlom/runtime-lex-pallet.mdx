## Historical purpose

The historical pallet implemented a marketplace for tokenized licenses/assets. Source-era examples describe:

- creating listings;
- sale, transfer, rental or sublicensing;
- direct purchase and possible bidding;
- escrowed payment;
- compliance eligibility before transfer;
- license validity/revocation checks;
- jurisdiction/credential constraints;
- royalty obligations;
- atomic transfer/release behavior.

The current CHLOM mapping preserves the lifecycle but does not require NFTs, crypto or a public chain.

## Rights gate

LEX cannot list more rights than the source/licensor holds.

```text
LISTED_RIGHTS <= DLA_RIGHTS <= SOURCE_RIGHTS
```

Any contradiction is `HOLD_RIGHTS_CONFLICT`.

## DLA dependency

A listing can reference a current Dynamic Licensing Asset or another governed rights object. Historical license NFTs map to stable asset/DLA records plus optional future token adapters.

```text
historical tokenized license
        |
modern mapping
        v
rights record + DLA + optional provider token alias
```

## Eligibility checks

Before final execution, LEX should resolve:

- listing current and not withdrawn/expired;
- seller authority still valid;
- rights scope still available;
- DLA active and transferable/sublicensable as required;
- buyer credentials/role/territory eligibility;
- policy version current;
- sanctions/risk evidence current when applicable;
- quantity/capacity available;
- agreement/assent valid;
- price/economic activation valid;
- payment state appropriate;
- timelock/review windows satisfied.

## Payment/escrow boundary

Historical sources describe atomic escrow. Current providers may require saga/compensation instead.

```text
PAYMENT AUTHORIZED
      !=
RIGHTS TRANSFERRED
      !=
ENTITLEMENT ACTIVATED
      !=
SETTLED
```

A provider payment success cannot manufacture an entitlement if transfer/rights gates fail.

## Sublicensing and rental

A sublicensing/rental listing must enforce parent constraints:

```text
child term <= remaining parent term
child territory ⊆ parent territory
child permissions ⊆ parent permissions
child transferability <= parent transferability
```

If the parent DLA is suspended/revoked, dependent children require policy-driven reevaluation/remedy.

## Disputes/remedies

LEX transactions can generate disputes about:

- misrepresented rights;
- non-delivery;
- payment failure;
- duplicate/overlapping rights;
- entitlement mismatch;
- cancellation/refund;
- provider execution conflict.

Those route to case/DREP/DAP rather than allowing the marketplace to erase its own history.

## Public-safe pseudocode

```text
purchase(listing, buyer):
  latest = read_canonical_listing(listing.id)
  require latest.active
  require rights_current(latest)
  qualification = evaluate_buyer(latest, buyer)
  if qualification != PASS: return qualification
  agreement = require_valid_assent(latest, buyer)
  payment = hold_payment(latest, buyer)
  transfer = attempt_rights_transfer(latest, buyer)
  if transfer.failed:
      compensate(payment)
      HOLD/FAIL with evidence
  activate_entitlement(transfer)
  reconcile(payment, transfer)
  append_DAIL_receipts()
```

## Failure modes

- stale listing -\> HOLD/re-read;
- seller loses authority -\> listing held/revoked;
- DLA revoked -\> deny execution;
- buyer qualification expires -\> re-evaluate;
- payment succeeds, transfer fails -\> compensate;
- transfer succeeds, provider entitlement fails -\> remedy/recovery path;
- rights overlap discovered after completion -\> dispute/remedy, no silent deletion;
- provider outage -\> transaction held, not automatically denied as user fault.

## Threat model

- chain-of-title fraud;

- double sale of exclusive capacity;
- payment replay;
- front-running/race conditions;
- seller/provider alias substitution;
- unauthorized sublicensing;
- price/split tampering;
- privacy leakage from qualification evidence;
- marketplace admin bypassing CHLOM authority.

## Tests

1. active transferable DLA \+ eligible buyer -\> PASS flow;
2. revoked DLA -\> DENY;
3. seller authority removed -\> HOLD/revoke listing;
4. child rights exceed parent -\> DENY;
5. duplicate purchase on single exclusive capacity -\> one succeeds, other holds/fails;
6. payment success \+ transfer failure -\> compensation;
7. expired qualification -\> re-evaluate;
8. stale search index -\> canonical state wins;
9. provider outage -\> hold/retry, preserve idempotency;
10. dispute -\> linked case and immutable transaction history.

## Current mapping

The current LEX service should remain **rights-first and provider-neutral**. Payment processors, storefronts, NFT standards, wallets and blockchain rails are replaceable adapters. ThriveEvergreen/current economic authority governs economic activation where applicable.
