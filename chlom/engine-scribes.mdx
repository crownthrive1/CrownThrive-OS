## Purpose

A Scribe is a **scoped human evidence contributor/reviewer** who can observe, interpret, document or attest information under a bounded assignment.

```text
CASE / SOURCE / OBJECT / EVENT
          |
          v
SCRIBE ASSIGNMENT
          |
ROLE + DOMAIN + CONFLICT CHECK
          |
          v
EVIDENCE REVIEW / OBSERVATION
          |
          v
SCRIBE RECORD / ATTESTATION CANDIDATE
          |
VERIFICATION / QUORUM IF REQUIRED
          |
          v
DAIL / CASE / ORACLE HUB
```

## What a Scribe is not

A Scribe is not automatically:

- a regulator;
- a judge/arbitrator;
- a licensed professional;
- a final decision authority;
- an oracle source for all domains;
- an employee/contractor merely by role name;
- authorized to view all evidence;
- allowed to publish restricted evidence.

## Domain scope

Examples of possible Scribe domains:

- rights/source provenance;
- licensing evidence;
- media/catalog metadata;
- policy/regulatory source extraction;
- provider state verification;
- identity/credential evidence review;
- audit evidence collection;
- technical/release evidence;
- cultural/canon source interpretation;
- economic/settlement evidence where authorized.

A Scribe assigned to one domain does not inherit authority in another.

## Conflict-of-interest checks

Before assignment/acceptance:

- subject relationship;
- economic interest;
- prior involvement;
- organizational conflict;
- role incompatibility;
- self-review/self-approval risk.

```text
scribe has conflict
   -> recuse / HOLD / assign alternate
```

## Evidence discipline

Scribes should cite/source their work rather than produce untraceable conclusions.

```text
statement
 -> source/evidence ref
 -> extraction/observation method
 -> uncertainty/conflict
 -> reviewer/attestation state
```

## Attestation

A Scribe may be authorized to issue an attestation for certain low/medium-risk facts. Higher-impact facts may require a verifier, quorum, professional reviewer or governance authority.

```text
SCRIBE RECORD
  !=
FINAL INSTITUTIONAL DECISION
```

## Quality/reliability

Quality can be evaluated through:

- evidence completeness;
- correction rate;
- reviewer agreement;
- timeliness;
- conflict disclosure;
- scope compliance;
- source citation quality.

Any numerical quality/reputation model must be separately specified/versioned; no universal score is invented here.

## Correction behavior

A Scribe correction must create lineage:

```text
observation v1
   -> correction reason/evidence
   -> observation v2
```

Original v1 remains available according to classification/audit policy.

## Relationship to OSN

```text
Scribe = human/domain participant
OSN = network coordinating machine sources + Scribes
Oracle Hub = evidence ingestion/normalization service
```

## Relationship to Cognitive Scribes

Cognitive Scribes add AI-assisted retrieval/analysis to the human layer. The human Scribe contract remains distinct so AI assistance does not obscure human responsibility/authority.

## Relationship to cases/audit

Cases and audits can request Scribe assignments for evidence collection or review. Scribes do not own case disposition merely because they contributed evidence.

## Failure modes

- no qualified Scribe -\> HOLD/route alternate;
- source inaccessible -\> HOLD;
- conflict discovered -\> recuse;
- unsupported assertion -\> reject/challenge;
- restricted evidence copied into public record -\> security/privacy incident;
- assignment scope exceeded -\> reject out-of-scope claims;
- Scribe unavailable past SLA -\> reassign/escalate;
- evidence later corrected -\> propagate correction lineage.

## Threat model

- bribery/collusion;
- fabricated evidence;
- copy/paste without source verification;
- hidden conflicts;
- privilege abuse;
- data exfiltration;
- AI-generated hallucination submitted as observed fact;
- reputation gaming;
- one Scribe becoming single point of truth.

## Test vectors

1. qualified unconflicted Scribe \+ valid source -\> observation accepted;
2. no source refs for factual claim -\> challenge/reject;
3. conflict detected -\> recusal;
4. Scribe outside domain -\> no authoritative use;
5. restricted evidence -\> restricted storage/public redaction;
6. AI-assisted note unsupported by source -\> not accepted as fact;
7. correction -\> append new version;
8. two Scribes conflict -\> create conflict set/review;
9. Scribe attestation beyond authority ceiling -\> reject;
10. case disposition uses Scribe evidence but separate decision authority.

## Restricted companion

May contain Scribe identities, private assignments, source access, conflict disclosures, reviewer-quality data, confidential evidence, security incidents and contractual/professional details.
