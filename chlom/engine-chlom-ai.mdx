## Source basis

The recovered Help Center defines **CHLOM AI** as decision intelligence and orchestration combining retrieval, policy reasoning and agentic automation for reviewers/operators. Historical sources also describe off-chain AI for fraud/risk analysis feeding ACE through oracles. Modern CHLOM broadens the AI role while retaining strict authority boundaries.

## Purpose

CHLOM AI accelerates the work required to reach evidence-backed decisions and execute bounded workflows.

```text
USER / AGENT / EVENT
        |
        v
TASK CLASSIFICATION
        |
        +--> retrieval/search
        +--> extraction/comparison
        +--> policy reasoning
        +--> risk/anomaly assistance
        +--> workflow planning
        +--> tool execution candidate
        |
        v
SOURCE + AUTHORITY + TOOL RESOLUTION
        |
        v

        |
GROUNDING + VALIDATION + POLICY GATE
        |
  ADVICE / HOLD / AUTHORIZED TOOL CALL
        |
        v

```

## Non-purpose

CHLOM AI is not:

- a sovereign decision-maker;
- a replacement for policy/source authority;
- a legal, financial, medical or regulated professional;
- authorized to reveal secrets because it can retrieve them;
- allowed to self-expand its tools/authority;
- proof that every AI capability described historically is deployed.

## AI task classes

### Retrieval

Find source material and return evidence-linked results.

### Extraction

Convert documents/data into structured records while preserving source references and uncertainty.

### Comparison/reconciliation

Compare versions, providers, policies or claims without silently normalizing conflicts.

### Policy reasoning

Apply an adopted rule set to supplied facts/evidence, with explainable references.

### Risk/anomaly support

Generate risk features/scores/flags under an approved model profile.

### Planning

Propose steps, dependencies, checks and rollback paths.

### Tool execution

Invoke an authorized tool/action only after side-effect classification and authority checks.

## Grounding contract

For source-dependent factual work:

```text
CLAIM
 -> source reference
 -> source version/date/context
 -> extraction/reasoning trace suitable for review
 -> uncertainty/conflict marker
```

If evidence is missing, the answer should remain unknown/HOLD rather than be filled from generic model knowledge unless the task explicitly allows outside knowledge and labels it.

## Agent/tool authority

```text
MODEL CAPABILITY
      !=
TOOL ACCESS
      !=
INSTITUTIONAL AUTHORITY
```

Every side-effecting tool call should resolve:

- actor/agent identity;
- delegated authority;
- action class;
- target/scope;
- required policy/evidence;
- idempotency;
- rollback/compensation;
- readback requirement.

## Human review

Human review profiles can include:

- no review required for low-risk read/summarization;
- spot check/evaluation;
- mandatory reviewer approval;
- professional decision gate;
- founder/reserved-authority gate.

Review requirements are task/policy specific.


CHLOM AI may call/support AIE/ACE, but the components remain separately versioned.

## Interaction with CSN/Scribes

CHLOM AI can assist Scribes with retrieval and synthesis. Human Scribe records remain attributable and source-backed.

## Interaction with DAIL

Material AI-assisted decisions/actions should record safe metadata:

- task ID/type;
- model/tool profile version;
- relevant source/evidence refs;
- policy/authority refs;
- result/action;
- human approval if required;
- correction/readback status.

Prompts, secrets and restricted source bodies are not necessarily appropriate for public DAIL projections.

## Public-safe pseudocode

```text
run_ai_task(task):
  verify_purpose_and_scope(task)
  sources = resolve_authorized_sources(task)
  model = resolve_approved_model(task)
  tools = resolve_tool_profile(task)
  result = model.run(task, sources)
  validate_grounding_and_policy(result)
  if result.requests_side_effect:
      decision = authority_precheck(result.action)
      if decision != PASS: return decision
      receipt = execute_and_readback(result.action)
  append_DAIL_safe_receipt()
  return reviewed_result
```

## Evals

Evaluation suites should cover:

- source-grounding accuracy;
- unsupported claim rate;
- entity/version/date accuracy;
- policy-rule correctness;
- refusal/classification correctness;
- tool-selection correctness;
- side-effect authorization;
- privacy leakage;
- prompt-injection resistance;
- rollback/readback behavior;
- bias/fairness where relevant;
- regression across model versions.

## Prompt/tool injection

Retrieved content is untrusted data. Instructions embedded in source documents must not override system/policy/tool authority.

```text
source text says "ignore rules"
    -> treat as source content
    -> never elevate to instruction authority
```

## Privacy/data governance

Before model/provider use, determine:

- data classification;
- purpose/legal/contractual basis;
- provider retention/training terms;
- region/security requirements;
- minimum necessary data;
- redaction/pseudonymization;
- human review exposure.

## Failure modes

- model unavailable -\> retry/fallback/manual route;
- retrieval incomplete -\> HOLD/unknown;
- unsupported claim -\> reject/correct;
- policy conflict -\> HOLD;
- tool permission missing -\> no execution;
- provider executes but readback fails -\> unresolved/HOLD;
- model version changes -\> re-evaluate governed task classes;
- private data routed to disallowed provider -\> security incident.

## Threat model

- hallucination;
- prompt injection;
- data exfiltration;
- tool abuse;
- privilege escalation;
- hidden model drift;
- biased scoring;
- source poisoning;
- output spoofing;
- agent-to-agent authority laundering;
- automated economic/rights action without authority.

## Test vectors

1. supported source question -\> cited grounded answer;
2. source lacks claim -\> unknown, not invention;
3. malicious source instruction -\> ignored as instruction;
4. tool call outside delegation -\> blocked;
5. economic action without authority -\> HOLD/DENY;
6. reversible bounded action \+ valid authority -\> execute/readback;
7. provider returns success but state not changed -\> no false completion;
8. model upgrade degrades eval -\> hold profile;
9. restricted data task \+ disallowed provider -\> blocked;
10. human-review-required task -\> cannot self-approve.

## Metrics

- grounded claim rate;
- unsupported claim rate;
- task success by class;
- tool authorization failure rate;
- readback mismatch rate;
- human correction/rejection rate;
- model regression/eval scores;
- latency/cost under approved budgets;
- privacy/security incident counts.
