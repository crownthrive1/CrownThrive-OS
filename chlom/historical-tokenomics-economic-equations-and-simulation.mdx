```text
allocation_j = S0 * a_j
```

This is archival arithmetic, not a current cap table or offering.

## Supply dynamics

Historical Appendix D defines:

```text
issuance_year = iS
burn_year = bN
ΔS = iS - bN
S_next = S + ΔS
```

Where:

- `S` = current supply;
- `i` = annual inflation rate;
- `b` = average amount burned per transaction;
- `N` = transaction count per year.

If slash burns or other burns exist:

```text
ΔS = iS - bN - B_slash - B_other
```

The extended equation is a reconstruction consistent with source mechanics.

## Equilibrium

The historical balancing target is approximately:

```text
iS ≈ bN
```

At that point:

```text
ΔS ≈ 0
```

Source example:

```text
i = 5%
S = 1,000,000,000
issuance = 50,000,000

b = 0.001
N = 50,000,000,000
burn = 50,000,000

net = 0
```

## Staking APY

Historical formula:

```text
APY_nominal = annual_reward_emission / average_staked_supply
```

Source example:

```text
reward_pool = 200,000,000
release horizon = 4 years
annual emission ≈ 50,000,000
average staked supply = 500,000,000
APY ≈ 10%
```

### Dilution-aware return

A derived analysis can separate nominal staking return from supply inflation:

```text
real_network_share_return ≈ (1 + staking_apy) / (1 + supply_growth_rate) - 1
```

This is an analytical reconstruction, not a source formula.

## Slashing

Historical source suggests illustrative slash fractions in roughly the `1%–10%` range depending on severity.

```text
slash = stake * slash_rate
stake_after = stake - slash
```

A governed system would require:

```text
misconduct_evidence
+ policy_version
+ authority
+ appeal/remedy rules
+ settlement decision
```

before a slash can execute.

## Fee burn

Historical whitepaper example:

```text
burn_fraction ≈ 20% of transaction fees
```

General model:

```text
burn_amount_t = fee_t * burn_fraction
annual_burn = Σ burn_amount_t
```

The historical percentage is not current.

## Dynamic fee stabilization

Genesis explores targeting a roughly stable effective fiat transaction cost, giving `$0.10` as an example target median fee.

A derived proportional controller:

```text
error_t = observed_fee_usd_t - target_fee_usd
fee_adjustment_t = -k_p * error_t
fee_units_next = clamp(fee_units_current + fee_adjustment_t,
                       min_fee,
                       max_fee)
```

A smoother proportional-integral form could be modeled as:

```text
adjustment_t = -k_p * error_t - k_i * Σ error
```

These are **control-system reconstructions** added for engineering clarity, not source-adopted monetary policy.

## Modified equation-of-exchange research

Genesis suggests a simplified conceptual relationship:

```text
P * T = k
```

This is used to reason about price, usage and economic feedback.

A more complete analysis would require supply velocity, unit definitions, market liquidity and demand functions. The original expression should be preserved as a conceptual source model rather than upgraded silently into formal economics.

## Burn-to-issuance ratio

Useful derived diagnostic:

```text
BIR = annual_burn / annual_issuance
```

Interpretation:

```text
BIR < 1  -> inflationary pressure from this mechanism
BIR = 1  -> issuance/burn balance
BIR > 1  -> deflationary pressure from this mechanism
```

This metric ignores market demand and other flows.

## Staking participation ratio

```text
stake_ratio = staked_supply / circulating_supply
```

The source argues that lower participation raises nominal yield under a fixed reward flow, creating an equilibrium incentive for more staking.

## Reward-per-stake unit

```text
reward_rate_per_unit = annual_rewards / total_stake
validator_reward_i ≈ eligible_stake_i * reward_rate_per_unit * performance_factor_i
```

`performance_factor_i` is a derived reconstruction consistent with validator uptime/performance concepts, not a historical formula.

## CHM compliance bond

Historical CHM may serve as a bond for high-responsibility actors such as issuers or oracles.

Generic bond-at-risk model:

```text
required_bond = base_bond * role_risk_multiplier * exposure_multiplier
```

This is a candidate reconstruction, not source-adopted CHM economics.

## Governance-participation economics

Historical design separates:

This attempts to buffer operational fee demand from governance speculation.

No claim is made that such separation guarantees price stability.

## Treasury allocation

Historical Prospectus discusses operating, incentive, reserve/insurance and growth funds.

Generic model:

```text
I = treasury inflow
w_ops + w_incentive + w_reserve + w_growth = 1

A_ops       = I * w_ops
A_incentive = I * w_incentive
A_reserve   = I * w_reserve
A_growth    = I * w_growth
```

Weights are policy parameters, not source-mandated percentages unless explicitly stated.

## Reserve-target feedback

Derived control:

```text
reserve_ratio = reserve_assets / modeled_exposure

if reserve_ratio < minimum:
    increase reserve allocation
elif reserve_ratio > target_max:
    permit policy-approved overflow
```

A finance/professional authority would be needed before using such a model for real-world reserves.

## Historical investor-protection pool

Genesis explores a micro-fee example:

```text
protection_pool_contribution = trade_value * 0.0001
```

because `0.01% = 0.0001` as a fraction.

The source describes this as an illustrative automated insurance/protection concept.

It is not a current insurance product or promise.

## Claims-cap model

A generic derived protection-pool model could be:

```text
eligible_payout = min(validated_loss, per_claim_cap, remaining_pool_capacity)
```

Real insurance activity would require separate legal, regulatory, actuarial and underwriting authority.

## Treasury market-operations research

Genesis discusses potential treasury buybacks or liquidity support during extreme market moves.

A conceptual trigger could be:

```text
price_deviation = (market_price - reference_price) / reference_price
```

but the source does not establish a production trigger, oracle method or execution policy.

## Liquidity depth

A derived market-health metric:

```text
slippage(q) = |execution_price(q) - mid_price| / mid_price
```

Historical text suggests deeper liquidity could reduce volatility; it does not specify a required market-making algorithm.

## Scenario simulator

Every historical token model should be simulated across at least:

```text
LOW ADOPTION
BASE ADOPTION
HIGH ADOPTION
STRESS / ATTACK
MARKET CRASH
ORACLE FAILURE
GOVERNANCE PARAMETER ERROR
```

A simple yearly recurrence:

```text
for year t:
    issuance_t = i_t * S_t
    burn_t = b_t * N_t
    slash_burn_t = modeled_slash_t
    S_(t+1) = S_t + issuance_t - burn_t - slash_burn_t
```

Outputs should include:

- supply;
- inflation/deflation;
- staking APY;
- treasury balance;
- reserve ratio;
- average fee burden;
- burn/issuance ratio;
- concentration indicators.

## Sensitivity analysis

For any parameter `x` and output `y`:

```text
sensitivity ≈ Δy / Δx
```

Priority sensitivities include:

- inflation rate;
- burn fraction;
- transaction volume;
- staking participation;
- treasury allocation weights;
- price volatility;
- oracle error;
- slash frequency.

## Concentration metric

A derived candidate concentration metric is Herfindahl-Hirschman style:

```text
HHI = Σ share_i²
```

This could measure validator, token-holder or oracle-provider concentration if such analysis were later needed.

It is not a historical CHLOM formula.

## Tokenomics failure modes

```text
High issuance + low usage
        -> persistent inflation

High burn + high usage
        -> excessive deflation / fee burden

Low stake participation
        -> security / concentration risk

High reward concentration
        -> centralization

Oracle-dependent fee control
        -> oracle manipulation risk

Treasury intervention
        -> governance / custody / market-risk exposure
```
