## Purpose

The Ledger Explorer is the searchable human interface for CHLOM's **current DAIL event/evidence/correction lineage** and, where appropriate, historical runtime/anchor projections.

Current DAIL means **Decentralized Autonomous Information Ledger**. The explorer must not imply that every DAIL record lives on a public blockchain.

```text
CANONICAL EVENTS / DECISIONS / CORRECTIONS
                 |
                 v
                DAIL
                 |
      +----------+----------+
      |                     |
 public-safe index      role-restricted index
      |                     |
      +----------+----------+
                 |
            LEDGER EXPLORER
```

## Primary roles

```text
public verifier
participant / object owner
issuer / reviewer
auditor / support operator
developer / integrator
governance reviewer
```

Each role receives a projection filtered by authorization and classification.

## Search identities

Search may support authorized lookup by:

- DAIL event/receipt ID;
- DLA ID;
- asset ID;
- case/dispute ID;
- attestation ID;
- proposal/decision ID;
- transaction/settlement ID;
- public identity/issuer alias;
- digest/hash where intentionally indexed;
- provider alias where role permits.

Search does not expose restricted objects through autocomplete/count leakage.

Core columns:


Sensitive fields appear only where the actor has access.

## Correction lineage

The explorer must visibly represent correction without erasure.

```text
EVENT E1
  |
  +--> CORRECTION C1
          |
          +--> SUPERSEDED BY E2
```

Display:

```text
Original record retained
Current interpretation/status: corrected
Correction reason class
Correction authority/reference
```

Do not make the corrected original disappear from authorized history.

## Historical versus current views

Where historical source/run-time records are imported, label them explicitly:

```text
Historical source-era record
Historical runtime concept
Current DAIL record
External anchor reference
```

No historical DAL event should be relabeled as if it were originally a DAIL event.

## Public-safe explorer

Public mode can expose only intentionally public records:

```text
public attestation state
public DLA verification
public governance decision
public proof/anchor digest
public asset/license lifecycle summary
```

It must not expose:

- private identity/evidence;
- confidential agreements;
- private cases;
- protected model/risk information;
- financial records not cleared for public release.

## Restricted explorer

Authorized internal users can search a richer projection. Sensitive evidence opens through Evidence Vault controls rather than inline public URLs.

## Event type detail

Event names are versioned:

```text
ct.domain.event.v1
```

The explorer can link to schema documentation and show whether the event type is active, deprecated or historical.

## Object lineage

For an object such as a DLA:

```text

  |

  |

```

The explorer can project the chronological events while the License Detail page provides current business context.

## Evidence references

Evidence rows show:

```text
evidence ID
type
classification
integrity/digest status
public/restricted
current/superseded
```

No automatic raw download for restricted evidence.

## Attestations

The explorer can render attestation verification:

```text
attestation ID
schema/version
issuer
subject/public alias
valid/revoked/superseded
proof/anchor
```

Attestation validity is not universal truth/authorization.

## Hash / anchor view

If a record has a Merkle/external anchor:

```text
record digest
batch/root reference
anchor system
anchor time/status
verification instructions
```

Anchor presence proves integrity/anchoring semantics, not factual correctness.

## Filtering

Filters should include:

- event domain/type;
- status;
- date/time;
- object type;
- public/restricted classification for authorized users;
- actor/issuer;
- policy/version;
- corrected/superseded;
- provider mismatch;
- anchored/unanchored if meaningful.

## Pagination / streaming

Large event histories use cursor pagination or streaming. New events should not reorder a user's current investigation unexpectedly; the UI can freeze an `as_of` view with explicit refresh.

## Export

Exports carry:

- query scope;
- as-of time;
- field/classification schema;
- generated-at;
- export ID/digest where required.

Restricted export is audited.

## Empty/error states

Distinguish:

- no records match;
- index syncing;
- canonical service unavailable;
- role has no access;
- requested record was corrected/superseded;
- public record withdrawn from public projection but preserved internally.

## Index/canonical boundary

```text
Explorer index
   !=
canonical state
```

Material downstream actions never use the explorer projection as sole authority; they re-read the appropriate domain service.

## Events

The explorer itself may use UX/search analytics under purpose/privacy rules, while domain events are sourced from DAIL/event bus. Export actions can generate audited events such as:

```text
ct.explorer.restricted_export.generated.v1
```

## Accessibility

- tables/filters keyboard accessible;
- timelines have list alternative;
- graphs have text relationships;
- digest/code fields readable/copyable;
- status/correction states not color-only;
- large event lists support skip navigation.

## Responsive behavior

Mobile uses search \+ filter drawer \+ record cards. Technical payload JSON can open in a dedicated scrollable panel.

## Restricted companion

Contains internal investigator fields, security/incident event types, protected correlation graphs, private finance/case events, raw-provider evidence links and forensic export controls.

## Invariants

```text
DAIL != blockchain requirement
explorer index != canonical state
record hash != factual truth
correction != deletion
public projection != full ledger
attestation valid != action authorized
historical DAL != current DAIL silently
reconstructed layout != recovered original visual
```
